# 공개 가중치 LLM 파동과 서로 다른 공개 범위

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[concept.대규모-언어-모델|대규모 언어 모델]], [[source.089|LLaMA 1과 제한적 공개 가중치 연구 배포]]<br>
> **읽고 나면:** 2023년 MPT·Falcon·Mistral 공개를 시간·model·data·code·license 축으로 나누고, architecture·benchmark·배포 가능성에 붙는 조건을 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 핵심 문장

2023년의 이른바 **공개 LLM 파동**은 하나의 조직적 운동이나 단일 license 체계가 아니었다. MosaicML의 MPT-7B, Technology Innovation Institute(TII)의 Falcon-7B·40B, MosaicML의 MPT-30B, Mistral AI의 Mistral 7B가 차례로 공개됐지만, 개발 일정·학습 data·architecture·배포 조건은 서로 달랐다. 공개된 것도 model weight, code, data, 학습 절차와 license 중 일부였으며 그 조합은 제품군과 variant마다 달랐다.

따라서 이 시기를 모두 **오픈 소스(open source)**라는 한 단어로 묶기보다 **공개 가중치(open weight)**와 artifact별 권리를 따로 기록하는 편이 정확하다. Weight를 내려받을 수 있다는 사실은 학습 corpus의 재배포, 전체 training log의 공개, 같은 결과의 재현, 상업적 이용과 안전한 제품 배포를 자동으로 뜻하지 않는다.

### 네 공개를 읽는 시간축

| 공개 시점 | 제품군 | 직접 확인되는 공개의 중심 | 시간축에서 주의할 점 |
| --- | --- | --- | --- |
| 2023-05-05 | MPT-7B 제품군 | Base weight·llm-foundry code와 여러 fine-tuned variant | Base와 Instruct·Chat의 license가 같지 않다. |
| 2023-05-25 전후 | Falcon-7B·40B | Weight와 custom model code, model card | Falcon-40B 학습은 2022년 12월 시작돼 LLaMA 1 공개보다 앞선다. |
| 2023-05-31 | Falcon license 변경 | Falcon-7B·40B의 Apache 2.0 전환 | 최초 공개 조건과 나중 조건을 구분해야 한다. |
| 2023-06-22 | MPT-30B 제품군 | 8K base와 Instruct·Chat variant | 7B와 30B의 학습량·문맥 길이·배치 조건을 섞지 않는다. |
| 2023-09-27 | Mistral 7B | Apache 2.0 weight와 reference implementation | 학습 corpus·token 수·compute는 공개되지 않았다. |

이 순서는 [[089_LLaMA 1과 제한적 공개 가중치 연구 배포|LLaMA 1]] 이후 여러 공개가 이어졌다는 연표를 보여 준다. 그러나 연표만으로 “LLaMA가 모든 개발을 시작했다”거나 회사들이 공동 계획 아래 움직였다고 결론 내릴 수 없다. Falcon-40B의 선행 학습 일정과 MPT의 수개월 개발 기간은 적어도 그런 단선적 인과를 지지하지 않는다.

### 이 문서의 범위

이 문서는 MPT-7B·30B, Falcon-7B·40B와 Mistral 7B의 **2023년 당시 base model과 명시된 variant**를 비교한다. 후속 Falcon·Mistral 세대, community quantization, 제3자 fine-tune이나 현재 서비스 조건을 소급하지 않는다. 사회적 민주화나 산업 혁신을 성과로 가정하지 않고, 1차 자료가 확인하는 artifact·실험·license 경계까지만 다룬다.

## 2단계 — 작동 원리

### 먼저 공개 장부를 분리한다

Model 공개는 예·아니오 한 칸으로 판정하지 않고 다음 순서로 읽는다.

1. **Weight:** 어느 checkpoint를 내려받아 실행·변형할 수 있는가?
2. **License:** Base와 Instruct·Chat 등 각 artifact에 어떤 사용·수정·재배포 조건이 붙는가?
3. **Code:** Model definition, training framework, inference reference 중 무엇이 공개됐는가?
4. **Data:** 원천 이름과 비율만 공개됐는가, 정제 recipe나 실제 dataset도 받을 수 있는가?
5. **과정 기록:** Token 수·hardware·시간·hyperparameter·checkpoint와 log가 어느 수준까지 남았는가?

2023년 5·6월 최초 발표 당시 MPT-7B·30B base는 Apache 2.0이었지만, 각 제품군의 Instruct variant는 CC-BY-SA-3.0, Chat variant는 CC-BY-NC-SA-4.0이었다. 이후 repository의 현재 license와 역사적 release 조건을 같은 시점으로 읽지 않는다. 하나의 제품군 이름만 보고 모든 checkpoint의 commercial use를 같게 판정할 수 없다. Falcon-7B·40B도 최초 custom license와 2023년 5월 31일 이후 Apache 2.0 상태를 시간에 따라 나눠야 한다. Mistral 7B의 base weight와 reference implementation은 Apache 2.0으로 공개됐지만, 이 license가 공개되지 않은 training corpus를 대신 제공하지는 않는다.

### Architecture 선택은 서로 다른 병목을 겨냥한다

세 제품군은 모두 decoder-only Transformer 계열이지만 효율을 만드는 층이 달랐다.

- MPT는 **선형 편향을 이용한 어텐션(Attention with Linear Biases, ALiBi)**을 사용한다. ALiBi는 position embedding을 학습하는 대신 head별 고정 기울기로 query–key score에 거리에 비례한 penalty를 더한다. 이는 MPT가 발명한 학습 가능한 bias가 아니라 Press 등이 먼저 제안한 고정 규칙이다.
- Falcon은 rotary position embedding(RoPE), [[FlashAttention]] kernel과 **다중 쿼리 어텐션(Multi-Query Attention, MQA)**을 결합했다. MQA는 여러 query head가 더 적은 key·value head를 공유해 inference의 KV cache와 memory bandwidth를 줄이는 구조 선택이다.
- Mistral 7B는 **그룹 쿼리 어텐션(Grouped-Query Attention, GQA)**과 **슬라이딩 윈도 어텐션(Sliding Window Attention, SWA)**을 사용한다. GQA는 MHA와 MQA 사이에서 query head를 여러 KV group에 배정하고, SWA는 각 layer가 직전 4,096개 hidden state만 직접 보게 한다.
- [[FlashAttention]]은 같은 attention 계산을 GPU 메모리 계층에 맞춰 재배치하는 I/O 인지형 kernel이다. ALiBi·MQA·GQA·SWA처럼 model이 연결하거나 저장하는 범위를 결정하는 architecture 선택과 같은 항목으로 세지 않는다.

어떤 기법도 제품군 이름과 동시에 처음 생긴 것으로 쓰지 않는다. ALiBi, GQA와 sliding/local attention에는 각각 선행 연구가 있고 MPT·Mistral은 이를 선택·조합했다. 새 model의 성과가 각 요소 하나의 독립 인과 효과였다고 말하려면 별도 ablation이 필요하다.

### Local 실행은 가능성이지 결과 보장이 아니다

Weight와 실행 code가 있으면 API만 제공되는 model보다 local inspection·fine-tuning·배포의 선택지가 넓어진다. 그러나 실제 실행에는 precision, quantization, KV cache, batch, context, GPU memory와 kernel 지원이 함께 작용한다. MPT-30B model card가 든 구체적 예는 16-bit에서 A100-80GB 한 대, 8-bit에서 A100-40GB 한 대다. 이는 일반 consumer PC 전체에 대한 검증이 아니다.

Local 실행은 data가 조직 밖으로 나가지 않는 구성을 설계할 **여지**를 주지만 privacy를 자동 보장하지도 않는다. Logging, retrieval store, telemetry, access control과 fine-tuning data 처리까지 포함한 system 설계가 필요하다. 같은 이유로 weight 공개만으로 총비용 절감, enterprise adoption이나 장기 유지보수 성과를 확정할 수 없다.

## 3단계 — 기술과 근거

### MPT-7B와 MPT-30B를 한 수치로 합치지 않는다

| 항목 | MPT-7B base | MPT-30B base |
| --- | ---: | ---: |
| 실제 parameter | 약 6.7B | 약 29.95B |
| 사전학습량 | 1T token | 1T token을 2K 길이로 학습한 뒤 50B token을 8K 길이로 추가 학습, 합계 1.05T |
| Base context | 2,048 | 8,192 |
| 주요 attention 선택 | ALiBi·FlashAttention | ALiBi·FlashAttention |
| 공개 license | Apache 2.0 | Apache 2.0 |

MPT-7B의 1T-token mixture는 영어 text와 code의 10개 subset으로 구성됐다. MPT-7B 발표가 기록한 **440대 A100-40GB와 약 9.5일이라는 수치**는 7B base run의 조건이다. 이 수치를 MPT-30B에 옮기거나 제품군 전체의 일반 훈련비로 부르지 않는다. MPT-30B의 8K도 7B base의 원래 문맥 길이가 아니며, MPT-7B-StoryWriter의 65K·84K fine-tuning 사례와도 구분한다.

Variant는 base checkpoint 위의 별도 artifact다. 2023년 최초 출시 당시 Instruct와 Chat은 서로 다른 fine-tuning data와 license를 사용했으며, Chat은 비상업 조항이 있는 CC-BY-NC-SA-4.0이었다. 따라서 “MPT는 모두 Apache 2.0이라 상업 사용 가능하다”는 문장은 release 시점·base와 fine-tuned checkpoint의 차이를 지운다.

### Falcon은 RefinedWeb만으로 학습한 model이 아니다

| 항목 | Falcon-7B | Falcon-40B |
| --- | ---: | ---: |
| 학습 token | 1.5T | 1T |
| Data mixture | RefinedWeb 영어 79%, books 7%, conversations 6%, code 3%, French 3%, technical 2% | RefinedWeb 영어 75%, 유럽 언어 web 7%, books 6%, conversations 5%, code 5%, technical 2% |
| 학습 hardware·기간 | 384대 A100-40GB, 약 2주 | 384대 A100-40GB, 약 2개월 |
| 주요 구조 | RoPE·FlashAttention·MQA·parallel attention/MLP | RoPE·FlashAttention·MQA·parallel attention/MLP |

RefinedWeb 연구는 Common Crawl에서 filtering과 deduplication을 거쳐 약 5T token 규모의 pool을 만들었다. 공개 extract는 그 전부가 아니라 tokenizer에 따라 약 500–650B, 통상 600B token으로 설명되는 부분이다. 더구나 위 표의 production Falcon은 RefinedWeb에 books·conversation·code·technical corpus 등을 섞었다. Web-only ablation의 결과를 Falcon-7B·40B 전체 성능이 web 정제만으로 생겼다는 증거로 바꾸지 않는다.

Falcon-40B 학습은 2022년 12월 시작됐고 Falcon-7B run은 2023년 3월에 진행됐다. 이 일정은 2023년 2월 LLaMA 1 공개 뒤에 개발이 일제히 시작됐다는 서사와 맞지 않는다. 또한 두 규모는 token 수와 mixture 비율이 다르므로 “같은 data를 크기만 바꿔 학습했다”고 단순화할 수 없다.

### Mistral 7B의 효율 수치와 미공개 장부

Mistral 7B는 실제 약 7.3B parameter, 32개 query head와 8개 key-value head, 최대 position 32,768과 sliding window 4,096을 사용한다. 고정 window는 rolling buffer로 KV cache 크기를 제한한다. 공식 발표의 16K sequence·4K window에서 약 2배 속도, 32K에서 rolling cache memory 약 8배 절감은 수정한 FlashAttention/xFormers 구현과 특정 실험 조건의 결과다. 모든 hardware·batch·context에서 유지되는 상수가 아니다.

공식 논문과 발표는 training corpus 구성, 총 token 수, 전체 compute와 hardware 장부를 공개하지 않았다. Weight와 reference implementation이 Apache 2.0이라는 사실만으로 이 model을 처음부터 재학습할 수 있는 data·recipe가 모두 공개됐다고 평가할 수 없다. MPT와 Falcon의 공개 수치가 더 많다는 사실도 완전한 재현을 뜻하지는 않지만, Mistral의 미공개 항목과는 분명히 다른 상태다.

### Benchmark는 비교군과 반례를 붙여 읽는다

Mistral 논문 Table 2는 저자들이 같은 evaluation pipeline으로 다시 실행한 Mistral 7B와 Llama 계열의 과제별 결과를 제시한다. Mistral 7B는 Llama 2 13B보다 MMLU에서 60.1 대 55.6, HellaSwag 81.3 대 80.7, HumanEval 30.5 대 18.9, GSM8K 52.2 대 34.3 등 대부분 항목에서 높았다. 그러나 NaturalQuestions는 28.8 대 29.0으로 조금 낮았다. 공식 홍보문의 “all benchmarks”를 개별 표의 반례 없이 반복하지 않는다.

이 비교군은 주로 Llama 2 13B, 공개되지 않은 Llama 2 34B 대신 LLaMA 1 34B, CodeLlama 7B였다. 당시 proprietary frontier model과 동일 조건에서 포괄적 parity를 입증한 시험이 아니다. 평가도 영어와 code 중심이며 multilingual 능력을 검증하지 않았다. MPT·Falcon의 보고 benchmark 역시 model version, prompt, shot 수, evaluation harness가 다르므로 서로 다른 표의 점수를 하나의 league table처럼 직접 정렬하지 않는다.

## 검증과 한계

### 원 웹글의 검증 정정

- **MPT·Falcon·Mistral은 모두 같은 의미의 open-source model이었다:** 공개 weight, code, data와 license를 분리해야 한다. 같은 제품군 안에서도 base·Instruct·Chat 조건이 다를 수 있다.
- **LLaMA 공개가 후속 개발을 시작시켰고 조직들이 조율된 노력으로 model을 만들었다:** 공개 순서만으로 직접 인과나 coordination을 입증할 수 없다. Falcon-40B 학습 시작은 LLaMA 1 발표보다 이르다.
- **MPT-7B는 정확히 7B이고 모든 MPT가 440대 A100에서 9.5일 학습됐다:** 실제 base는 약 6.7B이며 해당 hardware·기간은 MPT-7B run의 기록이다.
- **MPT는 전 제품군이 상업 이용 가능한 Apache 2.0이었다:** 2023년 최초 발표 당시 base와 llm-foundry는 Apache 2.0이지만 Instruct·Chat variant에는 다른 Creative Commons license가 붙었다. 현재 repository 상태를 그 역사적 조건에 소급하지 않는다.
- **Falcon의 성능은 공개된 RefinedWeb만으로 설명된다:** 공개 extract는 전체 5T 처리 pool의 일부이고, production Falcon은 별도 curated corpus를 섞었다.
- **ALiBi는 학습되는 position bias이고 MPT가 만들었다:** Head별 기울기는 고정되어 있으며 Press 등의 선행 연구가 제안했다.
- **Mistral이 GQA·SWA를 발명했다:** 두 구조 모두 선행 연구가 있다. Mistral의 기여는 이를 7.3B recipe와 kernel·cache 구현에 결합한 데 있다.
- **Mistral의 긴 문맥 성능은 32K 전체를 매 layer에서 dense attention한 결과다:** 최대 position은 32,768이지만 각 layer의 직접 window는 4,096다.
- **Mistral 7B가 Llama 2 13B와 proprietary model을 모든 지표에서 능가했다:** NaturalQuestions 반례가 있고, 공식 표의 직접 비교군과 protocol 범위를 넘어 proprietary parity를 결론 낼 수 없다.
- **모두 multilingual model로 검증됐다:** Falcon mixture 일부의 비영어 data와 multilingual 능력 평가를 같은 것으로 볼 수 없으며, Mistral 표도 multilingual benchmark를 제공하지 않는다.
- **일반 consumer hardware에서 쉽게 실행·fine-tune된다:** 공개 자료의 구체적 예에는 A100급 장치와 정밀도 조건이 포함된다. Quantization·offloading·제3자 port는 별도 검증 대상이다.

### Safety와 배포 책임

Base checkpoint는 next-token prediction model이지 검증된 assistant가 아니다. Instruction-tuned variant도 자동으로 안전해지지 않는다. Mistral 공식 발표는 Mistral 7B Instruct가 moderation mechanism을 갖지 않는다고 명시했다. Falcon model card도 base를 production에 그대로 배치하기보다 목적별 fine-tuning과 guardrail이 필요하다고 경고한다.

Safety는 적어도 세 층으로 나눠야 한다. 첫째는 base model의 사전학습 data와 행동, 둘째는 instruction tuning·preference alignment 같은 post-training, 셋째는 input/output filtering·권한·monitoring을 포함한 deployment control이다. 하나의 공개 license나 local 실행 가능성이 이 세 층을 대신하지 않는다.

### 확인되는 영향과 아직 남는 질문

확인되는 변화는 연구자와 개발자가 API 응답을 넘어서 weight를 실행·검사·변형할 선택지가 늘었다는 것이다. Apache 2.0 base checkpoint와 training·inference code의 공개는 제한적 연구 license보다 더 넓은 재사용 경로를 열었다. 동시에 variant별 license, 부분 data 공개와 누락된 training log는 [[공개 가중치와 재현 가능성은 같은 축인가|재현 가능성]]을 별도 문제로 남겼다.

반면 공개가 총비용을 낮췄는지, privacy를 향상했는지, 특정 산업의 채택을 만들었는지는 이 model card와 논문만으로 입증되지 않는다. 그런 결론에는 실제 deployment 구성, 운영 비용, 보안 사고, 조직별 채택 자료와 시간에 따른 비교가 필요하다. “파동”은 공개 수와 선택지의 증가를 묘사하는 이름이지 사회적 효과가 이미 측정됐다는 뜻이 아니다.
