# 통합 멀티모달 아키텍처의 공유 범위와 입출력 경계

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[concept.멀티모달-대규모-언어-모델|멀티모달 대규모 언어 모델]], [[concept.transformer|Transformer]]<br>
> **읽고 나면:** ‘통합 멀티모달’을 공유 embedding·공유 core·공유 token과 목적함수·제품 interface로 분해하고, 2024년 기원설과 효율·인간 수준·응용 성과에 관한 주장을 1차 자료의 범위로 교정할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 2024년은 탄생보다 설계 분화와 제품 노출의 시점이다

원 웹글은 책 목차에서 2024년 장으로 분류되지만 실제 게시일은 2025년 9월 15일이다. 글은 2024년에 text·image·audio·video를 하나의 architecture로 처리하는 돌파구가 일어나 ‘진정한 멀티모달 유창성’이 시작됐다고 설명한다. 그러나 2021년 [[CLIP]]은 image와 text를 joint embedding에 정렬했고, 2022년 [[Flamingo]]는 image·video와 text가 깊게 상호작용하는 gated cross-attention model을 공개했다. 2023년 ImageBind는 여섯 modality의 표현을 한 embedding space에 묶었고, Gemini 1.0과 Unified-IO 2도 2023년 12월에 공개됐다. 따라서 이 글은 2024년 당시 기록이 아니라 2025년에 작성된 2024년 회고로 읽어야 한다.

2024년에 확인되는 변화는 하나의 표준 architecture가 갑자기 발명된 사건이 아니다. GPT-4o는 회사 발표상 text·vision·audio를 단일 신경망에서 end-to-end로 학습한 제품 model이었고, Chameleon은 image·text token의 early fusion을, Emu3는 image·text·video의 next-token modeling을 공개했다. 이 사례들은 **무엇을 공유하는가**, **어떤 modality를 입력·출력하는가**, **어디까지 공개됐는가**가 서로 다르다.

따라서 2024년은 여러 통합 전략이 연구와 제품에서 눈에 띄게 분화·확장된 시점으로 쓰는 편이 정확하다. 원 웹글에서 보존할 핵심 질문은 ‘분리 model을 통합 model이 대체했는가’가 아니라 **multimodal system 안에서 representation·attention·weight·objective·interface 가운데 무엇이 실제로 공유되는가**다.

### 핵심 문장

- ‘통합’은 하나의 architecture 이름이 아니다. Shared embedding, shared backbone, shared token vocabulary, shared objective, shared checkpoint와 unified product interface는 별개 축이다.
- Modality별 tokenizer·encoder가 남아 있어도 shared core에서 깊은 상호작용을 할 수 있다. 반대로 vector 차원이나 chat 화면이 같아도 내부 계산이 하나라는 뜻은 아니다.
- Input modality, output modality, training modality와 실제 rollout modality를 각각 기록해야 한다.
- Joint embedding은 retrieval·classification에 쓸 수 있지만 그 자체가 open-ended 생성 model이나 세계 이해의 증거는 아니다.
- Dense attention의 weight가 달라진다고 계산 자체가 동적으로 건너뛰어지는 것은 아니다. 효율 우위는 token 수·encoder·decoder·hardware를 포함한 측정으로 확인해야 한다.
- 일부 benchmark의 강한 결과, 유창한 demo와 human-level multimodal understanding은 같은 주장이 아니다.

### ‘통합’이라는 말을 여섯 장부로 나눈다

| 공유 대상 | 확인 질문 | 그 자체로 보장하지 않는 것 |
| --- | --- | --- |
| Representation | Modality별 출력이 비교 가능한 joint embedding에 정렬되는가? | 단일 encoder, 생성, 인과 이해 |
| Sequence interface | 서로 다른 token이 같은 sequence·차원으로 들어가는가? | 동일 tokenizer, 동일 의미 단위 |
| Core weights | 여러 modality가 같은 Transformer layer를 통과하는가? | Pixel·waveform부터 완전한 단일 경로 |
| Training objective | 하나의 loss 또는 mixture로 공동 최적화되는가? | 모든 modality의 균등한 성능 |
| Checkpoint·decoder | 한 checkpoint가 여러 방향의 입출력을 직접 생성하는가? | 제품에서 모든 방향이 공개됨 |
| Product interface | 사용자가 한 대화면에서 여러 media를 다루는가? | 내부 model·tool·후처리가 하나임 |

## 2단계 — 작동 원리

### 공통 core 앞뒤의 modality 경계를 찾는다

일반적인 통합 system은 다음처럼 쓸 수 있다.

$$
z_m=T_m(x_m),
\qquad
h=F_\theta(z_{m_1},\ldots,z_{m_k}),
\qquad
y_o=H_o(h)
$$

$T_m$은 text tokenizer, vision encoder·VQ tokenizer, audio codec처럼 modality $m$의 raw input을 model representation으로 바꾼다. $F_\theta$는 일부 또는 전체 modality가 공유하는 core이고, $H_o$는 text head·image decoder·audio codec decoder·action head 같은 output 경계다.

‘단일 Transformer’라는 설명은 주로 $F_\theta$의 공유를 뜻한다. $T_m$과 $H_o$가 modality마다 달라질 수 있으므로 pixel·waveform·text가 처음부터 끝까지 같은 연산을 거친다고 확대하면 안 된다. Chameleon과 Emu3도 image를 discrete token으로 만드는 별도 tokenizer를 사용한다.

### 융합 시점과 부품 수는 같은 축이 아니다

Late fusion은 modality별 예측이나 높은 수준 representation을 마지막에 합친다. Early fusion은 낮은 수준 또는 token 단계에서 한 sequence를 만들고 shared layer가 상호작용하게 한다. Intermediate fusion과 cross-attention은 별도 stream을 유지하면서 중간 layer에서 정보를 주고받는다.

이 분류는 ‘model 하나 대 여러 model’과 일치하지 않는다. [[Flamingo]]는 동결된 vision encoder와 언어 model을 유지하지만, 언어 hidden state가 여러 layer의 gated cross-attention으로 visual memory를 읽는다. 이는 단순한 결과 결합이 아니다. 반대로 ImageBind는 여섯 modality를 joint embedding에 정렬하지만 modality별 encoder와 projection을 사용하며, 기본 model은 multimodal sequence를 생성하지 않는다.

### Shared embedding·shared dimension·shared semantics를 구분한다

Joint embedding 학습은 대응하는 pair의 score를 높이는 식으로 나타낼 수 있다.

$$
s(x_i,x_j)=
\frac{E_i(x_i)^\top E_j(x_j)}
{\lVert E_i(x_i)\rVert\lVert E_j(x_j)\rVert}
$$

[[CLIP]]은 image·text 이중 encoder를 대조 학습하고, ImageBind는 image를 binding modality로 삼아 text·audio·depth·thermal·IMU representation을 정렬했다. ImageBind가 모든 modality pair의 동시 자료를 요구하지 않았다는 결과는 joint space의 유용성을 보여 준다. 그러나 서로 다른 encoder의 출력이 가까워졌다는 사실만으로 token별 alignment, open-ended generation, 물리적 인과관계나 사람과 같은 개념 구조가 입증되지는 않는다.

### 입출력·학습·출시를 네 줄로 기록한다

하나의 model 설명에는 최소한 다음 네 줄이 필요하다.

1. **Training modalities:** 어떤 종류의 자료가 joint pretraining·post-training에 쓰였는가?
2. **Accepted inputs:** 어떤 조합을 checkpoint 또는 연구 protocol이 실제로 받는가?
3. **Generated outputs:** 어떤 modality를 같은 checkpoint가 직접 생성하는가?
4. **Released surface:** 발표 당시 제품·API에서 사용자가 실제로 쓸 수 있었는가?

GPT-4o 발표는 가능한 model input을 text·audio·image·video, output을 text·audio·image로 설명했다. 동시에 출시 당일에는 text·image input과 text output을 먼저 공개하고 audio·video 기능은 단계적으로 배포한다고 명시했다. Architecture claim, model capability와 product availability를 한 문장으로 합치면 시점과 범위를 모두 잃는다.

[[107_GPT-4o의 단일 신경망 공표와 실시간 멀티모달 배포 경계]]가 보여 주듯 평가에는 다섯째 줄도 필요하다. GPT-4o System Card의 여러 audio 평가는 text benchmark를 TTS 입력으로 바꾸고 출력 transcript를 채점했다. 이 경우 accepted input과 generated output은 audio여도 scoring oracle은 text에 놓인다. **평가 입력·출력·채점 modality와 변환기**를 함께 기록해야 음향 안전·지연·내용 정확성을 하나의 “멀티모달 점수”로 합치지 않을 수 있다.

## 3단계 — 기술과 근거

### 2021–2024년 사례는 서로 다른 통합을 가리킨다

| 공개 시점 | 사례 | 실제로 공유·결합한 것 | 입출력·공개 경계 |
| ---: | --- | --- | --- |
| 2021 | [[CLIP]] | 별도 image·text encoder를 대조 목적의 joint embedding에 정렬 | Image·text→similarity; open-ended generator가 아님 |
| 2022 | [[Flamingo]] | 동결 vision encoder·LM 사이에 학습되는 Resampler와 gated cross-attention | Image·video·text→text; modular하지만 deep fusion |
| 2023 | ImageBind | Image-paired data로 여섯 modality별 encoder·projection을 joint embedding에 정렬 | Retrieval·classification·composition 중심; 자체 생성 decoder 없음 |
| 2023-12 | Gemini 1.0 | 보고서상 image·audio·video·text를 공동 학습한 decoder-only Transformer 계열 | Pretrained family는 interleaved text·image native output을 기술하지만 post-trained API·Apps Model Card는 generated text output; 구현 세부 제한 공개 |
| 2023-12 | Unified-IO 2 | Text·action token, pretrained ViT·AST의 image·audio input embedding과 VQ-GAN image·audio output token을 한 encoder-decoder의 denoising mixture로 학습 | Text·image·audio·video/interleaved input→text·action·audio·image·label output; 120개가 넘는 dataset·220개 task |
| 2024-05 | GPT-4o | 회사 발표상 text·vision·audio를 한 신경망에서 end-to-end 학습 | 폭넓은 model I/O를 공표했으나 출시 기능은 단계적; 내부 세부 비공개 |
| 2024-05 | Chameleon | Discrete image·text·code token을 한 autoregressive sequence에서 early fusion | Image·text 이해·생성; 별도 image tokenizer, audio·video 없음 |
| 2024-09 | Emu3 | Image·text·video discrete token을 단일 8B Transformer family의 next-token 목적으로 학습 | 별도 vision tokenizer·audio 없음; 공개 post-training checkpoint는 이해용 Chat과 image 생성용 Gen으로 분리 |

Unified-IO 2와 Gemini 1.0이 2023년 12월에 공개됐다는 사실만으로도 2024년 단일 기원설은 성립하지 않는다. 반대로 이 표가 통합 model의 완전한 최초 계보를 정하는 것도 아니다. 여기서는 원 웹글의 2024년 범위를 검증하는 데 필요한 공개 사례만 비교한다.

### ‘통합 token 공간’도 최소 세 뜻이 있다

1. **공통 차원:** 서로 다른 feature를 같은 hidden width로 projection한다.
2. **공통 sequence:** Modality tag와 position을 가진 token을 interleave하고 같은 attention graph에 넣는다.
3. **공통 vocabulary·생성 목적:** Discrete token을 같은 autoregressive head 또는 encoder-decoder objective로 예측한다.

LLaVA처럼 projected visual feature를 language embedding sequence에 넣는 방식, Flamingo처럼 visual memory를 별도 key/value로 읽는 방식, Unified-IO 2처럼 연속 modality input embedding과 discrete output을 encoder-decoder denoising으로 잇는 방식, Chameleon·Emu3처럼 interleaved token을 next-token prediction으로 다루는 방식은 계산 경로가 다르다. 모두를 ‘같은 token space’로 부르면 tokenizer·attention mask·loss·decoder의 차이를 잃는다.

### Attention weight는 자동 compute routing이 아니다

원 웹글은 attention이 현재 modality와 과제에 따라 계산 자원을 동적으로 배분해 통합 model을 더 효율적으로 만든다고 주장한다. Dense self-attention에서 score가 작아져도 일반적으로 query–key score와 value aggregation 계산은 수행된다. 실제 token이나 expert 계산을 건너뛰려면 sparse attention, token pruning, routing, frame sampling 또는 별도 conditional-compute mechanism이 필요하다.

효율은 다음 항을 함께 측정해야 한다.

- Image resolution·patch 수, video frame rate·길이, audio sample·codec token 수
- Modality encoder·tokenizer와 output decoder의 parameter·FLOP·memory
- Shared core의 sequence length와 attention pattern
- Batch, hardware, precision, cache, streaming latency와 동시 사용자 조건
- 한 system이 실제로 수행하는 input→output 방향과 품질 목표

단일 checkpoint가 운영 복잡성을 줄일 수는 있다. 그러나 여러 modality token이 긴 dense sequence를 만들면 전문 model 조합보다 비쌀 수도 있다. Architecture label만으로 어느 쪽이 효율적인지 정할 수 없다.

### 평가는 modality pair와 방향별로 쪼갠다

‘멀티모달 성능’ 하나 대신 다음과 같은 cell을 따로 둔다.

| 평가 cell | 대표 질문 | 숨기기 쉬운 실패 |
| --- | --- | --- |
| Image→text | OCR·caption·VQA·chart 값이 맞는가? | 언어 prior로 보이지 않는 내용을 생성 |
| Text→image | Prompt의 객체·관계·문자를 보존하는가? | 미학 점수가 compositional failure를 가림 |
| Audio→text | 화자·배경음·언어·시간 정렬을 보존하는가? | 전사 정확도가 억양·paralinguistic 정보 손실을 숨김 |
| Video→text | 사건 순서와 긴 시간 의존성을 추적하는가? | Frame sampling으로 결정 순간 누락 |
| Interleaved input | Modality가 충돌할 때 근거를 선택하는가? | 한 modality를 무시해도 dataset shortcut으로 정답 |
| Mixed output | Text·image·audio 사이의 내용·시간 일관성이 있는가? | 각 output 품질은 높지만 서로 모순 |

‘Human-level’이라면 어떤 cell, dataset, metric, prompt, resolution, judge와 human baseline인지 밝혀야 한다. Chameleon·Emu3 같은 논문의 강한 task 결과는 해당 protocol에서의 비교이며, 모든 modality 조합의 견고한 이해나 일반 지능을 입증하지 않는다.

### 응용 가능성과 현장 효과를 분리한다

통합 input은 문서의 text·표·image를 함께 읽거나, 음성과 화면을 동시에 조건으로 답하거나, media 사이의 content workflow를 연결하는 데 유용할 수 있다. 그러나 원 웹글의 교육·접근성·의료·robotics·autonomous vehicle·smart-home 서술에는 application별 model, protocol, baseline, 사용자 연구, 안전 결과와 배포 통계가 없다.

접근성은 description의 자연스러움뿐 아니라 장애 당사자가 놓친 중요한 정보와 위험한 오류를 측정해야 한다. 교육은 답변 품질과 실제 학습 성과를, 의료는 임상 외부 검증·책임·privacy를, robotics와 차량은 perception benchmark가 아니라 closed-loop intervention과 failure safety를 요구한다. 가능한 사용례를 이미 달성된 변혁으로 바꾸지 않는다.

## 검증과 한계

### 원 웹글의 주요 정정

- **이 글은 2024년에 쓰인 동시대 기록이다:** 실제 게시일은 2025-09-15이며, 2024는 책의 사건 연도 표지다. 후대 회고와 당시 공개 자료를 구분한다.
- **통합 멀티모달 architecture는 2024년에 등장했다:** CLIP·Flamingo·ImageBind가 앞섰고, Gemini 1.0·Unified-IO 2도 2023년 12월에 공개됐다. 2024년은 GPT-4o·Chameleon·Emu3처럼 서로 다른 전략이 두드러진 시점이다.
- **GPT-4V는 별도 경로를 마지막에 결합했다:** GPT-4 technical report는 구체적 architecture와 training method를 공개하지 않았다. 외부 행동에서 fusion 위치를 역추론하지 않는다.
- **통합 model은 별도 encoder와 fusion을 제거했다:** ImageBind·Flamingo뿐 아니라 discrete-token model도 modality tokenizer·encoder·decoder를 남길 수 있다.
- **공유 representation에서는 같은 개념이 같은 embedding을 갖는다:** 대조 목적이 관련 pair를 가까이 만들 수 있지만, vector proximity를 동일한 개념 구조나 인과 이해로 확대할 수 없다.
- **Cross-modal attention은 2024년의 새 발명이다:** Flamingo는 2022년에 gated cross-attention으로 interleaved image·video–text 문맥을 처리했다.
- **Attention이 compute를 동적으로 배분한다:** Dense attention의 weight는 정보 혼합 계수다. Sparse routing이 없다면 낮은 weight가 해당 token 계산을 생략한다는 뜻이 아니다.
- **통합 architecture가 언제나 더 효율적이다:** Token length·encoder·decoder·hardware·quality 조건이 없는 일반 비교다.
- **하나의 model이 text·image·audio·video를 모두 이해하고 생성한다:** Model마다 입출력 방향이 다르며 ImageBind·Gemini 1.0·Chameleon·Emu3의 coverage도 서로 다르다.
- **Gemini 1.0은 text만 출력했거나 모든 제품이 image도 출력했다:** Technical report의 pretrained family는 native interleaved text·image output을 기술하지만, Model Card의 post-trained API·Apps surface는 generated text output으로 기록한다.
- **Emu3의 한 8B checkpoint가 지각과 생성을 모두 담당했다:** 공통 next-token architecture와 base family를 공유해도 공개 post-training weight는 understanding용 Emu3-Chat과 image generation용 Emu3-Gen으로 나뉜다.
- **2024년 model이 human-level multimodal fluency에 도달했다:** 이를 포괄하는 단일 평가가 제시되지 않았다. Task별 점수를 일반적 이해로 확대하지 않는다.
- **교육·접근성·창작·robotics·차량을 이미 변혁했다:** 원 웹글은 현장 효과·안전·광범위한 채택을 뒷받침할 자료를 제시하지 않는다.
- **통합 표현이 현대 architecture의 단일 표준이 됐다:** Joint embedding, bridge model, early-fusion generative model과 proprietary product system이 병존한다.
- **여러 modality 처리는 더 인간 같은 이해나 일반 지능의 증거다:** Sensor channel 수와 grounding·causal model·reliability는 별도 주장이다.

### 공개 자료가 남기는 한계

GPT-4와 GPT-4o는 내부 architecture·tokenizer·training data·loss와 ablation을 충분히 공개하지 않았다. 회사가 밝힌 end-to-end·single-network 범위는 인용할 수 있지만 공개 model의 layer diagram처럼 세부를 채울 수는 없다. Gemini 1.0 보고서도 high-level architecture와 multimodal 평가를 제공하되 modality interface의 모든 구현 세부를 공개하지 않는다.

Unified-IO 2·Chameleon·Emu3는 구조와 평가를 더 많이 공개하지만 서로 다른 dataset mixture·parameter 규모·alignment와 decoding protocol을 사용한다. 한 논문의 benchmark 우위를 ‘통합이 전문 model보다 항상 낫다’는 보편 명제로 바꾸지 않는다.

원 웹글은 특정 landmark model·표·metric을 거의 제시하지 않으므로, 실제 결과라기보다 여러 연구 방향을 합친 개념 서술에 가깝다. 이 소스 노트는 2024년 전체의 완전한 survey나 현재 제품 기능 목록이 아니라, 원문이 제기한 통합 주장의 증거 경계를 정리한다.

### 남는 질문

서로 다른 modality의 token budget을 공정하게 배분하는 법, 특정 channel을 무시하는 shortcut을 탐지하는 법, mixed output의 시간·사실 일관성을 평가하는 법, 새 modality를 추가할 때 기존 능력의 negative transfer를 막는 법은 열린 문제다. 또한 system이 한 checkpoint인지보다 사용자가 받는 결과가 어떤 encoder·tool·policy·decoder를 거쳤는지 추적할 provenance가 중요하다.
