# HELM과 다차원 언어 모델 평가

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[GLUE와 SuperGLUE]], [[067_GPT-3와 문맥 내 학습]]<br>
> **읽고 나면:** HELM이 16개 핵심 시나리오와 26개 표적 시나리오를 일곱 메트릭·표준화된 적응 절차로 평가한 방식과, 그 결과가 안전 인증이나 보편 순위를 뜻하지 않는 이유를 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 핵심 문장

Liang 등은 2022년 arXiv로 처음 공개하고 2023년 TMLR에 출판한 HELM(Holistic Evaluation of Language Models)에서 **평가할 사용 사례와 가치 기준을 먼저 분류하고, 같은 조건에서 여러 모델을 여러 메트릭으로 조밀하게 비교하는 방법**을 제안했다. HELM은 단일 점수가 아니라 시나리오와 메트릭의 행렬을 남긴다. 어떤 모델이 정확도에서는 앞서도 효율성·공정성·독성에서는 다른 양상을 보일 수 있기 때문이다.

초기 HELM은 16개 핵심 시나리오와 26개 표적 시나리오, 모두 42개 시나리오에서 12개 조직이 만든 30개 모델을 평가했다. 핵심 시나리오에는 가능한 범위에서 정확도·보정·강건성·공정성·편향·독성·효율성의 일곱 메트릭 범주를 적용했다. 가능한 112개 핵심 시나리오–메트릭 조합 가운데 실제 측정은 98개, 즉 87.5%였다.

### 왜 중요했는가

[[060_GLUE와 SuperGLUE의 집계 평가|GLUE와 SuperGLUE]]는 여러 영어 자연어 이해 과제를 공통 형식과 집계 점수로 비교하게 했다. 그러나 범용 생성 모델이 확산되자 서로 다른 과제뿐 아니라 prompt, 예시 수, 답안 제시 방식, 확률 접근 가능 여부와 API 조건도 결과를 크게 바꾸었다. 모델마다 유리한 일부 benchmark만 보고하면 표의 차이가 모델 역량인지 평가 조건인지 구분하기 어려웠다.

HELM이 제시한 답은 평가 항목을 무작정 늘리는 것이 아니었다. **넓은 범위를 택하되 빠진 영역을 명시하고, 정확도 밖의 가치를 같은 시나리오에서 재며, 모델 간 적응 절차를 통제하는 것**이었다. 이는 “인간처럼 보이는가”라는 한 행동 기준에서 과제·위험·비용별 증거로 이동하는 [[튜링 테스트와 LLM 평가]]의 문제의식과도 연결된다.

이 연구는 [[스탠퍼드 대학교|스탠퍼드]] CRFM이 중심이 된 다기관 협업으로 수행됐다. 같은 연구센터의 [[076_파운데이션 모델 보고서와 AI 생태계|파운데이션 모델 보고서]]가 제기한 내재·외재 평가와 정확도 밖의 가치 문제와 함께 읽을 수 있지만, HELM 결과도 특정 prompt와 benchmark에서 관측한 모델 행동이지 완성된 배포 시스템의 효용·위험을 대신하지 않는다.

### 이 문서의 범위

이 문서는 원 논문이 보고한 HELM 초기 평가를 다룬다. 오늘날의 HELM Classic, HELM Lite나 의료·비전·장문 맥락용 후속 suite를 초기 결과와 섞지 않는다. 또한 HELM을 모든 언어와 실제 배포 상황을 포괄한 안전 인증으로 해석하지 않는다. 논문 자체가 선택의 불완전성과 누락된 시나리오·메트릭·모델을 명시했다.

## 2단계 — 작동 원리

### 분류에서 결과 행렬까지

HELM의 평가 흐름은 다음 다섯 단계로 읽을 수 있다.

1. **시나리오 공간을 분류한다.** 시나리오는 과제(task)·도메인(domain)·언어(language)의 조합이다.
2. **범위와 실행 가능성을 기준으로 구체적 평가 대상을 고른다.** 선택하지 못한 영역도 누락 목록으로 남긴다.
3. **범용 모델을 시나리오에 적용할 방법을 정한다.** 적용 가능한 시나리오의 공통 비교에서는 단순한 5-shot prompting을 기본으로 삼았다.
4. **가능한 여러 메트릭을 같은 시나리오에서 계산한다.** 정확도만 별도 표에 두지 않고 위험과 비용을 함께 본다.
5. **점수와 원시 prompt·completion을 공개한다.** 집계표에서 개별 예시로 내려가 오류와 측정 방식을 감사할 수 있게 한다.

핵심 평가의 5-shot 표준화는 다섯 개의 문맥 예시와 같은 prompt를 모델 비교의 공통 조건으로 둔다는 뜻이다. 모든 모델의 최적 사용법을 찾았다는 뜻은 아니다. 표적 평가 가운데 허위정보·코드 생성처럼 과제별 적응 절차를 쓴 경우도 있다.

### 핵심 시나리오와 표적 평가

| 구분 | 규모 | 목적 | 읽을 때 주의할 점 |
| --- | ---: | --- | --- |
| 핵심 시나리오 | 16개 | 같은 사용 사례에서 여러 메트릭을 함께 측정 | `core`는 더 근본적인 과제라는 뜻이 아니라 다중 메트릭을 적용하는 집합이라는 뜻이다. |
| 표적 평가 | 7개 평가·26개 추가 시나리오 | 언어 이해, 지식, 추론, 암기·저작권, 허위정보, 편향, 독성을 더 깊게 검사 | 모든 일곱 메트릭을 반복하는 대신 특정 능력이나 위험을 분리해 본다. |
| 전체 | 42개 시나리오 | 30개 모델을 공통 장부에 놓음 | 가능한 모든 사용 사례·언어·위험을 열거한 전집이 아니다. |

핵심 시나리오는 질의응답, 정보 검색, 요약, 감성 분석, 독성 탐지, 언어 모델링의 여섯 사용자 대면 과제를 포함했다. 도메인은 여러 종류였지만 언어 범위는 영어였고, 아프리카계 미국인 영어 등 영어 변이 일부를 다루었다. 따라서 `holistic`은 모든 언어를 포함했다는 뜻이 아니라 **선택한 범위와 빠진 범위를 함께 드러내는 설계 원칙**이다.

### 일곱 메트릭은 서로 다른 질문이다

| 메트릭 범주 | HELM이 묻는 대표 질문 |
| --- | --- |
| 정확도(accuracy) | 과제의 정답·참조·목표를 얼마나 잘 충족하는가? |
| 보정(calibration) | 예측 확률과 실제 정답 빈도가 얼마나 대응하는가? |
| 강건성(robustness) | 의미 보존·의미 변화 교란에서 예측이 기대한 방식으로 유지되거나 바뀌는가? |
| 공정성(fairness) | 사회 집단을 바꾼 반사실 입력이나 집단별 자료에서 과제 정확도 격차가 나타나는가? |
| 편향(bias) | 생성 언어에서 인구통계학적 재현 불균형이나 고정관념적 연관이 나타나는가? |
| 독성(toxicity) | 생성문이 Perspective API의 독성 판정에 얼마나 자주 걸리는가? |
| 효율성(efficiency) | 추론 시간·처리량과, 자료가 있을 때 훈련 에너지·탄소 추정이 어떠한가? |

공정성과 편향은 같은 열이 아니다. HELM에서 공정성은 사회 집단에 따른 **과제별 정확도 차이**를 반사실 교란과 집단별 성능 격차로 측정한다. 편향은 과제 정확도와 명시적으로 연결하지 않고 **모델 생성의 언어 선택이 보이는 체계적 비대칭**을 인구통계학적 재현과 고정관념적 연관으로 측정한다.

독성 역시 안전 전체와 같지 않다. HELM은 독성 측정을 서로 다른 시나리오에 일관되게 적용해 확장성을 확보하려 했고, 탐지기로는 광범위하게 분석되어 한계가 알려진 Perspective API를 골랐다. 그러나 이는 구체적 배포 맥락을 결여한 조작화이며, NarrativeQA에서는 도메인 때문에 false positive가 늘었을 가능성도 남는다. 허위정보는 독성 열에 흡수하지 않고 별도의 표적 평가에서 다뤘다.

### 자동 평가와 제한된 인간 평가

대규모 결과 행렬은 확장 가능한 자동 메트릭을 중심으로 만들었다. 사람 평가가 42개 시나리오와 30개 모델 전부를 검수한 것은 아니다. 논문 본문 §8.5에서 상세 보고된 인간 평가는 두 허위정보 시나리오의 6개 모델에 한정된다. Appendix A는 요약 평가에도 인간 평가 작업이 있었음을 기여 내역으로 기록하지만, 본문은 그 결과와 범위를 제시하지 않는다.

따라서 사람 판단이 42개 시나리오·30개 모델·일곱 메트릭 전체를 검증했다고 읽으면 안 된다. 인간 평가는 자동 메트릭의 보편적 정답이 아니라 제한된 평가 절차의 일부였다.

## 3단계 — 기술과 근거

### 평가 규모와 비교 가능성

| 항목 | 원 논문 보고값 | 뜻 |
| --- | ---: | --- |
| 모델 | 30개·16개 family·12개 조직 | open, limited-access API, closed-access 모델을 함께 평가했다. |
| 시나리오 | 핵심 16개 + 표적 26개 = 42개 | 이 가운데 21개는 당시 주류 언어 모델 평가에서 쓰이지 않았던 시나리오였다. |
| 핵심 시나리오–메트릭 | 98 / 112 = 87.5% | 일곱 범주를 모든 핵심 시나리오에 적용하려 했으나 정의·타당성 문제로 14개 조합은 측정하지 않았다. |
| 기존 평가의 핵심 시나리오 coverage | 평균 17.9% | 과거 논문에 흩어진 결과를 합쳐도 모델별 공통 평가 범위가 성겼다. |
| HELM 평가 뒤 coverage | 96.0% | 남은 4.0%는 특정 모델의 확률·tokenization 등 기술 문제였다. 성능 정확도 96%가 아니다. |
| 평가 run | 4,939회 | 특정 모델–시나리오를 평가한 실행 단위다. |
| 처리량 | 12,169,227,491 tokens·17,431,479 queries | 약 122억 token과 1,743만 query를 처리했다. |
| 상용 API 비용 | $38,001 | 당시 가격과 대상 API에 조건화된 평가 비용이다. |
| 공개 모델 추론 compute | 약 19,500 GPU hours | 약 2만 GPU 시간이며 모델 훈련 비용이 아니라 이 평가에서 공개 모델을 실행한 비용이다. |

30개 모델은 크기와 훈련 방식뿐 아니라 접근성도 달랐다. 공개 가중치 모델은 연구진이 직접 추론했고, 상용 API에는 금전 비용을 기록했으며, 비공개 모델의 비용은 제공 조직이 부담했다. 이 장부는 서로 다른 접근 조건을 보이지만 훈련 자료·compute·architecture를 통제한 인과 실험은 아니다.

### 17.9%에서 96.0%가 된 것

논문이 개선했다고 보고한 17.9%→96.0%는 모델이 맞힌 정답의 비율이 아니다. **30개 모델을 16개 핵심 시나리오에 얼마나 조밀하게 배치했는가**를 나타내는 coverage다. 같은 시나리오와 prompt·metric으로 빈칸을 채워 head-to-head 비교 가능성을 높인 것이다.

하지만 표준화는 모델마다 최적인 적응을 찾아 주지 않는다. T0++처럼 0-shot 용도로 설계된 모델도 공통 5-shot 조건에 놓였고, 어떤 모델은 특정 시나리오·prompt·적응 방식에 더 적합할 수 있다. 동일 조건은 비교의 한 선택이지 모델의 절대 능력을 관측하는 중립적 창이 아니다.

### GPT-3와 InstructGPT를 같은 장부에서 읽기

[[067_GPT-3와 문맥 내 학습|GPT-3]]가 널리 알린 few-shot prompting은 HELM의 공통 적응 절차에 직접 연결된다. HELM은 모델별 prompt 최적화 대신 단순한 공통 prompt를 택해 모델 차이와 평가 조건 차이를 분리하려 했다. 이 선택은 비교 가능성을 높였지만 prompt 설계에 따른 성능 변화를 없애지는 않았다.

HELM 평가에서는 [[077_InstructGPT와 인간 선호 정렬|InstructGPT]] 계열의 `text-davinci-002`가 핵심 시나리오의 정확도·강건성·공정성에서 강한 결과를 보였다. 저자들은 평가한 instruction-tuned 모델들의 폭넓은 이점을 관찰했지만, 모델 family·자료·규모·비공개 훈련 절차가 함께 달랐다. 따라서 이 결과만으로 instruction tuning 하나의 순수 인과 효과나 모든 메트릭의 개선을 확정하지 않는다.

### 점수 행렬을 읽는 법

HELM은 GLUE식 과제별 정확도 벡터를 시나리오×메트릭 행렬로 확장했다. 이 행렬은 모델의 단일 종합 순위를 자동으로 정하지 않는다. 어떤 모델을 택할지는 사용자가 놓인 시나리오와 정확도·위험·비용의 우선순위에 따라 달라진다.

이 점은 [[자동 평가 지표는 무엇을 보상하는가]]의 질문을 평가 suite 전체로 넓힌다. 지표 선택은 수동적인 측정이 아니라 무엇을 좋은 모델로 보이게 만들지 정하는 유인이다. HELM은 이를 하나의 평균으로 감추기보다 메트릭 사이의 절충으로 남겼다.

### 공개 산출물과 재검사

연구진은 modular toolkit과 원시 prompt·completion을 공개했다. 덕분에 집계 점수에서 개별 출력으로 내려가 오류를 확인하고 새로운 메트릭을 사후 적용할 수 있다. 다만 API가 갱신되거나 폐기되면 같은 코드만으로 과거의 비공개 모델 응답을 재생할 수 없다. 공개 기록은 감사 가능성을 높이지만 외부 서비스의 재현성까지 보장하지 않는다.

## 검증과 한계

### raw 설명의 검증 정정

- **HELM은 모든 중요한 차원에서 모델을 평가했다:** 초기 구현은 영어 중심의 42개 시나리오와 일곱 메트릭 범주를 선택했다. 논문은 빠진 언어·도메인·상호작용·모델·메트릭을 별도로 열거했다.
- **일곱 메트릭을 16개 핵심 시나리오마다 모두 계산했다:** 가능한 조합은 112개였고 실제 측정은 98개, 87.5%였다. 일부 조합은 정의되지 않거나 측정 타당성이 낮아 제외했다.
- **견고성은 일반적인 적대적 공격·분포 이동·도메인 적응을 모두 시험했다:** HELM의 핵심 구현은 의미 보존·의미 변화 text perturbation과 이용 가능한 contrast set을 사용했다. 현실의 모든 공격·분포 이동을 포괄하지 않는다.
- **편향은 인구통계학적 동등성 검사이고 공정성과 같은 축이다:** 공정성은 집단별 과제 정확도 격차, 편향은 생성 언어의 재현·연관 비대칭으로 분리했다.
- **독성·허위정보·안전을 하나의 포괄적 safety 평가로 검증했다:** 독성은 Perspective API 기반 메트릭이고 허위정보는 별도 표적·인간 평가다. 안전은 일곱 메트릭 범주의 이름이 아니며 장기 안전 전체를 보증하지 않는다.
- **자동 지표와 인간 평가가 모든 모델·과제의 정량·정성 측면을 함께 포착했다:** 전체 행렬은 자동 평가 중심이다. 본문에서 상세 보고된 인간 평가는 두 허위정보 시나리오와 6개 모델에 한정됐다. Appendix A는 요약 평가 작업의 존재만 기록한다.
- **효율성은 모든 모델의 훈련과 추론 자원을 직접 profiling했다:** 추론 효율과 평가 비용을 기록하고, 공개된 자료가 있을 때 훈련 에너지·탄소를 추정했다. 비공개 모델의 전체 수명주기 비용을 직접 측정하지 않았다.
- **표준화된 조건은 어느 모델에도 공정한 최적 조건이다:** 적용 가능한 시나리오에서 사용한 공통 5-shot prompting은 비교를 위한 선택이다. 0-shot·fine-tuning·model-specific prompt에 더 적합한 모델을 불리하게 할 수 있다.
- **높은 HELM 점수는 실제 배포 준비와 안전성을 보장한다:** 평가 결과는 선택한 scenario·metric·prompt에서 관측한 행동이다. 사용자·도메인·운영 정책과 추가 적응이 다른 배포의 타당성은 별도 검증이 필요하다.
- **HELM이 곧바로 업계 표준이 되었고 다른 AI modality의 평가를 바꿨다:** 원 논문은 toolkit과 결과를 공개하고 living benchmark를 제안했다. 광범위한 후대 채택과 computer vision·speech에 대한 직접 영향은 후속 자료로 따로 검증해야 한다.
- **오픈 소스 공개가 빠른 채택을 입증했다:** 공개 코드·자료의 존재는 확인되지만 채택 속도와 인과 효과는 이 논문이 측정한 결과가 아니다.

### 오염과 일반화

대상 모델의 대규모 훈련 자료는 불완전하게 문서화되어 HELM test instance나 같은 분포에 노출됐는지 직접 확인하기 어려웠다. 연구진은 알려진 오염 증거를 Appendix G와 Table 13에 기록했지만 전체 오염 정도와 결과 타당성에 미친 영향은 불명확하다고 밝혔다.

Few-shot 평가는 정확한 test 문장뿐 아니라 평가 분포 자체가 훈련에 포함돼도 순수한 문맥 내 학습 주장에 영향을 받는다. 96.0% coverage가 contamination을 제거했다는 뜻은 아니다.

### prompt 민감성과 적응 선택

논문은 같은 모델·시나리오도 multiple-choice 적응 방식과 prompt에 따라 정확도가 크게 달라질 수 있음을 보였다. 선행 결과에서는 같은 모델·시나리오에서 prompt에 따라 정확도가 30%에서 80%까지 움직이는 사례도 인용했다. 적용 가능한 시나리오의 공통 5-shot prompt는 이 변수를 고정하지만, 다른 prompt·fine-tuning·chain-of-thought에서 순위가 유지됨을 보장하지 않는다.

연구진은 비용 때문에 문맥 예시 선택에 세 random seed만 쓰고 각 dataset 전체 대신 1,000개 instance를 평가한 경우가 많았다. Decoding hyperparameter 같은 더 낮은 수준의 선택에 대한 민감성도 전부 조사하지 못했다.

### 측정 타당성과 Perspective API

공정성·편향·독성은 단순한 자연량이 아니라 여러 방식으로 조작화할 수 있는 논쟁적 사회 개념이다. 집단 metadata가 없는 시나리오에서는 성능 격차를 계산할 수 없었고, counterfactual 치환도 복잡한 집단별 분포 차이를 모두 재현하지 못했다.

독성 측정은 Perspective API에 의존한다. 연구진은 이 탐지기가 널리 분석되어 한계가 알려졌다는 이유로 선택했지만, 그 한계가 사라진 것은 아니다. 논문은 NarrativeQA에서 도메인 때문에 false positive가 늘었을 가능성을 직접 경고했고, 독성을 하나의 탐지기 판정으로 조작화한 범위와 구체적 배포 맥락의 결손을 남겼다. 독성 점수가 낮다는 사실을 허위정보·조작·개인정보·위험 조언까지 포함한 안전성으로 확대하지 않는다.

### 배포 타당성과 변화하는 API

실제 사용에서는 모델을 도메인 자료로 fine-tune하고, 서로 다른 prompt·검색·도구·정책과 결합할 수 있다. HELM에서 낮은 모델도 작은 크기와 적응 용이성 때문에 특정 환경에는 더 적합할 수 있다. 실무자는 자신의 사용 조건에 맞는 scenario와 metric을 먼저 고른 뒤 결과를 읽어야 한다.

비공개 API는 평가 기간에도 바뀔 수 있고 제공자별 version 기록 관행도 일관되지 않았다. HELM은 질의 시각과 알려진 version을 기록했지만, 한 시점의 결과를 미래 서비스의 고정 성질로 읽을 수는 없다.

### 집계와 보편 순위의 한계

시나리오×메트릭 행렬은 절충을 보존하지만 결과량이 많고 단일 순위로 읽기 어렵다. 논문은 모든 가치·선호·상황을 만족하는 보편 집계가 있다고 보지 않았고, 단일 숫자로 합치는 문제를 후속 과제로 남겼다.

따라서 “HELM 1위”라는 문장에는 어떤 scenario와 metric을 어떤 가중치로 합쳤는지가 반드시 따라야 한다. 가중치를 정하는 순간 정확도·공정성·독성·효율성 가운데 무엇을 더 중요하게 보는지에 관한 가치 판단이 들어간다.
