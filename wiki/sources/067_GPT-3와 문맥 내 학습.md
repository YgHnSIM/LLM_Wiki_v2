# GPT-3와 문맥 내 학습

> [!note] 학습 안내
> **난이도:** 기초 → 중급<br>
> **선수 지식:** 없음 — prompt, demonstration, 가중치, forward pass의 역할을 이 문서에서 먼저 구분한다.<br>
> **읽고 나면:** GPT-3의 zero-shot·one-shot·few-shot 평가를 구분하고, prompt 조건부확률로 출력·후보 점수를 만드는 과정과 규모 확대의 실제 성과·한계를 원 논문 범위에서 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 이 연구가 풀려 한 문제

2020년 무렵의 전이 학습은 사전학습 모델을 과제마다 따로 미세조정하는 방식이 중심이었다. 이 방식은 강력했지만, 새 과제마다 label이 있는 자료와 가중치 갱신, 별도 checkpoint를 요구했다. Brown 등의 질문은 “가중치를 과제마다 바꾸지 않고, 자연어 지시와 몇 개 예시를 입력에 넣는 것만으로 과제를 지정할 수 있는가?”였다.

이 질문은 사람이 예시를 전혀 제공하지 않아도 된다는 뜻이 아니다. 예시가 있다면 누가 고를지, 어떤 순서와 형식으로 넣을지, 정답 후보를 어떻게 채점할지를 여전히 정해야 한다. 달라지는 것은 예시가 학습 단계의 dataset이 아니라 추론 한 번의 prompt 안에 들어간다는 점이다.

### 먼저 구분할 다섯 용어

- **가중치(parameter, $\theta$)**: 사전학습에서 바뀌고, 이 문서의 zero/one/few-shot 평가 중에는 고정되는 수치 묶음이다.
- **prompt 또는 문맥 $c$**: 과제 지시와 demonstration을 포함한 앞 token 열이다.
- **demonstration**: prompt 안에서 입력–출력 형식을 보여 주는 예시다. 과제별 optimizer 갱신에 쓰는 훈련 사례와 구분한다.
- **forward pass**: 고정한 가중치와 현재 prompt로 다음 token 확률을 계산하는 한 번의 실행이다. 역전파나 optimizer step, 곧 손실의 기울기로 가중치를 갱신하는 단계는 여기에 포함되지 않는다.
- **문맥 내 학습(in-context learning)**: 위와 같은 고정 가중치 forward pass에서 prompt의 지시·예시에 따라 출력이 달라지는 현상을 가리키는 평가·적응 방식이다.

### 핵심 문장

Brown 등은 2020년에 **1,750억 개 매개변수**를 가진 GPT-3를 발표했다. 이 연구의 핵심은 큰 모델 하나의 인상적인 출력이 아니라, 1억 2,500만 개부터 1,750억 개까지 여덟 규모를 같은 평가 틀에서 비교한 데 있다.

GPT-3는 추론할 때 가중치를 갱신하지 않고 자연어 지시와 입력–출력 예시를 문맥에 넣어 과제를 지정했다. Brown 등은 이 forward pass 안의 적응을 [[문맥 내 학습|문맥 내 학습(in-context learning)]]이라고 불렀다. zero-shot·one-shot·few-shot은 서로 다른 모델이 아니라 **추론 시 제공한 demonstration 수가 다른 조건**이다.

이 결과는 입력 문맥을 강력한 과제 인터페이스로 만들었다. 그러나 원 논문은 GPT-3 미세조정을 직접 평가하지 않았고, 여러 과제에서 fine-tuned 최고 성능에 크게 못 미쳤다. 따라서 “GPT-3가 미세조정을 없앴다”보다 “과제별 가중치 갱신 없이 경쟁적인 결과를 내는 범위를 크게 넓혔다”가 정확하다.

### 역사적 위치

[[GPT-1과 GPT-2]] 가운데 GPT-1은 사전 학습 뒤 과제별 지도 미세조정을 사용했고, GPT-2는 가중치 갱신 없이 text cue로 zero-shot 전이를 시험했다. GPT-3는 이 두 번째 경로를 모델·자료·문맥 규모와 체계적인 demonstration 비교로 확장했다.

같은 시기 [[언어 모델 스케일링 법칙]]은 token cross-entropy가 규모와 함께 대체로 매끄럽게 감소하는 경험 관계를 다루었다. GPT-3 논문은 그 관찰을 더 큰 compute 범위로 늘리고, 별도로 downstream 과제에서 규모와 문맥 예시의 상호작용을 측정했다. 평균 loss의 매끄러운 감소와 특정 과제 정확도의 모양은 같은 측정값이 아니다.

## 2단계 — 작동 원리

### 네 평가 조건을 구분한다

| 조건 | 추론 시 과제별 정보 | 가중치 갱신 | GPT-3 논문에서 직접 평가 |
|---|---|---|---|
| fine-tuning | 보통 수천~수십만 개의 표지 예시 | 있음 | 아니요, 후속 과제로 남김 |
| zero-shot | 자연어 과제 지시, demonstration 0개 | 없음 | 예 |
| one-shot | 자연어 지시와 demonstration 1개 | 없음 | 예 |
| few-shot | 자연어 지시와 문맥에 들어가는 여러 demonstration | 없음 | 예 |

Few-shot에서는 보통 2,048-token context window에 들어가는 10–100개 예시를 사용했다. 표지 자료가 전혀 필요 없다는 뜻은 아니다. 평가자는 예시를 선택하고 순서와 형식을 정하며, 다지선다에서는 후보의 언어 모델 확률을 비교하고 자유 생성에서는 과제별 metric으로 출력의 정답 여부를 판단했다.

### 가장 작은 prompt 예

설명용 번역 prompt를 다음처럼 쓴다고 하자.

> 영어를 프랑스어로 번역한다.
>
> cat → chat
>
> dog →

첫 줄과 첫 예시는 문맥 $c$, 새 입력 dog는 $x$, 뒤에 생성할 번역은 $y$ 역할을 한다. 모델은 가중치를 바꾸지 않고 이 전체 열을 읽은 뒤 다음 token 분포를 낸다. chien을 낸다면 그것은 “이 prompt 뒤에서 그 token이 이어질 확률이 높다”는 뜻이지, 이 작은 예가 GPT-3의 실제 출력이나 원 논문 benchmark를 재현한다는 뜻은 아니다.

### 입력 문맥이 과제 명세를 운반한다

문맥 내 학습에서는 지시, 몇 개의 입력–출력 쌍, 새 query를 하나의 token sequence로 이어 붙인다. 고정된 매개변수 $\theta$를 가진 자기회귀 모델은 그 문맥을 조건으로 다음 token을 예측한다. 출력 $y$가 여러 token이면, 현재 정답 token에 준 확률을 짧게 $q_t$로 쓸 수 있다.

\[
q_t
=
p_\theta(y_t\mid c,x,y_{<t})
\]

\[
p_\theta(y\mid c,x)
=
\prod_t q_t
\]

| 기호 | 이 연구의 prompt 평가에서 하는 일 | 종류 |
| --- | --- | --- |
| $c$ | 지시와 demonstration을 담은 앞 문맥 | token 열 |
| $x$ | 새 query 또는 과제 입력 | token 열 |
| $y$ | 모델이 완성할 전체 출력 | 길이가 달라질 수 있는 token 열 |
| $y_t$ | 출력의 $t$번째 token | 하나의 token |
| $y_{<t}$ | 현재 출력보다 앞서 나온 token들 | token 열 |
| $t$ | 출력 위치를 세는 인덱스 | $1$부터 출력 끝까지의 정수 |
| $q_t$ | 이 위치의 실제·후보 token에 준 조건부확률 | 0보다 크고 1 이하인 스칼라 |
| $\theta$ | 사전학습 뒤 고정한 모델 가중치 | 고차원 수치 묶음 |

$\prod$는 모든 출력 위치의 조건부확률을 곱하라는 기호다. 이는 출력 token들이 서로 독립이라는 뜻이 아니라, 결합확률을 이미 나온 token에 조건화한 연쇄 법칙으로 쓴 것이다.

추론 중에는 다음 관계가 유지된다.

\[
\theta_{\mathrm{after}}
=
\theta_{\mathrm{before}}
\]

즉 prompt가 바뀌면 activation과 다음 token 분포는 바뀌지만, GPT-3의 zero/one/few-shot 평가에서 optimizer step이나 역전파는 수행하지 않는다. 출력이 prompt에 따라 달라져도 과제별 지식이 가중치에 영구 저장됐다고 볼 수 없다.

여기서 activation은 현재 token 열을 처리할 때만 만들어지는 중간 계산값이다. 아래첨자 after와 before는 prompt를 처리한 뒤와 앞을 뜻한다. 그러므로 위 등식은 prompt가 parameter를 바꾸지 않는다는 뜻이지, 중간 계산값과 출력이 같다는 뜻은 아니다.

### 후보를 왜 로그확률로 비교하는가

다지선다나 짧은 label 과제에서는 후보 $y$마다 앞 식의 확률을 비교할 수 있다. 실제 구현은 아주 작은 확률을 직접 곱하는 대신 다음 점수를 자주 쓴다.

\[
S(y)
=
\sum_t\ln q_t
\]

$S(y)$는 이 문서에서 후보 $y$의 로그확률 점수다. $\ln$은 자연로그이며, 확률의 곱을 합으로 바꾸고 양의 확률에서 엄격히 증가하므로 후보의 대소 순서를 바꾸지 않는다. $\mathcal C$는 현재 과제에서 허용한 후보들의 집합이고, $\hat y$는 그중 선택된 후보다. 따라서 같은 후보 집합 안에서는 다음처럼 가장 높은 점수의 후보를 고를 수 있다.

\[
\hat y
=
\underset{y\in\mathcal C}{\operatorname{argmax}}
S(y)
\]

argmax는 가장 큰 점수 그 자체가 아니라 그 점수를 만든 후보를 반환한다. 후보 길이가 다르면 긴 후보가 더 많은 로그확률을 더하는 문제나 과제별 채점 규칙이 생길 수 있다. GPT-3 원 논문은 과제마다 prompt와 scoring rule을 부록에 제시했으므로, 이 일반식 하나가 모든 benchmark의 세부 채점 방식을 대체하지는 않는다. 학습 때 음의 로그가능도(NLL)를 최소화하는 식과 후보 평가 때 $S(y)$를 비교하는 식의 관계는 [[로그가능도]]에서 더 자세히 계산한다.

한 token짜리 두 label을 비교하는 설명용 예에서 $q_{\mathrm{positive}}=0.70$, $q_{\mathrm{negative}}=0.20$이라고 하자. 점수는 각각 $\ln0.70\approx-0.3567$, $\ln0.20\approx-1.6094$이므로 positive가 더 큰 점수를 얻는다. 확률이 1보다 작으면 로그는 음수여도, $-0.3567$이 $-1.6094$보다 크다. 이 수치는 산술 설명용이며 GPT-3의 실제 분류 benchmark 점수가 아니다.

### ‘학습’과 ‘패턴 인식’ 사이의 열린 문제

Brown 등은 사전 학습을 바깥 고리, forward pass의 문맥 적응을 안쪽 고리로 보는 meta-learning 그림을 제시했다. 동시에 이 용어를, 모델이 추론 시 새 과제를 처음 배우는지 아니면 사전 학습에서 본 패턴을 식별하는지에 대해 중립적으로 사용했다. 원 논문은 attention이 어떤 내부 알고리즘을 구현하는지 식별하지 않았다.

따라서 “모델이 prompt에서 새 규칙을 학습했다”는 문장은 관찰된 입출력 적응을 가리킬 때만 안전하다. 내부 인과 메커니즘이나 사람과 같은 학습 과정을 확정하는 설명으로 넓혀서는 안 된다.

## 3단계 — 기술과 근거

### 여덟 모델과 300B-token 학습

GPT-3 계열은 GPT-2와 같은 decoder-only [[Transformer]]를 바탕으로 하되, 층마다 dense attention과 locally banded sparse attention을 번갈아 사용했다. 가장 큰 모델은 96개 층, hidden size 12,288, 96개 attention head와 1,750억 개 매개변수를 가졌다.

| 모델 규모 | 125M | 350M | 760M | 1.3B | 2.7B | 6.7B | 13B | 175B |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 학습 token | 300B | 300B | 300B | 300B | 300B | 300B | 300B | 300B |

학습 자료 풀은 filtered Common Crawl 410B, WebText2 19B, Books1 12B, Books2 55B, Wikipedia 3B token으로 약 499B token이었다. 실제 학습에서는 품질이 높다고 본 자료를 더 자주 뽑아 모든 모델이 총 300B token을 처리했다. 300B를 서로 다른 고유 token 수나 자료 풀 전체 크기와 혼동하지 않는다.

원 논문의 “10배”는 GPT-3가 당시 이전의 가장 큰 **비희소 언어 모델**보다 약 10배 크다는 비교다. 1.5B GPT-2와 직접 비교하면 175B는 약 117배다. 따라서 “GPT-2보다 10배”라는 raw 설명은 비교 대상을 잘못 옮겼다.

\[
\frac{175\text{B}}{1.5\text{B}}
\approx
116.7
\]

여기서 B는 billion, 곧 10억 단위다. 분자와 분모가 같은 단위라 약분되며, 이 값은 **total parameter 수의 비**일 뿐 학습 token 수, active compute, 메모리, 지연 시간이나 과제 성능의 비가 아니다. 이 구분이 필요한 이유는 parameter 수 하나만으로 sparse 모델과 dense 모델, 서로 다른 자료·hardware·평가 조건을 같은 규모라고 말할 수 없기 때문이다.

### 경쟁적 결과와 큰 격차가 공존했다

Closed-book TriviaQA에서 GPT-3는 zero-shot 64.3%, one-shot 68.0%, few-shot 71.2%를 기록했다. Few-shot 71.2%는 같은 closed-book 비교에서 당시 fine-tuned 모델보다 높았고, retrieval을 사용하는 open-domain RAG의 68.0%도 넘었다. 이 결과는 가중치 갱신 없는 과제 적응의 강한 사례다.

그러나 SuperGLUE test에서 32개 예시를 사용한 GPT-3 few-shot 평균은 71.8이었다. fine-tuned BERT-Large 69.0은 넘었지만 당시 fine-tuned 최고 성능 89.0과는 큰 차이가 있었다. 세부 과제에서도 COPA·ReCoRD는 강했지만 WiC·MultiRC는 약했다. ANLI, RACE, QuAC 같은 과제도 큰 모델에서 계속 어려웠다.

이 대비는 “여러 과제에서 때때로 경쟁적”이라는 논문의 표현을 지지한다. 한두 최고 결과를 모든 언어 이해 과제로 일반화하지 않는다.

### 산술 결과는 규모·자리수·metric에 민감했다

산술 평가는 과제마다 무작위로 만든 2,000개 문항에서 정답 문자열 전체가 맞아야 하는 exact match를 사용했다. 175B few-shot 결과는 다음과 같다.

| 과제 | 덧셈 | 뺄셈 |
|---|---:|---:|
| 2자리 | 100.0% | 98.9% |
| 3자리 | 80.4% | 94.2% |
| 4자리 | 25.5% | 26.8% |
| 5자리 | 9.3% | 9.9% |

2자리 곱셈은 29.2%, 한 자리 수 세 개의 합성 연산은 21.3%였다. 13B에서 175B로 갈 때 특히 2·3자리 덧셈과 뺄셈에서 큰 점프가 보였지만, 자리수가 늘면 정확도가 빠르게 무너졌다. 이는 특정 prompt와 exact-match 과제에서 관찰한 규모별 곡선이지, 일반 산술 알고리즘을 안정적으로 획득했다는 증거는 아니다.

### 매끄러운 loss와 과제별 곡선

GPT-3의 validation cross-entropy는 [[066_신경 언어 모델의 스케일링 법칙]]이 다룬 power law를 약 두 자릿수의 compute 범위만큼 더 연장했다. 42개 accuracy benchmark 집계와 다수 개별 과제에서도 모델이 커질수록 대체로 성능이 좋아졌고, few-shot 이득이 더 빠르게 커지는 경향이 있었다.

그렇다고 모든 과제가 같은 비율로 개선되지는 않았다. 산술의 exact match처럼 급격해 보이는 곡선, TriviaQA처럼 매끄러운 곡선, 거의 개선되지 않는 NLI 결과가 함께 있었다. 후대의 [[손실 곡선과 능력 곡선 사이|‘창발 능력(emergent ability)’ 논쟁]]은 특정 metric에서 작은 모델에 보이지 않던 능력이 큰 모델에서 나타난다는 별도의 정의에서 출발했다. Brown 논문은 이 후대 용어를 핵심 결론으로 사용하지 않았다.

## 검증과 한계

### raw 설명의 검증 정정

- **GPT-3가 GPT-2보다 10배 컸다:** 논문의 10배 비교 대상은 이전 최대 비희소 언어 모델이다. GPT-2 1.5B와 비교하면 약 117배다.
- **문맥 내 학습이 미세조정의 필요성을 없앴다:** GPT-3 fine-tuning은 평가하지 않고 미래 작업으로 남겼다. SuperGLUE 71.8 대 fine-tuned SOTA 89.0처럼 큰 격차도 있었다.
- **여러 과제에서 높은 정확도로 안정적으로 적응했다:** TriviaQA 같은 강한 사례와 ANLI·RACE·QuAC 같은 실패가 공존하며, prompt·예시·scoring 조건도 성능에 영향을 준다.
- **사전 학습 중 본 패턴을 적용하는 내부 메커니즘이 확인됐다:** 새 과제 학습과 기존 패턴 인식 가운데 무엇인지 원 논문은 열어 두었다.
- **175B에서 능력이 갑자기 창발했다:** Brown 등은 대부분 과제에서 비교적 매끄러운 규모 향상을 보고했다. 후대의 엄격한 창발 정의를 소급하지 않는다.
- **GPT-3가 코드 생성·설명·debugging을 입증했다:** Brown 논문의 benchmark에는 code generation 평가가 없다. 후속 code 전용 모델의 별도 근거는 [[071_Codex와 HumanEval 기반 코드 생성 평가]]에서 확인한다.
- **API 배포와 prompt engineering 산업을 원 논문이 확립했다:** 이는 후대 제품·실무 역사이며 2020년 논문의 직접 실험 결과가 아니다.

### 설명용 prompt·점수와 원 실험의 경계

이 문서의 번역 prompt, $q_t$, $S(y)$와 positive·negative의 수치는 문맥 내 조건화와 로그확률 비교를 보이기 위한 편집부 예다. Brown 등의 실제 평가는 과제마다 서로 다른 instruction, demonstration 수와 순서, candidate scoring 또는 생성 metric을 사용했다. 따라서 이 작은 계산을 TriviaQA·SuperGLUE·산술의 실제 score나 GPT-3 내부 activation의 재현으로 읽지 않는다.

### benchmark contamination

연구진은 사전 학습 자료에서 평가 세트와 겹치는 문서를 제거하려 했지만 filtering bug 때문에 검출된 overlap 일부만 제거됐다. 막대한 재학습 비용 때문에 모델을 다시 학습하지 못했고, 사후에 pretraining 자료와 13-gram이 겹치는 예시를 제외한 clean subset을 만들었다.

대부분 benchmark에서 원 점수와 clean subset 점수 차이는 작았지만, PIQA와 Winograd 등 일부 결과는 추가 검토 대상으로 표시됐다. 보수적인 overlap 기준이 실제 오염을 과대 추정했을 가능성과, 오염 효과가 작았을 가능성을 구분해야 한다. 사후 분석이 모든 test leakage 위험을 제거했다는 뜻은 아니다.

### 적용 범위와 남은 한계

문맥 내 예시는 과제 형식을 알려 주지만 최신 사실, 근거, 일관성, 공정성이나 안전성을 자동으로 보장하지 않는다. 모델은 긴 생성에서 반복·모순을 보였고, 논문은 bias·misuse·energy use를 별도 위험으로 다뤘다. 모델 규모, 학습 자료, sparse attention, prompt와 평가 설계가 함께 바뀌었으므로 성과를 매개변수 수 하나의 단독 인과로 돌릴 수도 없다.

## 학습 확인

### 확인 질문과 답

1. GPT-3 논문의 zero-shot·one-shot·few-shot은 무엇을 달리하고 무엇을 고정하는가?

   **답:** prompt 안 demonstration 수를 0개·1개·여러 개로 달리하고, 사전학습된 가중치 $\theta$는 모두 고정한다. 세 조건 모두 forward pass만 수행하며 task별 역전파나 optimizer step은 없다.

2. TriviaQA 71.2와 SuperGLUE 71.8 대 89.0을 함께 봐야 하는 이유는 무엇인가?

   **답:** 가중치 갱신 없는 few-shot 적응이 강했던 사례와 당시 fine-tuned 최고 성능에 크게 못 미친 사례가 함께 있기 때문이다. 한 benchmark의 최고 결과만으로 모든 언어 과제에서 미세조정을 대체했다고 결론낼 수 없다.

3. 13B에서 175B 사이의 산술 점프만으로 일반적인 ‘창발 능력’을 확정할 수 없는 이유는 무엇인가?

   **답:** 해당 곡선은 특정 자리수·prompt·exact-match metric의 결과이고, 다른 과제는 매끄럽게 개선되거나 거의 개선되지 않았다. 원 논문도 후대의 불연속 창발 정의를 핵심 결론으로 제시하지 않았다.
