# 신경 언어 모델의 스케일링 법칙

> [!note] 학습 안내
> **난이도:** 심화<br>
> **선수 지식:** [[대규모 언어 모델]], [[Perplexity]], [[Transformer]]<br>
> **읽고 나면:** Kaplan 등의 경험적 power law가 무엇을 어떤 조건에서 예측했는지 설명하고, 그 compute 배분을 Chinchilla가 어떻게 수정했는지 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 예측 대상은 ‘능력’이 아니라 token 손실이다

Kaplan 등은 2020년에 decoder-only [[Transformer]] 언어 모델의 **test cross-entropy loss**가 모델 크기 $N$, 데이터 크기 $D$, 최적으로 사용한 학습 compute $C_{min}$과 어떤 관계를 이루는지 측정했다. 다른 두 축이 병목이 아닌 조건에서 각 관계는 매끄러운 power law로 근사됐다. 이 [[언어 모델 스케일링 법칙]]은 큰 학습 run의 손실과 자원 배분을 추정하는 경험 모델이지, 모든 downstream 능력·사실성·안전성·지능을 훈련 전에 정확히 예언하는 공식이 아니다.

주된 실험 조건은 다음과 같다.

| 축 | Kaplan 등의 범위·정의 |
|---|---|
| 모델 $N$ | embedding을 제외한 768–1.5B parameters |
| 데이터 $D$ | 22M–23B tokens |
| 자료·tokenization | WebText2, 50,257 BPE vocabulary |
| 주 모델 | decoder-only Transformer, 대체로 1,024-token context |
| 주 metric | token 평균 cross-entropy, nats |

### 핵심 문장

- $L(N)$은 데이터와 학습이 충분할 때, $L(D)$는 모델 용량과 최적화가 충분할 때의 조건부 fit이다.
- 모델 크기 지수 $\alpha_N\approx0.076$은 $N$을 두 배로 늘릴 때 해당 조건의 손실이 약 $2^{-0.076}\approx0.95$배가 된다는 뜻이다. 정확도 5%p 상승이나 모든 능력의 동일한 개선을 뜻하지 않는다.
- Kaplan 연구는 고정 compute 배분을 명시적으로 다뤘고 $N_{opt}\propto C^{0.73}$, $D_{opt}\propto C^{0.27}$을 제안했다.
- 2022년 Chinchilla 연구는 같은 문제를 재측정해 model size와 training tokens를 각각 대략 $C^{0.5}$로 키우는 배분을 제시했다.

## 2단계 — 작동 원리

### 세 개의 단변량 power law

한 축만 성능을 제한하도록 다른 병목을 충분히 풀었을 때 Kaplan 등의 대표 fit은 다음과 같다.

$$
L(N)=\left(\frac{N_c}{N}\right)^{\alpha_N},
\qquad \alpha_N\approx0.076,
$$

$$
L(D)=\left(\frac{D_c}{D}\right)^{\alpha_D},
\qquad \alpha_D\approx0.095,
$$

$$
L(C_{min})=\left(\frac{C_c^{min}}{C_{min}}\right)^{\alpha_C^{min}},
\qquad \alpha_C^{min}\approx0.050
$$

$N_c$, $D_c$, $C_c^{min}$의 수치는 vocabulary와 tokenization 등에 의존한다. 논문도 이 scale 상수에 근본적인 의미를 부여하지 않았다. 경험 구간에서 직선처럼 보이는 log–log 관계와 모든 조건에 적용되는 자연 법칙을 구분해야 한다.

### 모델과 데이터의 공동 병목

모델과 데이터가 동시에 제한될 때 사용한 결합식은 다음과 같다.

$$
L(N,D)=\left[
\left(\frac{N_c}{N}\right)^{\alpha_N/\alpha_D}
+\frac{D_c}{D}
\right]^{\alpha_D}
$$

데이터 $D$를 고정한 채 모델 $N$만 늘리면 data-limited·overfitting 영역에 들어가고, 모델을 고정한 채 데이터만 늘리면 capacity limit 때문에 수익이 체감한다. 논문의 fit에서는 overfitting penalty를 피하기 위한 데이터가 대략 $D\propto N^{0.74}$로 늘었다. 이는 compute-optimal한 처리 token 배분과 같은 질문이 아니다.

### 고정 compute에서의 배분

논문은 비임베딩 학습 compute를 대략 $C\approx6NBS$로 추정했다. $B$는 batch의 token 수, $S$는 parameter update 수다. fixed compute에서 얻은 경험적 배분은 다음과 같다.

| 배분 축 | Kaplan fit |
|---|---:|
| optimal model size $N$ | $C_{min}^{0.73}$ |
| critical batch $B$ | $C_{min}^{0.24}$ |
| serial steps $S$ | $C_{min}^{0.03}$ |
| processed data $D=B\cdot S$ | $C_{min}^{0.27}$ |

이 결론은 큰 모델을 비교적 적은 데이터로 학습하고 수렴보다 일찍 멈추는 편이 loss 기준 compute 효율적이라는 처방으로 이어졌다.

## 3단계 — 기술과 근거

### 실제로 확인한 일반화 범위

모델은 WebText2로 학습됐고 BooksCorpus·Common Crawl·English Wikipedia·Internet Books 등 다른 text distribution에서도 test loss를 측정했다. 다른 분포의 손실도 모델 크기와 함께 비슷하게 개선됐지만 일정한 offset이 있었다. 이는 **다른 text distribution의 language-model loss**에 관한 결과다. 질의응답·독해·번역 benchmark의 task metric을 직접 평가해 loss에서 능력을 예측한 실험은 아니다.

논문은 depth·width·attention head·feed-forward dimension을 바꾸며 고정된 비임베딩 parameter 수에서 loss 차이가 비교적 작다는 결과도 냈다. 그러나 이는 합리적인 범위의 당시 Transformer shape에 대한 관찰이다. 모든 architecture, optimizer, 자료 품질과 context length가 중요하지 않다는 결론은 아니다.

### power law와 수익 체감

power law는 규모 확대의 이득이 계속된다는 표현과 **수익 체감**을 동시에 담는다. 지수가 작으면 같은 비율의 손실 감소를 얻기 위해 자원을 거듭제곱으로 더 늘려야 한다. Kaplan 등도 discussion에서 power law이므로 diminishing returns가 있다고 썼고, loss가 0이 되기 전에 관계가 결국 평탄해져야 한다고 밝혔다.

이 연구는 경험 법칙의 이론을 제시하지 못했다. Appendix C는 작은 데이터, 매우 긴 context에서 빠진 compute 항, critical batch 외삽, regularization·learning-rate 선택 등을 caveat로 열거한다. 관측 범위 밖 extrapolation에는 이 불확실성을 함께 붙여야 한다.

### Chinchilla가 수정한 것

Hoffmann 등은 2022년에 70M–16B parameters와 5B–500B tokens에 걸친 400개 이상의 모델을 분석했다. 세 접근의 fit은 compute가 증가할 때 model parameters와 training tokens를 거의 같은 비율로 늘리는 결과를 냈다.

| 연구 | $N_{opt}$ 지수 | $D_{opt}$ 지수 |
|---|---:|---:|
| Kaplan et al. 2020 | 0.73 | 0.27 |
| Hoffmann et al. 2022 | 약 0.46–0.50 | 약 0.50–0.54 |

70B Chinchilla는 1.4T tokens로 학습돼 같은 compute budget의 280B Gopher보다 여러 downstream 평가에서 강했다. 이것은 Kaplan이 compute 배분을 다루지 않았음을 보여 주는 결과가 아니라, 기존 배분이 model size를 너무 빠르게 늘리고 data를 너무 느리게 늘렸음을 재추정한 결과다. Chinchilla 역시 대규모 직접 비교 수가 제한되고 높은 compute 영역을 외삽했으므로 영구적인 보편 상수로 읽지 않는다.

## 검증과 한계

### raw 설명의 검증 정정

- **실험은 768 thousand parameters에서 시작했다**: 원 논문 §3의 최솟값은 768개의 비임베딩 parameter다.
- **모델 capability를 훈련 전에 정확히 예측했다**: 직접 fit한 대상은 조건이 명시된 token cross-entropy loss다.
- **architecture·dataset과 무관한 근본 법칙을 발견했다**: 주 결과는 WebText2 decoder-only Transformer 조건이며 보편 이론은 확립되지 않았다.
- **QA·독해 등 downstream 결과가 loss와 함께 예측 가능함을 확인했다**: 해당 task를 직접 평가하지 않았고 §8에서 후속 조사 문제로 남겼다.
- **power law는 diminishing returns나 한계가 없음을 뜻한다**: 논문은 반대로 power law의 수익 체감과 결국 필요한 평탄화를 명시했다.
- **Kaplan 연구는 fixed compute의 model–data 균형을 다루지 않았다**: §6과 Appendices A–B가 $N_{opt}$·$D_{opt}$ 배분을 직접 분석했다.
- **Chinchilla가 빈 문제를 처음 해결했다**: 같은 문제의 Kaplan식 0.73/0.27 배분을 약 0.5/0.5로 다시 추정했다.
- **법칙이 GPT-3의 175B 선택과 PaLM·GPT-4의 성공을 직접 결정했다**: 개별 모델의 1차 자료와 설계 기록 없이는 이 인과를 확정할 수 없다.
- **실패 run은 수백만 달러이고 여러 조직이 이 법칙을 표준으로 채택했다**: 이 두 논문은 그러한 비용·채택 범위를 조사하지 않았다.

### loss 밖의 품질

낮은 cross-entropy는 평균 token 예측이 좋아졌다는 뜻이다. 특정 task의 정확도, calibration, factuality, bias, 안전성, 제어 가능성은 각 속성에 맞는 평가가 필요하다. 매끄러운 평균 loss 곡선이 개별 능력의 모양을 곧바로 정하지도 않는다.

이 간극을 창발 판정으로 읽을 때 필요한 metric·관측 간격의 구분은 [[손실 곡선과 능력 곡선 사이]]에서 비교한다.

학습 compute 최적과 전체 수명주기 비용도 다르다. inference가 반복되면 더 작은 model의 serving 비용이 중요해지고, 사용할 수 있는 고품질 data·hardware memory·parallelism·wall-clock deadline이 이론적 배분을 제한한다.

## 학습 확인

### 확인 질문

1. $L(N)$ fit을 읽을 때 데이터와 compute 병목을 함께 확인해야 하는 이유는 무엇인가?
2. $N$을 두 배로 늘려 loss가 약 0.95배가 된다는 결과를 downstream 정확도 5%p 상승으로 바꿀 수 없는 이유는 무엇인가?
3. Kaplan의 0.73/0.27과 Chinchilla의 약 0.5/0.5는 어떤 질문에 대한 서로 다른 경험적 답인가?
