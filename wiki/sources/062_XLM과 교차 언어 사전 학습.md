# XLM과 교차 언어 사전 학습

> [!note] 학습 안내
> **난이도:** 기초 → 심화<br>
> **선수 지식:** token은 문장의 작은 조각이며, [[마스크드 언어 모델링]]은 일부 조각을 숨겨 맞히는 학습이라는 정도면 충분하다. 확률·log·행렬의 뜻은 본문에서 풀어 쓴다.<br>
> **읽고 나면:** 원 XLM 논문의 CLM·MLM·TLM 수식을 항별로 읽고, shared BPE·언어 sampling·병렬 문장·영어 label fine-tuning이 각각 어디에 쓰였는지 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

Conneau와 Lample의 2019년 XLM 논문은 “여러 언어를 하나의 모델이 다룬다”는 넓은 주장보다 더 좁고 검증 가능한 질문을 다룬다. **여러 언어의 label 없는 text로 사전 학습한 encoder를 영어 NLI label로 fine-tune했을 때, 다른 언어의 NLI에도 전이되는가?** 그리고 병렬 문장쌍이 있을 때 TLM을 더하면 그 전이가 좋아지는가를 비교했다.

원 논문을 읽을 때는 다음 세 장부를 분리해야 한다.

| 장부 | 실제로 들어간 자료 | 이 논문에서 뜻하는 역할 |
|---|---|---|
| 언어 text | XNLI 언어들의 Wikipedia 등 비표지 문장 | shared encoder의 사전 학습 |
| 병렬 문장 | 영어와 다른 언어가 짝인 문장쌍 | TLM의 추가 문맥 |
| 과제 label | 영어 NLI training label | 분류기와 encoder fine-tuning |

다른 언어의 XNLI test label은 모델을 업데이트하는 데 쓰지 않고, 마지막 예측이 맞았는지 채점하는 데만 쓴다. 따라서 zero-shot은 “target 언어가 학습에서 완전히 사라졌다”가 아니라 “target-language **NLI label**로 fine-tune하지 않았다”는 뜻이다.

이 논문이 비교한 세 objective도 서로 다른 질문을 한다.

| 설정 | 모델이 보는 문맥 | 이번에 맞힐 token | 병렬 자료 |
|---|---|---|---|
| CLM | 같은 언어의 왼쪽 token | 다음 token | 없음 |
| MLM | 같은 언어의 좌우 token | 가린 token | 없음 |
| MLM+TLM | 단일 언어 문맥과 번역문 문맥 | 양쪽 문장에서 가린 token | TLM에 필요 |

raw는 zero-shot을 “훈련에서 전혀 보지 않은 언어”로 넓히고, 원 논문이 평가하지 않은 Italian QA·교차 언어 정보검색·few-shot·범용 배포까지 XLM의 직접 성과처럼 묶는다. 이 소스 문서는 보존된 raw를 고치지 않고, 원 논문이 실제로 한 계산과 평가 경계를 분리해 기록한다.

## 2단계 — 작동 원리

### 한 번의 학습을 네 단계로 나누어 본다

1. 여러 언어 문장에서 shared BPE vocabulary를 만든다. 큰 언어가 vocabulary를 독점하지 않게 문장 뽑기 비율을 평탄화한다.
2. 그 vocabulary와 하나의 Transformer를 공유해 CLM 또는 MLM을 학습한다. 이 단계에는 병렬문도 과제 label도 필요 없다.
3. 병렬 문장쌍이 있으면 TLM batch를 MLM batch와 번갈아 학습한다. 번역문은 출력해야 할 정답 문장이 아니라 빈칸을 푸는 추가 문맥이다.
4. 영어 NLI label로 분류기를 붙여 fine-tune하고, 같은 가중치를 15개 언어 XNLI test 입력에 적용한다.

가령 ‘The sky is blue’와 ‘Le ciel est bleu’가 같은 뜻의 병렬 문장이라고 하자. 설명에서는 단어 단위로 썼지만 실제 XLM은 BPE subword를 쓴다. TLM에서 영어 ‘blue’를 가리면 영어의 나머지 문장뿐 아니라 프랑스어 ‘bleu’도 모델이 읽는 문맥에 남을 수 있다. 반대로 프랑스어 token을 가렸을 때도 영어가 도움을 준다. 이 양방향 빈칸 복원이 TLM의 핵심이다.

### zero-shot에서 “없는 것”과 “있는 것”

| 시점 | target 언어 비표지 text | target 언어 NLI label | target 언어 test 정답 |
|---|---|---|---|
| 사전 학습 | 있음 | 없음 | 없음 |
| 영어 fine-tuning | 입력으로 쓰지 않음 | 없음 | 없음 |
| target 언어 평가 | 있음 | parameter 업데이트에는 없음 | 채점에만 사용 |

맨 마지막 칸의 정답은 benchmark가 accuracy를 계산하려면 필요하다. 그러나 loss를 역전파하여 parameter를 바꾸지 않으므로, 이 논문의 protocol에서는 target-language supervised fine-tuning이 아니다. 이 점을 빼면 zero-shot·translate-train·target-language fine-tuning을 같은 실험으로 착각하기 쉽다.

### 병렬 문장을 쓴다고 곧바로 번역기를 학습하는 것은 아니다

번역기는 보통 source 문장 $x$를 보고 target $y=(y_1,\ldots,y_n)$ 전체를 순서대로 출력한다. TLM은 두 문장을 모두 이미 입력으로 받고, 선택한 빈칸만 맞힌다. 따라서 TLM은 교차 언어 encoder를 사전 학습하는 objective이고, 논문에서 별도로 평가한 지도·비지도 MT system의 최종 번역 decoder objective와 같은 것은 아니다.

## 3단계 — 기술과 근거

### shared BPE를 만들기 전에 언어 비율을 바꾼다

논문은 언어 $i$의 문장 수를 $n_i$라고 두고 먼저 원자료 비율을 계산한다.

$$
p_i=\frac{n_i}{\sum_jn_j}.
$$

그다음 BPE 학습에 넣을 문장을 다음 확률로 뽑는다.

$$
q_i=\frac{p_i^\alpha}{\sum_jp_j^\alpha},
\qquad \alpha=0.5.
$$

- $p_i$는 corpus가 원래 차지한 비율이다.
- $\alpha$는 불균형을 누그러뜨리는 정도다.
- $p_i^\alpha$는 각 언어의 원 비율에 주는 새 가중치다.
- 분모는 모든 언어의 새 가중치를 더한 값이므로, 결과 $q_i$를 확률로 쓸 수 있게 한다.

예를 들어 A 언어가 100문장, B 언어가 25문장이면 $p_A=0.8$, $p_B=0.2$다. $\alpha=0.5$이면

$$
q_A=\frac{\sqrt{0.8}}{\sqrt{0.8}+\sqrt{0.2}}
\approx0.667,
\qquad
q_B\approx0.333.
$$

B는 원자료의 20%였지만 BPE 표본에서는 약 33%가 된다. $\alpha=1$은 원자료 비율을 그대로 보존하고, $0<\alpha<1$은 작은 corpus 쪽을 상대적으로 더 자주 뽑는다. 이 수식이 쓰이는 이유는 큰 언어의 data가 많다는 사실을 지우기보다, vocabulary가 작은 언어의 token을 지나치게 글자 단위로 쪼개지 않도록 **표본 구성**을 조절하기 위해서다.

논문은 CLM·MLM 학습 batch의 언어를 뽑을 때도 같은 꼴의 $q_i$를 쓰지만 그때는 $\alpha=0.7$을 썼다. 0.5는 BPE code 학습, 0.7은 이후 training batch 선택이다. 서로 다른 단계의 두 숫자를 하나의 hyperparameter로 합치지 않는다.

### 모델 입력에는 token·위치·언어 벡터가 함께 들어간다

논문의 Figure 1을 수식으로 풀면 $t$번째 입력은 다음처럼 볼 수 있다.

$$
e_t
=E_{\mathrm{tok}}[v_t]
+E_{\mathrm{pos}}[r_t]
+E_{\mathrm{lang}}[\ell_t].
$$

$v_t$는 BPE vocabulary 안 token 번호, $r_t$는 문장 안 위치, $\ell_t$는 언어 번호다. $E_{\mathrm{tok}}$·$E_{\mathrm{pos}}$·$E_{\mathrm{lang}}$에서 각각 길이 $d$인 행 하나를 꺼내어 더하므로 $e_t$도 길이 $d$다. 따라서 Transformer는 “무슨 조각인가”, “어디에 있는가”, “어느 언어 문장인가”를 같은 차원의 입력으로 받는다.

shared BPE와 shared parameter는 숫자·고유명·같은 문자권의 subword처럼 표면형 anchor가 있을 때 특히 유용하다. 그러나 ‘dog’와 ‘chien’처럼 모양이 다른 번역어의 의미가 BPE merge 하나만으로 정렬되지는 않는다. 공동 parameter 학습과, 병렬 자료가 있다면 TLM의 교차 언어 문맥이 추가 신호를 준다.

### CLM·MLM은 어느 위치를 답으로 삼는지가 다르다

문장을 $x=(x_1,\ldots,x_T)$, model parameter를 $\theta$라고 하자. CLM은 이전 token만 보고 현재 token을 예측한다.

$$
\mathcal{L}_{\mathrm{CLM}}(x)
=-\sum_{t=1}^{T}
\log p_\theta(x_t\mid x_{<t},\ell).
$$

- $x_{<t}$는 $x_1$부터 $x_{t-1}$까지의 왼쪽 문맥이다.
- causal mask 때문에 현재 token과 미래 token은 볼 수 없다. 그렇지 않으면 답을 읽고 답을 맞히는 문제가 된다.
- 각 $-\log p_\theta(\cdot)$는 한 target token의 벌점이다. 모든 위치에 더해 문장 전체 loss를 만든다.

MLM은 위치 집합 $M$을 고르고, 원문 $x$를 손상시킨 입력 $x^{\mathrm{in}}$을 만든다.

$$
x^{\mathrm{in}}=\operatorname{corrupt}(x,M),
\qquad
\mathcal{L}_{\mathrm{MLM}}(x)
=-\sum_{i\in M}
\log p_\theta(x_i\mid x^{\mathrm{in}},\ell).
$$

$x^{\mathrm{in}}$은 모델이 실제로 보는 입력, $x_i$는 가리기 전의 정답이다. XLM은 BPE token의 15%를 골라 그중 80%를 [MASK], 10%를 무작위 token, 10%를 그대로 둔다. token이 100개인 stream이면 평균적으로 15개를 고르고, 약 12개·1.5개·1.5개가 각 경우에 속한다. 이것은 한 batch의 기대값이며 모든 문장이 꼭 같은 정수 구성을 갖는다는 뜻은 아니다.

음의 log는 확률을 크게 만드는 일과 loss를 작게 만드는 일을 같은 방향으로 만든다. 정답에 0.8을 준 예측의 $-\ln(0.8)\approx0.223$보다 0.2를 준 예측의 $-\ln(0.2)\approx1.609$이 훨씬 큰 벌점을 받는다. 또한 여러 위치의 확률을 곱한 문장 확률은 log를 취하면 합으로 바뀌므로, token별 학습 신호를 더해 최적화할 수 있다.

### TLM은 두 언어에서 가린 token 모두에 loss를 준다

병렬 문장을 $x=(x_1,\ldots,x_m)$, $y=(y_1,\ldots,y_n)$라고 두고, 이어 붙인 입력을 $z=[x;y]$라 하자. $M_x$와 $M_y$는 각각 두 언어에서 가린 위치다.

$$
z^{\mathrm{in}}
=\operatorname{corrupt}(z,M_x\cup M_y),
$$

$$
\mathcal{L}_{\mathrm{TLM}}(x,y)
=
-\sum_{i\in M_x}\log p_\theta(x_i\mid z^{\mathrm{in}})
-\sum_{j\in M_y}\log p_\theta(y_j\mid z^{\mathrm{in}}).
$$

첫 합은 $x$의 빈칸, 둘째 합은 $y$의 빈칸을 복원하는 벌점이다. 두 문장이 모두 입력으로 있으므로, 예를 들어 영어의 가린 token은 남은 영어 문맥과 프랑스어 번역문을 함께 읽을 수 있다. 원 논문은 alignment를 돕기 위해 target 문장의 position을 다시 시작했다.

반대로 NMT의 전형적인 target 생성 loss는 다음과 같다.

$$
\mathcal{L}_{\mathrm{NMT}}(x,y)
=-\sum_{t=1}^{n}
\log p_\theta(y_t\mid y_{<t},x).
$$

NMT에서는 $y_t$가 지금 출력해야 하는 target token이고 $y_{<t}$만 이전 출력으로 볼 수 있다. TLM의 두 합은 source·target 한 방향을 정하지 않고 양쪽 빈칸에 놓인다. 그러므로 TLM이 병렬 문장을 쓰는 것이 사실이어도, TLM을 곧바로 번역 decoder 학습이라고 부르면 예측 경계가 달라진다.

### MLM+TLM은 두 종류의 batch를 교대한다

논문은 MLM과 TLM을 함께 쓸 때 monolingual MLM batch와 parallel TLM batch를 번갈아 학습했다. 이를 일반적인 확률적 학습 관점으로 쓰면, MLM batch를 고를 비율을 $r$이라 할 때 평균 loss는 다음 꼴로 이해할 수 있다.

$$
\mathbb{E}[\mathcal{L}_{\mathrm{batch}}]
=r\,\mathbb{E}[\mathcal{L}_{\mathrm{MLM}}]
+(1-r)\,\mathbb{E}[\mathcal{L}_{\mathrm{TLM}}].
$$

이 $r$은 교대 batch의 의미를 설명하기 위한 일반 표기다. 논문이 하나의 고정 $r$을 보고했다는 뜻은 아니다. 중요한 사실은 CLM·MLM의 monolingual text와 TLM의 parallel pair가 같은 종류의 한 input이 아니라 서로 다른 batch로 들어간다는 점이다.

### 영어 NLI label이 target 언어에 도착하는 경로

논문은 pretrained Transformer의 첫 hidden state 위에 무작위 초기화한 선형 classifier를 올리고, 영어 NLI training set으로 모든 parameter를 fine-tune했다. 이를 단순화하면

$$
h=h_\theta(s),\qquad
a=Wh+b,\qquad
p(c\mid s)=\operatorname{softmax}(a)_c
$$

로 쓸 수 있다.

- $s$는 한 NLI 입력 문장쌍, $h\in\mathbb{R}^{d}$는 encoder 표현이다.
- $W\in\mathbb{R}^{C\times d}$와 $b\in\mathbb{R}^{C}$는 $C$개 class의 점수를 만드는 classifier다.
- $a$는 class별 점수, softmax는 그 점수를 합이 1인 확률로 바꾼다.
- 영어 정답 $y_k^{\mathrm{en}}$에는 $-\log p(y_k^{\mathrm{en}}\mid s_k^{\mathrm{en}})$를 더해 $h$를 만드는 encoder와 $W,b$를 함께 바꾼다.

target 언어 평가에서는 같은 $h_\theta$, $W$, $b$를 바꾸지 않고 입력만 바꾼다. 전이가 성공하려면 shared multilingual pretraining이 영어와 target 언어의 과제 관련 의미를 classifier가 재사용할 수 있는 표현으로 만들어야 한다. 이것은 실험으로 측정한 성질이며, 언어가 shared vocabulary에 있었다는 사실만으로 자동 보장되지는 않는다.

### 결과의 차이는 단위와 추가 조건을 함께 읽는다

XNLI 15개 언어 평균 accuracy는 XLM MLM이 71.5, MLM+TLM이 75.1이었다.

$$
75.1\%-71.5\%=3.6\%\text{p}.
$$

이는 3.6 퍼센트포인트 차이다. 같은 표에서 종전 최고 70.2와 75.1의 차이는 4.9퍼센트포인트다. 3.6과 4.9는 기준선이 다르므로 바꾸어 쓰면 안 된다. 또 MLM+TLM은 TLM loss만 덧붙인 통제 실험이 아니라 parallel data를 함께 이용한 설정이다. 이 수치는 해당 data·architecture·training recipe에서 추가 병렬 TLM 설정과 함께 관측된 상승이지, 모든 언어와 과제에서의 보편적 보장이나 TLM만의 순수 효과를 뜻하지 않는다.

원 논문은 다음처럼 서로 다른 과제를 직접 평가했다.

| 과제 | 대표 결과 | 그 숫자가 답하는 질문 |
|---|---:|---|
| XNLI | MLM+TLM 평균 75.1 accuracy | 영어 label을 15개 언어 입력에 얼마나 전이하는가 |
| 비지도 MT | German→English 34.3 BLEU | 해당 WMT 조건에서 사전 학습 초기화가 번역에 도움이 되는가 |
| 지도 MT | Romanian→English 38.5 BLEU | 해당 WMT16 조건의 지도 번역 품질은 어떤가 |
| 저자원 LM | Nepali perplexity 157.2→109.3 | Hindi·English data를 함께 쓴 특정 Nepali LM의 불확실성이 줄었는가 |
| word similarity | SemEval17 Pearson 0.69 | 특정 cross-lingual 단어 유사도 평가에서 상관이 어떤가 |

accuracy·BLEU·perplexity·Pearson은 측정 대상도 방향도 다르다. 이 다섯 수치를 더하거나 평균내어 하나의 “XLM 점수”로 읽을 수는 없다.

### 원 논문의 구현·자료 경계

XNLI language model은 12-layer Transformer, 약 95k vocabulary를 사용했고, 언어 모델링 학습에는 64개 Volta GPU를 사용했다. CLM·MLM은 256-token stream 64개 batch를 사용했고 TLM은 길이가 비슷한 문장으로 된 4,000-token mini-batch를 사용했다. TLM의 병렬 자료는 한쪽이 영어인 pair였으며, 논문은 영어와 모든 언어 사이에 균등한 병렬 corpus가 있었다고 주장하지 않는다.

이 수치는 shared encoder가 언어별 모델 파일 수를 줄일 가능성과는 별개로, 실제 사전 학습 compute와 data 준비 비용이 작았다는 뜻이 아니다. 언어별 성능·간섭·native evaluation·배포 비용도 한 평균 accuracy나 vocabulary 수만으로 결론낼 수 없다.

## 검증과 한계

### 검증 정정

- **XLM은 하나의 고정 모델이다**: 원 논문은 CLM·MLM·MLM+TLM 설정을 비교했다.
- **CLM을 끝낸 뒤 TLM으로 넘어간다**: MLM+TLM은 monolingual MLM batch와 parallel TLM batch를 교대했다.
- **zero-shot은 훈련에서 보지 않은 언어를 뜻한다**: target 언어의 비표지 text는 pretraining에 있었고, 없는 것은 target-language NLI fine-tuning label이다.
- **TLM은 번역문을 생성한다**: TLM은 양쪽 문장의 masked token을 복원한다. 최종 target sequence를 순서대로 생성하는 NMT loss와 다르다.
- **shared BPE가 번역어 의미를 자동 정렬한다**: BPE는 표면형 anchor와 shared table을 제공할 뿐이며, 의미 전이는 공동 학습·문맥·병렬 신호에 의존한다.
- **Italian QA·교차 언어 정보검색·few-shot이 입증됐다**: 원 논문의 직접 평가는 XNLI·지도/비지도 MT·Nepali LM·word similarity다.
- **TLM만이 성공 원인이다**: monolingual-only MLM도 XNLI 평균 71.5를 냈고, MLM+TLM은 parallel data와 함께 75.1을 냈다.
- **하나의 모델이 deployment compute를 크게 줄였다고 측정했다**: 논문은 64 Volta GPU 사전 학습 조건을 적었지만, 보편적 배포 비용 절감을 측정한 것은 아니다.

### 남는 한계

TLM은 병렬 corpus가 있는 언어쌍에서 강한 교차 언어 문맥을 주지만, 그런 data가 없는 언어에는 그대로 적용할 수 없다. 작은 언어의 sampling을 평탄화해도 없는 text·label·품질 검수·평가 집합은 생기지 않는다. shared parameter가 positive transfer를 만들 수 있는 동시에 언어 간 간섭을 만들 가능성도 있으며, 평균 성능 상승은 언어별 격차를 보여 주지 않는다.

XLM은 다국어 전이 기제를 보여 주는 중요한 실험이지만, 저자원 언어의 형평성·문화적 적합성·장기 유지 비용까지 해결했다는 증거는 아니다. 그러한 주장에는 언어별 data 장부와 독립적인 native evaluation이 더 필요하다.
