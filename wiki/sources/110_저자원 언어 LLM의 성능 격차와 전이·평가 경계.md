# 저자원 언어 LLM의 성능 격차와 전이·평가 경계

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[XLM]], [[언어 모델 전이 학습]]<br>
> **읽고 나면:** 2025년의 세 연구가 사람 번역 benchmark, 합성 code-switch와 합성 병렬 data를 각각 어떻게 사용했는지 구분하고, 한 과제의 영어–Hindi 격차 축소를 여러 언어의 범용 성능이나 사회적 형평성으로 확대할 수 없는 이유를 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

원문은 2025년에 합성 data 생성, 교차언어 전이와 특화 학습을 결합한 하나의 돌파구가 여러 [[저자원 언어]]에서 영어에 가까운 성능을 달성하고 교육·의료·사업·문화 보존까지 바꾸었다고 서술한다. 그러나 글에는 그 돌파구의 연구팀, model, dataset, 언어 목록, benchmark, 수치, DOI나 외부 참고문헌이 없다. 따라서 원문은 문제를 제기하는 출발 자료로 보존하되, 공개 지식의 근거는 같은 시기와 주제의 1차 연구별로 다시 구성해야 한다.

### 세 연구가 실제로 한 일

원문과 가장 가까운 2025년 증거는 하나의 system이 아니라 서로 다른 세 연구다.

| 연구 | 실제 입력과 과제 | 직접 확인된 결과 | 확인하지 않은 것 |
| --- | --- | --- | --- |
| Alhanai 등 | 8개 아프리카 언어의 사람 번역 WinoGrande·MMLU와 기존 3개 언어, Llama 3 미세조정 | 영어 대비 격차 측정, 단일언어·교차언어 전이, 번역 품질과 문화 적합 문항의 조건별 개선 | 합성 학습 data, 격차 제거, 아프리카 전체, 현장 배포 |
| Nagar 등 | 1,200개 CommonSenseQA 질문의 Hindi–English 합성 code-switch, Llama-3-8B-Instruct QLoRA | 한 CMI 조건에서 English 90.4%, Hindi 85.6% | 여러 언어, 자유 생성·번역, 문화 보존, 범용 성능 |
| de Gibert 등 | GPT-4o가 English Europarl을 7개 언어로 번역한 합성 병렬 data, MT model 학습·미세조정 | 여러 MT 설정의 개선과 일부 방향의 하락, 언어별 합성 품질 차이 | 범용 LLM 능력, 영어와 동등한 품질, 실제 이용 효과 |

이 대응은 원문이 실제로 세 논문을 인용했다는 뜻이 아니다. 원문에는 외부 연구 인용이 없으므로, 공개일 이전에 존재하고 기술 어휘가 가장 가까운 1차 자료를 역추적한 결과다.

### 핵심 문장

- 2025년에는 저자원 언어의 평가 자료와 적응 방법을 넓힌 중요한 연구들이 있었지만, 여러 언어에서 영어 수준의 범용 LLM 성능을 입증한 단일 돌파구는 확인되지 않는다.
- [[저자원 언어]]는 화자 수가 적다는 뜻이 아니라 특정 언어·과제·시점에 corpus, tokenizer, label, benchmark, 전문 인력과 계산·배포 자원이 상대적으로 부족하다는 뜻이다.
- 합성 data와 교차언어 전이는 부족한 관측을 보충할 수 있지만 교사 model의 오류·언어 범위, 사람 검수, 실제 언어 사용과의 차이를 없애지 않는다.
- 한 번역 benchmark나 선택형 QA에서 영어와의 격차가 줄었다는 사실은 교육 성과, 의료 안전, 경제 참여, 문화 보존이나 디지털 접근성의 개선을 직접 측정한 것이 아니다.
- XLM·NLLB·BLOOM·MaLA-500·Aya가 이미 2019–2024년에 다국어 전이, 불균형 sampling, vocabulary 확장과 광범위한 평가를 다뤘으므로 2025년을 이 원리들의 최초 기점으로 둘 수 없다.

### 사실·비교 해석·미입증 영향

| 층위 | 이 문서에서 다루는 방식 |
| --- | --- |
| 확인된 사실 | 각 연구의 언어, data, model, 학습 절차, metric, 비교 조건과 수치 |
| 비교를 통한 해석 | 세 연구가 사람 번역, 합성 code-switch, 합성 MT data라는 서로 다른 자원 보강 경로를 보여 준다는 점 |
| 미입증 영향 | 교육·의료·사업의 실제 배포, 언어 사용 증가, 공동체 권한, 문화 전승, 수십억 명의 접근 개선과 다른 modality로의 직접 계보 |

## 2단계 — 작동 원리

### 저자원 언어 파이프라인은 하나의 data 수치로 설명할 수 없다

언어별 model 품질을 비교하려면 최소한 다음 장부를 분리해야 한다.

| 장부 | 확인할 것 | 하나로 합칠 때 생기는 오류 |
| --- | --- | --- |
| 언어·공동체 | 언어 변이, 방언, 문자, code-switch, 누가 이름과 범위를 정했는가 | language label 하나를 모든 화자의 대표로 봄 |
| 자연 자료 | 문서·발화 수, token, 장르, 시대, 출처, 동의와 권리 | raw token 수를 자연성·대표성과 동일시 |
| 학습 신호 | 단일언어, 병렬, 주석, instruction, synthetic data와 사람 검수 | 서로 다른 supervision을 단순한 “더 많은 data”로 합침 |
| 표현 | normalization, 문자 coverage, [[서브워드 토큰화|tokenizer]], vocabulary와 sequence 길이 | 문자열 표현 가능성을 효율·품질의 동등성과 혼동 |
| 전이·계산 | 공유 parameter, sampling, fine-tuning, base model, GPU·API 의존성 | 학습 sample 절감을 전체 개발 비용 절감으로 확대 |
| 평가 | native/번역 문항, 과제, shot, answer 언어, metric, 언어별 표본과 사람 평가 | 평균 하나를 범용 언어 능력으로 봄 |
| 배포·통제 | weight·code·data license, 실행 비용, 안전, 유지 보수와 공동체 의사 결정 | benchmark 개선을 실제 접근과 형평성으로 동일시 |

### Alhanai: 먼저 평가 자원을 만들고 격차를 측정한다

Alhanai 등은 Amharic, Bambara, Igbo, Sepedi, Shona, Sesotho, Setswana와 Tsonga의 WinoGrande 3,674문항과 MMLU의 virology·clinical knowledge·college medicine를 사람이 번역했다. 약 100만 단어의 새 자료를 만들고 기존 Afrikaans·Zulu·Xhosa 평가를 더해 11개 아프리카 언어를 비교했다. WinoGrande·MMLU는 5-shot accuracy, Belebele는 0-shot accuracy로 측정했다.

이후 절차는 다음과 같다.

1. GPT-3.5·GPT-4·GPT-4o, Llama 3 8B·70B, Phi 3, Aya23·Aya101과 BLOOMZ를 같은 번역 benchmark에서 비교한다.
2. 사람 번역 문항을 LLM-as-an-Annotator로 점수화해 data 품질 조건을 나눈다. 이는 합성 학습 문항 생성이 아니라 이미 번역된 문항의 선별 절차다.
3. Llama 3 70B를 언어별로 미세조정하고 같은 언어 안의 개선과 다른 언어로의 전이를 나눠 측정한다.
4. 영어 원문과 문화적으로 더 알맞게 조정한 목표언어 문항의 정확도 차이를 비교한다.

사람 번역과 검증에 약 40,218.78달러가 들었다. 즉 이 연구의 개선은 data 수집을 기법으로 대체한 사례가 아니라 사람 번역·검수, model 적응과 평가 설계를 함께 투자한 사례다.

### Nagar: 합성 code-switch 질문으로 한 언어쌍을 적응시킨다

Nagar 등은 CommonSenseQA의 1,200개 질문으로 Hindi–English 합성 code-switch data를 만들었다. GPT-3.5가 Hinglish를 생성한 `GPTgen`과 CoCoa 300M으로 Code-Mixing Index(CMI)를 0–16.7%, 16.7–30%, 30–50%로 통제한 세 조건을 사용했다. 질문만 섞고 답 선택지는 영어로 유지했으며, 수동 검토는 50개 묶음마다 하나씩, 약 24개 표본에 그쳤다.

`Meta-Llama-3-8B-Instruct`는 QLoRA로 5 epoch, learning rate $3\times10^{-5}$, batch size 32 조건에서 미세조정됐다. 연구는 5-fold cross-validation을 사용하고 질문마다 비결정적 출력을 다섯 번 생성해 최빈 선택지를 채택했다. 이 절차는 Hindi 전용 자연 문장 생성 능력보다 **합성 code-switch 질문에서 영어 선택지를 고르는 상식추론 accuracy**를 측정한다.

### de Gibert: 폐쇄형 교사 model로 합성 병렬 data를 만든다

de Gibert 등은 GPT-4o-2024-08-06으로 English Europarl을 Basque, Scottish Gaelic, Georgian, Icelandic, Macedonian, Somali와 Ukrainian으로 번역했다. 언어별 약 202만–235만 정렬 문장을 만들고 Europarl의 다중 병렬 구조를 이용해 147개 언어쌍으로 pivot했다. 다만 39개 후보 언어 가운데 GPT-4o가 FLORES-200 표본에서 이미 쓸 만한 번역을 낸 7개를 골랐으므로, 교사 model이 거의 다루지 못하는 언어까지 대표하지 않는다.

합성 data는 약 60.6M Transformer-base, OPUS-MT, NLLB-200-distilled-1.3B와 Llama-3.2-3B-Instruct의 MT 학습·미세조정에 사용됐다. 결과는 ChrF와 COMET, 평가자를 확보한 5개 언어의 언어별 100문장 사람 평가로 측정됐다. Scottish Gaelic과 Somali는 사람 평가자를 구하지 못했다. 이는 범용 LLM의 언어 이해 실험이 아니라 특정 번역 방향의 MT 실험이다.

## 3단계 — 기술과 근거

### 영어–아프리카 언어 격차는 줄었지만 사라지지 않았다

Alhanai 등의 GPT-4o 비교에서 영어와 11개 아프리카 언어 평균의 accuracy 격차는 과제에 따라 12.0–19.9 percentage points였다. 언어와 과제에 따른 격차는 더 크게 벌어졌고, 논문은 미세조정한 Llama 3 70B도 GPT-4o보다 낮았다고 명시한다.

| 비교 | 평균 변화 | 뜻 |
| --- | ---: | --- |
| 같은 언어의 미세조정 | +5.6 points | target-language data가 그 언어 평가를 개선한 평균 |
| 다른 언어 data에서의 교차언어 전이 | +2.9 points | 일부 공통 신호가 이동했지만 단일언어 적응보다 작은 평균 |
| high-quality data 대 low-quality data | +5.4 points | 번역 문항의 선별·품질 관리가 중요했음 |
| 문화적으로 조정한 문항 대 영어 기준 번역 문항 | +3.0 points | 문항 맥락의 적합성이 accuracy에 영향을 줌 |

가장 잘 맞는 과제·data 조건에서는 평균 최대 +17.4 points, 일부 문화 적합 조건에서는 최대 +15.6 points가 관찰됐다. 이 최댓값은 모든 언어의 보편 이득이 아니다. 문화 적합 문항에서 점수가 높아졌다는 사실도 model이 언어 문화를 보존하거나 공동체를 대표한다는 검증과 다르다.

### `near-English`는 Hindi 한 과제의 조건부 수치다

Nagar 등의 Table 1은 다음 결과를 보고한다.

| 조건 | English accuracy | Hindi accuracy | 격차 |
| --- | ---: | ---: | ---: |
| Base | 78.0% | 54.0% | 24.0 points |
| GPTgen | 88.8% | 79.6% | 9.2 points |
| CMI 1 | 81.6% | 75.2% | 6.4 points |
| CMI 2 | 90.4% | 85.6% | 4.8 points |
| CMI 3 | 87.2% | 77.2% | 10.0 points |

CMI 2의 4.8-point 격차가 원문의 “영어에 가까운 성능”과 가장 닮았다. 그러나 이는 Hindi–English 한 언어쌍, 합성 code-switch CommonSenseQA 질문, 영어 answer option, Llama-3-8B-Instruct 한 model과 예비 교차검증 평균에 묶인다. 다른 CMI 조건에서는 격차가 6.4–10.0 points였고, 번역·자유 생성·문화 이해·현장 이용은 평가하지 않았다.

연구 상태도 함께 기록해야 한다. 이 논문은 NAACL 2025 Student Research Workshop의 non-archival work-in-progress다. 논문은 5 epoch·learning rate $3\times10^{-5}$·batch 32를 적지만 공개 repository의 기본값은 32 epoch·$5\times10^{-4}$·batch 12로 달랐고 결과 checkpoint가 없다. 그림은 Llama-3.1-8B, 본문과 code는 Llama-3-8B-Instruct를 가리킨다. 따라서 수치를 완전 재현된 정설로 취급하지 않는다.

### 합성 번역 data도 언어와 방향에 따라 이득이 달랐다

de Gibert 등의 NLLB 미세조정은 English→7개 목표언어에서 평균 +2.95 ChrF를 얻었다. Llama 미세조정의 평균 증분은 +20.63 ChrF였지만 절대 성능은 작은 MT 전용 model보다 낮았다. 비영어 방향에서도 Finnish→Somali와 반대 방향 OPUS-MT는 +14.78·+21.64 ChrF였으나 Finnish↔Ukrainian은 -1.21·-1.78 ChrF로 하락했다.

합성 품질도 균일하지 않았다. Macedonian과 Ukrainian 사람 평가에서는 80–100점 구간이 92%를 넘었지만 Georgian은 약 40%가 40점 미만의 unacceptable 품질이었다. Bicleaner-AI와 사람 평가의 Spearman 상관은 5개 언어 중 4개에서 0.26 미만이었고 Georgian은 0.39였으며, CometKiwi와 사람 평가의 상관은 0.21–0.64였다. 합성 data가 규모를 제공한다는 사실과 자연성·정확성·문화 적합성을 보장한다는 주장은 분리해야 한다.

### 2025년보다 앞선 다국어 전이·적응 계보

| 시기 | 확인된 선행 | 이번 문서에서의 경계 |
| --- | --- | --- |
| 2019 XLM | shared BPE, 언어 sampling 평탄화, monolingual MLM과 parallel TLM, XNLI 전이 | target 언어의 비표지 text가 있었으며 언어 형평성 평가가 아님 |
| 2022 NLLB | 200개 언어, FLORES-200, 40,000개 초과 번역 방향, data mining·역번역·희소 MoE·regularization | MT model이며 범용 LLM·생산·의료·법률 이용을 입증하지 않음 |
| 2022 BLOOM | 46개 자연어의 ROOTS와 공개 checkpoint·문서 | 언어별 data 양과 성능이 불균등하고 큰 실행 비용이 남음 |
| 2024 Aya | 101개 언어 instruction tuning과 99개 언어 판별·생성·사람 평가 | 넓은 언어 목록과 모든 언어의 동일 품질은 다름 |
| 2024 MaLA-500 | Glot500-c 534개 언어, vocabulary extension과 continued pretraining | language coverage·tokenizer 적응과 과제별 성능을 분리해야 함 |

따라서 2025년 연구는 이 계보 위에서 새 benchmark와 특정 적응 실험을 보탰다. “저자원 언어 문제를 data가 아니라 기법으로 처음 해결한 전환점”이라는 연표는 성립하지 않는다.

### Tokenizer는 문자열 포괄성과 언어별 효율을 나눈다

공유 subword vocabulary나 byte fallback은 임의 문자열을 표현할 수 있게 할 수 있다. 그러나 같은 내용을 언어마다 비슷한 token 수로 나타내고 같은 downstream 품질을 낸다는 뜻은 아니다. Rust 등은 9개 언어·5개 과제의 통제 비교에서 사전 학습 data 양뿐 아니라 vocabulary 안의 언어 representation과 tokenizer가 중요했으며, multilingual model의 tokenizer를 언어 전용 tokenizer로 교체하면 거의 모든 언어·과제에서 성능이 개선됐다고 보고했다.

이 결과도 mBERT 계열의 해당 언어·과제 비교에 한정된다. 모든 modern LLM에서 tokenizer 하나가 성능 격차의 단일 원인이라는 뜻은 아니다. Data 양·장르, parameter sharing, sampling, script, fine-tuning과 evaluation을 함께 봐야 한다.

## 검증과 한계

### 원문 서사의 검증 정정

- **2025년에 하나의 결정적 특화 LLM 돌파구가 등장했다:** 원문은 system·paper·model을 이름 붙이지 않는다. 확인 가능한 것은 서로 다른 data·과제·model을 사용한 여러 연구다.
- **여러 저자원 언어에서 영어와 가까운 범용 성능을 달성했다:** Alhanai 등의 GPT-4o 격차는 평균 12.0–19.9 points였다. 4.8-point 격차는 Nagar 등의 Hindi 합성 code-switch CommonSenseQA 한 설정뿐이다.
- **progressive fine-tuning·curriculum learning·저데이터 전용 regularization이 2025 해법의 핵심이었다:** 원문이 어느 실험을 가리키는지 식별할 수 없고, 가장 가까운 세 연구의 공통 절차도 아니다.
- **합성 data가 언어의 문법·문화·진정성을 보존했다:** Nagar는 실제 code-switch 자연성의 한계를, de Gibert는 Georgian 품질 실패를 보고했다. 문화 보존 지표는 없다.
- **적은 data만으로 해결하는 technique-centric 전환이 일어났다:** Alhanai는 약 4만 달러의 사람 번역·검증을, Nagar는 기존 CommonSenseQA와 폐쇄형 GPT-3.5를, de Gibert는 Europarl과 대량 GPT-4o 생성을 사용했다. Data와 기법은 대체 관계가 아니다.
- **저자원↔저자원 고품질 번역이 일반화됐다:** Finnish–Somali 방향은 개선됐지만 Finnish–Ukrainian OPUS-MT는 하락했다. 언어쌍과 model별 결과를 보존해야 한다.
- **교육·의료·사업용 도구가 실제로 제공됐다:** 세 연구는 제품, 기관, 사용자 수, 임상·교육 outcome이나 장기 운영을 평가하지 않았다.
- **AI가 언어 보존·부흥과 디지털 격차 감소를 실현했다:** 가능한 활용 방향이지, 언어 사용 증가·세대 전승·접근·채택·피해 분포를 측정한 결과가 아니다.
- **수십억 명이 고급 AI에 새로 접근했다:** 잠재 화자 수와 실제 접근권·비용·안전·혜택을 혼동한 주장이다.
- **2025 연구가 이후 수년과 비전·멀티모달·의료영상에 영향을 미쳤다:** 2025-08-28 공개 시점에 이후 수년의 효과를 확정할 수 없고 직접 인용·계보 근거도 없다.

### 세 연구에 남은 한계

Alhanai 등의 자료는 중요한 사람 번역 benchmark지만 실제 아프리카 현지 사용을 위해 처음부터 만든 native task가 아니다. 언어별 번역 수정률은 4.9–65.3%로 달랐고, 방언·번역자 차이와 11개 언어 범위가 남는다. 각 언어를 따로 미세조정했기 때문에 하나의 공동 다국어 적응 결과도 아니다.

Nagar 등의 결과는 한 언어쌍·작은 fold·선택형 CSR에 제한된다. 합성 generator의 혼합 비율·자연성·편향, 제한된 수동 검수와 공개 recipe 불일치가 남고, code·파생 data repository에는 감사 시점에 LICENSE가 없었다. 논문 CC BY 4.0, CommonSenseQA의 조건, Meta Llama 3 Community License와 GPT-3.5의 독점 서비스 조건을 서로 구분해야 한다.

de Gibert 등의 실험은 GPT-4o가 이미 쓸 만한 번역을 내는 7개 언어를 먼저 골랐고 Europarl domain에 집중했다. 사람 평가는 평가자를 확보한 5개 언어에서 각각 100문장이며 Scottish Gaelic과 Somali는 빠졌다. 폐쇄형 교사 model, benchmark contamination 가능성과 OpenAI usage policy 의존성이 남고, 가장 어려운 미지원 언어의 합성 data 품질을 입증하지 않는다.

### Benchmark 개선과 사회적 형평성 사이

언어별 accuracy·ChrF의 개선은 model 선택과 연구 방향을 바꾸는 실질적 증거다. 이를 “단지 benchmark일 뿐”이라고 무효화해서도 안 된다. 그러나 사회적 형평성은 누가 data와 언어 범주를 정했는지, 오류 비용이 누구에게 돌아가는지, model·compute를 누가 이용할 수 있는지, 공동체가 수정·거부·유지할 권한을 갖는지, 실제 교육·의료·경제·언어 사용 outcome이 나아졌는지를 추가로 묻는다.

현재 확인한 1차 연구는 앞부분의 model·benchmark 개선을 지지하지만 뒷부분의 실제 배포와 분배 결과를 측정하지 않았다. 이 둘을 분리하는 것이 성과를 축소하지 않으면서도 원문의 형평성 주장을 과대평가하지 않는 방법이다.
