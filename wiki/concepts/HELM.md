# HELM

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[GLUE와 SuperGLUE]], [[067_GPT-3와 문맥 내 학습]]<br>
> **읽고 나면:** HELM의 시나리오–적응–메트릭–실행 구조를 설명하고, 다차원 평가 결과를 단일 순위나 안전 인증과 구분해 읽을 수 있다.

## 1단계 — 먼저 잡을 핵심

### 한 문장 정의

**HELM(Holistic Evaluation of Language Models)**은 언어 모델을 여러 사용 시나리오와 여러 가치 기준에서 같은 적응 조건으로 비교하고, 점수뿐 아니라 평가 절차와 원시 출력을 공개하는 평가 프레임워크다.

HELM의 `holistic`은 모든 언어·과제·위험을 빠짐없이 측정했다는 뜻이 아니다. 평가할 공간을 넓게 분류하고, 실제로 포함한 범위와 빠진 범위를 함께 드러내며, 정확도 밖의 여러 메트릭을 같은 장부에 놓겠다는 설계 원칙이다.

### 세 가지 핵심 직관

HELM은 언어 모델 평가의 문제를 세 방향에서 다시 구성했다.

1. **넓은 범위:** 서로 다른 과제·도메인·언어를 시나리오 공간으로 조직하고 모델별 평가 공백을 보이게 한다.
2. **다중 메트릭:** 정확도뿐 아니라 보정·강건성·공정성·편향·독성·효율성을 가능한 범위에서 함께 측정한다.
3. **표준화와 투명성:** 모델마다 다른 prompt와 보고 형식 때문에 생기는 차이를 줄이고, 결과에서 실제 prompt·completion까지 거슬러 내려갈 수 있게 한다.

이 셋은 서로 대체되지 않는다. 많은 과제를 모아도 정확도 하나만 보면 위험과 비용을 놓친다. 여러 메트릭을 계산해도 모델마다 prompt·예시 수가 다르면 직접 비교가 어렵다. 같은 조건으로 평가해도 포함한 언어와 사용 사례가 좁으면 그 밖의 배포 환경을 대표하지 않는다.

### 무엇과 구분해야 하는가

HELM은 하나의 새 언어 모델이나 하나의 dataset이 아니다. 모든 결과를 합쳐 보편적인 `HELM score` 하나를 산출하는 순위표도 아니다. 어떤 모델이 실제 제품에 안전하게 배포될 수 있음을 인증하는 제도도 아니다.

초기 HELM의 평가 대상은 표준화된 방식으로 시나리오에 적응한 **언어 모델**이었다. Retriever·tool·memory·content policy·사용자 interface를 결합한 완성 시스템은 별도의 시스템 수준 평가가 필요하다. 이 경계는 [[파운데이션 모델]]과 그 위에 조립된 응용을 구분하는 방식과 연결된다.

### 왜 중요한가

단일 점수는 모델 선택을 간단하게 만들지만, 어떤 능력과 실패를 평균 안에 숨겼는지 알기 어렵다. HELM은 모델 $A$가 정확도에서는 앞서도 효율성이나 독성에서는 다른 양상을 보일 수 있다는 점을 시나리오×메트릭 행렬로 보존했다.

따라서 HELM 결과를 읽는 첫 질문은 “어느 모델이 1위인가?”가 아니다. “내 사용 시나리오는 무엇이며, 그 시나리오에서 어떤 메트릭을 우선하고, 비교 조건과 빠진 위험은 무엇인가?”가 먼저다.

## 2단계 — 작동 원리

### 네 구성 요소

HELM의 평가 단위는 다음 네 요소로 나눌 수 있다.

| 요소 | 묻는 질문 | HELM에서의 역할 |
| --- | --- | --- |
| 시나리오(scenario) | 모델이 어느 과제·도메인·언어에서 무엇을 해야 하는가? | 사용 사례와 평가 자료의 범위를 정한다. |
| 모델(model) | 어느 언어 모델을 비교하는가? | 크기·훈련 방식·접근 조건이 다른 평가 대상을 포함한다. |
| 적응(adaptation) | 범용 모델을 그 시나리오에 어떻게 적용하는가? | Prompt, 문맥 예시, 답안 형식과 model interface를 정한다. |
| 메트릭(metric) | 출력의 어떤 속성을 어떤 규칙으로 재는가? | 정확도·위험·비용을 서로 다른 열로 계산한다. |

시나리오는 단순한 dataset 이름보다 넓다. HELM은 과제(task), 도메인(domain), 언어(language)의 조합으로 시나리오 공간을 분류했다. 같은 질문 답변 과제라도 일반 web 자료와 특정 전문 domain, 영어와 다른 언어는 서로 다른 사용 조건이 된다.

### 입력에서 결과까지

한 평가 흐름은 다음과 같이 읽을 수 있다.

1. 시나리오 $S$에서 평가 instance와 허용된 참조 정보를 가져온다.
2. 적응 방법 $A$가 instance와 문맥 예시를 모델 $M$이 받을 prompt로 바꾼다.
3. 모델이 completion이나 선택지별 확률 같은 원시 출력 $O$를 만든다.
4. 각 메트릭 $m_j$가 같은 출력을 서로 다른 기준으로 평가해 결과 $R_j$를 만든다.
5. 결과를 집계하되 개별 prompt와 completion도 보존해 오류를 다시 확인할 수 있게 한다.

이를 간단히 쓰면 다음과 같다.

$$
O=\operatorname{Run}(M,S,A), \qquad R_j=m_j(O,S)
$$

이 식의 요점은 모델 점수가 $M$만의 고정 속성이 아니라는 데 있다. 시나리오 $S$, prompt와 예시를 정하는 $A$, 측정 규칙 $m_j$가 달라지면 같은 모델의 결과도 달라진다.

### 공통 5-shot 적응의 의미

초기 HELM은 적용 가능한 시나리오의 공통 비교에서 단순한 5-shot prompting을 기본 적응으로 사용했다. 최대 다섯 개의 문맥 예시와 공통 prompt 규칙을 두어 모델마다 다른 prompting engineering이 만드는 차이를 줄이려는 선택이었다. 언어 모델링처럼 문맥 예시가 적용되지 않는 시나리오와 별도 적응법을 쓴 표적 평가는 이 설명의 예외다.

표준화는 모든 모델에 가장 좋은 사용법을 찾아 준다는 뜻이 아니다. Zero-shot 지시를 위해 훈련한 모델이나 특정 답안 형식에 민감한 모델은 공통 5-shot 조건에서 불리할 수 있다. 표적 평가 가운데 code 생성·허위정보처럼 목적에 맞춘 다른 적응 절차를 사용한 경우도 있다.

### 여러 메트릭을 같은 시나리오에서 본다

하나의 질의응답 시나리오를 예로 들면 정확도는 정답을 맞혔는지 묻는다. 보정은 높은 확률을 준 답이 실제로도 그만큼 자주 맞는지 묻는다. 강건성은 의미를 보존하거나 의도적으로 바꾼 입력에서 응답이 기대한 방식으로 유지·변화하는지 묻는다. 공정성은 관련 집단에 따라 과제 정확도 격차가 나타나는지 묻는다.

이 값들은 같은 단위가 아니며 서로 자동으로 합쳐지지 않는다. HELM은 메트릭별 결과와 절충을 남겨, 사용자가 자신의 시나리오와 가치 우선순위에 맞춰 읽게 한다.

### 결과 행렬을 읽는 순서

HELM 표를 볼 때는 다음 순서를 따른다.

1. 먼저 관심 있는 시나리오가 실제 사용 조건과 얼마나 가까운지 확인한다.
2. 어떤 adaptation과 model version으로 실행했는지 확인한다.
3. 정확도와 함께 관련 위험·비용 메트릭을 나란히 본다.
4. 큰 차이가 있으면 원시 prompt·completion과 표본 수 및 불확실성을 확인한다.
5. 측정되지 않은 메트릭과 포함되지 않은 언어·도메인을 남은 검증 항목으로 기록한다.

## 3단계 — 기술과 근거

### 초기 HELM의 평가 규모

Liang 등은 2022년 arXiv로 처음 공개하고 2023년 TMLR에 출판한 초기 HELM에서 12개 조직이 만든 30개 언어 모델을 42개 시나리오에 놓았다.

| 구분 | 규모 | 역할 |
| --- | ---: | --- |
| 핵심 시나리오 | 16개 | 같은 사용 사례에 가능한 여러 메트릭을 적용해 절충을 본다. |
| 표적 시나리오 | 26개 | 언어 이해·지식·추론·암기·저작권·허위정보·편향·독성 같은 특정 능력과 위험을 더 깊게 검사한다. |
| 전체 시나리오 | 42개 | 30개 모델의 비교 범위를 공통 장부에 포함한다. |

`핵심(core)`은 본질적으로 더 중요한 과제라는 뜻이 아니다. 다중 메트릭을 조밀하게 적용하는 공통 비교 집합이라는 운영상 구분이다. 표적 평가에는 모든 메트릭을 반복 적용하기보다 특정 질문에 맞춘 시나리오와 절차가 들어간다.

### 일곱 메트릭 범주

| 메트릭 | 측정하려는 대표 질문 | 확대 해석하지 말아야 할 것 |
| --- | --- | --- |
| 정확도(accuracy) | 과제의 정답·참조·목표를 얼마나 잘 충족하는가? | 일반 지능이나 모든 사용 조건의 유용성 |
| 보정(calibration) | 예측 확률과 실제 정답 빈도가 얼마나 대응하는가? | 설명의 진실성이나 모델의 자기 인식 |
| 강건성(robustness) | 정해진 text perturbation에서 예측이 기대대로 유지·변화하는가? | 현실의 모든 공격과 분포 이동에 대한 견고성 |
| 공정성(fairness) | 사회 집단에 따라 과제별 정확도 격차가 나타나는가? | 가능한 모든 차별과 실제 개인별 harm |
| 편향(bias) | 생성 언어에 인구통계학적 재현 불균형이나 고정관념적 연관이 나타나는가? | 공정성과 동일한 단일 속성 |
| 독성(toxicity) | 생성문이 Perspective API의 독성 기준에 얼마나 자주 걸리는가? | 허위정보·조작·개인정보·위험 조언을 포함한 안전 전체 |
| 효율성(efficiency) | 추론 시간·처리량과, 자료가 있을 때 훈련 energy·carbon 추정이 어떠한가? | 비공개 모델의 전체 수명주기 비용 |

16개 핵심 시나리오와 일곱 메트릭이면 가능한 범주 조합은 112개다. 실제 측정은 98개, 즉 87.5%였다. 일부 조합은 메트릭이 정의되지 않거나 타당하게 계산하기 어려워 비워 두었다. 이는 빈칸을 임의의 점수로 채우는 대신 측정의 적용 범위를 드러낸 선택이다.

### 17.9%에서 96.0%로 넓힌 것

초기 HELM이 보고한 17.9%→96.0%는 모델 정확도의 향상이 아니다. 30개 모델이 16개 핵심 시나리오에서 얼마나 조밀하게 평가되었는지를 나타내는 **coverage**다. 기존 모델 논문에 흩어진 결과만 모으면 평균 17.9%의 핵심 시나리오만 비교할 수 있었고, HELM의 공통 실행 뒤에는 96.0%를 채웠다.

남은 4.0%는 일부 모델의 확률 접근·tokenization·interface 같은 기술 조건 때문에 실행하지 못한 칸이다. 평가 칸을 많이 채우면 head-to-head 비교는 쉬워지지만, benchmark contamination이나 측정 타당성이 자동으로 해결되지는 않는다.

### GLUE에서 HELM으로 넓어진 평가 단위

[[GLUE와 SuperGLUE]]와 HELM은 모두 평가 조건을 표준화해 모델 비교를 개선했지만 구조와 목적이 다르다.

| 비교 축 | GLUE·SuperGLUE | 초기 HELM |
| --- | --- | --- |
| 중심 대상 | 여러 영어 NLU task의 transfer 성능 | 여러 언어 모델의 사용 시나리오별 능력·위험·비용 |
| 결과 구조 | 과제별 metric과 aggregate score | 시나리오×메트릭 행렬과 원시 출력 |
| 적응 조건 | 과제별 supervised training·fine-tuning을 허용 | 핵심 비교는 공통 5-shot prompting 중심 |
| 측정 범위 | 분류·회귀·추론·독해 task 성능 | 정확도와 보정·강건성·공정성·편향·독성·효율성 |
| 주요 사각지대 | 영어·과제 집합·집계 평균·leaderboard 포화 | 영어 중심 범위·prompt 민감성·비용·자동 메트릭·배포 타당성 |

HELM은 GLUE를 폐기한 것이 아니라 표준화의 단위를 확장했다. GLUE가 task와 metric을 공통 suite에 놓았다면, HELM은 prompt를 포함한 adaptation과 model access 조건까지 비교 장부에 넣고 같은 시나리오에서 여러 가치 기준을 측정했다.

### 파운데이션 모델과 평가 대상의 경계

[[파운데이션 모델]]은 광범위하게 사전 학습한 공통 기반이 여러 과제와 응용에 적응되는 생태계상의 역할을 가리킨다. HELM은 이 가운데 언어 모델을 여러 시나리오에 공통 방식으로 적응시켜 행동을 비교한다.

그러나 기반 모델, 적응 모델과 실제 제품은 같은 평가 대상이 아니다. HELM에서 관측한 모델 행동은 특정 prompt·dataset·metric에 조건화된다. 실제 응용은 retriever, tool, policy와 interface를 추가하고 다른 사용자·domain에 배포된다. 따라서 HELM 결과는 기반 모델 선택의 한 증거가 될 수 있지만 완성 시스템의 외재 타당성을 대신하지 않는다.

### 공개 산출물과 제한된 인간 평가

HELM은 modular toolkit, 평가 설정, 원시 prompt와 completion을 공개했다. 집계 점수가 이상할 때 개별 예시로 내려가 원인을 확인하고, 새로운 메트릭을 과거 출력에 다시 적용할 수 있게 한 것이다.

전체 행렬은 확장 가능한 자동 메트릭을 중심으로 만들었다. 사람 평가가 42개 시나리오와 30개 모델 전부의 정답을 판정한 것은 아니다. 원 논문 본문 §8.5에서 상세 보고된 인간 평가는 두 허위정보 시나리오의 6개 모델에 한정된다. Appendix A는 요약 평가에도 인간 평가 작업이 있었음을 기여 내역으로 기록하지만, 본문은 그 결과와 범위를 제시하지 않는다. “자동·인간 평가를 결합했다”는 말은 이 제한과 함께 써야 한다.

### 평가도 자원을 소비한다

초기 연구는 4,939개의 run에서 약 122억 token과 1,743만 query를 처리했다. 당시 가격으로 상용 API에 38,001달러를 지출했고, 공개 모델 추론에는 약 19,500 GPU 시간이 들었다.

이 수치는 모델 훈련 비용이 아니라 HELM 평가 자체의 규모와 비용이다. 넓은 scenario×model×metric 행렬은 비교 가능성을 높이지만 반복 실행의 자원 장벽도 만든다. 평가 예산 때문에 많은 dataset을 1,000개 instance로 제한하고 문맥 예시 선택에 세 random seed만 사용한 조건을 결과와 함께 읽어야 한다.

## 검증과 한계

### 확인된 사실

- 초기 HELM은 30개 모델, 16개 핵심 시나리오와 26개 표적 시나리오를 공통 평가 장부에 놓았다.
- 핵심 시나리오에서는 가능한 범위에서 일곱 메트릭을 함께 적용했고 112개 범주 조합 중 98개를 측정했다.
- 적용 가능한 시나리오의 공통 5-shot prompting은 모델 간 적응 조건을 통제하기 위한 선택이었다.
- 연구진은 결과표와 함께 원시 prompt·completion과 modular toolkit을 공개했다.
- 17.9%→96.0%는 핵심 시나리오에 대한 모델 평가 coverage의 변화이지 정확도 상승이 아니다.

### 흔한 오해와 정정

- **Holistic이면 모든 중요한 영역을 포괄한다:** 초기 평가는 영어 중심의 42개 시나리오와 선택한 일곱 메트릭 범주다. 논문은 누락된 언어·domain·interaction·model·metric을 명시했다.
- **일곱 메트릭을 모든 핵심 시나리오에 빠짐없이 계산했다:** 실제 측정은 98/112 조합이었다.
- **공정성과 편향은 같은 축이다:** 공정성은 과제별 집단 성능 격차, 편향은 생성 언어의 재현·연관 비대칭을 중심으로 구분했다.
- **독성 점수가 낮으면 모델은 안전하다:** Perspective API 기반 독성은 안전의 한 조작화일 뿐이며 허위정보도 별도 표적 평가였다.
- **공통 prompt는 모든 모델의 최적 조건이다:** 비교 조건을 같게 한 것이며 model-specific prompting·zero-shot·fine-tuning에서 같은 순위가 유지된다는 보장은 없다.
- **인간이 모든 결과를 검수했다:** 자동 메트릭이 중심이고 본문에서 상세 보고된 인간 평가는 두 허위정보 시나리오와 6개 모델에 한정됐다. Appendix A는 요약 평가 작업의 존재만 기록한다.
- **96.0%는 성능 정확도다:** 평가 행렬 coverage다.
- **HELM 1위 모델이 보편적으로 가장 좋다:** 원 논문은 모든 가치와 상황을 만족하는 보편 집계를 제시하지 않았다.
- **초기 HELM 결과가 현재 API의 고정 성질이다:** 비공개 API와 서비스 model은 바뀔 수 있어 평가 시점과 version을 함께 기록해야 한다.

### 측정 타당성과 일반화 한계

HELM이 점수를 표준화해도 메트릭이 추상 개념을 완전하게 측정한다는 보장은 없다. Perspective API 기반 독성은 구체적 배포 맥락을 결여한 조작화이며, 원 논문은 NarrativeQA에서 도메인 때문에 false positive가 늘었을 가능성을 지적했다. Counterfactual 치환과 집단별 정확도 격차도 실제 사회의 모든 공정성 문제를 재현하지 않는다.

대규모 모델의 훈련 자료는 불완전하게 문서화되어 평가 instance나 같은 분포의 자료에 노출됐는지 모두 확인하기 어렵다. 원 논문은 알려진 contamination 증거를 기록했지만 전체 오염 정도와 성능에 미친 영향을 확정하지 못했다.

Prompt, 문맥 예시, multiple-choice answer format과 decoding 설정에 따라 같은 모델의 점수가 크게 달라질 수 있다. 공통 adaptation은 한 변수를 고정할 뿐 prompt 민감성을 없애지 않는다.

초기 핵심 시나리오는 영어였고 실제 대화의 장기 상태, 다국어·다문화 사용, multimodal input, 검색·도구 사용과 반복 행동을 포괄하지 않았다. 후속 HELM suite가 범위를 확장해도 특정 version의 결과를 다른 version과 섞지 않는다.

### 집계에는 가치 판단이 들어간다

시나리오와 메트릭을 하나의 점수로 합치려면 가중치를 정해야 한다. 그 순간 정확도·공정성·독성·효율성 가운데 무엇을 더 중요하게 볼지에 관한 가치 판단이 들어간다. 서로 다른 단위와 타당성을 가진 값을 단순 평균하면 약점과 절충을 다시 숨길 수 있다.

HELM은 이 문제를 해결된 보편 순위로 제시하지 않았다. 사용자는 배포 맥락에 맞는 시나리오와 메트릭을 먼저 고르고, 누락된 위험을 별도 평가해야 한다.

### 근거 범위

이 문서의 정의, 초기 평가 규모, 메트릭과 한계는 Liang 등의 2023년 TMLR 논문과 그 공개 산출물에 근거한다. 2025년 회고 raw는 학습 출발 자료로 보존하지만 사실 검증의 단독 근거로 사용하지 않는다.

이 문서는 HELM이 곧바로 업계 표준이 됐거나 다른 AI modality의 평가를 인과적으로 바꿨다고 주장하지 않는다. 후대의 HELM Classic·Lite와 domain별 suite는 초기 개념의 확장 사례지만, 채택 규모와 영향에는 각 version의 문서와 수용 자료가 필요하다.
