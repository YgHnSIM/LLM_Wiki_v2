# 언어 모델 스케일링 법칙

> [!note] 학습 안내
> **난이도:** 심화<br>
> **선수 지식:** [[Perplexity]], [[대규모 언어 모델]]<br>
> **읽고 나면:** scaling law 식의 변수·병목·관측 범위를 확인하고, 단일 loss 곡선과 compute-optimal 배분 및 downstream 능력을 서로 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

언어 모델 스케일링 법칙(language model scaling law)은 모델·데이터·학습 compute 같은 **규모 변수**와 언어 모델 loss 사이에서 관측한 규칙적 관계를 경험식으로 표현한다. 대표적인 2020년 Kaplan fit은 조건이 맞을 때 token cross-entropy가 규모의 음의 거듭제곱으로 감소함을 보였다.

$$
L(X)\propto X^{-\alpha},
\qquad X\in\{N,D,C\}.
$$

이 식을 읽을 때는 네 가지를 함께 적는다.

1. $L$이 어떤 자료·tokenization의 어떤 metric인가?
2. $X$에 포함하거나 제외한 자원은 무엇인가?
3. 다른 규모 축이 병목이 아니라는 조건이 충족됐는가?
4. 관측 구간 안의 interpolation인가, 구간 밖 extrapolation인가?

## 2단계 — 작동 원리

### log–log 직선과 작은 지수

$L=aX^{-\alpha}$의 양변에 logarithm을 취하면 다음과 같다.

$$
\log L=\log a-\alpha\log X.
$$

log–log 좌표에서 기울기가 $-\alpha$인 직선으로 보이므로 여러 규모의 run을 한 fit으로 비교할 수 있다. Kaplan 연구의 model-size 지수 $\alpha_N\approx0.076$이라면 $N$을 $r$배 늘릴 때 loss 배수는 $r^{-0.076}$이다. 작은 지수는 개선이 매끄럽다는 뜻과 동시에 같은 추가 개선에 매우 큰 자원이 필요하다는 뜻이다.

### 단변량 곡선의 병목 조건

| 읽는 곡선 | 필요한 조건 | 조건이 깨질 때 |
|---|---|---|
| $L(N)$ | 충분한 data와 training | data 부족·미수렴이 model 효과를 가림 |
| $L(D)$ | 충분한 model capacity와 적절한 early stopping | 작은 model의 capacity floor |
| $L(C)$ | model·batch·steps의 정의된 배분 | suboptimal allocation이 compute 효과를 가림 |

따라서 서로 다른 논문이 같은 $C$를 말해도 FLOP 추정식, embedding 포함 여부, sequence-length 항, batch 효율 보정이 다르면 지수를 바로 비교할 수 없다.

### joint fit과 compute frontier

model과 data를 함께 변화시킨 $L(N,D)$ fit은 한 축의 부족이 다른 축의 이득을 막는 영역을 표현한다. compute frontier는 주어진 $C$에서 loss가 가장 낮은 $N$, $D$, batch와 steps 조합을 찾는다. 이는 단순히 “클수록 좋다”가 아니라 **어느 축을 얼마나 함께 키울 것인가**의 문제다.

여기서 $D$는 처리한 token 수를 세지만 source composition·quality proxy·sampling weight를 하나씩 표현하지는 않는다. 같은 $D$라도 [[데이터 품질과 분포 다양성은 같은 축인가|필터와 분포 설계]]가 다르면 서로 다른 학습 분포다.

### 희소 모델에서는 $N$을 다시 나눈다

Kaplan의 대표 fit은 dense Transformer 계열에서 non-embedding parameter $N$을 사용했다. [[전문가 혼합]] 같은 sparse architecture에서는 total parameters와 한 token에서 활성화되는 shared·expert parameters가 달라질 수 있다. Expert 수를 늘려 total $N$을 키우면서 top-$k$를 고정하면 active expert FLOPs는 같은 비율로 늘지 않는다.

따라서 dense model의 $L(N)$ 곡선에 sparse model의 total parameter를 그대로 넣어 같은 capacity point로 비교하지 않는다. Total parameters, active FLOPs, data token, hardware·wall-clock, memory·communication과 loss를 함께 보고 architecture별 fit을 다시 확인해야 한다. MoE는 dense scaling law를 반박하는 예외가 아니라, $N$과 $C$의 대응을 바꾸는 설계 축이다.

## 3단계 — 기술과 근거

### Kaplan 2020의 두 종류 데이터 배분

Kaplan 연구에는 혼동하기 쉬운 두 관계가 있다.

- overfitting을 피하며 model size를 늘릴 때 필요한 dataset 규모: 대략 $D\propto N^{0.74}$
- fixed compute에서 loss를 최소화하도록 처리할 token을 배분할 때: $N_{opt}\propto C^{0.73}$, $D_{opt}\propto C^{0.27}$

첫째는 model을 충분히 학습할 data floor에 관한 관계이고, 둘째는 compute budget의 최적 배분이다. 지수에 같은 0.7대 값이 보여도 독립 변수와 질문이 다르다.

Kaplan fit은 큰 model이 같은 loss에 더 적은 token·step으로 도달한다는 sample efficiency를 강조했다. 그래서 compute-optimal run은 매우 큰 model을 비교적 적은 data로 학습하고 수렴 전에 멈추는 형태가 됐다. 이 처방은 당시 data·optimizer·critical batch 추정에 묶인 경험 결과다.

### Chinchilla 2022의 재추정

Hoffmann 등은 여러 model size를 서로 다른 token 수까지 학습한 curve, isoFLOP profile, parametric loss fit의 세 접근을 사용했다. 세 결과는 $N_{opt}$와 $D_{opt}$를 compute와 거의 같은 제곱근 비율로 늘리는 데 모였다.

$$
N_{opt}\propto C^{a},
\qquad D_{opt}\propto C^{b},
\qquad a\approx b\approx0.5.
$$

이는 model을 덜 키우고 token을 더 많이 처리해야 한다는 수정이었다. ‘Kaplan law가 거짓’이라는 단순 판정이 아니라, 다른 run 설계와 더 넓은 token 조건에서 compute frontier를 다시 맞춘 결과다.

세 방법의 지수는 다음처럼 조금씩 달랐다.

| 접근 | $N_{opt}$ 지수 | $D_{opt}$ 지수 |
| --- | ---: | ---: |
| Training-curve envelope | 0.50 | 0.50 |
| IsoFLOP profile | 0.49 | 0.51 |
| Parametric loss fit | 0.46 | 0.54 |

700억 parameter Chinchilla를 1조 4천억 token으로 훈련한 비율에서 약 20 tokens/parameter라는 경험 지침이 나왔다. 이는 당시 dense Transformer·tokenizer·objective·MassiveText mixture와 schedule에 조건화된 근사다. $D$는 누적 token 노출량이지 data quality·distribution diversity·고유 문서 수를 나타내지 않는다.

### loss와 downstream metric

token cross-entropy $L$와 [[Perplexity]]는 $PPL=e^L$로 연결된다. 같은 tokenization·자료에서 loss가 낮아지는 것은 평균 next-token probability가 개선됐음을 뜻한다. 그러나 exact match, BLEU, MMLU accuracy, 사실성, calibration과 안전성은 loss의 단순 단위 변환이 아니다.

큰 모델의 여러 task 성능이 scale과 함께 변할 수 있어도 변화율·threshold·prompt 민감성은 task마다 다르다. aggregate loss power law만으로 개별 능력의 출현이나 실패를 미리 확정하지 않는다.

그 차이를 실제 task 곡선과 후대 창발 논쟁으로 비교하려면 [[손실 곡선과 능력 곡선 사이]]를 본다.

## 검증과 한계

### scaling law를 보편 법칙으로 오해하지 않기

경험 fit의 계수와 지수는 architecture, data mixture·quality, tokenizer, optimizer, context length, regularization, target loss와 compute 계산에 영향을 받는다. Kaplan 논문은 일부 Transformer shape 변화가 약한 효과를 보였지만, 모든 model family가 같은 지수를 가진다고 입증하지 않았다.

관측한 최댓값보다 훨씬 큰 compute로 외삽하면 작은 slope 오차도 매우 큰 model·token 차이를 만든다. Chinchilla도 large-scale 직접 비교와 high-compute frontier의 곡률이 제한적이라는 한계를 남겼다. fit의 신뢰 구간, leave-one-scale-out 예측과 실제 frontier run을 함께 보는 편이 안전하다.

### 세 비용을 나누기

- **training compute:** 한 번의 pretraining에 들어간 FLOP와 wall-clock
- **inference compute:** 배포 뒤 token을 생성하거나 score할 때 반복되는 비용
- **data cost:** 수집·정제·중복 제거·품질 관리와 법적·윤리적 비용

loss 기준 training-optimal model이 전체 서비스 비용에서도 최적이라고 보장되지 않는다. 요청량이 많으면 더 작은 model의 inference 이점이 커지고, 제한된 고품질 data에서는 token 수만 늘려도 같은 효과가 나지 않을 수 있다.

### 능력·안전의 별도 평가

scaling curve는 평균 예측 손실을 압축한다. minority slice, 긴 문맥, adversarial input, memorization, bias와 harmful behavior를 각각 드러내지 못한다. scale에 따른 model quality를 주장하려면 이러한 축을 별도 protocol로 측정해야 한다.
