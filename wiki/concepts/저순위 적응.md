# 저순위 적응

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[언어 모델 전이 학습]], 행렬의 rank와 미세조정의 기본 개념<br>
> **읽고 나면:** LoRA 계열을 “작은 adapter” 하나로 뭉뚱그리지 않고 target module·rank allocation·weight parameterization·basis sharing·scaling·quantization initialization으로 나눠 비교할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 한 문장 정의

**저순위 적응(Low-Rank Adaptation)**은 큰 사전 학습 weight를 동결하고, 그 weight의 task-specific 변화를 작은 rank의 행렬 factor로 표현해 일부 parameter만 학습하는 [[언어 모델 전이 학습|부분 매개변수 적응]] 방법군이다.

LoRA의 기본식은 다음과 같다.

$$
W'=W_0+\Delta W,
\qquad
\Delta W=\frac{\alpha}{r}BA
$$

$W_0\in\mathbb R^{d_{\text{out}}\times d_{\text{in}}}$는 동결되고, $B\in\mathbb R^{d_{\text{out}}\times r}$, $A\in\mathbb R^{r\times d_{\text{in}}}$만 학습한다. $r$가 작으면 한 weight matrix에 추가되는 parameter는 $r(d_{\text{in}}+d_{\text{out}})$개다. 전체 matrix의 $d_{\text{in}}d_{\text{out}}$개를 다시 학습하는 것보다 훨씬 작을 수 있다.

### 작은 parameter 수 뒤의 여섯 선택

저순위 적응은 하나의 고정 recipe가 아니다.

1. **Target module:** 어느 attention·feed-forward matrix에 update를 붙이는가?
2. **Rank:** 각 update의 중간 차원을 얼마로 두는가?
3. **Allocation:** 같은 총 rank를 layer와 matrix 사이에 어떻게 나누는가?
4. **Parameterization·sharing:** Factor를 layer별로 학습하는가, weight 좌표를 바꾸는가, basis를 공유하는가?
5. **Scaling:** Rank가 바뀌어도 update와 gradient의 크기를 어떻게 유지하는가?
6. **Base representation·initialization:** Base를 BF16·4-bit 등 어떤 형태로 저장하고 adapter를 어디서 시작하는가?

[[101_LoRA 이후 PEFT 변형의 설계 축과 연표]]의 다섯 변형은 이 선택 가운데 서로 다른 축을 바꾼다.

## 2단계 — 작동 원리

### Forward·backward·merge를 분리한다

학습 중 forward는 frozen path와 adapter path를 더한다.

$$
y=W_0x+\frac{\alpha}{r}BAx
$$

Backward는 $A,B$에만 gradient를 저장하므로 trainable weight와 optimizer state가 줄어든다. 그러나 $W_0$를 읽는 memory, activation과 matrix multiplication 자체가 없어지는 것은 아니다. 학습 뒤 shape이 맞으면 $\Delta W$를 $W_0$에 더해 하나의 weight로 병합할 수 있다. 따라서 training memory 절감과 inference latency는 다른 장부다.

### AdaLoRA는 rank의 위치를 바꾼다

AdaLoRA는 $\Delta W=P\Lambda Q$라는 SVD형 factorization을 학습하고, singular value와 대응 vector triplet의 중요도를 추적한다. 높은 초기 총 budget을 cubic schedule로 줄이며 덜 중요한 triplet을 mask한다. 핵심은 layer별 rank를 수동으로 다르게 줄 수 없었던 문제가 아니라, 같은 총 budget 안에서 update component를 자동으로 재배분하는 데 있다.

### DoRA는 weight의 좌표를 바꾼다

DoRA는 pretrained weight를 열별 magnitude와 unit direction으로 나눈다.

$$
W'=m\frac{W_0+BA}{\lVert W_0+BA\rVert_c}
$$

$m$은 직접 학습하고 direction에 LoRA update를 적용한다. Training graph에는 normalization 비용이 추가되지만 최종 weight로 병합할 수 있어 별도 inference adapter 연산을 남기지 않을 수 있다.

### VeRA는 basis를 공유한다

VeRA는 frozen random matrix $A,B$를 같은 shape의 layer 사이에 공유하고 layer별 두 scaling vector만 학습한다.

$$
W'=W_0+\Lambda_bB\Lambda_dA
$$

Layer마다 독립 low-rank factor를 저장하지 않으므로 adapter parameter가 매우 작아진다. 반면 공유 basis가 표현할 수 있는 update 공간이라는 제약이 생기고, 전체 base·activation memory와 연산량은 parameter 수만큼 줄지 않는다.

### rsLoRA와 LoftQ는 scale과 시작점을 바꾼다

rsLoRA는 높은 rank에서 표준 $\alpha/r$ scaling의 gradient가 약해지는 문제를 $\alpha/\sqrt r$로 바꾼다. LoftQ는 quantized matrix $Q$와 low-rank residual이 원 weight를 잘 근사하도록 fine-tuning 전 초기화를 번갈아 최적화한다.

$$
\min_{Q,A,B}\lVert W-Q-AB^\top\rVert_F
$$

[[QLoRA]]는 frozen base의 저장 dtype·계산 dtype·adapter 학습을 결합한 memory recipe이고, LoftQ는 quantization error를 반영한 adapter initialization이다.

## 3단계 — 기술과 근거

### 무엇을 비교해야 하는가

| 질문 | 비교 변수 | 놓치기 쉬운 조건 |
| --- | --- | --- |
| 품질이 좋아졌는가? | 같은 base·data·metric의 task score | 다른 model size·evaluator·prompt |
| Parameter가 줄었는가? | Trainable parameter와 adapter file | Frozen base·activation·buffer |
| Memory가 줄었는가? | Peak VRAM과 CPU offload | Batch·sequence·precision·checkpointing |
| 더 빠른가? | Training wall-clock·throughput | 추가 importance·normalization·초기화 |
| 추론이 가벼운가? | Merge 뒤 latency·memory | Dynamic adapter 교체와 kernel |
| 재현 가능한가? | Base ID·target module·rank·scale·seed | Adapter만 공개하고 base·tokenizer 누락 |

Trainable parameter가 같은 비교도 target module이 다르면 공정하지 않을 수 있다. [[QLoRA]] 연구가 rank보다 all-linear layer coverage의 영향을 크게 관찰한 사례처럼, update를 어디에 붙였는지가 rank 숫자보다 중요할 수 있다.

### 서로 다른 benchmark 결과를 합치지 않는다

AdaLoRA는 DeBERTaV3·RoBERTa의 GLUE, SQuAD와 생성 과제에서 budget allocation을 평가했다. DoRA는 LLaMA commonsense reasoning, visual instruction과 image/video-text task를 다뤘다. VeRA는 RoBERTa GLUE·E2E, image classification과 7B·13B instruction tuning을 평가했다. rsLoRA는 높은 rank의 gradient·학습 동역학을 중심으로, LoftQ는 낮은 bit quantization 설정의 language modeling·instruction task를 중심으로 검증했다.

이 결과들은 한 leaderboard의 동일 조건이 아니다. “AdaLoRA는 중요 layer에, DoRA는 큰 domain shift에, VeRA는 극단적 효율에 항상 최선”이라는 선택표를 만들려면 같은 base·data·budget의 교차 비교가 더 필요하다.

### Adapter도 완전한 실행 artifact가 아니다

저순위 update에는 사전 학습 지식 전체가 들어 있지 않다. 실행에는 정확한 base checkpoint와 tokenizer가 필요하고, target module 이름·shape, rank·alpha, dropout, precision, code version과 merge 여부도 맞아야 한다. 작은 adapter의 license가 base weight·training data의 access 조건을 지우지도 않는다.

## 검증과 한계

### Rank는 의미 단위가 아니다

Rank component나 높은 importance score를 사람이 이해하는 기술·사실·문법 module로 곧바로 해석하지 않는다. AdaLoRA importance는 현재 loss·data·optimization에 대한 parameter 민감도다. Layer별 budget pattern은 실험 단서이지 의미적 기능의 인과 설명이 아니다.

### 낮은 rank 가설의 범위

LoRA 원 논문은 여러 task update에 낮은 intrinsic rank가 있을 수 있다는 실험적 단서를 제시했다. 그렇다고 모든 지식 재구성·domain shift가 낮은 rank로 충분하거나, 반대로 어려운 task는 반드시 높은 intrinsic rank를 요구한다고 확정할 수는 없다. Full fine-tuning과의 비교에는 같은 data·optimization·parameter budget뿐 아니라 forgetting과 calibration도 필요하다.

### PEFT는 objective나 안전을 결정하지 않는다

LoRA 계열은 gradient가 어디로 흐르는지와 update를 어떻게 표현하는지를 정한다. 어떤 행동을 학습할지는 instruction·preference·domain data와 loss가 결정한다. 작은 adapter를 학습했다는 사실만으로 factuality, robustness, privacy나 safety가 보장되지 않는다.

### 효율과 영향 사이

Adapter storage, optimizer memory와 일부 training cost를 낮출 수 있다는 결과는 중요하다. 그러나 기업 채택, cloud bill, 접근성, 에너지와 탄소 효과는 실제 workload·hardware·전력과 조직 자료로 측정해야 한다. Parameter 수를 환경 효과의 대리값으로 바로 사용하지 않는다.
