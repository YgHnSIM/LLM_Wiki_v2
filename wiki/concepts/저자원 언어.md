# 저자원 언어

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[concept.말뭉치-기반-학습|말뭉치 기반 학습]], [[concept.언어-모델-전이-학습|언어 모델 전이 학습]]<br>
> **읽고 나면:** 저자원 언어를 화자 수나 말뭉치 크기 하나로 규정하지 않고, 언어·과제·시점별 data·도구·평가·계산·통제권의 상태로 진단하며 데이터 희소성과 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 핵심 정의

[[저자원 언어]](low-resource language)는 **어떤 언어가 특정 시점의 특정 언어 기술 과제를 수행하는 데 필요한 자료·도구·전문 인력·계산·평가·운영 자원을 충분히 제공받지 못한 관계적 상태**를 가리킨다. 언어 자체의 문법이 단순하거나 불완전하다는 뜻이 아니며, 영구히 고정되는 자연적 속성도 아니다.

따라서 “언어 $L$은 저자원이다”보다 “2025년의 언어 $L$은 임상 질의응답을 평가할 원어민 작성 자료와 안전 검증 체계가 부족하다”처럼 **시점·과제·modality·자원 종류**를 함께 적는 편이 정확하다. 같은 언어도 일반 웹 text는 많지만 대화 음성, 수어 video, OCR, 의료 용어, 특정 방언 또는 원어민 평가 자료는 부족할 수 있다.

### 서로 다른 네 개념

| 개념 | 무엇을 묻는가 | 저자원 언어와의 관계 |
| --- | --- | --- |
| 화자 수 | 그 언어를 쓰는 사람이 얼마나 많은가 | 화자가 많아도 digital corpus·도구·평가가 부족할 수 있고, 화자가 적어도 잘 정비된 자원을 가질 수 있다. |
| 소수·위기 언어 | 정치·사회적 지위와 세대 간 전승이 어떤가 | 겹칠 수 있지만 NLP resource level과 동의어가 아니다. |
| [[데이터 희소성]] | 가능한 사건 조합에 비해 실제 관측이 얼마나 부족한가 | 고정 어휘 안 확률 추정의 수학적 문제이며, 권리·tool·compute·benchmark까지 포함하는 사회기술적 상태와 다르다. |
| 언어 자원 부족 | 특정 과제를 만들고 검증·배포할 조건이 있는가 | 이 문서가 다루는 핵심이며 여러 자원 장부의 결합으로 판단한다. |

Joshi 등은 언어를 자원 수준에 따라 분류하면서 세계의 언어·화자 분포와 NLP dataset·도구·출판의 분포가 같지 않음을 보였다. Blasi 등도 기계번역, 언어 이해, 질의응답, 음성 합성, parsing과 morphology를 함께 비교해 기술 효용과 연구 관심의 불균등을 확인했다. 이 결과들은 하나의 corpus 크기만으로 언어 기술의 지원 정도를 대신할 수 없음을 보여 준다.

### 핵심 문장

- 저자원은 언어 공동체의 결함이 아니라 언어 기술 생태계에서 자원이 배분된 결과를 기술하는 말이다.
- 자원은 단일언어 text뿐 아니라 병렬·주석·instruction 자료, tokenizer와 입력 도구, 전문 인력, compute, benchmark, 사람 평가, license와 유지 보수 권한을 포함한다.
- 더 많은 언어 이름을 model card에 적는 것과 각 언어에서 유용하고 안전하며 통제 가능한 품질을 제공하는 것은 다르다.
- 합성 data와 교차언어 전이는 관측과 학습 신호를 보충하지만, 실제 화자의 동의·대표성·원어민 평가·현장 책임을 자동으로 만들지 않는다.

## 2단계 — 작동 원리

### 일곱 개 자원 장부

저자원 상태를 진단할 때는 최소한 다음 장부를 분리한다.

| 장부 | 확인할 항목 | 대표적인 오판 |
| --- | --- | --- |
| 언어·공동체 정의 | 언어와 방언의 경계, 문자, code-switch, 사용 영역, 명명 권한 | ISO code 하나를 균질한 공동체로 간주함 |
| 자연 자료와 권리 | text·speech·video의 양, 장르·시대·지역, provenance, 동의, license | web token 수를 자연성·대표성·사용 권한과 동일시함 |
| 표현·도구 | keyboard, font, OCR, ASR, normalization, tokenizer, 사전·형태 분석기 | 문자열을 encode할 수 있으면 같은 비용과 품질을 얻는다고 봄 |
| 학습 신호 | 단일언어, 병렬, 주석, instruction, preference, synthetic data와 사람 검수 | 서로 다른 supervision을 모두 “data 양”으로 합침 |
| 적응·계산 | base model, sampling, parameter sharing, fine-tuning, GPU·API와 전문 인력 | 적은 target sample을 전체 개발 비용 절감으로 바꿈 |
| 평가 | native/번역 문항, 과제·방언·domain, metric, 표본 수, 원어민·전문가 평가 | 한 benchmark 평균을 언어 전체 능력으로 일반화함 |
| 배포·governance | weight·code·data 접근, 실행 비용, 안전, 수정·거부권, 유지 보수 | benchmark 개선을 실제 접근성과 형평성으로 동일시함 |

이 장부들은 서로 연결되지만 교환 가능하지 않다. 예를 들어 합성 병렬 문장 200만 쌍은 MT supervision을 늘릴 수 있어도 음성 자료, 현지 의료 문항, tokenizer 효율, 원어민 평가자, 배포 책임 주체를 만들어 주지 않는다.

### 자료 종류를 먼저 구분한다

- **단일언어 자료**는 그 언어의 분포와 표현을 학습하는 데 쓰인다. 규모가 커도 장르·방언·시대가 좁을 수 있다.
- **병렬 자료**는 두 언어의 대응 문장으로 번역과 정렬 신호를 준다. Europarl처럼 특정 domain에 치우칠 수 있다.
- **주석 자료**는 정답 label, 구조, 선호 또는 전문가 판단을 더한다. 수집 비용과 범주 설계가 품질에 직접 영향을 준다.
- **instruction 자료**는 지시와 응답 형식의 적응을 돕지만 해당 언어의 모든 사실·문화·안전 판단을 포괄하지 않는다.
- **평가 자료**는 학습 자료와 독립적으로 무엇을 잘하는지 판별한다. 번역 benchmark와 원어민이 목표 사용을 위해 처음부터 쓴 native benchmark는 같은 증거가 아니다.

### 전이와 합성의 역할

[[XLM]] 같은 다국어 사전 학습은 공유 vocabulary·parameter와 monolingual 또는 parallel objective로 언어 간 표현을 전이한다. NLLB는 data mining, 역번역과 shared model로 200개 언어의 번역 방향을 넓혔다. 이 경로는 target 언어의 표지 data 요구를 줄이거나 번역 signal을 늘릴 수 있다.

합성 data는 큰 언어 또는 폐쇄형 교사 model의 능력을 이용해 질문·번역·code-switch 예시를 만든다. 그러나 교사 model이 잘 다루는 언어를 먼저 고르는 selection bias, hallucination, 부자연스러운 혼합, domain 복제와 license·API 의존성을 함께 가져온다. 사람 검수와 실제 사용 분포에서의 평가 없이 “authentic language data”로 간주해서는 안 된다.

## 3단계 — 기술과 근거

### 무엇을 수치로 기록할 것인가

| 층위 | 최소 기록 단위 | 단독으로 결론 내릴 수 없는 이유 |
| --- | --- | --- |
| corpus | 문서·시간·byte·token, 중복 제거 후 양, source·장르·시대·방언 | token 수는 권리·대표성·truthfulness를 말하지 않는다. |
| sampling | 원래 비율과 실제 학습 노출량, epoch·up/down-sampling | 저장량과 model이 실제 본 양이 다를 수 있다. |
| tokenizer | 문자 coverage, unknown/fallback, fertility 또는 같은 내용의 token 길이 | 표현 가능성과 효율·downstream 품질은 다르다. |
| 학습 | base model, parameter 수, objective, language pair, update 범위, compute·API | target sample 수만으로 총비용과 재현성을 알 수 없다. |
| 평가 | task·domain·언어 변이, native/번역 여부, shot, answer 언어, metric·표본 수 | 한 선택형 accuracy를 자유 생성·번역·현장 안전으로 일반화할 수 없다. |
| 사람 판단 | 평가자 언어 변이·전문성, rubric, 표본, 합의·불일치 | 자동 metric만으로 자연성·문화 적합성·위험을 확정할 수 없다. |
| 접근·통제 | license, weight·code·data 공개성, 실행 가격, 수정·거부·유지 권한 | model이 존재한다는 것과 공동체가 이용·통제할 수 있다는 것은 다르다. |

Rust 등은 9개 언어와 5개 과제를 통제해 비교하면서, multilingual model의 사전 학습 data 양뿐 아니라 공유 vocabulary 안의 언어별 representation과 tokenizer 적합성이 성능 격차에 중요함을 보였다. 언어 전용 tokenizer로 교체한 실험은 거의 모든 언어·과제에서 개선됐다. 이는 tokenizer가 중요한 자원임을 뒷받침하지만, 해당 mBERT 계열 실험을 모든 LLM의 보편적 배수로 확대하지는 못한다.

### 같은 ‘저자원’ 안에서도 병목은 다르다

[[110_저자원 언어 LLM의 성능 격차와 전이·평가 경계]]가 검증한 2025년 연구들은 서로 다른 장부를 보강했다.

| 사례 | 먼저 부족했던 것 | 추가한 자원 | 확인된 범위 |
| --- | --- | --- | --- |
| Alhanai 등 | 8개 아프리카 언어의 비교 가능한 평가와 적응 자료 | 약 100만 단어의 사람 번역 WinoGrande·MMLU, 검수·문화 적합 문항, 400개 초과 Llama 3 70B fine-tune | 11개 언어의 선택형 benchmark; 단일언어 평균 +5.6 points, 교차언어 평균 +2.9 points |
| Nagar 등 | Hindi–English code-switch 상식추론 적응 자료 | 1,200개 합성 CommonSenseQA 질문과 CMI별 QLoRA | 한 언어쌍·한 과제; 최선 조건 English 90.4%, Hindi 85.6% |
| NLLB | 광범위한 저자원 MT data·평가·방향 | mined·back-translated data, FLORES-200, shared MT model | 200개 언어와 40,000개 초과 번역 방향; 범용 LLM·현장 형평성 평가는 아님 |

Alhanai 등의 사람 번역·검증 비용은 약 40,218.78달러였고 언어별 번역 수정률은 4.9–65.3%였다. 이는 “적은 data만 있으면 algorithm이 해결한다”는 단순한 그림과 다르다. 새 benchmark를 만드는 번역자·검수자와 언어별 품질 차이 자체가 핵심 자원이다.

Nagar 등의 가장 작은 English–Hindi 격차는 CMI 2 조건의 4.8 percentage points였다. 그러나 질문만 Hindi–English로 섞고 answer option은 영어로 두었으며 수동 검토는 약 24개 표본이었다. 이 수치는 여러 언어의 범용 `near-English` 품질이 아니라 한 합성 code-switch 선택형 과제의 조건부 결과다.

### 언어 수와 품질은 별도 축이다

model이 다루는 언어 수는 coverage의 한 지표다. 하지만 다음 항목이 없으면 품질과 형평성을 대신하지 못한다.

1. 각 언어가 실제 학습 mixture에서 얼마나 노출됐는가.
2. tokenizer가 그 문자와 형태를 어떤 길이와 손실로 표현하는가.
3. 목표 사용과 맞는 native 평가가 있는가.
4. 언어별 평균뿐 아니라 방언·domain·오류 유형이 보고되는가.
5. 공동체가 data·model·배포를 검토하고 수정하거나 거부할 수 있는가.

XLM은 2019년에 다국어 전이와 language sampling 불균형을 명시적으로 다뤘고, NLLB는 2022년에 MT data·평가를 200개 언어로 넓혔다. [[BLOOM]]도 46개 자연어를 포함한 ROOTS corpus와 공개 checkpoint를 제공했지만 언어별 data 양과 성능은 균등하지 않았다. 언어 목록을 넓히는 일은 중요한 기반이지만 언어별 자원 장부를 닫는 종착점은 아니다.

## 검증과 한계

### 이 용어가 가릴 수 있는 것

“저자원”이라는 label은 비교와 지원 우선순위를 정하는 데 유용하지만, 원인을 언어 내부로 돌리면 정치적 선택을 숨길 수 있다. 식민 언어 중심의 교육·출판·행정, platform 수집 정책, 상업적 투자, 연구 funding, copyright·privacy 규칙, 문자와 방언의 표준화 권력이 어떤 언어에 자원이 쌓이는지를 바꾼다. “resource-poor language”보다 “under-resourced language”라는 표현을 쓰는 이유도 부족을 자연적 속성이 아니라 누적된 배분 상태로 보려는 데 있다.

언어와 방언의 경계도 기술 team이 일방적으로 고정할 수 없다. 하나의 language code 아래에서 표준어만 모으면 지역 변이와 code-switch 공동체가 지워질 수 있고, 반대로 자원 수를 부풀리기 위해 같은 자료를 여러 언어에 중복 계상할 수도 있다. 자원 목록에는 자료를 만든 사람, 대표되지 않은 집단과 명명·검수 권한을 함께 기록해야 한다.

### 개선과 해결을 구분한다

- **확인 가능한 개선:** 특정 언어·과제의 accuracy·ChrF, tokenizer 효율, human-rated translation quality, 공개 data·weight·도구의 추가.
- **별도로 확인할 결과:** 실제 이용 가능성, 비용, 장애·문해력·device 조건, 교육·의료 outcome, 오류 피해 분포, 언어 사용 증가와 세대 간 전승.
- **현재 근거만으로 확정할 수 없는 주장:** 합성 data가 문법·문화의 진정성을 보장했다, 한 benchmark 격차 축소가 사회적 형평성을 달성했다, 언어 coverage 수가 곧 사용자 접근 인구다.

Joshi·Blasi의 세계적 분포 분석은 불균등의 존재를 보여 주지만, 모든 언어의 현재 자원 수준을 영구 분류하는 명부는 아니다. 기술·정책·공동체 사업에 따라 자원은 변하며, text 중심 연구는 speech·sign language·multimodal 자원 상태를 충분히 대변하지 못한다. 따라서 이 개념 문서는 진단 틀이지 고정된 언어 서열표가 아니다.
