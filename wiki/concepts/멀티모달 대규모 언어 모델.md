# 멀티모달 대규모 언어 모델

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[Transformer]], [[CLIP]], [[Flamingo]]<br>
> **읽고 나면:** 멀티모달 LLM을 하나의 architecture 이름이 아니라 입력 encoder·bridge·언어 model·훈련 경계·출력의 조합으로 분해하고, 서로 다른 model의 성능과 공개 수준을 비교할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 한 문장 정의

**멀티모달 대규모 언어 모델(multimodal LLM, MLLM)**은 image·video·audio·sensor state 같은 비언어 입력을 언어 model의 조건으로 연결해, 주로 자연어 또는 구조화 text를 생성하는 model 또는 system 계열이다.

이 명칭은 [[Transformer]]처럼 단일한 계산 graph를 지정하지 않는다. 같은 범주 안에서도 시각 정보를 별도 cross-attention memory로 읽을 수 있고, 고정 수 query로 압축할 수 있으며, projection된 visual token이나 연속 sensor embedding을 text token 사이에 넣을 수도 있다. 비교할 때는 다음 다섯 경계를 먼저 적는다.

1. 어떤 모달리티를 입력받는가?
2. 각 입력을 어떤 encoder가 표현하는가?
3. Bridge가 정보를 압축·정렬·융합하는 방식은 무엇인가?
4. 사전 학습 backbone과 bridge 가운데 무엇을 동결하거나 갱신하는가?
5. Text·image·audio·action 가운데 무엇을 직접 출력하는가?

### 관련 범주와 겹치지만 같지 않다

[[CLIP]]은 image와 text를 함께 학습한 vision-language model이지만, 기본 interface는 두 전역 embedding의 유사도 비교다. [[Flamingo]]·BLIP-2·LLaVA·GPT-4V처럼 open-ended text를 생성하는 model과 출력 방식이 다르다. Text-to-image 확산 model은 text 조건에서 pixel 또는 image latent를 생성하므로, image를 입력받아 text를 생성하는 MLLM과 반대 방향의 decoder를 갖는다.

“Large multimodal model”은 언어 외 출력을 포함하는 더 넓은 뜻으로 쓰이기도 한다. 따라서 약어보다 실제 입출력 signature를 함께 쓰는 편이 정확하다.

## 2단계 — 작동 원리

### Encoder–bridge–decoder로 분해한다

Image $I$, text prompt $x$, 출력 text $y$가 있을 때 대표적인 흐름은 다음과 같다.

$$
I\xrightarrow{E_v}Z_v\xrightarrow{B}V,
\qquad
p(y_t\mid I,x,y_{<t})=D(V,x,y_{<t}).
$$

$E_v$는 patch·region·frame을 feature로 바꾸고, $B$는 이 feature를 언어 decoder $D$가 소비할 형태로 옮긴다. 핵심 차이는 $B$의 위치와 정보량이다.

| Bridge 유형 | 대표 사례 | 계산 의미 |
| --- | --- | --- |
| 전역 shared embedding | CLIP | image·text vector의 유사도 비교; 자체로 open-ended decoder가 아님 |
| 연속 입력 prefix | Frozen | 학습되는 vision encoder가 만든 embedding을 동결 autoregressive LM 앞에 배치 |
| 고정 query 병목 | BLIP-2 Q-Former | 학습 query가 시각 feature에서 text 관련 정보를 추출·압축 |
| 삽입형 cross-attention | Flamingo | 언어 hidden state가 별도 시각 memory를 key/value로 읽음 |
| Encoder-decoder visual token | PaLI | ViT patch feature를 pooling 없이 mT5 encoder-decoder의 cross-attention에 전달 |
| 선형 projection token | LLaVA | CLIP grid feature를 LLM word-embedding 차원의 token sequence로 변환 |
| 연속 observation token | PaLM-E | image·robot state encoder 출력을 text token과 같은 차원의 sequence로 삽입 |
| 비공개 | [[GPT-4|GPT-4V]] | 외부 동작만으로 특정 encoder나 bridge를 확정할 수 없음 |

“같은 embedding 차원”은 “word와 image가 같은 의미 단위로 표현된다”는 뜻이 아니다. 차원이 맞아야 matrix 연산이 가능하다는 interface 조건과, 대조 목적이나 생성 목적을 통해 의미가 정렬되는 학습 조건을 분리해야 한다.

### 동결과 갱신은 model마다 다르다

Frozen은 언어 model을 동결하고 vision encoder를 학습해 image-conditioned continuous prefix를 만들었다. Flamingo는 시각 encoder와 causal LM을 동결하고 Resampler·gated cross-attention block을 학습했다. PaLI의 주된 224×224 사전 학습은 vision component를 동결하고 language component를 갱신했지만, PaLI-17B의 짧은 588×588 고해상도 단계는 전체 parameter를 갱신했다. BLIP-2의 두 단계 사전 학습은 image encoder와 LLM을 모두 동결한 채 Q-Former와 projection을 학습하지만, downstream captioning에서는 image encoder를 갱신할 수 있다. LLaVA는 첫 단계에서 projection만 갱신하고, 둘째 단계에서는 vision encoder를 계속 동결하면서 projection과 LLM을 visual instruction data로 갱신했다. PaLM-E의 기본 구성은 encoder·projection·PaLM을 end-to-end로 갱신하며, frozen-PaLM은 별도 비교 조건이다.

동결 backbone을 쓰면 이미 학습한 능력을 재사용하고 gradient memory를 줄일 수 있지만 전체 system의 pretraining 비용이나 inference 비용이 작다는 뜻은 아니다. 또 작은 bridge는 image의 모든 세부가 보존된다고 보장하지 않는다. 반대로 LLM까지 갱신하면 시각 instruction에 더 깊게 적응할 수 있지만 text-only 능력 저하와 data·compute 비용을 함께 평가해야 한다.

### Instruction following과 visual grounding은 별도 문제다

Visual instruction tuning은 `(image, instruction, response)` 자료로 사용자의 질문 형식에 맞는 답을 생성하도록 한다. 그러나 자연스럽고 자세한 답은 image 근거가 정확하다는 보증이 아니다. Model은 image feature보다 언어 prior에 기대 plausible한 물체·관계·문자를 만들어 낼 수 있다.

따라서 평가는 최소한 다음 층으로 나눈다.

- **지각:** OCR, 물체·속성, 개수, 위치, chart 값
- **결합:** Text 지시가 가리키는 image 영역과 관계를 올바르게 선택하는가?
- **추론:** 관찰된 근거로 답을 도출하며 보이지 않는 사실을 만들어 내지 않는가?
- **지시 준수:** 요구된 형식·길이·출력 schema를 따르는가?
- **불확실성·안전:** 판독할 수 없거나 고위험인 경우 한계를 드러내는가?

## 3단계 — 기술과 근거

### Query 수와 visual token 수는 정보 병목이다

고해상도 image는 많은 patch token을 만든다. 이를 그대로 긴 언어 context에 넣으면 self-attention과 memory 비용이 커진다. Flamingo의 Resampler와 BLIP-2의 Q-Former는 고정 수 latent/query로 시각 정보를 줄여 이 비용을 제어한다. LLaVA의 초기 구조는 CLIP grid feature를 선형 변환해 visual token으로 사용한다.

Token 수, image 해상도, crop·tile 전략은 OCR·작은 물체·chart·counting 성능에 직접 영향을 줄 수 있다. “Model parameter가 같다”는 이유만으로 서로 다른 image preprocessing 조건의 benchmark를 동일 조건으로 보아서는 안 된다.

### Cross-attention과 token insertion은 정보 흐름이 다르다

Flamingo에서는 text hidden state가 새 cross-attention layer에서 시각 memory를 읽는다. 이 시각 token은 일반 text token과 같은 causal self-attention sequence에 단순히 끼워 넣은 것이 아니다. LLaVA에서는 projection된 visual feature가 language embedding token으로 조건 sequence에 들어간다. PaLM-E는 여러 continuous observation encoding을 text와 interleave한다.

표면적으로 모두 “시각 token”이라고 부를 수 있지만 attention mask, positional encoding, layer별 접근 위치와 gradient path가 다르다. 이 차이는 여러 image의 순서, 긴 video, spatial detail과 사전 학습 LLM 보존 방식에 영향을 준다.

### Model 능력과 배포 system을 분리한다

실제 제품은 resize·OCR·retrieval·content filtering·prompt template·tool call·후처리를 model 주위에 둘 수 있다. 사용자에게 하나의 chat interface로 보인다는 사실은 내부가 하나의 end-to-end model이라는 뜻이 아니다. 반대로 여러 module을 썼다는 사실만으로 깊은 cross-modal interaction이 불가능한 것도 아니다.

GPT-4 technical report는 image와 text 입력에 대한 출력 사례를 공개했지만 model 크기와 구체적 architecture를 공개하지 않았다. GPT-4V system card는 text·image data와 RLHF라는 높은 수준의 훈련 설명, early-access pilot과 안전 평가를 제공했다. 이런 비공개 model은 기능·release·위험을 검증할 수 있어도 bridge 종류를 공개 model처럼 비교할 수 없다.

## 검증과 한계

### 자주 생기는 범주 오류

- **Vision-language model은 모두 MLLM이다:** CLIP 같은 이중 encoder는 large language decoder가 없는 구성일 수 있다.
- **Image를 token으로 만들면 text와 같은 의미 공간이다:** 차원 정합, 학습된 정렬과 동일한 의미 구조는 서로 다른 주장이다.
- **Multimodal input이면 image도 출력한다:** GPT-4V의 공개 interface는 image 입력에서 text를 출력했다. Image generation은 별도 model·tool일 수 있다.
- **Unified interface면 architecture도 하나다:** 같은 chat 화면 뒤에서 여러 encoder·bridge·policy·tool이 협력할 수 있다.
- **자연스러운 설명이면 grounded reasoning이다:** 언어 유창성과 visual evidence 충실도는 따로 측정해야 한다.
- **Human-level benchmark면 일반적인 시각 이해다:** Dataset·metric·prompt·해상도·judge 범위를 벗어나 일반화할 수 없다.

### 대표적인 실패와 위험

작은 글자·복잡한 chart·정밀한 공간 관계·개수에서 잘못 읽을 수 있고, image와 충돌하는 언어 prior로 hallucination할 수 있다. GPT-4V system card의 평가에서도 가까운 text component 병합, 문자·수학 기호 누락, 공간 위치·색 mapping 오류와 비로마자 OCR 약화가 관찰됐다. 얼굴·신분·건강·위치 같은 민감 정보를 근거 없이 추론하거나 stereotype을 생성할 위험도 있다. Image 안의 명령문이 system의 instruction 계층을 교란하는 visual prompt injection도 model 밖의 입력 검증을 요구한다.

GPT-4V system card는 beta tester가 hallucination과 오류를 발견했고, 의료 image 해석이 일관되지 않았으며, 당시 version을 의료 기능이나 전문 판단의 대체로 볼 수 없다고 기록했다. 특정 제품의 완화책은 멀티모달 model 일반의 안전성을 보장하지 않는다.

### 비교에서 남는 공개성 한계

공개 연구는 architecture·training data·ablation을 비교할 수 있지만 실제 제품 규모와 사용량이 다를 수 있다. 비공개 제품은 실제 배포 사례와 red-team 결과를 제공하더라도 내부 구성·data·compute 비교가 제한된다. 동일한 표에서 빈칸을 추측으로 채우지 않고 “비공개” 자체를 재현성 정보로 남겨야 한다.
