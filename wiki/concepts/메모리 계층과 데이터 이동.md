# 메모리 계층과 데이터 이동

> [!note] 학습 안내
> **난이도:** 입문 → 중급<br>
> **선수 지식:** 없음 — 저장 용량, 한 번 가져오는 시간과 초당 옮기는 양부터 구분한다.<br>
> **읽고 나면:** cache·HBM·SRAM을 단순한 빠르기 순서가 아니라 용량·지연·대역폭·관리 방식의 계층으로 읽고, 같은 FLOPs인데 실행 시간이 다른 이유를 operational intensity와 실제 byte 이동으로 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 계산하려면 먼저 값을 가져와야 한다

연산 유닛은 weight와 activation이 도착해야 곱셈을 시작할 수 있다. 장치의 최고 FLOP/s가 커져도 필요한 값을 멀리 있는 메모리에서 반복해서 가져오면 연산기는 기다린다. 이때 병목은 “메모리가 느리다”는 한 문장이 아니라 적어도 세 축으로 나뉜다.

- **용량(capacity):** 값을 모두 저장할 수 있는가?
- **지연 시간(latency):** 한 요청의 값이 도착할 때까지 얼마나 기다리는가?
- **대역폭(bandwidth):** 일정 시간에 총 몇 byte를 옮길 수 있는가?

큰 창고는 많이 저장하지만 작업대에서 멀 수 있다. 작은 작업대는 빠르게 접근하지만 필요한 모든 재료를 올릴 수 없다. 컴퓨터는 이 교환을 register와 온칩 memory, cache, device memory, host memory, storage 같은 여러 층으로 다룬다. 정확한 이름과 연결 방식은 장치마다 다르며, “SRAM은 항상 이것, HBM은 항상 저것”이라는 하나의 보편 배치를 가정하지 않는다.

### FLOPs와 byte는 다른 장부다

두 프로그램이 같은 행렬곱과 같은 FLOPs를 수행해도 하나는 같은 tile을 가까운 메모리에서 여러 번 재사용하고, 다른 하나는 중간값을 큰 메모리에 썼다가 다시 읽을 수 있다. 두 번째 프로그램은 더 많은 byte를 이동하므로 memory bandwidth에 막힐 수 있다.

[[FlashAttention]]은 이 차이를 선명하게 보여 준다. 표준 dense attention과 같은 수학적 출력을 계산하면서도 전체 score·probability 행렬을 HBM에 저장하지 않고 SRAM tile 안에서 online softmax를 누적한다. 산술 복잡도는 여전히 sequence 길이에 대해 이차적이지만, 중간 저장과 HBM 읽기·쓰기를 줄여 실행 시간이 짧아질 수 있다.

## 2단계 — 작동 원리

### 지역성과 재사용이 가까운 층을 가치 있게 만든다

최근 사용한 값이나 가까운 주소를 다시 사용할 가능성을 **지역성(locality)**이라 한다. Cache는 이 패턴을 이용해 느린 하위 memory의 값을 작은 빠른 층에 보관한다. 가속기 kernel의 tiling도 계산에 필요한 조각을 온칩 memory에 올려 여러 출력에 재사용한다.

행렬곱 $Y=XW$에서 $X$의 한 tile과 $W$의 한 tile을 가져와 여러 부분합에 사용하면, 각 곱셈마다 원격 memory에 다시 요청하는 경로보다 byte당 더 많은 계산을 한다. 그러나 tile이 빠른 memory에 들어가지 않거나 접근이 불규칙하면 재사용 계획이 깨진다. Cache·tiling은 데이터 이동을 없애는 장치가 아니라 특정 접근 패턴에서 이동을 줄이는 방법이다.

### 메모리 장벽은 상대적인 격차다

Wulf와 McKee는 1995년에 processor 성능이 DRAM보다 빠르게 향상되면 memory access 한 번의 비용이 processor cycle로 계속 커진다고 지적했다. 핵심은 DRAM의 절대 시간이 전혀 개선되지 않는다는 말이 아니다. 연산기가 같은 시간에 더 많은 일을 할 수 있게 될수록 memory를 기다리며 잃는 작업 기회가 커진다는 뜻이다.

Cache가 평균 지연을 낮춰도 working set이 너무 크거나 miss가 많고 접근이 불규칙하면 문제가 다시 나타난다. 대역폭을 넓혀 여러 요청을 함께 처리해도 다음 주소가 이전 결과에 의존하면 긴 지연을 숨기기 어렵다. 그래서 memory wall은 하나의 고정 벽보다 workload와 계층 설계에 따라 이동하는 병목이다.

### Roofline은 계산과 이동의 상한을 한 그림에 놓는다

Operational intensity $I$를 주 메모리와 오간 byte당 연산 수로 두고, 장치 최고 연산률을 $P_{\mathrm{peak}}$, memory bandwidth를 $B_{\mathrm{mem}}$이라 하면 Roofline의 기본 상한은

$$
P_{\mathrm{attainable}}\le
\min\left(P_{\mathrm{peak}}, B_{\mathrm{mem}}I\right)
$$

로 적는다. $I$가 낮으면 기울어진 memory bandwidth 지붕에 막히고, 충분히 높으면 수평인 compute 지붕에 가까워진다. 이는 정확한 실행 시간을 예언하는 식이 아니라 현재 최적화에서 어느 자원이 더 강한 상한인지 찾는 모델이다.

여기서 byte를 어느 경계에서 세는지가 중요하다. 원 논문은 DRAM traffic을 중심으로 했지만, GPU attention에서는 HBM과 SRAM 사이 이동을 따로 셀 수 있다. Cache hit·network traffic·host transfer를 포함하는지에 따라 $I$와 병목 해석이 바뀐다.

### Attention에서 중간값이 커진다

한 head의 $Q,K,V\in\mathbb R^{N\times d}$에서

$$
S=QK^{\mathsf T}\in\mathbb R^{N\times N}
$$

을 만들면 score 원소는 $N^2$개다. 순진한 실행은 $S$와 softmax 결과 $P$를 HBM에 쓰고 다음 kernel에서 다시 읽을 수 있다. Sequence $N$이 두 배가 되면 이 중간 행렬 원소 수는 네 배가 된다.

FlashAttention은 query와 key·value를 tile로 나누고 SRAM에 올려 score tile, row max, 정규화 합과 부분 출력을 누적한다. 전체 $S$와 $P$를 HBM에 물질화하지 않으며 backward에서 일부 값을 재계산한다. 더 많은 FLOPs를 허용해 비싼 HBM traffic과 저장 공간을 줄이는 시간–공간 교환이다.

## 3단계 — 기술과 근거

### FlashAttention Figure 2를 측정 장부로 읽기

FlashAttention 원 논문의 Figure 2는 A100, GPT-2 medium, sequence 1,024, head dimension 64, 16 heads, batch 64의 forward와 backward를 비교했다. 논문 장부에서는 재계산으로 FLOPs가 약 13% 늘었지만 HBM 읽기·쓰기가 약 8분의 1로 줄고 실행 시간은 약 3분의 1이 됐다.

| 항목 | 기록 |
| --- | --- |
| 작업 | GPT-2 medium attention forward+backward |
| 규모 | sequence 1,024, head dimension 64, 16 heads, batch 64 |
| 결과 계약 | 표준 dense softmax attention과 같은 수학적 결과 |
| 시스템 경계 | A100의 attention 실행 비교 |
| 고정 조건 | 논문 Figure 2의 model·shape·GPU와 비교 구현 |
| 지표 | FLOPs, HBM read/write byte, 실행 시간 |

이 사례는 “FLOPs가 늘면 반드시 느려진다”가 틀릴 수 있음을 보여 준다. 그렇다고 FlashAttention이 모든 model과 hardware에서 정확히 3배 빠르다는 뜻도 아니다. Sequence, dtype, head dimension, GPU 세대와 baseline kernel이 바뀌면 배수가 달라진다.

### 용량·대역폭·추가 공간을 분리한다

| 주장 | 실제로 묻는 것 | 자동으로 따라오지 않는 것 |
| --- | --- | --- |
| 모델이 memory에 들어간다 | weight·activation·optimizer·cache의 peak byte가 용량 이하인가 | 빠른 실행 |
| bandwidth가 높다 | 초당 옮길 수 있는 byte가 많은가 | 낮은 단일 요청 latency |
| 추가 memory가 선형이다 | algorithm이 저장하는 중간값이 입력 길이와 어떻게 자라는가 | 산술량도 선형 |
| I/O가 줄었다 | 정한 memory 경계의 byte 이동이 줄었는가 | end-to-end model 시간이 같은 비율로 감소 |

“메모리 효율적”이라는 말에는 어느 행을 뜻하는지 적어야 한다.

### 데이터 이동 비용의 최소 계산

어떤 kernel이 $F$ FLOPs와 $M$ byte의 memory traffic을 만든다면 operational intensity는

$$
I=\frac{F}{M}\quad\text{FLOPs/byte}
$$

이다. 같은 $F$에서 $M$을 절반으로 줄이면 $I$는 두 배가 된다. 하지만 cache나 fusion으로 실제 DRAM traffic이 달라지면 source code의 tensor 크기만 더한 $M$과 hardware counter의 $M$이 다를 수 있다. 정밀도를 FP32에서 FP16으로 바꾸면 원소당 byte는 줄지만 결과 계약과 지원 연산도 바뀌므로 “같은 작업”인지 다시 확인해야 한다.

## 검증과 한계

- **직접 영향:** FlashAttention은 HBM–SRAM 이동을 명시적으로 분석하고 이를 줄이는 exact attention algorithm과 kernel을 제시했다.
- **가능 조건:** GPU의 높은 행렬 처리량과 memory 계층은 attention 실행의 조건이지만, memory wall 논문이 Transformer 설계에 직접 영향을 주었다는 근거는 제시하지 않는다.
- **병행 맥락:** 1995년 memory wall과 2009년 Roofline은 2022년 FlashAttention을 이해하는 앞선 문제 언어다. 연대적 선행만으로 직접 계보를 주장하지 않는다.
- **후대 유추:** Roofline을 HBM–SRAM 경계에 적용할 때는 원 논문의 DRAM 중심 operational intensity를 어느 경계로 바꿨는지 밝힌다.

Memory hierarchy는 장치마다 다르고 hardware counter도 완전한 원인을 자동으로 알려 주지 않는다. 전력·network·host·storage까지 병목이 확장되면 단일 device Roofline만으로 end-to-end service를 설명할 수 없다. 또한 같은 byte와 FLOPs라도 수치 형식과 연산 순서가 달라 결과 오차가 바뀔 수 있다.

## 학습 확인

1. 용량, 지연 시간, 대역폭이 서로 대체되지 않는 이유를 각각 한 사례로 설명하라.
2. FlashAttention이 추가 memory를 줄이면서도 dense attention의 $O(N^2d)$ 산술량을 없애지 않는 이유는 무엇인가?
3. 새로운 kernel의 FLOPs는 10% 늘고 HBM traffic은 절반, 실행 시간은 20% 줄었다. 이 결과를 Roofline과 측정 장부로 설명하고 보편화하려면 무엇을 더 확인해야 하는가?

다음에는 후속 owner인 **수치 형식·혼합 정밀도·양자화**에서 원소당 byte를 줄일 때 결과 계약이 어떻게 바뀌는지, **분산 학습과 집단 통신**에서 memory 경계가 장치 사이 network로 확장될 때 무엇을 세는지 이어서 배운다.

[[집적도 증가에서 가속기까지 무엇이 더 필요했나]]는 이 owner의 memory wall을 집적도·power·parallel shift·CUDA·TPU 사이의 역사적 연결고리로 배치한다.
