# 사고 연쇄 프롬프팅

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[concept.문맥-내-학습|문맥 내 학습]], [[concept.자기회귀-생성|자기회귀 생성]]<br>
> **읽고 나면:** few-shot·zero-shot 사고 연쇄가 답을 만드는 흐름을 설명하고, 그 출력의 그럴듯함·정답 정확도·인과적 충실성을 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 한 문장 정의

사고 연쇄 프롬프팅(chain-of-thought prompting, CoT prompting)은 언어 모델이 최종 답을 내기 전에 **중간 추론 단계를 자연어 token으로 생성하도록 prompt를 구성하는 방법**이다. 원래의 few-shot 방식은 `문제 → 중간 단계 → 답`의 예시를 보여 주고, 후속 zero-shot 방식은 단계별 풀이를 요구하는 짧은 문구로 같은 출력 형식을 유도한다.

CoT는 모델의 weights를 갱신하지 않는다. 새로 생성된 중간 token이 뒤의 token을 조건화하므로, 한 번에 답만 생성할 때와 다른 autoregressive 경로를 만들 뿐이다. 따라서 CoT는 [[문맥 내 학습]]과 prompting의 한 방법이지 별도 훈련 알고리즘이 아니다.

### 무엇과 구분해야 하는가

CoT 출력은 모델이 밖으로 생성한 text다. 이를 신경망 내부에서 실제로 일어난 모든 계산이나 인간의 사적 사고와 동일시하지 않는다. 중간 단계가 문법적이고 설득력 있어 보여도 계산이 틀릴 수 있고, 답이 맞아도 적어 놓은 경로가 답을 만든 실제 원인을 빠뜨릴 수 있다.

또한 CoT는 문제를 여러 독립 model 호출로 분할하는 workflow와 같지 않다. 기본 few-shot CoT는 한 completion 안에서 중간 단계와 답을 이어 생성한다. Zero-shot-CoT의 대표 구현은 추론문 생성과 답 추출에 두 번 prompting하지만, 각 단계의 weights는 계속 고정된다.

### 왜 중요한가

다단계 산술·상식·기호 과제에서는 즉답보다 중간 상태를 text로 남기는 방식이 최종 답 정확도를 높일 수 있다. 연구자는 어느 단계에서 오류가 드러났는지 관찰할 수도 있다. 그러나 이 관찰 가능성은 투명성의 단서일 뿐, 출력된 설명이 model 결정의 인과적 기록이라는 보증은 아니다.

## 2단계 — 작동 원리

### Few-shot CoT는 세 요소를 예시로 보여 준다

Wei 등의 원래 구성은 demonstration마다 다음 세 요소를 한 묶음으로 제시한다.

1. **입력 문제:** 수학 문장제나 상식·기호 추론 질의다.
2. **사고 연쇄:** 답에 이르는 중간 자연어 단계와 계산을 적는다.
3. **최종 답:** 일정한 문구와 형식으로 정답을 끝에 둔다.

여러 묶음 뒤에 새 문제를 놓으면 model은 demonstration의 형식을 이어 중간 단계 $r$과 답 $a$를 생성한다. Prompt와 새 문제를 $D,x$라 할 때 생성 sequence는 다음처럼 나눠 쓸 수 있다.

$$
p(r,a\mid D,x)=p(r\mid D,x)\,p(a\mid D,x,r)
$$

이 식은 생성된 $r$이 $a$의 token 확률에 조건으로 들어간다는 뜻이다. 이것만으로 $r$이 model 내부 결정의 유일하거나 충실한 원인이었다고 입증되지는 않는다.

### 표준 few-shot과의 차이는 답 예시 안에 있다

표준 few-shot prompting도 문제–답 예시를 주지만 답 사이의 중간 경로는 생략한다. Few-shot CoT는 같은 문맥 적응 구조에서 각 답을 `중간 단계 + 최종 답`으로 확장한다. 따라서 비교할 때는 model checkpoint, 예시 문제, 예시 순서, decoding과 답 추출 규칙을 같게 하고 rationale 유무만 바꿔야 한다.

예시 rationale은 공짜 자료가 아니다. 복잡한 문제의 올바른 중간 단계를 사람이 작성하거나 검수해야 하며, 과제 형식과 맞지 않는 예시는 성능을 떨어뜨릴 수 있다.

### Zero-shot-CoT는 추론과 답을 두 단계로 뽑는다

Kojima 등의 대표 Zero-shot-CoT pipeline은 손으로 쓴 demonstration 없이 다음 두 호출을 사용했다.

1. **추론 추출:** 문제 뒤에 `Let's think step by step`을 붙여 중간 추론문 $r$을 생성한다.
2. **답 추출:** 원래 문제와 생성된 $r$ 뒤에 과제의 답 형식에 맞는 문구를 붙여 최종 답 $a$를 다시 생성·parse한다.

수치 답에는 `Therefore, the answer (arabic numerals) is`, 객관식에는 `Therefore, among A through E, the answer is`처럼 서로 다른 answer trigger를 썼다. 그러므로 Zero-shot-CoT를 단지 한 문장을 덧붙인 단일 호출로 요약하면 원 실험의 답 추출 조건을 놓친다.

## 3단계 — 기술과 근거

### 효과는 규모·과제·prompt에 조건부였다

Wei 등은 GPT-3 계열 350M–175B, LaMDA 422M–137B, PaLM 8B·62B·540B와 UL2 20B, Codex를 대상으로 산술·상식·기호 과제를 비교했다. 수학 문장제 대부분에는 사람이 만든 같은 여덟 CoT 예시를 사용했고, 모델 출력은 기본적으로 greedy decoding으로 생성했다.

그 실험에서는 작은 모델이 유창하지만 논리적으로 틀린 연쇄를 생성해 표준 prompting보다 나빠지기도 했고, 뚜렷한 이득은 대략 100B 규모에서 관찰됐다. PaLM 540B의 GSM8K 정확도는 표준 8-shot prompting 17.9%에서 CoT 56.9%로 높아졌다. 이는 당시 선택한 모델군·prompt·dataset·exact-answer 채점 조건의 결과이지, 모든 100B 이상 모델에 적용되는 보편 임계값이 아니다.

간단한 단일 단계 문제에서는 중간 text를 만드는 이득이 작거나 음수였다. 반대로 여러 중간 상태를 유지해야 하는 문제에서 향상이 더 컸다. CoT의 유효성을 말할 때는 “추론 과제”라는 이름만 볼 것이 아니라 문제 깊이, 답 형식과 metric을 함께 확인해야 한다.

### Zero-shot 수치도 특정 실행 조건의 비교다

Kojima 등은 주로 2022년의 `text-davinci-002`를 greedy decoding으로 실행하고, 같은 trigger를 여러 과제에 적용했다. 이 조건에서 Zero-shot-CoT는 MultiArith 정확도를 17.7%에서 78.7%로, GSM8K를 10.4%에서 40.7%로 높였다. PaLM 540B에서도 MultiArith 25.5%→66.1%, GSM8K 12.5%→43.0%가 보고됐다.

그러나 모든 과제에서 좋아진 것은 아니다. 같은 논문의 CommonsenseQA에서는 68.8%에서 64.6%로 낮아졌다. Prompt 문구, answer trigger, model version, example–task 적합성과 채점 parser가 달라지면 결과도 달라질 수 있다.

### 추가 token과 호출이 비용을 만든다

CoT는 task별 fine-tuning run을 요구하지 않지만 추론 비용을 없애지 않는다. Few-shot 예시는 context window를 차지하고, 중간 연쇄는 completion token과 latency를 늘린다. 대표 Zero-shot-CoT는 두 번 호출하므로 단순 zero-shot보다 요청 수도 많다.

따라서 효율 비교에는 정답률뿐 아니라 prompt token, 생성 token, model 호출 횟수, 지연과 rationale 제작·검수 비용을 포함해야 한다. 단순 과제에서 긴 CoT를 강제하면 정확도 이득 없이 비용과 오류 표면만 늘 수 있다.

### 후속 계보는 선형 연쇄의 다른 한계를 바꿨다

- **Self-consistency:** 하나의 greedy 연쇄를 믿는 대신 여러 reasoning path를 표본화하고 최종 답의 다수결을 취한다. 답의 안정성을 높일 수 있지만 표본 수만큼 생성 비용이 증가한다.
- **Tree of Thoughts:** 한 줄로만 전진하지 않고 중간 thought 후보를 분기·평가·탐색하며 필요하면 다른 branch로 돌아간다. 이는 search와 상태 평가를 추가한 확장이다.
- **ReAct:** 추론 text와 외부 action, 그 결과인 observation을 교대로 기록한다. 내부 지식만으로 닫힌 연쇄를 만드는 대신 environment의 정보를 다음 단계에 다시 넣는다.

이 방법들은 CoT가 성공했다는 이유만으로 자동으로 우월하지 않다. 각 방법은 더 많은 sampling, 평가 호출이나 tool interaction을 요구하고, 과제별 search·action 설계라는 새 실패 조건을 만든다.

## 검증과 한계

### 세 가지 타당성을 분리한다

| 판단 대상 | 묻는 질문 | 확인 방법의 예 | 보장하지 않는 것 |
|---|---|---|---|
| 출력의 그럴듯함 | 중간 text가 문법적이고 앞뒤가 맞아 보이는가? | 사람 읽기, 일관성 검사 | 계산의 정확성, 답의 정확성 |
| 답 정확도 | 최종 답이 정답·reference와 일치하는가? | exact match, 객관식 accuracy | 중간 단계의 옳음, 설명의 충실성 |
| 인과적 충실성 | 적어 놓은 근거가 실제로 답을 바꾼 원인을 빠짐없이 반영하는가? | 입력 편향 개입, rationale·answer의 민감도 비교 | 유창함만으로는 판정할 수 없음 |

Wei 등의 LaMDA 137B 오류 분석에서는 정답 사례 50개 가운데 두 개가 잘못된 중간 단계로 우연히 정답에 도달했다. 이 작은 수동 표본만으로 전체 충실성을 추정할 수는 없지만, 답 정확도와 연쇄 정확도를 따로 봐야 한다는 직접 사례다.

### CoT 설명은 사후 합리화가 될 수 있다

Turpin 등은 GPT-3.5와 Claude 1.0의 입력에 객관식 선택지 순서 같은 편향 신호를 넣었다. Model의 답은 그 신호에 영향을 받았지만 생성된 CoT는 신호를 언급하지 않고 선택을 합리화하는 경우가 있었다. 13개 BIG-Bench Hard 과제 묶음에서는 잘못된 답으로 유도했을 때 accuracy가 최대 36% 낮아졌다.

이 결과는 모든 CoT가 거짓 설명이라는 뜻이 아니다. 다만 사람에게 설득력 있는 rationale을 그대로 model의 숨은 계산 기록이나 안전성 증거로 취급할 수 없음을 보여 준다. 고위험 결정에서는 외부 근거 확인, 반례·개입 시험과 독립 검증이 필요하다.

### 흔한 오해와 적용 범위

- **단계가 길수록 더 깊이 추론한다:** 길이는 token 비용과 계산 기회를 늘리지만, 중복·환각·오류 전파도 늘릴 수 있다.
- **정답이면 rationale도 맞다:** 우연한 상쇄나 사후 합리화로 맞는 답에 도달할 수 있다.
- **rationale이 맞으면 model 내부가 투명해진다:** 출력 단계의 타당성과 내부 계산에 대한 인과적 충실성은 별도 문제다.
- **CoT는 모든 규모와 과제를 개선한다:** 초기 연구에서도 작은 모델·단순 문제·일부 상식 과제에서는 이득이 없거나 성능이 낮아졌다.
- **Zero-shot-CoT는 예시도 비용도 없다:** 사람 작성 demonstration은 없지만 대표 pipeline은 두 호출과 더 긴 출력을 사용한다.

이 문서는 prompt로 외부에 중간 text를 생성하는 CoT를 다룬다. 공개되지 않는 내부 scratchpad, 별도 verifier로 학습한 reasoning model, program execution과 formal proof search는 관련될 수 있지만 같은 개념으로 묶지 않는다.

### 프롬프팅으로 끌어낸 연쇄와 후훈련으로 강화한 연쇄

[[106_DeepSeek-R1의 강화학습 파이프라인과 증류 경계]]의 R1-Zero는 `Let's think step by step` 같은 prompt만으로 고정된 weight의 출력을 바꾼 사례가 아니다. DeepSeek-V3-Base에서 같은 문제의 여러 응답을 만들고, 정답 정확도와 출력 형식 보상을 이용하는 [[그룹 상대 정책 최적화|GRPO]]로 정책 자체를 갱신했다. 정식 R1은 여기에 콜드 스타트 CoT 지도 미세조정, 거부 샘플링과 추가 SFT, 두 번째 정렬 RL을 결합했다. 따라서 prompt로 중간 text를 유도하는 CoT와, 그런 출력을 더 자주 생성하도록 후훈련한 reasoning model을 같은 방법으로 부르지 않는다.

후훈련으로 긴 풀이·재검토·전략 전환이 늘어도 출력의 인과적 충실성이 자동으로 보장되지는 않는다. R1-Zero의 정확도 보상은 주로 최종 답을, 형식 보상은 지정된 출력 경계를 검사하며 중간 단계가 참인지 또는 model 내부 계산을 빠짐없이 드러내는지는 판정하지 않는다. 관찰 가능한 추론 행동의 강화와 별도 추론 기관·인간 같은 자기 성찰의 존재를 구분해야 한다.
