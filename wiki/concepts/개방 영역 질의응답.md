# 개방 영역 질의응답

> [!note] 학습 안내
> **난이도:** 입문<br>
> **선수 지식:** 없음<br>
> **읽고 나면:** 개방 영역 질의응답의 지식 범위·자료 접근·답 형식·평가 축을 설명하고, 개방이라는 이름이 보장하지 않는 능력을 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

개방 영역 질의응답(open-domain question answering)은 한정된 데이터베이스 스키마나 좁은 전문 어휘에 질문 주제를 미리 가두지 않고, 여러 분야의 자료에서 답을 찾는 과업이다. “개방”은 주제와 지식 원천의 폭을 뜻하지 모든 입력 양식·언어 능력·최신 세계 상태를 무제한으로 처리한다는 뜻은 아니다.

## 2단계 — 작동 원리

### 후보 생성과 답 선택

개방 영역에서는 질문과 정확히 같은 문장이 자료에 없거나 같은 이름이 여러 대상을 가리킬 수 있다. 따라서 질문 분석, 문서·구절 검색, 후보 생성, 근거 점수화, 답 순위화가 흔한 구성 요소가 된다. [[DeepQA]]는 이 구성을 여러 병렬 분석기로 구현했다.

후보 재현율과 최종 정밀도는 구분해야 한다. 정답을 후보군 안에 넣는 단계에서 놓치면 뒤의 답 선택기가 고칠 수 없다. 반대로 후보를 지나치게 넓히면 계산량과 오답 경쟁이 커진다. 답하지 않을 수 있는 시스템에서는 정밀도와 답변률 사이의 선택, 즉 불확실성 calibration도 과업의 일부다.

## 3단계 — 기술과 근거

### 제한 영역과의 비교

LUNAR는 월석·토양의 화학 분석 데이터라는 명확한 영역에서 영어 질문을 의미 표현과 데이터베이스 검색으로 연결했다. 어휘·관계·답할 수 있는 질문의 범위를 설계할 수 있었으므로 깊은 영역 해석이 가능했지만 다른 주제로 확장하려면 사전과 지식 구조를 다시 만들어야 했다.

[[IBM Watson]]은 역사·과학·문학·대중문화 등 다양한 *Jeopardy!* clue를 처리했다. 하나의 관계형 데이터베이스가 아니라 문서 corpus와 여러 구조 지식 자원에서 후보와 근거를 모았다. 이것이 개방 영역의 폭을 보여주지만, 실제 입력은 전자 텍스트 clue이고 출력은 짧은 단일 답이었다.

### 과업을 정의하는 축

개방 영역 QA를 비교하려면 이름보다 다음 조건을 먼저 확인해야 한다.

| 축 | 확인할 질문 |
| --- | --- |
| 지식 범위 | 어떤 주제·시점·언어의 자료를 포함하는가? |
| 자료 접근 | 폐쇄 corpus, 시험 중 검색, 실시간 웹 중 무엇을 쓰는가? |
| 입력 | 짧은 질문, 문서가 붙은 질문, 대화, 음성·영상 중 무엇인가? |
| 답 단위 | 개체명, 짧은 구절, 문장, 설명, 여러 답 중 무엇인가? |
| 근거 | 출처 문서와 구절을 반환·검증하는가? |
| 평가 | 정답률, 정밀도·답변률, 순위, 시간, calibration 중 무엇인가? |
| 행동 | 답변·보류·도구 사용·추가 질문을 어떻게 선택하는가? |

같은 “개방 영역”이라도 시험 중 인터넷이 금지된 Watson, 고정 passage 집합을 검색하는 벤치마크, 현재 웹을 검색하는 시스템은 서로 다른 조건이다.

### 외부 메모리와 검색 증강

2014년 [[메모리 네트워크]]는 질문에 맞는 [[외부 메모리]] 슬롯을 반복 선택해 답을 순위화했다. large-scale QA 실험은 1,400만 사실 전체에서 자유롭게 문장을 생성한 것이 아니라 기존 시스템의 상위 후보를 재순위화한 단답 과제였다. 2020년 RAG는 DPR로 초기화한 dense Wikipedia passage 검색기와 BART-large seq2seq 생성기를 결합했다.

원 RAG의 개방 영역 QA 평가는 Natural Questions, TriviaQA, WebQuestions, CuratedTREC의 질문–짧은 답 쌍을 사용하고 Exact Match(EM)를 보고했다. Table 1의 RAG-Sequence test EM은 NQ 44.5, TriviaQA 56.8과 TQA-Wiki 68.0, WebQuestions 45.2, CuratedTREC 52.2였다. 이 숫자는 고정된 2018년 12월 영어 Wikipedia 색인과 각 데이터셋의 정답 문자열 평가에서 나온 결과이며, 장문 설명의 근거 충실성이나 현재 웹의 최신성을 측정한 값이 아니다.

같은 논문이 다룬 나머지 범위도 지표가 달랐다. Open MS MARCO는 BLEU-1·ROUGE-L, Jeopardy 질문 생성은 BLEU-1·Q-BLEU-1과 제한된 사람 평가, FEVER 사실 검증은 label accuracy로 평가했다. 그러므로 ‘RAG가 지식 집약적 과제에서 강했다’는 결론은 여러 과제별 결과의 묶음이지, 하나의 EM이나 사실성 지표로 현대 장문 챗봇·법률·의료·실시간 검색까지 검증했다는 뜻이 아니다.

### 현대 LLM과의 연결

현대 [[대규모 언어 모델]]은 매개변수에 학습된 패턴으로 답하거나 외부 검색과 도구를 결합해 개방 영역 질문에 대응할 수 있다. 생성 능력은 짧은 정답을 넘어 설명과 대화를 가능하게 하지만, 유창한 출력과 사실적 근거는 별개다. 검색 성공, 근거의 적합성, 생성 충실성, 최신성, 답변 보류를 각각 평가해야 한다.

Watson에서 현대 LLM으로 단일한 직접 계보를 긋기보다, **후보를 놓치지 않는 검색**, **근거와 답의 연결**, **불확실성을 행동으로 바꾸는 방식**이라는 지속되는 평가 질문을 비교하는 편이 정확하다.

## 검증과 한계

### 개방 영역이 보장하지 않는 것

- 모든 질문에 답할 수 있다는 완전성을 보장하지 않는다.
- 답이 corpus에 없거나 낡았을 때 최신 사실을 자동으로 만들지 않는다.
- 짧은 정답이 맞았다는 사실만으로 설명·추론 경로가 옳다고 보장하지 않는다.
- 텍스트 질의응답 성공이 음성·영상·행동 계획·장기 대화 능력을 뜻하지 않는다.
- 한 벤치마크의 높은 점수가 다른 언어·도메인·위험 수준으로 그대로 이전되지 않는다.

## 학습 확인

1. 개방 영역 질의응답에서 개방은 무엇의 폭을 뜻하는가?

3. 개방 영역이라는 이름이 최신성·설명·시청각 이해·다른 도메인 성능을 보장하지 않는 이유는 무엇인가?
