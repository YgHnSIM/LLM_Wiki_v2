# 가속기와 행렬 계산

> [!note] 학습 안내
> **난이도:** 입문–중급<br>
> **선수 지식:** [[내적·행렬곱과 선형변환]] — 행렬곱의 입력·출력 shape를 모르면 2단계의 작은 예부터 따라가도 된다.<br>
> **읽고 나면:** CPU·GPU·TPU를 단순한 속도 서열로 놓지 않고, 같은 행렬 계산을 어떤 병렬 단위·메모리 경로·수치 형식으로 실행하는지 설명하며 최고 연산률과 실제 모델 시간을 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 가속기는 수학식을 바꾸지 않고 실행 경로를 바꿀 수 있다

신경망에서 행렬곱이 많다는 사실만으로 GPU나 TPU가 언제나 빠른 것은 아니다. 가속기는 특정한 계산과 데이터 이동 패턴을 여러 실행 유닛에 나누고, 같은 값을 가까운 메모리에서 재사용하며, 지원하는 수치 형식으로 높은 처리량을 내도록 설계한 장치다.

예를 들어

$$
Y=XW
$$

에서 $X\in\mathbb R^{4\times8}$, $W\in\mathbb R^{8\times16}$이면 출력은 $Y\in\mathbb R^{4\times16}$이다. 64개 출력 원소마다 길이 8인 내적을 계산하므로 단순히 곱셈만 세면 $4\cdot16\cdot8=512$번이다. CPU·GPU·TPU 모두 같은 $Y$를 계산할 수 있지만, 512개의 곱셈과 덧셈을 묶는 방식, $X$와 $W$를 가져오는 위치, 동시에 처리하는 수와 누산 정밀도가 다르다.

작은 행렬 하나에서는 kernel 시작과 데이터 전송의 고정 비용 때문에 CPU가 더 빠를 수도 있다. 큰 batch와 큰 행렬처럼 독립적인 작업이 충분하고 데이터 재사용이 높으면 많은 연산 유닛을 가진 가속기의 처리량을 활용하기 쉽다. 따라서 “가속 가능”은 수학적 연산 종류와 실제 shape·batch·memory path를 함께 말해야 하는 조건부 주장이다.

### CPU·GPU·TPU는 역할이 다른 실행 설계다

여기서 세 이름은 모든 세대에 통하는 단일 구조를 뜻하지 않는다. 대표적인 설계 방향을 비교하는 말이다.

| 장치 방향 | 강점으로 삼는 것 | 잘 맞을 수 있는 작업 | 놓치기 쉬운 조건 |
| --- | --- | --- | --- |
| 범용 CPU | 복잡한 제어, 낮은 단일 작업 지연, 큰 범용 명령 집합 | 전처리, 분기 많은 코드, host orchestration | vector unit·core 수·memory가 세대마다 다르다. |
| GPU | 많은 thread와 넓은 throughput, 프로그래밍 가능한 병렬 kernel | 큰 행렬곱, convolution, attention, 병렬 elementwise 연산 | 분기 발산, 작은 kernel, host 전송과 memory traffic이 병목일 수 있다. |
| 특화 ML accelerator | 정해진 tensor 연산·수치 형식·데이터 경로에 회로를 집중 | 지원되는 큰 행렬·tensor 계산 | 지원하지 않는 연산, compiler mapping과 시스템 통신 비용이 남는다. |

“GPU는 병렬이고 CPU는 순차적이다”라고 단정하지 않는다. CPU도 SIMD와 여러 core를 사용하고 GPU kernel 안에도 의존성과 동기화가 있다. 차이는 병렬성의 유무가 아니라 어떤 병렬 단위와 제어·메모리 자원에 설계 비용을 집중했는가에 있다.

## 2단계 — 작동 원리

### 행렬곱을 작은 tile로 나눈다

큰 $XW$를 한 번에 처리하지 않고 출력의 작은 직사각형인 **tile**로 나눌 수 있다. 한 tile을 계산하는 동안 필요한 $X$의 행 조각과 $W$의 열 조각을 빠른 온칩 메모리에 올리고 여러 번 재사용한다. 각 실행 유닛은 곱셈-누산

$$
s\leftarrow s+x_iw_i
$$

을 반복한다. 여기서 $s$는 부분합이다. 곱셈과 덧셈을 몇 개 묶어 세는지는 FLOP 보고 규칙에 따라 달라질 수 있으므로, 처리량 수치를 비교할 때는 연산 계산법도 확인해야 한다.

Tile이 너무 작으면 재사용이 적고 kernel 관리 비용의 비중이 커진다. 너무 크면 register나 shared memory·SRAM에 들어가지 않아 동시에 실행할 수 있는 block 수가 줄 수 있다. 최적 tile은 수학식에서 유일하게 나오지 않고, shape·dtype·장치 메모리·compiler와 kernel 구현이 함께 정하는 공학적 선택이다.

### CUDA는 병렬 장치를 프로그래밍 가능한 대상으로 만든다

Nickolls 등이 설명한 CUDA 모델에서는 같은 kernel을 실행하는 thread를 block과 grid로 조직한다. Block 안 thread는 shared memory를 사용하고 동기화할 수 있으며, 서로 다른 block은 더 독립적으로 schedule된다. 이는 GPU의 많은 실행 유닛을 그래픽 단계가 아닌 일반 계산에 연결하는 프로그래밍 모델이었다.

그러나 CUDA code를 썼다는 사실만으로 높은 성능이 보장되지는 않는다. 연속적인 memory access, 충분한 병렬 작업, thread 간 균형, kernel fusion과 지원 라이브러리가 필요하다. 실제 딥러닝은 연구자가 모든 행렬곱 kernel을 직접 쓰기보다 framework가 계산 그래프를 만들고, compiler·BLAS 계열 library·kernel이 장치 명령으로 낮추는 층을 사용한다.

### 특화 가속기는 범용성을 성능과 교환한다

Jouppi 등이 평가한 1세대 TPU는 65,536개의 8-bit MAC을 가진 matrix multiply unit과 28 MiB의 software-managed 온칩 메모리를 사용했다. 논문의 생산 추론 작업에서는 CPU·GPU와 비교한 큰 성능·에너지 이점을 보고했지만, 이는 2017년에 공개한 특정 칩과 MLP·CNN·LSTM 추론, 비교 장치, 99백분위 지연 조건의 결과다.

이 사례가 보여주는 일반 원리는 “TPU가 언제나 GPU보다 빠르다”가 아니다. 복잡한 범용 제어 대신 반복되는 행렬 계산과 예측 가능한 데이터 경로에 면적·전력을 집중하면, 맞는 작업에서 더 높은 처리량과 에너지 효율을 얻을 수 있다는 것이다. 반대로 지원되지 않는 연산이나 host·network 통신의 비중이 커지면 특화된 matrix unit이 기다릴 수 있다.

### 모델에서 장치까지 여섯 층을 통과한다

한 모델 연산이 실제 속도가 되기까지 다음 층을 지난다.

1. **모델 연산:** attention, FFN, normalization처럼 무엇을 계산하는가
2. **tensor shape:** batch·sequence·hidden 차원이 병렬 작업을 얼마나 만드는가
3. **알고리즘:** 같은 결과를 어떤 계산 순서와 중간값으로 얻는가
4. **kernel·compiler:** 연산을 tile·fusion·thread와 장치 명령으로 어떻게 낮추는가
5. **device:** 연산 유닛, 수치 형식, 메모리 용량·대역폭이 무엇인가
6. **system:** 여러 장치, host, network, storage를 포함한 끝단 시간이 얼마인가

위층의 같은 수학도 아래층 구현에 따라 시간이 달라지고, 아래층의 높은 최고 처리량도 위층 작업이 충분히 공급되지 않으면 사용되지 않는다.

## 3단계 — 기술과 근거

### Transformer 원 논문의 가속기 조건

2017년 Transformer는 입력·정답 목표열이 주어진 훈련에서 여러 위치의 attention과 FFN을 행렬 연산으로 묶기 쉬웠다. 원 논문의 base 모델은 8개 NVIDIA P100 GPU에서 12시간, big 모델은 같은 수의 GPU에서 3.5일 훈련됐다고 보고했다. 이 수치는 Transformer 구조의 가능 조건을 보여 주지만, GPU가 self-attention이라는 아이디어를 직접 낳았다는 근거는 아니다.

#### 측정 장부

| 항목 | Transformer 논문에서 확인할 값 |
| --- | --- |
| 작업 | WMT 2014 기계 번역 모델 훈련 |
| 규모 | base 또는 big 모델, 8개 P100 GPU |
| 결과 계약 | 논문이 보고한 번역 BLEU와 학습 목적 |
| 시스템 경계 | 논문 구현의 전체 훈련 시간 |
| 고정 조건 | 같은 논문 안의 전처리·batch·optimizer·hardware 조건 |
| 지표 | base 12시간, big 3.5일과 BLEU |

다른 논문의 GPU 시간과 바로 나누면 model size, token 수, precision, software와 quality target이 달라진다. P100의 최고 FLOP/s만으로 위 훈련 시간을 다시 계산할 수도 없다. Attention 외에 embedding, FFN, normalization, optimizer, communication과 입력 pipeline이 함께 실행되기 때문이다.

### 가속기 성능을 읽는 최소 공식

작업이 수행한 유효 연산 수를 $F$, 걸린 시간을 $T$라고 하면 달성 연산률은

$$
P_{\mathrm{achieved}}=\frac{F}{T}
$$

로 적을 수 있다. 장치 최고 연산률 $P_{\mathrm{peak}}$와 비교한 이용률은

$$
u=\frac{P_{\mathrm{achieved}}}{P_{\mathrm{peak}}}
$$

이다. $u<1$인 이유는 실패가 아니라 instruction mix, memory 이동, 의존성, communication과 유휴 구간을 포함한 실제 실행 조건 때문이다. 서로 다른 dtype의 peak를 같은 숫자로 비교하거나, 품질을 달리한 근사 연산을 같은 $F$로 취급하면 이 비율도 의미가 흐려진다.

### 무엇이 필연이고 무엇이 선택인가

| 구분 | 내용 |
| --- | --- |
| 수학적 요구 | $X\in\mathbb R^{m\times k}$와 $W\in\mathbb R^{k\times n}$의 안쪽 차원 $k$가 같아야 한다. |
| 병렬 가능성 | 서로 의존하지 않는 출력 원소·tile은 동시에 계산할 수 있다. |
| 공학적 선택 | tile 크기, thread 배치, fusion, dtype, memory layout과 device 수 |
| 시스템 조건 | host 전송, 장치 간 통신, scheduler, 입력 pipeline과 품질 목표 |

행렬곱이 병렬 가능하다는 수학적 사실과 특정 GPU kernel이 빠르다는 측정 결과를 같은 문장으로 합치지 않는다.

### CS_WIKI와 함께 읽기

[CS_WIKI의 「도메인 특화 가속기」](https://yghnsim.github.io/CS_Wiki/concepts/%EB%8F%84%EB%A9%94%EC%9D%B8-%ED%8A%B9%ED%99%94-%EA%B0%80%EC%86%8D%EA%B8%B0/)는 범용성과 효율의 교환을 컴퓨터 구조 발전사에서 설명한다. 이 링크는 맥락 독서이며, 이 문서의 사실 근거는 frontmatter에 등록한 CUDA·TPU·Transformer 1차 자료다.

## 검증과 한계

- **직접 영향:** Transformer 논문은 P100 GPU를 실제 훈련에 사용했고 계산 복잡도와 sequential operations를 비교했다. 이것은 실행 조건에 대한 직접 근거다.
- **가능 조건:** 많은 위치 계산을 큰 행렬로 묶을 수 있는 GPU와 library stack은 Transformer 훈련의 실현 조건이었다. GPU가 구조 선택의 유일한 원인이라는 주장은 아니다.
- **병행 맥락:** CUDA와 특화 ML accelerator의 발전은 신경망 계산을 넓혔지만, 모든 장치 발전이 Transformer 연구팀의 직접 설계 근거였다고 볼 수는 없다.
- **후대 유추:** 오늘날 CPU·GPU·TPU의 일반적 역할을 2017년 장치에 그대로 소급하지 않는다. 세대별 memory·precision·compiler가 다르다.

이 문서는 transistor, instruction set와 microarchitecture 전체를 설명하지 않는다. 또한 가속기 구매 가격, 공급망과 환경 비용은 같은 처리량 비교 밖의 문제다. 실제 시스템 선택에는 model quality, batch, latency, energy, 개발 생태계와 가용성을 별도로 측정해야 한다.

## 학습 확인

1. 같은 $Y=XW$를 계산해도 작은 행렬에서는 CPU가, 큰 batch에서는 GPU가 유리할 수 있는 이유를 고정 비용·병렬 작업 수·데이터 이동으로 설명하라.
2. TPU 논문의 15–30배 성능 수치를 모든 GPU와 모든 LLM 학습에 적용할 수 없는 조건을 세 가지 쓰라.
3. 새로운 accelerator의 “2배 빠름” 주장을 발견했다면 작업·규모·결과 계약·시스템 경계·고정 조건·지표를 채우고, peak 처리량과 end-to-end 시간을 구분하라.

다음에는 [[메모리 계층과 데이터 이동]]에서 연산기가 충분히 많아도 데이터가 제때 도착하지 않으면 왜 기다리는지 배운다. 그 뒤 [[Transformer는 무엇을 병렬화했고 무엇을 남겼나]]에서 가속기 가능성과 모델 의존성을 한 역사 장면으로 연결한다.

역사적 횡단 경로 [[집적도 증가에서 가속기까지 무엇이 더 필요했나]]은 transistor 집적에서 CUDA GPU와 TPU 특화까지의 중간 조건을 다룬다.
