# T5

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[인코더-디코더]], [[마스크드 언어 모델링]]<br>
> **읽고 나면:** T5의 text-to-text interface와 sentinel span corruption이 pretraining에서 과제별 supervised fine-tuning으로 이어지는 흐름을 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 한 문장 정의

T5(Text-to-Text Transfer Transformer)는 분류 label, answer, summary와 translation을 모두 target token sequence로 표현해 같은 [[인코더-디코더]] Transformer와 생성 loss로 학습하는 model family이자 transfer-learning framework다.

중요한 통합은 `text input → text output`이라는 interface에 있다. 하나의 pretrained model family를 여러 과제에 재사용할 수 있지만, T5의 대표 최종 결과는 대체로 각 과제의 labeled example로 별도 fine-tuning한 checkpoint에서 나왔다. 하나의 frozen model이 모든 과제를 zero-shot으로 해결했다는 뜻이 아니다.

## 2단계 — 작동 원리

### pretraining에서 downstream task까지

1. C4 text 일부를 sentinel span corruption으로 교란한다.
2. encoder는 교란된 text를 양방향으로 읽는다.
3. decoder는 cross-attention을 사용해 제거된 span sequence를 생성한다.
4. downstream input 앞에 `summarize:`나 `translate English to German:` 같은 task prefix를 붙인다.
5. 분류도 class label string을 생성하도록 만들고, 같은 token likelihood로 fine-tune한다.
6. 평가는 accuracy·F1·ROUGE·BLEU 등 각 task의 metric으로 수행한다.

task prefix는 model이 supervised training에서 과제를 구분하도록 학습한 text 식별자다. 자유로운 자연어 instruction을 해석하거나 처음 보는 과제를 zero-shot으로 일반화한다는 보장은 없다.

### text-to-text가 바꾸는 경계

과제별 neural head와 서로 다른 output loss가 공통 decoder로 이동한다. 반면 dataset, label 의미, prefix, decoding 조건과 평가 metric은 여전히 과제별이다. 따라서 architecture의 공통화와 과제 정의의 소멸을 구분해야 한다.

## 3단계 — 기술과 근거

### architecture

T5 baseline은 bidirectional encoder와 causal decoder를 쓰며 decoder가 encoder output에 attention한다. 원 Transformer와 비교하면 layer normalization의 배치와 relative position signal 등에 구현 차이가 있다. 그러나 연구의 중심은 새로운 block 하나보다 공통 framework에서 architecture·objective·data·transfer recipe를 비교한 데 있다.

같은 계산 예산의 architecture 비교에서 encoder–decoder는 비교 language model보다 parameter가 약 두 배였지만 계산량은 비슷하게 맞췄다. parameter 수를 FLOPs·memory·latency와 같은 값으로 해석해서는 안 된다.

### Switch Transformer는 원 T5와 구분한다

[[069_전문가 혼합과 희소 활성 스케일링]]의 Switch Transformer는 T5 계열 encoder–decoder와 span-corruption pretraining을 출발점으로 삼았지만, 일부 dense FFN을 top-1 [[전문가 혼합|Switch FFN]]으로 바꾼 후속 sparse architecture다. 원 T5 논문의 대표 model이 MoE였다는 뜻은 아니다.

따라서 T5의 text-to-text interface·objective와 Switch의 token routing·expert capacity를 서로 다른 설계 축으로 기록한다. Switch의 속도·규모 결과도 원 T5의 모든 variant나 현대 decoder-only MoE에 자동으로 이전하지 않는다.

### sentinel span corruption

대표 objective는 전체 token의 15%를 선택해 평균 길이 3의 연속 span으로 묶는다. input의 각 span을 고유 sentinel로 바꾸고, target에는 `sentinel + 제거된 span`을 순서대로 이어 붙인 뒤 다음 sentinel로 끝을 표시한다.

- input: `Thank you <X> me to your party <Y>`
- target: `<X> for inviting <Y> last week <Z>`

sentinel은 input의 빈 위치와 target의 복원 segment를 대응시키며 마지막 sentinel은 target 경계도 알린다. decoder가 원문 전체가 아니라 제거된 부분만 생성하므로 target이 짧다. 원 비교에서 여러 denoising variant의 성능 차이는 작았고 평균 span 길이 3은 품질과 속도를 함께 고려한 선택이었다.

### transfer와 multi-task recipe

T5는 full fine-tuning, adapter 계열과 여러 multi-task mixture를 비교했다. 단순히 supervised task를 계속 섞는 하나의 multi-task training이 모든 과제에서 우월하지는 않았다. 최종 model은 multi-task pretraining 뒤 각 task에 개별 fine-tuning했다. `shared output interface`, `shared pretrained checkpoint`, `shared final weights`는 서로 다른 공유 수준이다.

### 원 FLAN은 T5가 아니다

[[072_지시 미세조정과 FLAN의 제로샷 일반화]]의 2021년 원 FLAN은 T5 checkpoint를 instruction-tune한 모델이 아니라 **137B decoder-only LaMDA-PT**를 사용했다. T5의 text-to-text interface와 task prefix가 지시 기반 다과제 학습을 이해하는 중요한 선행 비교점인 것은 맞지만, 이를 원 FLAN의 직접 architecture 계보로 쓰면 encoder–decoder와 decoder-only 차이가 사라진다.

따라서 T5와 FLAN을 비교할 때는 공통 text interface라는 유사성과 실제 architecture·checkpoint를 분리해야 한다. 같은 architecture에서도 task별 supervised fine-tuning, multi-task pretraining, instruction tuning 가운데 어떤 data·holdout·checkpoint 절차를 썼는지 확인한다.

### 결과를 읽는 조건

T5-11B는 최종 24개 task 가운데 18개에서 당시 최고 결과를 냈다. 하지만 WMT English→German 32.1 BLEU는 Table 14의 prior best 33.8보다 낮았다. 번역 방향은 English→German·French·Romanian으로 제한됐다. T5가 SQuAD answer를 text로 생성했어도 이 논문은 별도의 abstractive QA 과제를 평가하지 않았으므로 자유로운 abstractive QA 능력의 증거가 아니다.

## 검증과 한계

### 흔한 오해와 적용 경계

- T5는 모든 통합 NLP의 최초 발명이 아니라 선행 transfer method를 공통 framework에서 체계적으로 비교한 연구다.
- 공통 text output은 공통 metric을 뜻하지 않는다.
- task prefix는 현대 natural-language instruction이나 unseen-task zero-shot과 동일하지 않다.
- 원 FLAN은 T5 기반이 아니며, T5의 task prefix 결과를 FLAN식 held-out-task instruction generalization의 직접 증거로 쓸 수 없다.
- C4의 filtering은 사실성·중립성·대표성을 보장하지 않는다.
- encoder–decoder가 parameter를 더 가진다는 사실만으로 계산이 정확히 두 배라고 할 수 없다.
- 모든 과제를 text로 직렬화할 수 있어도 그것이 모든 과제의 가장 정확하거나 효율적인 표현이라는 보장은 없다.
- GPT-3·PaLM·GPT-4·BART 전체를 T5의 직접 후속으로 묶으려면 별도 계보 근거가 필요하다.

T5-11B의 최고 결과는 큰 model과 pretraining budget, C4와 task별 fine-tuning에 의존한다. English 중심 web data의 편향과 contamination, 생성 decoder의 inference 비용, label string·prefix 선택의 민감성도 따로 평가해야 한다.
