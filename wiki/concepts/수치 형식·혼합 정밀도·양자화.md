# 수치 형식·혼합 정밀도·양자화

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[concept.수치-안정성과-log-sum-exp|수치 안정성과 log-sum-exp]]<br>
> **읽고 나면:** 저장 bit 수, 연산 입력 형식, 누산 형식과 optimizer state를 따로 기록하고, mixed precision·post-training quantization·QLoRA를 같은 “저정밀도”로 합치지 않으며 memory·속도·품질의 결과 계약을 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 숫자를 적는 칸이 줄면 이득과 손실이 함께 생긴다

유한한 bit로 실수를 저장하면 표현할 수 있는 범위와 간격이 제한된다. 넓은 범위를 담으려면 가까운 수 사이 간격이 거칠어질 수 있고, 촘촘한 간격에 집중하면 아주 크거나 작은 값을 담기 어렵다. 낮은 정밀도는 weight·activation·gradient 한 원소의 byte를 줄이고 지원 hardware에서 더 많은 연산을 동시에 수행하게 할 수 있지만, overflow·underflow·rounding error와 model quality 변화를 만든다.

그래서 “16-bit model”, “4-bit 학습” 같은 짧은 이름만으로 실행을 설명할 수 없다. 적어도 다음 역할을 분리한다.

| 역할 | 묻는 질문 |
| --- | --- |
| 저장 형식 | Weight·activation·gradient·optimizer state를 memory에 몇 bit로 두는가? |
| 연산 입력 형식 | Matrix unit에 어떤 형식의 값을 넣는가? |
| 누산 형식 | 많은 곱의 합을 어떤 더 넓은 형식에 모으는가? |
| 갱신 형식 | 작은 optimizer update를 어느 형식의 master weight에 더하는가? |
| 전송 형식 | Device·node 사이에서 몇 byte를 보내는가? |
| 결과 계약 | Bitwise 일치, loss·accuracy 허용치, latency 중 무엇을 유지해야 하는가? |

같은 model에서도 역할별 형식을 다르게 쓰는 것이 **혼합 정밀도**(mixed precision)다. 연속값을 적은 수의 code와 scale로 근사하는 것이 **양자화**(quantization)다. 둘은 겹칠 수 있지만 같은 절차가 아니다.

### Memory 절감과 가속은 자동으로 같지 않다

FP32 weight를 4-bit code로 저장하면 이론적인 raw weight byte는 원소당 4 byte에서 0.5 byte로 줄 수 있다. 그러나 scale·zero point·codebook metadata가 더해지고, 계산 전에 더 넓은 형식으로 dequantize할 수 있으며, activation·KV cache·temporary buffer는 다른 형식을 쓸 수 있다.

따라서 checkpoint가 8분의 1이라는 근사에서 end-to-end memory나 latency가 8분의 1이라고 결론 내리지 않는다. Hardware가 해당 low-bit kernel을 효율적으로 지원하고 dequantization·memory traffic 감소가 다른 비용보다 커야 실제 속도 이득이 된다.

## 2단계 — 작동 원리

### 혼합 정밀도 학습은 역할을 나눈다

Micikevicius 등의 2018년 구성은 FP16 weight·activation·gradient를 사용하면서 FP32 master weight를 유지하고, 일부 누산을 FP32로 수행하며 loss scaling으로 작은 gradient가 FP16 범위 아래로 사라지는 위험을 줄였다.

간단히 loss $L$에 scale $s>1$을 곱해 backward하면

$$
\nabla_\theta(sL)=s\nabla_\theta L
$$

이므로 gradient를 계산한 뒤 $s$로 다시 나눌 수 있다. 작은 값이 중간 FP16 표현에서 0으로 반올림되는 것을 줄이는 장치다. $s$가 너무 크면 overflow가 생길 수 있어 finite 여부를 확인하고 scale을 조정해야 한다.

FP32 master weight는 작은 update가 FP16 눈금에서 사라지는 것을 막는다. Model forward에 쓰는 낮은 형식과 optimizer가 갱신을 누적하는 형식을 분리하는 것이다. 모든 연산을 FP16으로 바꾸는 단순 치환이 아니다.

### 선형 양자화는 scale과 code를 정한다

실수 $x$를 정수 code $q$로 근사하는 대표적인 affine 양자화는

$$
q=\operatorname{clip}\left(
\operatorname{round}\left(\frac{x}{s}\right)+z,
q_{\min},q_{\max}
\right)
$$

로 쓸 수 있다. $s>0$은 scale, $z$는 zero point다. 복원값은

$$
\hat x=s(q-z)
$$

이다. 서로 다른 $x$가 같은 $q$로 반올림될 수 있으므로 일반적으로 $\hat x=x$가 아니다. Scale을 tensor 전체에 하나 둘지 group·channel마다 둘지, outlier를 어떻게 다룰지는 오차와 metadata·kernel 비용의 공학적 선택이다.

Bit 수가 같아도 code가 균등 간격인지, codebook을 쓰는지, weight만 양자화하는지 activation도 양자화하는지에 따라 방법이 다르다. “4-bit”는 하나의 algorithm 이름이 아니다.

### QLoRA는 저장과 계산 형식을 다시 분리한다

QLoRA는 pretrained base weight를 4-bit NormalFloat(NF4)로 저장하고 동결한다. Forward와 backward에서 base block을 BF16 등 계산 형식으로 dequantize해 행렬곱에 사용하며, 학습되는 값은 별도의 LoRA adapter다.

즉 다음 세 값을 구분한다.

1. **Base 저장:** 4-bit NF4 code와 quantization metadata
2. **Base 계산:** 더 넓은 compute dtype으로 dequantized된 값
3. **학습 parameter:** LoRA의 낮은 rank matrix와 optimizer state

QLoRA는 4-bit base weight 전체에 gradient update를 직접 적용하는 방법이 아니다. Double quantization은 quantization constant 자체의 memory를 줄이고, paged optimizer는 unified memory를 이용해 긴 sequence batch의 peak memory spike를 다루는 별도 장치다.

### 낮은 정밀도는 수치 경로를 바꾼다

덧셈은 결합 법칙이 실수 수학에서는 성립해도 유한 정밀도에서는 연산 순서에 따라 반올림이 달라질 수 있다. Parallel reduction, tensor core 누산과 quantized dequantization은 bitwise 결과를 바꿀 수 있다. 그래서 결과 계약을 다음처럼 나눈다.

- 같은 bit pattern
- 정한 수치 오차 이내
- 같은 loss·accuracy 범위
- 같은 task quality threshold
- 같은 latency·memory 목표를 만족

혼합 정밀도 논문과 QLoRA의 주장은 주로 model quality를 정한 실험 범위에서 유지하며 memory·성능 이득을 얻는다는 것이다. 모든 입력에 대한 bitwise 동일성을 보장하지 않는다.

## 3단계 — 기술과 근거

### Mixed Precision Training의 측정 장부

| 항목 | 기록 |
| --- | --- |
| 작업 | CNN·RNN·GAN 등의 supervised·generative model 학습 |
| 규모 | 논문별 model·batch와 지원 GPU |
| 결과 계약 | FP32 baseline과 비교한 model accuracy·quality |
| 시스템 경계 | Forward·backward·optimizer를 포함한 학습 |
| 고정 조건 | FP16 storage/compute, FP32 master weight·누산, loss scaling |
| 지표 | Memory footprint, throughput·시간, model quality |

논문은 memory를 거의 절반으로 줄일 수 있고 지원 연산기에서 속도 이득을 얻을 수 있음을 보였다. “항상 정확히 2배 빠르다”거나 모든 optimizer state까지 절반이라는 뜻은 아니다.

### QLoRA 65B의 측정 장부

| 항목 | 기록 |
| --- | --- |
| 작업 | 동결한 quantized base에 LoRA를 붙인 instruction fine-tuning |
| 규모 | 최대 65B parameter base, 단일 48GB GPU 사례 |
| 결과 계약 | 논문의 16-bit fine-tuning·LoRA 비교와 MMLU·chat 평가 |
| 시스템 경계 | Base storage·dequantized compute·adapter training의 peak GPU memory |
| 고정 조건 | NF4, double quantization, paged optimizer, LoRA target·rank와 compute dtype |
| 지표 | Peak memory, 학습 가능 model 크기, benchmark·사람/자동 평가 |

65B를 48GB에서 학습했다는 문장은 모든 65B model·sequence·batch가 48GB에 들어간다는 일반식이 아니다. QLoRA paper의 model, adapter, gradient checkpointing, batch와 implementation 조건이 포함된 결과다.

### 세 절감 전략을 분리한다

| 전략 | 주로 줄이는 장부 | 수학·품질 경계 | 남는 비용 |
| --- | --- | --- | --- |
| Mixed precision | 원소당 byte와 지원 matrix 연산 시간 | Rounding·range, loss scaling·master weight | 넓은 state·누산, 불안정 감시 |
| Quantization | Weight·activation·cache의 저장·이동 byte | $\hat x\ne x$, calibration·fine-tuning 품질 | Scale metadata, dequantization·low-bit kernel |
| Sparse activation | Token당 실행 expert FLOPs | Router·capacity·load balance와 quality | Total weight memory, AllToAll 통신 |

[[전문가 혼합]]은 숫자의 bit를 줄이는 방법이 아니다. Token마다 일부 expert만 실행해 active compute를 줄일 수 있지만 전체 expert weight는 저장해야 한다. 낮은 정밀도와 MoE를 결합하면 storage, active FLOPs, communication과 품질을 각각 기록해야 한다.

### CS_WIKI와 함께 읽기

[CS_WIKI의 「낮은 정밀도는 AI의 컴퓨팅 능력을 어떻게 바꾸는가」](https://yghnsim.github.io/CS_Wiki/analyses/%EB%82%AE%EC%9D%80-%EC%A0%95%EB%B0%80%EB%8F%84%EB%8A%94-ai%EC%9D%98-%EC%BB%B4%ED%93%A8%ED%8C%85-%EB%8A%A5%EB%A0%A5%EC%9D%84-%EC%96%B4%EB%96%BB%EA%B2%8C-%EB%B0%94%EA%BE%B8%EB%8A%94%EA%B0%80/)는 bit 수·throughput·에너지·유효 결과를 하나의 성능 계약으로 읽는 컴퓨터사 맥락을 제공한다. 현재 문서는 그 틀을 mixed precision과 QLoRA의 정확한 값 경로에 적용한다.

## 검증과 한계

- **직접 영향:** Mixed Precision Training은 FP16과 FP32 역할 분담·loss scaling을 제시했고, QLoRA는 frozen NF4 base와 BF16 계산·LoRA 학습을 명시했다.
- **가능 조건:** 낮은 정밀도 tensor 연산을 지원하는 accelerator와 kernel은 memory 절감을 wall-clock 이득으로 바꾸는 조건이다. Bit 수만으로 속도를 보장하지 않는다.
- **병행 맥락:** Memory wall과 Roofline은 byte 이동 감소의 가치를 설명하지만, 1995·2009년 문헌이 QLoRA 설계에 직접 영향을 주었다고 주장하지 않는다.
- **후대 유추:** 오늘날 FP8·새 quantizer의 결과를 2018 mixed precision이나 2023 QLoRA 성과에 소급하지 않는다.

이 문서는 IEEE 부동소수점 표준 전체, stochastic rounding, quantization-aware training과 모든 post-training quantizer를 다루지 않는다. Hardware·compiler가 low-bit 형식을 내부에서 어떻게 변환하는지도 구현별로 확인해야 한다. 특히 perplexity나 몇 개 benchmark가 같다는 사실은 긴 tail 입력·안전성·calibration까지 같음을 보장하지 않는다.

## 학습 확인

1. “4-bit model”이라는 말만으로 저장 memory와 연산 속도를 알 수 없는 이유를 base weight·metadata·compute dtype·activation으로 설명하라.
2. Mixed precision의 FP32 master weight와 loss scaling은 각각 어떤 정보 손실을 줄이는가?
3. 새 quantizer가 checkpoint를 4배 줄이고 latency를 10%만 줄였다. 여섯 항목 측정 장부에서 dequantization, activation·KV cache와 hardware kernel을 어떻게 확인할지 적어라.
