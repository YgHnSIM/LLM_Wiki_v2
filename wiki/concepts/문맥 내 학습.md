# 문맥 내 학습

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[concept.자기회귀-생성|자기회귀 생성]], [[concept.언어-모델-전이-학습|언어 모델 전이 학습]]<br>
> **읽고 나면:** 문맥 내 학습에서 무엇이 입력으로 바뀌고 무엇이 고정되는지 설명하며, zero-shot·one-shot·few-shot·fine-tuning을 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 한 문장 정의

문맥 내 학습(in-context learning, ICL)은 사전 학습된 언어 모델의 매개변수를 갱신하지 않고, **현재 입력 문맥에 놓인 지시와 demonstration을 조건으로 새 query의 출력을 바꾸는 방식**이다. 2020년 GPT-3 논문은 사전 학습을 바깥 고리, forward pass 안의 문맥 적응을 안쪽 고리로 보는 meta-learning 관점에서 이 용어를 체계화했다.

여기서 ‘학습’은 모델 가중치가 영구히 바뀐다는 뜻이 아니다. prompt를 치우면 과제별 상태도 보통 사라진다. 관찰되는 것은 같은 가중치가 입력 sequence에 따라 다른 조건부 분포를 만든다는 사실이다.

### 인접 개념과 구분한다

| 방식 | 과제 정보가 들어가는 위치 | 추론 중 가중치 갱신 | 과제별 변화의 지속성 |
|---|---|---:|---|
| zero-shot prompting | 자연어 지시 | 없음 | 현재 context |
| one-shot prompting | 지시와 예시 1개 | 없음 | 현재 context |
| few-shot prompting | 지시와 예시 여러 개 | 없음 | 현재 context |
| 지시 미세조정 | 여러 과제의 지시–target loss | 앞선 학습 단계에서 있음 | instruction-tuned checkpoint |
| fine-tuning | 표지 자료의 loss와 optimizer | 있음 | 새 checkpoint·adapter 등에 지속 |

문맥 내 학습과 few-shot은 완전한 동의어가 아니다. Few-shot은 demonstration 수가 적은 한 평가 조건이고, 넓은 의미의 문맥 내 학습에는 demonstration 없는 zero-shot 조건이나 예시 수를 늘린 조건도 포함할 수 있다. 문서에서 어느 정의를 쓰는지 밝히는 편이 안전하다.

## 2단계 — 작동 원리

### 지시·예시·query를 한 sequence로 만든다

가장 단순한 prompt는 다음 세 부분을 잇는다.

1. **instruction:** 무엇을 출력할지 자연어로 설명한다.
2. **demonstration:** 입력과 기대 출력의 형식을 하나 이상 보여 준다.
3. **query:** 같은 형식으로 새 입력을 주고 출력을 비워 둔다.

예를 들어 감성 분류에서는 `문장 → 긍정/부정` 쌍을 몇 개 제공한 뒤 새 문장의 label을 생성하게 할 수 있다. 이때 예시는 새 model을 훈련하는 mini-batch가 아니라, 다음 token 분포를 계산할 현재 sequence의 일부다.

### 고정된 가중치로 다음 token을 조건화한다

지시와 $k$개 demonstration을 $c_k$라 하고 새 입력을 $x_*$라 하자. 고정된 매개변수 $\theta$는 출력을 다음처럼 생성한다.

$$
p(y_*\mid c_k,x_*;\theta)
=\prod_t p(y_{*,t}\mid c_k,x_*,y_{*,<t};\theta)
$$

$k=0$이면 zero-shot, $k=1$이면 one-shot, $k>1$이면 few-shot 조건이 된다. 모델 내부에서는 [[Transformer]]의 attention과 MLP가 문맥 표현을 바꾸지만, 역전파·optimizer step·checkpoint 저장은 일어나지 않는다.

### 출력은 task뿐 아니라 평가 규칙에도 의존한다

같은 과제라도 prompt 문구, demonstration의 선택·순서·label 단어와 delimiter가 달라지면 조건부 분포가 달라질 수 있다. 다지선다에서는 생성 문자열 대신 후보별 likelihood를 비교할 수 있고, 답 길이를 보정할지 여부도 결과를 바꾼다. 자유 생성에서는 exact match, F1, BLEU처럼 어떤 metric을 적용하는지가 성능의 의미를 정한다.

따라서 ICL 성능을 비교할 때는 최소한 model checkpoint, context length, instruction, demonstration pool·수·순서, decoding·scoring과 metric을 함께 기록해야 한다. “예시 몇 개를 줬다”만으로는 재현 가능한 실험 조건이 되지 않는다.

### CoT는 demonstration과 답 추출 조건을 바꾼다

Few-shot [[사고 연쇄 프롬프팅|CoT]]는 별도의 학습법이 아니라, demonstration의 출력을 `정답`에서 `중간 단계 + 정답`으로 확장한 ICL 조건이다. 반면 Zero-shot-CoT는 demonstration을 주지 않고 짧은 유도 문구로 풀이를 생성한 뒤, 그 풀이를 다시 문맥에 넣어 최종 답을 뽑는 2단계 절차다. 두 방식 모두 가중치는 고정되지만 prompt가 관측되는 능력·오류 표면과 출력 token 비용을 바꾼다. 따라서 ICL 평가 조건에는 rationale 예시·생성 여부, answer-extraction prompt·parser, 출력 token 수·지연·비용까지 포함해야 한다.

## 3단계 — 기술과 근거

### GPT-3가 체계화한 평가 축

[[067_GPT-3와 문맥 내 학습]]은 125M부터 175B까지 여덟 model size를 모두 300B token으로 학습하고, 같은 과제에서 zero-shot·one-shot·few-shot을 비교했다. Few-shot은 2,048-token context에 들어가는 예시를 보통 10–100개 사용했다. 모든 조건에서 과제별 gradient update는 없었고, GPT-3 자체의 fine-tuning은 평가하지 않았다.

42개 accuracy benchmark의 집계에서는 model size가 커질수록 세 조건이 대체로 좋아졌고, few-shot 곡선이 더 빠르게 상승하는 경향이 보였다. 이는 큰 모델이 문맥 정보를 더 효과적으로 활용한다는 관찰을 지지한다. 하지만 이 집계는 서로 다른 dataset과 metric을 묶은 휴리스틱 요약이며, 논문도 단일한 엄격 benchmark로 보지 말라고 경고했다.

### 과제에 따라 이득이 달랐다

Closed-book TriviaQA에서 175B GPT-3는 zero-shot 64.3%, one-shot 68.0%, few-shot 71.2%로 예시가 늘수록 개선됐다. 반면 SuperGLUE few-shot 평균은 71.8로 fine-tuned BERT-Large 69.0보다 높았지만 당시 fine-tuned 최고 성능 89.0보다 낮았다. 과제 안에서도 COPA·ReCoRD와 WiC·MultiRC의 결과가 크게 달랐다.

산술 exact match는 규모와 자리수에 특히 민감했다. 175B few-shot은 2자리 덧셈 100.0%, 3자리 덧셈 80.4%였지만 4자리 25.5%, 5자리 9.3%로 떨어졌다. 13B에서 175B 사이의 큰 점프는 특정 평가에서 threshold처럼 보일 수 있으나, 일반 계산 능력이나 다른 metric의 불연속성을 자동으로 뜻하지 않는다.

### 지시 미세조정과 문맥 내 학습은 결합할 수 있다

[[지시 미세조정]]은 inference instruction을 쓰더라도 ICL과 adaptation 위치가 다르다. [[072_지시 미세조정과 FLAN의 제로샷 일반화]]의 zero-shot FLAN은 여러 다른 과제의 instruction–target mixture로 전체 weights를 먼저 갱신하고, 보류 과제에는 demonstration 없이 instruction을 주었다. 별도 few-shot 조건은 학습 과제에서도 무작위 exemplar가 든 형식으로 모델을 미세조정했으며, 보류 과제의 exemplar만 inference에서 처음 제공했다.

보류 과제의 few-shot exemplar는 optimizer가 처리한 mini-batch가 아니라 현재 sequence의 일부이므로 그 추론 단계는 ICL이다. 그러나 그 전에 만든 checkpoint도 다른 과제의 exemplar 형식을 포함한 gradient update의 산물이다. 하나의 pipeline 안에서 `weights를 바꾼 few-shot-format instruction tuning`과 `보류 과제에서 weights를 고정한 in-context adaptation`이 연속해서 쓰였다고 말해야 하며, 같은 zero-shot checkpoint에 예시만 추가한 결과로 읽지 않는다.

### Flamingo는 demonstration에 image와 video를 더한다

[[Flamingo]]는 ICL의 문맥을 text-only sequence에서 image·video·text가 교차하는 prompt로 넓힌다. 사전 학습이 끝난 뒤 few-shot 평가에서는 시각 encoder, 언어 model과 두 모듈을 잇는 bridge의 weights를 모두 고정하고, support example의 시각 입력과 text를 query 앞에 배치한다. 각 image·video는 64개 visual token으로 압축되어 언어 token과 같은 vocabulary 항목이 되는 대신, gated cross-attention이 조회하는 별도 key/value memory로 남는다.

Open-ended 과제에서는 이 문맥을 조건으로 다음 text token을 생성하고, close-ended 과제에서는 후보 completion의 log-likelihood를 비교한다. 논문의 open-ended zero-shot 조건도 완전히 빈 prompt가 아니라 downstream 예시 두 개에서 visual input만 뺀 text-only example으로 출력 형식을 지정한다. Close-ended zero-shot은 후보 likelihood를 직접 비교하므로 이 text example을 넣지 않았다. Few-shot에서는 무작위 예시 외에 frozen visual feature로 query와 비슷한 image를 찾는 RICES를 사용할 수 있어, shot 수뿐 아니라 example selection도 평가 조건이다.

이 확장은 가중치 고정이라는 ICL의 경계는 유지하지만 문맥 비용과 민감성도 키운다. Example 순서·형식에 따라 결과가 달라지고, 2,048-token 길이로 학습된 언어 model에서 VisDial 32-shot prompt가 4,096–8,192 token으로 늘어나자 16-shot보다 상대 성능이 약 30% 낮아졌다. 따라서 multimodal ICL을 비교할 때는 visual example 수, 선택 방식, prompt 순서, context length와 open/closed-ended scoring을 함께 기록해야 한다.

### loss scaling과 ICL scaling은 별개다

[[언어 모델 스케일링 법칙]]은 주로 평균 token cross-entropy와 모델·데이터·compute 사이의 경험적 관계를 설명한다. 낮은 loss는 next-token probability가 평균적으로 개선됐다는 뜻이지만, 특정 prompt에서 정답 label 문자열을 생성하는 exact-match 정확도와 같은 값은 아니다.

GPT-3 논문은 validation loss가 매끄러운 power law를 이어 가는 동시에 downstream task 곡선은 서로 다른 모양을 보인다는 점을 보여 준다. ICL의 규모 효과를 말할 때는 underlying output distribution, prompt, metric과 관측한 model size를 분리해야 한다.

### meta-learning은 설명 틀이지 확인된 내부 알고리즘이 아니다

Brown 등은 language-model pretraining을 outer loop, 한 sequence 안의 task adaptation을 inner loop로 묘사했다. 그러나 “추론 시 새 task를 처음 학습한다”와 “사전 학습에서 접한 task·format을 알아본다”를 실험으로 판별하지 않았다. Meta-learning이라는 표현은 두 가능성을 포함하는 구조적 설명이었다.

후대 연구는 induction head, implicit regression, Bayesian inference 같은 여러 메커니즘을 제안했지만, GPT-3 원 논문 하나로 보편적인 ICL 알고리즘을 확정할 수 없다. 모델·층·과제·자료에 따라 서로 다른 회로와 휴리스틱이 같은 행동 표면에 기여할 수 있다.

## 검증과 한계

### 흔한 오해

- **ICL에는 과제별 자료가 전혀 없다:** few-shot prompt에는 label이 있는 demonstration이 들어가며, 예시 선택에도 비용이 든다.
- **ICL은 fine-tuning과 같은 학습을 forward pass에서 한다:** 두 방식은 출력 적응이라는 행동을 공유할 수 있지만, parameter update와 지속성이 다르다.
- **지시 미세조정 model의 zero-shot은 ICL과 같은 무학습 조건이다:** 현재 task의 demonstration은 없지만 다른 task의 지도 mixture가 이미 weights를 바꿨다.
- **큰 모델이면 모든 과제에서 ICL이 fine-tuning을 이긴다:** GPT-3의 SuperGLUE·ANLI·RACE·QuAC 결과가 이 일반화를 반박한다.
- **prompt에 맞춘 출력은 새 규칙을 이해했다는 증거다:** pattern recognition, memorization, heuristic과 새 task learning을 구분하려면 별도 개입과 분포 밖 평가가 필요하다.
- **급격한 정확도 상승은 곧 본질적인 창발이다:** [[손실 곡선과 능력 곡선 사이]]에서 비교하듯 비선형 metric, prompt, 표본화한 model scale과 바닥 효과가 곡선 모양에 영향을 줄 수 있다.

### 문맥의 제약

Demonstration은 context window를 사용하므로 예시 수가 늘면 query·배경 지식에 쓸 token이 줄어든다. 예시 순서와 label frequency가 편향을 만들 수 있고, 긴 prompt는 inference 비용과 지연도 늘린다. CoT처럼 rationale을 추가하면 사람이 검사할 중간 표면은 늘지만 그만큼 생성 token과 답 추출 실패 가능성도 늘어난다. ICL은 과제별 훈련 run을 줄일 수 있지만 반복 요청에서 항상 가장 싼 적응 방식이라고 보장되지 않는다.

또한 prompt는 모델이 사전 학습에서 얻은 지식과 편향을 조건화할 뿐, 외부 사실을 검증하거나 출처를 제공하지 않는다. 최신 지식·근거가 필요한 과제에서는 retrieval, tool use나 별도 검증이 필요할 수 있고, 안정적인 좁은 행동에는 fine-tuning이나 다른 parameter adaptation이 더 적합할 수 있다.

### 오염과 평가 독립성

인터넷 규모 사전 학습 자료에는 benchmark item이나 매우 비슷한 text가 포함될 수 있다. GPT-3 연구는 overlap 제거 bug 뒤 13-gram 기준 clean subset을 만들어 사후 비교했고 대부분 결과 차이가 작다고 보고했다. 그러나 이는 특정 검사에서 큰 차이를 찾지 못했다는 뜻이지, 모든 demonstration-free 성능이 순수한 unseen-task 일반화임을 보증하지 않는다.
