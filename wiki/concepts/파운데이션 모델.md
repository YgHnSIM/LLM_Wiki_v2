# 파운데이션 모델

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[언어 모델 전이 학습]]<br>
> **읽고 나면:** 파운데이션 모델을 큰 언어 모델·완성된 AI 제품과 구분하고, 공통 기반의 훈련·적응·배포 과정에서 이익과 결함이 전파되는 방식을 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 한 문장 정의

**파운데이션 모델(foundation model)**은 광범위한 데이터로 대규모 훈련한 뒤 다양한 후속 과제에 적응할 수 있어, 여러 AI 응용의 공통 기반 역할을 하는 모델이다.

‘foundation’은 이 모델이 여러 응용에서 중심적인 기반이면서도 그 자체로 완성된 사용자 시스템은 아니라는 뜻을 함께 담는다. ‘AI의 근본 원리’를 뜻하는 foundational model이라는 표현과 구분한다.

### 크기보다 역할을 본다

[[대규모 언어 모델]]은 주로 text data, language-modeling objective와 model scale을 가리킨다. 파운데이션 모델은 modality가 아니라 여러 downstream application의 기반으로 재사용되는 **기능과 위치**를 가리킨다.

그래서 많은 LLM은 파운데이션 모델이지만 두 용어는 동의어가 아니다. [[CLIP]] 같은 image–text model도 여러 image task에 적응되면 파운데이션 모델이 될 수 있다. 반대로 model이 크다는 사실만으로 여러 응용의 기반 역할이 입증되지는 않는다.

### 왜 중요한가

하나의 기반을 여러 응용이 공유하면 개선과 결함의 전파 범위가 커진다. Base model을 더 효율적이고 견고하게 만들면 여러 파생 모델이 이익을 받을 수 있다. 같은 구조는 bias·security vulnerability·data omission을 많은 응용에 퍼뜨리는 단일 실패점도 만든다.

따라서 파운데이션 모델은 model architecture만의 개념이 아니다. Data 생산·수집, compute와 학습, model access, 적응, 배포와 실제 영향이 연결된 사회기술적 생태계를 분석하는 단위다.

## 2단계 — 작동 원리

### 훈련에서 배포까지 다섯 계층

파운데이션 모델 기반 system은 다음 계층으로 나눠 볼 수 있다.

| 계층 | 핵심 입력과 결정 | 대표 결과 |
|---|---|---|
| Data 생산·큐레이션 | 누가 만든 어떤 자료를 수집·제외·가공하는가 | Pretraining corpus |
| 기반 훈련 | Objective, architecture, compute와 optimizer를 어떻게 정하는가 | Foundation checkpoint |
| 적응 | Task data·instruction·prompt·adapter로 무엇을 바꾸는가 | Adapted model 또는 task behavior |
| 시스템 조립 | Retriever·tool·memory·filter·UI를 어떻게 결합하는가 | 사용자용 application |
| 배포 | 어느 domain과 사용자에게 어떤 규칙으로 적용하는가 | 실제 효용과 harm |

이 구분은 책임을 한곳에 몰지 않게 한다. 기반 model의 공통 결함을 무시하면 하위 응용마다 같은 문제를 반복해 고치게 된다. 반대로 실제 deployment failure를 모두 base model 탓으로 돌리면 adaptation data와 domain decision의 기여를 놓친다.

### 적응은 한 가지 방법이 아니다

적응(adaptation)은 사전 학습 결과를 특정 과제나 사용 조건에 맞추는 과정이다.

- [[BERT]]는 하나의 pretrained encoder를 여러 과제에 전체 미세조정했다.
- GPT-3의 [[문맥 내 학습]]은 task-specific gradient update 없이 prompt의 지시와 예시로 출력을 조건화했다.
- [[CLIP]]은 자연어 class description을 image classifier weight처럼 사용해 zero-shot classification을 구성했다.
- [[지시 미세조정]]은 여러 과제의 instruction–target example로 model weight를 먼저 갱신한 뒤 보지 못한 과제를 지시로 지정한다.

이 방법들은 supervision이 들어가는 위치와 비용이 다르다. 파운데이션 모델은 이 가운데 하나를 정의 요건으로 선택하는 말이 아니라, 여러 적응 경로가 공통 기반을 재사용하는 관계를 묶는 상위 개념이다.

### 창발과 동질화

CRFM 보고서는 파운데이션 모델의 의미를 창발(emergence)과 동질화(homogenization)로 요약했다.

- **창발:** 사람이 task behavior를 규칙으로 직접 구성하지 않고 학습 과정에서 암묵적으로 유도한다. 예상 밖 능력과 실패를 사후 평가해야 한다.
- **동질화:** 여러 application이 같은 방법뿐 아니라 같은 pretrained model까지 공유한다. 개선을 재사용하는 지렛대와 결함이 퍼지는 공통 실패점을 함께 만든다.

2021년의 창발은 특정 parameter 임계점에서 benchmark score가 갑자기 나타난다는 좁은 주장보다 넓다. 능력 곡선의 불연속을 주장하려면 별도로 task·metric·prompt·model family·scale sample을 고정해야 한다.

### 내재 평가와 외재 평가

내재 평가(intrinsic evaluation)는 적응 전 base model의 representation·behavior·bias 같은 성질을 조사한다. 외재 평가(extrinsic evaluation)는 특정 task로 적응한 뒤 실제 성능과 harm을 측정한다.

둘은 연결되지만 같지 않다. 내재 bias가 harm 가능성을 알릴 수 있어도 어느 집단이 어떤 불이익을 받는지는 application context에서 확인해야 한다. Base model끼리 비교할 때도 adaptation data·access와 compute budget이 다르면 결과 원인을 분리하기 어렵다.

## 3단계 — 기술과 근거

### 정의의 네 요소

Bommasani 등 §1의 정의는 다음 요소를 결합한다.

1. **광범위한 데이터:** 단일 downstream dataset보다 넓은 raw data를 사용한다.
2. **대규모 학습:** 큰 data와 compute를 사용하며 일반적으로 self-supervision으로 pretraining한다.
3. **여러 후속 과제:** 하나의 checkpoint가 하나보다 넓은 task 집합의 출발점이 된다.
4. **적응 가능성:** Fine-tuning 같은 개입으로 task-specific system을 만든다.

‘일반적으로’ 자기지도 학습을 쓴다는 말은 모든 파운데이션 모델이 같은 objective를 가져야 한다는 뜻이 아니다. ‘광범위함’과 ‘대규모’에도 보편적인 수치 경계는 없다. 이 개념은 엄밀한 parameter threshold보다 생태계에서의 역할을 분류한다.

### 한 모델과 많은 모델

하나의 foundation checkpoint를 $F$라고 하고, 과제 $i$의 적응 연산을 $A_i$라고 하면 파생 모델은 다음처럼 표시할 수 있다.

$$
M_i=A_i(F;D_i,R_i).
$$

$D_i$는 적응 data, $R_i$는 compute·access·prompt 같은 적응 자원이다. 같은 $F$를 공유해도 $A_i$, $D_i$와 $R_i$가 다르면 $M_i$의 성능과 위해는 달라진다.

실제 응용은 다시 retriever·tool·policy·interface를 포함한 system $S_i$ 안에 $M_i$를 넣는다. 이 간단한 표기는 foundation model이 중요하지만 완성된 AI system의 유일한 원인은 아니라는 경계를 보여 준다.

### 공유 결함은 자동으로 같은 결과를 만들지 않는다

기반 layer의 문제는 여러 파생 모델이 공유할 가능성이 있다. 그러나 adaptation은 결함을 증폭·완화하거나 새로운 결함을 만들 수 있다. Deployment domain도 같은 model output에 다른 의미와 위험을 부여한다.

그래서 평가 장부에는 적어도 foundation checkpoint, adaptation method·data·budget, system component와 deployment context를 함께 적는다. [[AI 시연과 실제 성능]]이 model demo와 완성된 product behavior를 구분하는 이유도 같다.

### 재사용과 접근의 비용 장부

Pretrained checkpoint를 재사용하면 매 응용이 처음부터 큰 model을 훈련할 필요는 줄어든다. 그러나 비용이 사라지는 것이 아니라 기반 계층으로 이동하고 여러 응용에 나뉘어 상각된다.

Weight가 공개되지 않거나 API access가 제한되면 외부 개발자는 가능한 adaptation과 audit 범위가 좁아진다. Open-weight여도 inference hardware, domain data와 engineering expertise가 필요하다. ‘적응 비용 절감’과 ‘개발 권력 민주화’를 같은 주장으로 쓰지 않는다.

### 사회기술적 위험

CRFM 보고서는 불평등과 fairness, misuse, environmental impact, law, economics와 ethics of scale을 기술 장과 같은 수준에서 다뤘다. Model이 중간 자산이므로 책임 경계도 provider와 application developer 사이에 걸쳐 있다.

환경 장부에는 큰 일회성 training뿐 아니라 반복 inference와 배포 비용도 들어간다. 반면 하나의 training run을 여러 application이 공유하면 비용을 상각할 수 있다. 정확한 비교에는 energy뿐 아니라 grid carbon intensity, hardware efficiency와 사용량이 필요하다.

## 검증과 한계

### 흔한 오해

- **파운데이션 모델은 매개변수가 매우 큰 LLM이다:** LLM과 겹치지만 정의의 중심은 downstream 기반 역할이다.
- **모든 언어·영역·양식을 학습해야 한다:** Broad data는 상대적인 범위이며 모든 modality 포함을 요구하지 않는다.
- **Prompt만으로 여러 task를 해야 한다:** Fine-tuning도 보고서가 명시한 적응이다.
- **Foundation은 AI의 근본 원리라는 뜻이다:** Model의 역할과 불완전성을 강조하는 이름이지 AI 전체의 토대라는 선언이 아니다.
- **기반 model score가 곧 제품 성능이다:** Adaptation·retrieval·tool·filter·interface와 deployment가 결과를 바꾼다.
- **재사용하면 자동으로 민주화된다:** Task별 training cost는 낮출 수 있지만 model access와 compute ownership은 더 집중될 수 있다.
- **공통 결함은 모든 응용에서 같은 harm을 만든다:** 결함 전파 가능성과 실제 context-specific harm은 별도로 측정해야 한다.
- **2021년 창발은 불연속 능력 곡선의 뜻이다:** 당시 보고서는 명시적으로 구성되지 않은 행동이라는 더 넓은 의미를 썼다.

### 범주의 경계

Definition에는 data breadth·compute scale·task range의 수치 threshold가 없다. 같은 이름 아래 BERT, GPT-3와 CLIP처럼 architecture·objective·access가 다른 model이 들어간다. 공통 생태계를 분석하는 데는 유용하지만 구체적인 기술 비교에서는 각 차이를 다시 펼쳐야 한다.

‘파운데이션 모델’이 후대에 널리 쓰였다는 사실만으로 이 범주가 자연적으로 주어진 것은 아니다. 이름은 무엇을 함께 연구할지 정하는 편집적 선택이다. 특정 대규모 pretraining regime을 중심에 놓아 다른 AI 접근과 관련 역사를 덜 보이게 할 가능성도 검토해야 한다.

### 근거 범위

핵심 정의와 창발·동질화, 중간 자산과 내재·외재 평가는 CRFM 보고서 v3에 근거한다. BERT·GPT-3·CLIP은 서로 다른 adaptation 경로를 보이기 위한 각 원 논문의 사례다.

이 문서는 모든 후대 model이 실제로 하나의 공통 결함을 상속했거나, 파운데이션 모델이라는 용어가 특정 정책·투자를 인과적으로 바꿨다고 주장하지 않는다. 그러한 영향에는 별도의 수용사와 deployment 자료가 필요하다.
