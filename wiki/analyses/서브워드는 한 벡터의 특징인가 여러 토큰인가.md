# 서브워드는 한 벡터의 특징인가 여러 토큰인가

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[단어 임베딩]], [[서브워드 토큰화]]<br>
> **읽고 나면:** FastText의 문자 특징과 BPE·SentencePiece의 토큰 시퀀스가 문맥과 만나는 위치를 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 비교 질문과 잠정 결론

[[049_FastText와 서브워드 표현의 두 경로]]에서 FastText와 BPE를 함께 읽으면 둘 다 “단어를 조각으로 나누어 희귀어를 처리한다”는 한 문장으로 요약하기 쉽다. 그러나 이 문장은 조각이 모델에서 맡는 역할을 생략한다.

FastText의 문자 n-gram은 **한 단어 벡터를 계산하는 내부 특징**이다. BPE의 subword는 **모델이 순서대로 읽고 쓰는 여러 token**이다. SentencePiece는 그 token sequence를 만드는 **훈련·부호화 도구**다. 같은 subword라는 말 아래 특징, 시퀀스 단위, tokenizer 구현이라는 세 층이 섞여 있다.

독립적으로 물어야 할 질문은 “어느 방법이 단어를 더 잘 쪼개는가?”보다 다음에 가깝다.

> 문자열 조각은 어느 단계에서 결합되고, 결합되기 전후 어느 단위가 문맥과 상호작용하는가?

## 2단계 — 작동 원리

### 네 인터페이스를 같은 표에 놓기

| 방법 | 모델이 받는 sequence 단위 | 문자열 조각의 역할 | 결합 시점 | 문맥화 | 대표 희소성 대응 |
| --- | --- | --- | --- | --- | --- |
| 기본 SGNS | word type 하나 | 내부 조각 없음 | word lookup에서 한 벡터 | 정적 | 빈도 cutoff 밖은 표현 없음 |
| FastText | word token 하나 | 입력 word vector의 문자 n-gram 특징 | 문맥 점수 계산 전 합산 | 정적 | 공유 n-gram 합으로 OOV 근사 |
| BPE NMT | 여러 variable-length subword token | encoder·decoder의 독립 sequence position | 신경망 층 안에서 상호작용 | 모델 상태에 따라 문맥화 | 작은 기본 symbol과 merge 어휘 |
| SentencePiece | 선택 model이 만든 subword token | tokenizer의 출력 symbol | downstream model에 들어가기 전 | 도구 자체는 표현을 학습하지 않음 | raw text·공백·분절 규칙 관리 |

이 표는 “subword를 쓴다”가 하나의 구조 범주가 아님을 보여준다. FastText는 모델 입력 position 수를 유지하고, BPE는 position 수를 바꾸며, SentencePiece는 그 position을 만드는 인터페이스를 제공한다.

## 3단계 — 기술과 근거

### 기본 SGNS에서 공유되지 않는 것

기본 Skip-gram with negative sampling에서 중심 word type $w$와 문맥 word type $c$는 별도 입력·출력 벡터를 가진다. 한 양성 쌍의 대표 목적은 다음과 같다.

$$
\log\sigma(u_w^\top v_c)
+\sum_{i=1}^{k}\log\sigma(-u_w^\top v_{n_i})
$$

“running”과 “runner”가 철자를 공유해도 $u_{\text{running}}$과 $u_{\text{runner}}$는 독립 parameter다. 두 단어가 비슷해지는 근거는 주로 문맥 쌍이다. 희귀 굴절형마다 관측이 흩어지면 각 벡터가 받는 직접 신호도 줄어든다.

### FastText: 조각을 먼저 합하고 문맥과 한 번 상호작용하기

FastText는 중심 단어의 입력 벡터를 문자 n-gram 벡터 합으로 바꾼다.

$$
u_w=\sum_{g\in G_w}z_g,\qquad
s(w,c)=u_w^\top v_c
$$

문자 조각 각각이 sequence position을 차지하지 않는다. 모든 $z_g$를 더한 뒤 word-level 문맥 벡터 $v_c$와 점수를 계산한다. 한 n-gram은 그것을 포함하는 여러 중심 단어의 gradient를 공유하므로 드문 단어가 더 흔한 철자 패턴의 신호를 빌릴 수 있다.

이 구조에서는 같은 단어가 한 문장에 나타날 때마다 기본적으로 같은 합성 벡터를 갖는다. 주변 문맥은 벡터를 학습하는 통계지만 추론 시 단어 감각별 벡터를 새로 만들지는 않는다. “bank” 안 문자 조각이 금융·강둑 의미를 별도 position에서 추론하지 않는다.

관측 단어에는 완전한 단어의 특별 항목도 포함된다. 따라서 FastText는 순수하게 접사만 조합하는 모형이 아니다. word-specific signal과 공유 철자 signal을 한 합에 넣는다.

### BPE: 조각을 펼친 뒤 각각 문맥과 상호작용하기

Sennrich 등의 BPE NMT는 단어를 여러 variable-length symbol로 바꾼다. 가장 빈번한 인접 symbol pair를 반복 병합해 어휘를 만들고, 드문 단어는 더 작은 조각의 열로 남긴다.

예를 들어 한 word가 세 subword로 분절되면 encoder에는 세 position이 생긴다. attention이나 recurrent state는 이 position들을 따로 읽을 수 있고, decoder도 여러 step에 걸쳐 출력한다. 의미 합성은 tokenizer가 세 벡터를 미리 더해 끝내는 것이 아니라 downstream network의 문맥 계산 안에서 일어난다.

이 차이는 정보 병목과 계산 비용을 함께 바꾼다.

- 더 작은 어휘는 embedding·출력 행렬과 희귀 symbol의 추정을 줄일 수 있다.
- 같은 문자열을 더 많은 position으로 펼치면 sequence가 길어진다.
- 조각마다 attention과 hidden-state 상호작용이 가능하지만 더 먼 위치를 연결해야 한다.
- 생성에서는 한 단어를 완성하는 데 여러 autoregressive step이 필요할 수 있다.

BPE merge는 압축 빈도로 선택되며 형태소 분석이 아니다. 형태 경계와 우연히 맞을 수 있지만 의미적으로 독립된 조각임을 보장하지 않는다.

### 같은 문자열 조각도 서로 다른 gradient를 받는다

FastText의 “ing” n-gram과 BPE vocabulary의 “ing” token이 표면상 같아도 학습 사건이 다르다.

- FastText n-gram 벡터는 그 조각을 포함한 중심 단어가 문맥 word를 예측할 때 다른 n-gram들과 함께 갱신된다.
- BPE token embedding은 그 token position이 번역·언어 모델의 sequence objective에 참여할 때 갱신된다.
- FastText 합에서는 어느 n-gram이 현재 문맥에서 중요한지 별도 attention으로 고르지 않는다.
- BPE token은 위치별 hidden state를 얻어 같은 표면 token도 주변 sequence에 따라 다른 표현이 될 수 있다.

따라서 두 방법의 공통점은 “문자열 조각 parameter를 여러 단어가 공유한다”는 수준이다. 무엇을 하나의 학습 사건으로 보고 어디서 조합하는지는 다르다.

### SentencePiece: 표현 모형이 아니라 경계 계약

SentencePiece는 raw sentence에서 subword model을 훈련하고 token ID로 encode한 뒤 다시 decode하는 틀이다. 공백을 meta symbol로 취급해 normalized text의 경계를 보존한다. BPE와 Unigram model 등 서로 다른 segmentation을 지원한다.

Unigram model은 한 vocabulary에서 가능한 여러 segmentation의 확률을 다룬다. subword regularization은 훈련 중 여러 분절을 표본화해 하나의 결정적 경계에 대한 과적합을 줄이려 한다. 이 과정도 token embedding이나 Transformer hidden state를 SentencePiece 자체가 학습한다는 뜻은 아니다.

tokenizer와 model 사이에는 경계 계약이 있다.

1. normalization이 어떤 문자를 같게 만드는가?
2. 공백·단어 경계를 복원할 수 있는가?
3. 기본 alphabet 또는 byte fallback이 어떤 문자열을 덮는가?
4. token ID와 model embedding 행렬이 같은 vocabulary version을 공유하는가?

이 계약이 어긋나면 좋은 언어 모형도 원문 구별을 잃거나 unknown token을 받는다.

### OOV를 세 문제로 나누기

“OOV 해결”도 최소 세 질문으로 나눠야 한다.

#### 1. 부호화 가능성

입력 문자열을 유한한 ID 열이나 벡터로 만들 수 있는가? FastText는 hash된 n-gram index를 만들 수 있고, character-complete 또는 byte-fallback tokenizer는 문자열을 token 열로 나타낼 수 있다.

#### 2. 통계적 신뢰도

그 index의 parameter가 충분히 학습됐는가? 보지 못한 FastText n-gram은 유용한 gradient가 없을 수 있고, BPE의 매우 드문 조각도 추정이 약하다. 형식적으로 표현된다는 사실이 정보량을 보장하지 않는다.

#### 3. 의미 추론

새 문자열이 가리키는 개념을 문맥에서 알아낼 수 있는가? FastText 정적 합은 철자 유사성에 의존한다. BPE 기반 contextual model은 주변 문맥을 활용할 수 있지만 새 사실·이름의 지시 대상을 자동으로 아는 것은 아니다.

이 세 층을 합치면 “unknown token이 없으므로 OOV 문제가 해결됐다”는 과장이 생긴다.

### 문자 단위도 전처리에서 이미 결정된다

문자 n-gram이나 character-initialized BPE에서 “문자”는 중립적인 자연 단위가 아니다. Unicode normalization, 대소문자, 악센트, 공백, 완성형 음절과 분해 자모, byte 변환이 기본 symbol을 바꾼다.

한국어에서 “한”을 한 개의 완성형 음절로 볼지 ㅎ·ㅏ·ㄴ에 대응하는 자모 열로 정규화할지에 따라 공유되는 n-gram과 sequence 길이가 달라진다. 어느 쪽이 항상 낫다는 결론은 없고 말뭉치·과제·오류 유형을 함께 평가해야 한다.

### 비교 읽기 체크리스트

새 subword 방법을 볼 때 다음을 확인한다.

1. 조각이 feature인가 sequence token인가?
2. tokenizer와 representation model 가운데 무엇을 학습하는가?
3. 조각을 합하는 시점은 문맥 계산 전인가, 신경망 층 안인가?
4. word-specific parameter와 공유 subword parameter를 함께 쓰는가?
5. OOV 주장은 부호화 가능성·통계적 신뢰도·의미 추론 중 무엇을 뜻하는가?
6. 기본 symbol과 normalization은 무엇인가?
7. 어휘 크기 감소가 sequence 길이·메모리·생성 step에 주는 비용은 무엇인가?
8. 형태소와 일치한다는 평가는 실제 boundary 자료로 했는가, 예시 몇 개의 직관인가?

이 질문들은 “subword를 사용했다”는 분류보다 모델이 실제로 공유하고 계산하는 단위를 더 정확히 보여준다.

## 검증과 한계

### 확인된 사실, 비교 해석, 입증되지 않은 계보

확인된 사실은 다음과 같다.

- 기본 SGNS는 word type별 입력·출력 벡터를 사용한다.
- FastText는 완전 단어 항목과 문자 n-gram 벡터를 합해 word-level 문맥 점수를 계산한다.
- 논문 구현은 n-gram을 고정 hash bucket에 사상한다.
- 2016년 BPE NMT는 문자·문자열 pair merge로 variable-length token sequence를 만든다.
- SentencePiece는 raw sentence에서 BPE·Unigram model을 다루는 tokenizer/detokenizer 틀이다.

비교 해석은 **subword 방법의 핵심 차이가 조각의 모양보다 조합 시점과 문맥 상호작용 단위에 있다**는 것이다. 이 관점은 character CNN, byte model, learned tokenizer를 읽을 때도 재사용할 수 있다.

입증되지 않은 것은 FastText가 BPE·SentencePiece·현대 LLM tokenizer의 직접 역사적 원인이라는 단일 계보다. BPE NMT는 2016년 발표됐고 FastText word-vector 논문은 2017년 출판되었다. 확인되는 것은 단어 원자성의 희소성 문제를 비슷한 시기에 서로 다른 인터페이스로 다뤘다는 사실이다.
