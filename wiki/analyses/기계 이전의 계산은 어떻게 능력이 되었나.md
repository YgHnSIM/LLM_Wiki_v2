# 기계 이전의 계산은 어떻게 능력이 되었나

> [!note] 학습 안내
> **난이도:** 입문 → 중급<br>
> **선수 지식:** 없음 — 수학 표, 인간 계산자, 작업표와 검산을 이 문서 안에서 처음 정의한다.<br>
> **읽고 나면:** 컴퓨팅 능력이 전자 장치의 연산률 이전에도 결과의 선계산·저장·배포, 작업 분해, 중간 상태 전달과 검산의 결합으로 만들어졌음을 설명하고, 이를 N-gram·embedding·LLM 계산과 직접 계보 없이 비교할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 계산은 머릿속 산술만이 아니었다

기계식·전자식 컴퓨터 이전에도 천문, 항해, 측량과 공학은 많은 수치 계산을 요구했다. 한 사람이 매번 처음부터 계산하는 대신 자주 쓰는 함수 값을 미리 구해 **수학 표(mathematical table)**로 인쇄했고, 여러 **인간 계산자(human computer)**가 정해진 절차와 작업표에 따라 연산을 나누어 수행했다.

이때 계산 능력은 세 층으로 만들어졌다.

1. **재사용:** 자주 필요한 값을 한 번 계산해 표에 저장하고 여러 사람이 조회한다.
2. **분업:** 복잡한 계산을 덧셈·뺄셈 같은 수행 가능한 단계로 나누고 사람·도구에 배분한다.
3. **검증·배포:** 중간값과 최종값을 독립적으로 확인하고, 편집·조판·인쇄해 같은 판본을 전달한다.

값을 계산했다는 사실만으로 사용 가능한 능력이 되지 않는다. 틀린 자릿수를 걸러 내고 사용자가 정확한 행을 찾을 수 있는 판본으로 배포해야 한다.

### 속도보다 먼저 비용의 위치를 바꿨다

수학 표는 계산을 없애지 않는다. 여러 사용자가 나중에 반복할 계산을 제작 조직이 미리 수행한다. 비용은 **사용 시점**에서 **표 제작 시점**으로, 개인에게서 중앙 조직으로 이동한다.

이 구조를 보여 주는 단순한 사고 실험을 해 보자. 사용자 $U=20$명이 같은 종류의 값을 각자 $r=50$번 필요로 하고, 직접 계산은 한 번에 $c=1$분, 표 조회는 $l=0.05$분이라고 하자. 표에 필요한 서로 다른 항목이 $M=100$개이고 검산·편집 비용이 $V=200$분이라면 직접 계산의 총시간은

$$
C_{\mathrm{direct}}=Urc=20\cdot50\cdot1=1000\text{분}
$$

이다. 표를 만드는 방식은

$$
C_{\mathrm{table}}=Mc+Url+V
=100\cdot1+20\cdot50\cdot0.05+200
=350\text{분}
$$

이다. 이 숫자는 역사적 프로젝트의 실측값이 아니라 비용 이동을 설명하는 예다. 사용자가 적거나 검산·출판비가 크면 표가 더 비쌀 수 있고, 자주 재사용될수록 선계산 비용을 나누어 부담할 수 있다.

## 2단계 — 작동 원리

### 결과를 저장하면 다음 사용자의 작업이 짧아진다

표의 한 행은 입력과 미리 계산한 출력의 쌍이다. 예를 들어 $x$와 $f(x)$를 여러 행에 적어 두면 사용자는 $f$를 다시 전개하지 않고 해당 $x$의 행을 찾는다. 입력이 표 사이에 있으면 보간이 필요할 수 있고, 범위를 벗어나면 표가 답하지 못한다.

따라서 표는 범용 계산기가 아니다. 다음 조건을 가진 유한한 재사용 장치다.

- 어떤 함수와 입력 범위를 미리 정한다.
- 정밀도와 반올림 자릿수를 고정한다.
- 값뿐 아니라 행·열 제목, 단위와 판본을 전달한다.
- 조회·보간 오류와 잘못된 판본 사용이 남는다.

“결과를 저장한다”는 선택은 빠른 조회와 좁은 적용 범위를 교환한다.

### 작업표는 사람 사이의 실행 인터페이스였다

대규모 계산에서는 모든 참여자가 전체 수학 이론을 다시 판단하지 않는다. 설계자는 공식을 고르고 초기값과 작업 순서를 정한다. 계산자는 작업표의 현재 값을 읽고 지정한 산술을 수행해 다음 칸에 쓴다. 감독자와 검산자는 예외와 불일치를 다른 경로로 보낸다.

이때 작업표는 단순 종이가 아니라 다음 정보를 전달하는 인터페이스다.

| 역할 | 전달하는 것 |
| --- | --- |
| 문제 설계 | 어떤 값과 정밀도가 필요한가 |
| 알고리즘 설계 | 어느 순서로 어떤 연산을 반복하는가 |
| 초기값 준비 | 반복 계산을 어디서 시작하는가 |
| 실행 | 현재 입력·중간값에서 다음 값을 계산하기 |
| 검산 | 독립 결과·일관성 조건과 비교하기 |
| 편집·출판 | 단위·표기·행 순서와 판본을 고정하기 |

조직은 CPU와 같지 않다. 사람은 의미를 이해하고 예외에 대응하며 권력·임금·교육의 사회적 조건 속에서 일한다. 비교할 수 있는 것은 복잡한 계산을 실행 가능한 단계와 전달 규칙으로 만든다는 구조다.

### 검산은 생산량의 일부다

같은 잘못된 공식을 두 사람이 반복하면 결과가 일치해도 참값은 아닐 수 있다. 그래서 독립적인 계산 경로, 차분·합계 같은 일관성 검사, 알려진 기준값, 원고와 교정쇄 대조를 조합해야 한다.

계산 항목 수만 센 처리량 $Q_{\mathrm{raw}}$와 검산을 통과한 항목 수를 센 $Q_{\mathrm{valid}}$를 구분하면

$$
Q_{\mathrm{raw}}=\frac{N_{\mathrm{computed}}}{T},\qquad
Q_{\mathrm{valid}}=\frac{N_{\mathrm{passed}}}{T}
$$

로 쓸 수 있다. 이는 당시 기관의 표준 지표가 아니라 오늘의 분석식이다. 공용 표의 실제 능력은 많이 계산한 항목보다 정한 품질 기준을 통과해 배포된 항목에 가깝다는 점을 보인다.

### 자동화는 오류 경계를 옮긴다

배비지는 반복 산술뿐 아니라 계산된 숫자를 활자로 옮기는 경계도 기계화하려 했다. 이 연결은 사람의 전사·조판 오류를 줄일 수 있다. 그러나 잘못된 초기값, 부적절한 방법, 기계 제작 결함이나 표 설계 오류를 없애지는 않는다.

자동화된 잘못은 더 빠르고 동일하게 복제될 수 있다. 그러므로 “사람이 빠졌다”보다 **어느 오류 접점이 줄고 어느 검증 책임이 남았는가**를 물어야 한다.

## 3단계 — 기술과 근거

### 드 프로니: 계산 완료와 사회적 사용은 달랐다

Ivor Grattan-Guinness가 분석한 1790년대 드 프로니 프로젝트는 로그·삼각함수표를 대규모 분업으로 계산했다. 계산은 1801년에 완료됐지만 방대한 출판 비용 때문에 전체 결과가 당시 널리 배포되지 못했다.

이 사례는 계산 가능성과 사용 가능성을 분리한다. 수학적으로 값을 만들 수 있고 조직이 계산을 끝냈어도 검산·편집·조판·자금·유통이 막히면 공용 인프라가 되지 못한다.

### 배비지: 계산에서 인쇄까지의 경계를 보았다

Charles Babbage의 1822년 발표문은 두 계의 차분을 쓰는 소형 기계로 제곱수, 삼각수와 $x^2+x+41$ 값의 표를 반복해 만들었다고 보고한다. 더 중요한 부분은 계산 결과가 정한 순서대로 활자를 배치하는 방법을 고안했다는 설명이다.

이는 완전한 차분 기관과 자동 인쇄소가 이미 운영됐다는 뜻이 아니다. 원문이 직접 확인하는 것은 소형 계산 장치의 시험과 자동 조판 구상이다. 배비지가 계획대로 구현된 인쇄본의 오류 가능성을 없앨 수 있다고 강하게 주장했지만, 설계·초기값·제작 오류까지 사라진다는 증명은 아니다.

### Mathematical Tables Project: 조직이 실행 환경이었다

NIST가 정리한 1938–1946년 Mathematical Tables Project는 삼각함수·지수·로그 등의 표 37권을 만들었고 peak 시점에 약 450명이 참여했다. Gertrude Blanch가 이끈 계획위원회는 알고리즘과 작업표를 만들었다. 대부분의 계산자는 덧셈을 수행했고, 더 적은 집단이 뺄셈·한 자리 곱셈·나눗셈 같은 다른 작업을 맡았다.

소수의 계산기계는 대다수 계산자의 반복 연산을 대신하기보다 책임자들이 초기값을 만들고 결과를 검증하는 데 사용됐다. 이 구성에서 memory는 작업표와 원고, control flow는 역할별 전달, error handling은 예외를 다른 집단으로 보내는 규칙에 일부 담겼다. 이것은 현대 기계 구조와의 **후대 유추**이지 동일한 architecture라는 역사적 주장에는 해당하지 않는다.

### 이 본편의 측정 장부

| 항목 | 기록 |
| --- | --- |
| 작업 | 로그·삼각함수·천문·항법 등에 재사용할 수치 항목을 계산·검산·출판하기 |
| 규모 | 서로 다른 표 항목 수, 반복 횟수, 계산자·검산자·장비와 판본 수 |
| 결과 계약 | 정한 함수·입력·자릿수·단위에 맞고 독립 검산을 통과한 배포 가능 항목 |
| 시스템 경계 | 문제·알고리즘 설계에서 작업표, 반복 산술, 검산, 편집·조판·인쇄·배포까지 |
| 고정 조건 | 함수·입력 범위·초기값·정밀도·반올림·작업 규칙과 판본 |
| 지표 | 계산·검산 통과 항목/시간, 노동·장비·출판 비용, 오류·정오표와 실제 배포 범위 |

이 장부는 장치 FLOPs가 없던 시대에도 능력을 비교할 수 있게 한다. 계산 속도만 높고 검산·출판이 막히면 사용 가능한 결과는 늘지 않는다.

### LLM까지 이어지는 공통 질문

[[001_섀넌의 N-gram 모델]]과 [[N-gram 모델]]은 corpus의 count를 미리 모아 다음 token 확률을 조회한다. [[단어 임베딩]]의 lookup은 token ID에 대응하는 학습된 벡터 행을 가져온다. 두 경우 모두 반복 계산 일부를 사전에 만든 자료 구조로 옮긴다는 점에서 수학 표와 비교할 수 있다.

그러나 같은 것은 아니다. N-gram count는 corpus 통계와 smoothing 규칙을 담고, embedding row는 gradient 학습으로 얻은 parameter이며, Transformer의 다음 token 분포는 여러 layer를 매번 실행해 만든다. 수학 표가 LLM의 직접 조상이라는 근거는 없다.

비교에서 얻는 질문은 더 일반적이다.

- 무엇을 미리 계산해 저장하고 무엇을 요청 시점에 계산하는가?
- 작업을 어느 단위로 나누고 중간 상태를 어떤 형식으로 전달하는가?
- Raw 연산량이 아니라 검증된 결과를 어떻게 세는가?
- 자동화 뒤 오류는 어디로 이동하고 누가 수정 책임을 지는가?

[[LLM을 만든 수학]]의 작은 계산도 token ID, vector, attention weight, residual, loss와 gradient를 중간 상태로 기록하고 손계산·회귀 test로 대조한다. 규모는 달라도 신뢰 가능한 계산이 단계·shape·검증 경로를 요구한다는 질문은 남는다.

### CS_WIKI와 함께 읽기

[CS_WIKI의 「인간 계산자와 계산 공장」](https://yghnsim.github.io/CS_Wiki/analyses/%EC%9D%B8%EA%B0%84-%EA%B3%84%EC%82%B0%EC%9E%90%EC%99%80-%EA%B3%84%EC%82%B0-%EA%B3%B5%EC%9E%A5/)은 드 프로니·배비지·Mathematical Tables Project·ENIAC·SEAC까지 실행 주체의 이동을 더 길게 추적한다. 현재 문서는 그중 기계 이전의 재사용·분업·검산만 떼어 LLM 계산을 읽기 위한 첫 비교 축으로 사용한다.

## 검증과 한계

- **직접 영향:** Grattan-Guinness의 연구 장은 드 프로니 프로젝트가 배비지에게 준 영향을 다룬다. Babbage의 1822년 원문은 차분 기계와 자동 조판 구상을 직접 기록한다.
- **가능 조건:** 표 수요, 인쇄·유통, 작업을 나눌 표준 절차와 숙련된 감독은 계산 결과를 사회적으로 재사용하게 한 조건이다. 어느 하나가 특정 기계를 필연적으로 낳지는 않았다.
- **병행 맥락:** 1790년대 프랑스 프로젝트와 1938–1946년 미국 MTP는 다른 기관·목적의 사례다. 둘을 하나의 조직 계보가 아니라 계산을 분해·검산하는 비교 사례로 읽는다.
- **후대 유추:** 작업표를 memory·interface, 역할 전달을 control flow로 부르는 것은 현대 개념을 이용한 분석이다. 당시 참여자가 현대 computer architecture를 설계했다는 뜻이 아니다.

이 문서는 모든 고대·근대 수학 표의 역사, 식민·군사 목적과 계산 노동의 성별·계급 관계를 완전하게 다루지 않는다. “미숙련”은 NIST가 설명한 배정 작업의 단순성을 가리키며 참여자의 지적 능력이나 노동 가치를 평가하는 말로 사용하지 않는다.

또한 수학 표와 model parameter의 유사성은 비용을 미리 지불해 재사용한다는 제한된 비교다. Model은 고정된 입력–출력 행만 저장하지 않고 학습된 함수로 새 입력을 처리한다. 이 차이를 지우면 LLM을 거대한 lookup table이라고 잘못 설명하게 된다.

## 학습 확인

1. 수학 표가 개인의 반복 계산 시간을 줄이면서도 전체 계산·검산·출판 비용을 없애지 않는 이유를 설명하라.
2. Mathematical Tables Project에서 알고리즘, 작업표, 기본 연산, 예외 전달과 검산은 각각 어떤 역할을 했는가?
3. 수학 표, N-gram count table과 embedding lookup의 공통점 하나와 서로 다른 점 두 가지를 적어라.

다음에는 **언어와 계산을 기계의 절차로 만든 이론·기호 표현**을 따라가며, 조직적으로 실행 가능한 절차와 무엇이 계산 가능한지를 정의하는 형식 모델의 차이를 본다.
