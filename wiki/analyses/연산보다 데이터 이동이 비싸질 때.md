# 연산보다 데이터 이동이 비싸질 때

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[메모리 계층과 데이터 이동]], [[수치 형식·혼합 정밀도·양자화]] — FLOPs·byte·통신을 처음 구분한다면 각 문서의 1단계만 먼저 읽는다.<br>
> **읽고 나면:** memory wall에서 mixed precision·FlashAttention·MoE·QLoRA까지를 한 줄의 “경량화”가 아니라, 값을 적게 옮기기·가까이 재사용하기·일부 경로만 실행하기·적은 bit로 저장하기라는 서로 다른 대응으로 비교할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 연산 장치가 빨라질수록 다른 시간이 보인다

LLM의 실행 비용을 FLOPs 하나로만 읽으면 이상한 결과가 생긴다. FlashAttention은 backward에서 일부 값을 재계산해 FLOPs가 늘어도 HBM traffic이 줄어 더 빨라질 수 있다. Mixed precision은 원소당 byte와 지원 연산 시간을 줄이지만 수치 안정 장치가 필요하다. MoE는 token당 일부 expert만 계산하지만 전체 weight memory와 AllToAll 통신은 남는다. QLoRA는 frozen base를 4-bit로 저장하지만 계산할 때 더 넓은 형식으로 dequantize한다.

네 방법은 모두 “효율”을 높일 수 있지만 서로 다른 장부를 바꾼다.

| 대응 | 줄이려는 주된 병목 | 유지하거나 새로 확인할 것 |
| --- | --- | --- |
| Mixed precision | 원소당 저장·전송 byte, 지원 matrix 연산 시간 | Range·rounding·loss scaling과 model quality |
| FlashAttention | Attention 중간값·HBM–SRAM traffic | 같은 dense attention 결과, 재계산 FLOPs |
| Sparse MoE | Token당 활성 FFN FLOPs | Total weight memory, routing·AllToAll·load balance |
| QLoRA | Base weight와 optimizer의 fine-tuning memory | Dequantized compute, adapter 품질·peak memory |

“더 적은 계산”과 “더 적은 데이터 이동”은 같은 열이 아니다.

### Memory wall은 LLM보다 오래된 문제 언어다

Wulf와 McKee는 1995년에 processor와 DRAM의 개선 격차가 커지면 실제 실행이 memory access에 지배될 수 있다고 경고했다. 2009년 Roofline은 달성 성능을 peak compute와 `memory bandwidth × operational intensity` 중 작은 값으로 제한해 compute-bound와 memory-bound를 나눴다.

이 문헌이 Transformer나 QLoRA를 직접 예견한 것은 아니다. 다만 연산기 peak만으로 실제 성능을 설명할 수 없다는 **병행 맥락**을 제공한다. LLM 시대에는 경계가 DRAM–CPU뿐 아니라 HBM–SRAM, accelerator 사이 network, storage–GPU, weight·KV cache 이동으로 확장됐다.

## 2단계 — 작동 원리

### 첫 대응: 적은 bit로 옮기되 중요한 계산은 넓게 남긴다

Mixed precision은 모든 값을 무조건 낮은 형식으로 바꾸지 않는다. FP16 weight·activation·gradient와 FP32 master weight·일부 누산, loss scaling을 결합해 memory와 지원 연산의 이득을 얻으면서 작은 update와 gradient가 사라지는 위험을 줄인다.

이 변화는 operational intensity의 분모인 byte를 줄일 수 있고 accelerator가 낮은 형식에서 더 높은 matrix throughput을 제공하면 분자의 실행 속도도 바꿀 수 있다. 그러나 수렴과 최종 quality가 정한 허용 범위를 벗어나면 빠른 실행도 유효한 결과가 아니다.

### 둘째 대응: 중간값을 큰 memory에 쓰지 않는다

표준 attention은 $S=QK^{\mathsf T}$와 $P=\operatorname{softmax}(S)$의 $N\times N$ 중간값을 HBM에 물질화할 수 있다. FlashAttention은 SRAM tile 안에서 online softmax와 부분 출력을 누적하고 backward에 필요한 일부 값을 재계산한다.

2022년 논문 Figure 2의 조건에서는 FLOPs가 약 13% 늘었지만 HBM read/write가 약 8분의 1로 줄고 시간은 약 3분의 1이 됐다. 산술량을 덜 세는 algorithm이 아니라 **같은 결과를 얻는 계산 순서와 memory schedule**을 바꾼 algorithm이다.

### 셋째 대응: 모든 parameter를 매 token에 실행하지 않는다

Sparse MoE는 router가 token마다 $E$개 expert 중 $k$개를 선택한다. $k\ll E$이면 total parameter를 크게 늘리면서 token당 active expert FLOPs를 제한할 수 있다. Switch Transformer는 top-1 routing으로 한 expert를 선택해 routing을 단순화했다.

하지만 선택되지 않은 expert도 checkpoint와 학습 state에 저장되고, expert가 다른 장치에 있으면 token representation을 AllToAll로 보낸다. 특정 expert에 token이 몰리면 capacity 초과·drop이나 load imbalance가 생긴다. “1T parameter지만 dense model과 비슷한 FLOPs”에서 1T는 저장·용량 축, 비슷한 FLOPs는 활성 실행 축이다.

### 넷째 대응: Base를 적은 bit로 저장하고 작은 update만 학습한다

QLoRA는 4-bit NF4로 저장한 pretrained base를 동결하고, compute dtype으로 dequantize해 forward·backward를 수행하며 LoRA adapter만 학습한다. Full fine-tuning처럼 base 전체의 gradient·optimizer state를 만들지 않는다.

이 방식은 단일 48GB GPU에서 65B base를 fine-tune한 사례를 만들었지만 “65B 추론이 언제나 빠르다”는 결과는 아니다. Weight를 읽는 byte는 줄 수 있어도 dequantization kernel, activation, KV cache와 token-by-token decode 시간이 남는다.

## 3단계 — 기술과 근거

### FlashAttention 측정 장부

| 항목 | 기록 |
| --- | --- |
| 작업 | GPT-2 medium attention forward+backward |
| 규모 | A100, sequence 1,024, head dimension 64, 16 heads, batch 64 |
| 결과 계약 | 표준 dense softmax attention과 같은 수학적 출력 |
| 시스템 경계 | Attention kernel의 FLOPs·HBM traffic·시간 |
| 고정 조건 | 논문 Figure 2의 model·shape·device·baseline |
| 지표 | 약 13% 추가 FLOPs, 약 8배 적은 HBM R/W, 약 3배 짧은 시간 |

같은 Figure 안의 장부이므로 인과 해석이 강하지만, 다른 GPU·sequence·kernel에도 같은 배수를 적용할 수는 없다.

### Sparse MoE 측정 장부

| 항목 | 기록 |
| --- | --- |
| 작업 | Dense FFN을 sparse expert layer로 바꾼 language model 학습·추론 |
| 규모 | Expert 수 $E$, token당 top-$k$, capacity factor, device 수 |
| 결과 계약 | 같은 data·token budget과 비교한 loss·downstream quality |
| 시스템 경계 | Router, expert FFN, token dispatch·gather와 전체 model |
| 고정 조건 | Total/active parameter, precision, routing·parallelism |
| 지표 | Active FLOPs, total parameter·memory, AllToAll byte, wall-clock·quality |

Switch의 “4배 speedup” 같은 보고는 논문이 정한 T5-XXL baseline·hardware·quality 조건에서 읽는다. Expert 수만 늘려도 communication·memory와 routing 불균형이 커질 수 있다.

### QLoRA 측정 장부

| 항목 | 기록 |
| --- | --- |
| 작업 | Quantized frozen base의 instruction fine-tuning |
| 규모 | 최대 65B base, 단일 48GB GPU 사례 |
| 결과 계약 | 논문의 16-bit 비교와 MMLU·chat 평가 |
| 시스템 경계 | GPU peak memory와 adapter 학습 |
| 고정 조건 | NF4·double quantization·paged optimizer·LoRA와 compute dtype |
| 지표 | Peak memory, 학습 가능한 model 규모, benchmark·사람 평가 |

Checkpoint raw byte, peak GPU memory, training throughput과 inference latency는 별도 지표다.

### 한 장부에 합치지 말아야 할 네 값

$$
\text{total parameters}
\ne
\text{active parameters}
\ne
\text{active FLOPs}
\ne
\text{bytes moved}
$$

이 네 값은 단위와 시스템 경계가 다르다. Dense·MoE·quantized model을 비교할 때 model quality와 token 수를 같게 두지 않으면 “효율”의 분자도 달라진다.

### 인과 관계 감사

- **직접 영향:** FlashAttention은 HBM I/O를 명시적 비용 모델에 넣었고, QLoRA는 quantized base memory를 fine-tuning 병목으로 직접 다뤘다.
- **가능 조건:** 낮은 정밀도 연산기·온칩 memory·fused kernel과 빠른 interconnect가 각 절감안을 실제 wall-clock으로 바꾸는 조건이다.
- **병행 맥락:** Memory wall과 Roofline은 데이터 이동 병목의 오래된 언어지만 후속 LLM algorithm의 직접 설계 계보로 단정하지 않는다.
- **후대 유추:** FlashAttention-2·3, 새로운 FP8·quantizer와 후속 MoE routing 성과를 최초 논문에 소급하지 않는다.

### CS_WIKI와 함께 읽기

[CS_WIKI의 「전력 장벽은 성능 향상의 의미를 어떻게 바꾸었는가」](https://yghnsim.github.io/CS_Wiki/analyses/%EC%A0%84%EB%A0%A5-%EC%9E%A5%EB%B2%BD%EC%9D%80-%EC%84%B1%EB%8A%A5-%ED%96%A5%EC%83%81%EC%9D%98-%EC%9D%98%EB%AF%B8%EB%A5%BC-%EC%96%B4%EB%96%BB%EA%B2%8C-%EB%B0%94%EA%BE%B8%EC%97%88%EB%8A%94%EA%B0%80/)는 작업/J와 활성 면적을 peak 성능과 분리한다. 현재 본편의 low precision·sparse activation도 energy 이득을 주장하려면 실제 workload와 device 전력 경계를 별도로 측정해야 한다.

## 검증과 한계

이 본편은 서로 다른 논문의 절감 배수를 한 순위표로 만들지 않는다. FlashAttention의 kernel runtime, QLoRA의 peak memory, Switch의 training speedup은 작업·baseline·hardware와 결과 계약이 다르다. 각 방법은 둘 이상을 결합할 수도 있어 효과를 독립적으로 분리하려면 ablation이 필요하다.

Memory traffic 감소가 energy 감소와 상관될 수 있지만 joule을 직접 측정하지 않은 논문에서 탄소·전력 배수를 추정하지 않는다. MoE의 total parameter가 capacity를 늘릴 가능성도 동일 quality의 인과 효과로 자동 해석하지 않는다. Quantization benchmark가 유지돼도 calibration·tail input·안전성은 별도 검증 대상이다.

다음 본편 **모델 능력에서 서비스 능력으로**는 학습·kernel 장부를 반복 요청의 prefill·decode, KV cache, batching, tail latency와 가용성으로 확장한다.

## 학습 확인

1. FlashAttention이 FLOPs를 더 쓰고도 빨라질 수 있는 이유를 Roofline의 두 지붕과 HBM traffic으로 설명하라.
2. Sparse MoE가 active FLOPs를 줄여도 total memory와 communication이 줄지 않을 수 있는 이유는 무엇인가?
3. “4-bit MoE가 dense FP16보다 8배 효율적”이라는 문장을 발견했다. Total/active parameter, dtype별 byte, dequantization, routing·AllToAll, quality와 wall-clock을 여섯 항목 측정 장부로 다시 작성하라.

이후 다음 본편 **모델 능력에서 서비스 능력으로**에서 같은 model을 여러 사용자가 요청할 때 throughput과 한 요청의 지연·가용성이 어떻게 갈라지는지 이어서 배운다.
