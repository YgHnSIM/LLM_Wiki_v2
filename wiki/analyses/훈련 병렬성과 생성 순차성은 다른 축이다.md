# 훈련 병렬성과 생성 순차성은 다른 축이다

[[045_Sequence-to-Sequence 학습과 신경 기계 번역]], [[053_WaveNet과 표본 단위 신경 오디오 생성]], [[054_Transformer와 자기어텐션 기반 시퀀스 모델링]]을 함께 읽으면 “이 모델은 병렬인가?”라는 질문이 지나치게 거칠다는 사실이 드러난다. RNN·인과 합성곱·masked self-attention은 시퀀스를 다루지만 **이미 알려진 위치 표현을 계산하는 의존성**과 **아직 모르는 출력을 실제로 생성하는 확률 의존성**이 다르다.

비교에 필요한 축은 최소 네 가지다.

1. 한 층에서 위치 $t$의 hidden representation이 앞 위치 계산을 기다리는가?
2. 훈련 때 정답 이전 출력 전체를 입력으로 사용할 수 있는가?
3. 추론 때 출력 $y_t$를 만들기 전에 $y_{t-1}$이 실제로 필요한가?
4. 병렬화와 별개로 전체 연산량·메모리·출력 단위 수는 얼마나 큰가?

이 축을 나누면 “Transformer는 병렬이고 RNN은 순차적”이라는 입문 설명을 더 정확한 시스템 판단으로 바꿀 수 있다.

## 두 종류의 의존 그래프

첫 번째는 **표현 계산 그래프**다. RNN은

$$
h_t=f(h_{t-1},x_t)
$$

이므로 $h_t$를 계산하려면 $h_{t-1}$을 기다려야 한다. 정답 token을 모두 알아도 한 시퀀스 안의 recurrent hidden state는 차례로 계산된다.

인과 합성곱과 masked self-attention은 다르다. 입력 시퀀스 $x_{1:T}$가 이미 주어지면 미래 누설을 막는 receptive field나 mask를 적용한 채 모든 출력 위치를 큰 행렬 연산으로 계산할 수 있다. 인과성은 미래 값을 **사용하지 않는다**는 제약이지 계산 위치를 반드시 하나씩 실행하라는 제약이 아니다.

두 번째는 **출력 확률 그래프**다. [[자기회귀 생성]]은

$$
p(y\mid x)=\prod_{t=1}^{T}p(y_t\mid y_{<t},x)
$$

처럼 분해된다. 훈련에서는 정답 $y_{<t}$를 알고 있으므로 모든 위치의 조건을 한꺼번에 구성할 수 있다. 생성에서는 $y_t$를 실제로 뽑기 전까지 $y_{t+1}$의 완전한 조건이 존재하지 않는다. 표현 backbone이 합성곱이든 attention이든 이 ancestral sampling의 순차성은 남는다.

## 네 구조를 같은 표에 놓기

| 구조 | 정답 시퀀스가 있는 훈련의 위치 계산 | 자기회귀 생성 | 주요 병목 |
| --- | --- | --- | --- |
| LSTM encoder/decoder | hidden state가 앞 시점에 의존해 시퀀스 내부는 순차적 | token별 순차적 | $O(n)$ 순차 상태 갱신, 긴 gradient path |
| [[WaveNet]] causal convolution | 실제 파형을 입력하면 표본 위치를 병렬 계산 가능 | 오디오 표본별 순차적 | 초당 약 16,000회 예측, 유한 수용 영역 |
| Transformer encoder | 모든 입력 위치를 병렬 계산 가능 | encoder 자체는 출력을 생성하지 않음 | 표준 self-attention의 $O(n^2d)$ 계산·메모리 |
| Transformer causal decoder | 이동한 정답열과 mask로 token 위치를 병렬 계산 가능 | token별 순차적 | attention 비용, decode step 수와 메모리 대역폭 |

이 표는 ‘병렬’이 모델 전체의 단일 속성이 아님을 보여 준다. encoder의 표현 계산, decoder의 teacher-forced 훈련, decoder의 실제 sampling은 서로 다른 단계다.

## teacher forcing이 RNN과 Transformer에서 다른 이유

teacher forcing은 훈련 시 이전 **정답 출력**을 입력으로 주는 관행이다. 이것이 제거하는 불확실성은 $y_{t-1}$을 기다리는 문제다. RNN에는 별도의 $h_{t-1}$ 의존이 남는다.

LSTM decoder에서는 정답 $y_{t-1}$을 미리 알아도

$$
h_t=f(h_{t-1},y_{t-1},c)
$$

이므로 모든 $h_t$를 동시에 계산할 수 없다. 반면 Transformer decoder는 이동한 정답열 전체에서 query·key·value를 만들고 triangular mask로 미래 연결만 차단한다. 모든 위치의 입력이 알려져 있어 한 번의 병렬 연산으로 층 출력을 계산할 수 있다.

그러나 추론 시에는 두 모델 모두 앞선 실제 출력이 필요하다. Transformer가 해결한 것은 주로 **훈련 backbone의 순환 의존**이지 자기회귀 확률 분해 자체가 아니다.

## WaveNet이 보여 준 더 극단적인 시간 해상도

WaveNet은 Transformer보다 한 해 먼저 이 분리를 선명하게 보였다. 팽창 인과 합성곱은 실제 오디오 전체가 있는 훈련에서 모든 위치의 loss를 병렬 계산한다. 하지만 원형은 16kHz 파형의 표본을 하나씩 생성했다. 1초 음성에 약 16,000번의 조건부 sampling이 필요하다.

텍스트 decoder도 순차적이지만 한 문장의 token 수는 파형 표본 수보다 훨씬 적다. 따라서 “둘 다 자기회귀”라는 수학적 공통점만으로 serving latency를 비교할 수 없다. 출력 표현의 시간 해상도와 한 step의 비용을 함께 보아야 한다.

[[Transformer]]의 표준 self-attention은 긴 입력에서 모든 위치 쌍을 계산하므로 훈련 병렬성이 있어도 총연산·메모리는 $n^2$로 커진다. 반대로 국소 causal convolution은 층별 연산이 길이에 선형적일 수 있지만 넓은 수용 영역에 여러 층이 필요하다. 순차 단계 수, 총 FLOPs, 메모리와 통신량은 서로 다른 성능 축이다.

## KV cache가 없애는 것과 남기는 것

causal Transformer 생성에서 이전 token의 key와 value를 cache하면 매 step마다 과거 prefix 전체의 K·V를 다시 계산하지 않아도 된다. 이는 중복 계산을 줄이는 중요한 최적화다. 하지만 $y_t$가 정해져야 그 위치의 K·V를 cache하고 $y_{t+1}$로 갈 수 있으므로 출력 token 수만큼의 순차 round는 남는다.

따라서 cache는 **한 step의 비용**을 줄이지만 **step 사이의 확률 의존성**을 제거하지 않는다. speculative decoding도 작은 draft 모델과 검증으로 여러 후보 token을 한 번에 받아들이려 하지만, 정확한 목표 분포를 유지하는 조건과 acceptance가 성능을 좌우한다. 이런 기법을 ‘Transformer 생성이 완전히 병렬’이라는 근거로 읽지 않는다.

## 생성 병렬화에는 무엇을 바꿔야 하는가

순차 round를 크게 줄이려면 보통 모델의 분해·잠재 변수·학습 절차 가운데 하나를 바꿔야 한다. Parallel WaveNet은 순차 WaveNet teacher의 분포를 inverse autoregressive flow student에 probability density distillation해 병렬 표본 생성을 가능하게 했다. 이는 원 teacher를 단순 실행 최적화한 것이 아니라 별도의 student와 목적을 도입한 변화다.

텍스트의 비자기회귀 번역, masked iterative refinement, diffusion·flow 생성도 여러 위치를 함께 예측하지만 독립성 가정·반복 횟수·다중 양식 출력·품질이라는 다른 trade-off를 갖는다. “순차 생성은 하드웨어 구현이 느려서 생긴 우연”이 아니라 확률 분해와 sampling 절차에 연결된 제약이므로, 병렬화는 대개 모델링 가정의 변경을 요구한다.

## 성능 문구를 읽는 네 질문

새 시퀀스 모델이 ‘parallel’ 또는 ‘fast’라고 주장할 때 다음을 묻는다.

1. **어느 단계인가?** encoder, teacher-forced training, prefill, autoregressive decode 가운데 무엇을 측정했는가?
2. **어느 단위인가?** text token, audio sample, codec token, image patch의 시퀀스 길이는 얼마인가?
3. **어느 자원인가?** FLOPs, memory capacity, memory bandwidth, device communication, wall-clock latency 가운데 무엇이 병목인가?
4. **어느 품질 조건인가?** 같은 likelihood·BLEU·MOS·분포를 유지하는가, 아니면 distillation·근사·독립성 가정을 추가했는가?

이 질문 없이 ‘RNN보다 병렬’, ‘실시간보다 빠름’, ‘긴 문맥 처리’라는 문구만 비교하면 서로 다른 단계와 하드웨어 조건을 한 숫자로 합치게 된다.

## 확인된 사실과 비교 해석

확인된 사실은 다음과 같다.

- LSTM의 recurrent hidden state는 teacher forcing 아래에서도 시점별 의존을 갖는다.
- WaveNet과 Transformer decoder는 정답 이력이 있는 훈련에서 causal 제약을 유지하며 위치를 병렬 계산할 수 있다.
- 두 모델의 표준 자기회귀 sampling은 앞선 실제 출력에 의존한다.
- Transformer self-attention의 병렬성은 길이 제곱 계산·메모리를 없애지 않는다.
- Parallel WaveNet의 병렬 생성은 별도 student와 distillation을 도입했다.

비교에서 얻는 재사용 가능한 해석은 **훈련 병렬성은 표현 계산 그래프의 속성이고, 생성 순차성은 출력 확률 분해와 sampling 절차의 속성**이라는 것이다. 두 속성은 결합될 수 있지만 같은 축이 아니다.

아직 입증되지 않은 보편 명제도 남는다. 모든 자기회귀 분포가 실용적으로 병렬 생성될 수 없다는 일반 불가능 정리를 이 자료가 제공하지는 않는다. 반대로 한 모델에서 병렬 sampling을 달성했다고 모든 분포·품질·지연 조건에서 자기회귀 방식을 대체할 수 있다는 결론도 나오지 않는다.
