# 사전 학습 지식은 과제에 어떻게 도착하는가

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[언어 모델 전이 학습]], [[대규모 언어 모델]]<br>
> **읽고 나면:** 사전 학습 지식이 특징·전체 매개변수·저순위 adapter·시간순 corpus 적응·입력 문맥·외부 기억·언어 공유·모달리티 bridge·생성 목표 잠재·교차 어텐션 조건을 통해 도착하는 경로와, 각 경로의 갱신·보존 경계를 독립적으로 비교할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 비교 질문과 잠정 결론

[[057_ELMo와 ULMFiT의 두 전이 학습 경로]], [[058_BERT의 마스크드 양방향 사전 학습]], [[059_GPT-1과 GPT-2의 전이 방식 변화]], [[062_XLM과 교차 언어 사전 학습]], [[063_T5와 Text-to-Text 통합 프레임워크]], [[067_GPT-3와 문맥 내 학습]], [[070_CLIP과 대조적 언어-이미지 사전 학습]], [[084_Flamingo와 게이트 교차 어텐션 기반 퓨샷 시각-언어 학습]], [[093_멀티모달 LLM과 시각-언어 연결 방식의 분화]], [[105_통합 멀티모달 아키텍처의 공유 범위와 입출력 경계]], [[085_DALL·E 2와 CLIP 잠재 표현 기반 계층적 확산 생성]], [[086_잠재 확산 모델과 Stable Diffusion v1 공개]], [[071_Codex와 HumanEval 기반 코드 생성 평가]], [[072_지시 미세조정과 FLAN의 제로샷 일반화]], [[076_파운데이션 모델 보고서와 AI 생태계]], [[091_QLoRA와 4비트 양자화 미세조정]], [[101_LoRA 이후 PEFT 변형의 설계 축과 연표]], [[102_지속 사전 학습의 연표와 지식 갱신 경계]]를 함께 읽으면 ‘대규모 자료에서 사전 학습한 뒤 후속 과제에 전이하거나 새 생성기에 재사용한다’는 공통 문장이 실제로는 여러 다른 계산 경계를 가린다는 사실이 드러난다. 지식은 **표현**, **전체 매개변수**, **동결 base와 학습 adapter**, **adapter 내부의 allocation·parameterization·sharing·scaling·initialization**, **시간순으로 갱신되는 base**, **목표 영역 분포**, **다과제 감독**, **입력 문맥과 외부 기억**, **언어 사이 공유**, **이미지와 언어의 정렬**, **연속 prefix·시각 memory·query 병목·projected token과 같은 bridge**, **shared-core token sequence와 생성 목적**, **생성해야 할 중간 잠재**, **잡음 제거기가 읽는 조건 memory** 가운데 어디를 통해 도착하며, 과제 명세는 head·cue·instruction·adapter·text·multimodal demonstration·class prompt·공통 text output·생성 prior·cross-attention·실행 선택 가운데 어디에 놓이는가?

이 질문은 모델 이름보다 과제 적응과 생성기 재사용의 위치를 비교한다.

## 2단계 — 작동 원리

### 먼저 분리해야 할 열아홉 경계

전이와 사전 학습 구성 요소의 생성기 재사용을 설명하려면 최소 열아홉 가지를 구분해야 한다.

1. 사전 학습 모델의 매개변수를 후속 과제에서 고정하는가?
2. 목표 과제의 비표지 text로 먼저 영역 적응하는가?
3. 표지 예시가 가중치를 바꾸는가, 입력 문맥에만 놓이는가?
4. 과제별 구조가 깊은 network인가, 작은 출력층인가, text cue인가?
5. 사전 학습 text, fine-tuning label, 평가 입력의 언어가 서로 같은가?
6. output architecture·loss만 공통인가, final checkpoint와 metric까지 공유하는가?
7. 입력과 출력이 같은 모달리티인가, 서로 다른 모달리티의 표현을 어떤 점수로 연결하는가?
8. 영역 분포의 다음-token 학습, 과제 형식의 지도 미세조정, 추론 후보의 실행 선택을 서로 분리했는가?
9. 여러 과제의 supervision으로 공통 weights를 갱신했는가, 현재 평가 task의 label까지 갱신했는가, 아니면 inference instruction만 제공했는가?
10. 관측한 능력·실패는 foundation model, adapted model, deployed system 가운데 어느 층의 것인가?
11. 적응자는 model-parameter gradient, continuous-input gradient, model output만 반환하는 API 가운데 어느 수준에 접근할 수 있는가?
12. 비언어 표현이 연속 prefix, 별도 key/value memory, query 병목, encoder–decoder visual token, projected token, continuous observation token 가운데 어떤 경로로 이동하는가?
13. 시각 encoder·bridge·language model 가운데 무엇을 동결하고 무엇을 갱신했으며, 그 사전 학습 경계와 downstream fine-tuning·prompt adaptation을 구분했는가?
14. 사전 학습 표현이 후보 class prototype, 별도 key/value memory, 생성 prior의 target, 잡음 제거기의 조건 가운데 어떤 역할을 맡는가?
15. 생성 상태는 pixel, 공유 image embedding, 오토인코더의 공간 latent 가운데 어디에 있고, 고정된 표현 모듈과 새로 학습한 생성 모듈의 경계는 어디인가?
16. Base weight의 저장 dtype, matrix multiplication의 compute dtype과 실제로 gradient update를 받는 parameter dtype을 분리했는가?
17. 같은 instruction–target data를 쓰더라도 전체 weights를 갱신했는가, 일부 adapter만 갱신했는가, 아니면 입력 문맥에만 example을 두었는가?
18. 같은 frozen-base adapter 경로에서도 rank budget을 어디에 배분하고, weight 좌표·basis·scaling·quantization initialization 가운데 무엇을 바꾸었는가?
19. 새 corpus가 시간순으로 들어올 때 base·adapter·외부 index 가운데 무엇을 갱신하고, 새 분포 적응과 이전 능력 보존을 어떤 평가 행렬로 분리했는가?

같은 ‘fine-tuning’도 이 경계에 따라 다르고, 같은 ‘zero-shot’도 모델이 어떤 task cue와 scoring rule을 받았는지, target 언어의 text와 label 가운데 무엇을 보았는지에 따라 다르다.

|---|---|---|---|---|
| ELMo | biLM 고정 | 층 혼합 가중치와 과제 모델 학습 | 기존 과제 구조에 문맥 특징 추가 | 위치별 hidden representation |
| ULMFiT | AWD-LSTM에서 시작 | 목표 영역 LM 뒤 분류기·LM 전체 적응 | concat pooling classifier | 전체 매개변수와 영역 분포 |
| BERT | MLM encoder에서 시작 | 작은 출력층과 encoder 전체 적응 | `[CLS]`·token·span head | 전체 매개변수 |
| GPT-1 | causal LM에서 시작 | 구조화 입력과 출력층으로 전체 적응 | delimiter와 class/후보 head | 전체 매개변수 |
| GPT-2 zero-shot | causal LM 고정 | 과제별 가중치 갱신 없음 | cue·continuation·후보 scoring | 입력 문맥과 decoding rule |
| XLM zero-shot XNLI | multilingual MLM·TLM encoder에서 시작 | 영어 NLI label로 encoder·classifier 적응 | 같은 classifier를 target 언어 입력에 적용 | shared multilingual parameter와 영어 task weights |
| T5 | span-corruption encoder–decoder에서 시작 | task label로 전체 model을 개별 fine-tuning | prefix가 붙은 source text→target text | 전체 매개변수; 과제 명세는 공통 생성 interface |
| FLAN | 137B LaMDA-PT에서 시작 | 평가 cluster를 제외한 여러 과제의 instruction–target mixture로 전체 model 미세조정 | 현재 instruction·input·분류 OPTIONS | 다른 과제의 감독을 축적한 weights와 현재 inference text |
| GPT-3 in-context | causal LM 고정 | task-specific gradient update 없음; instruction·demonstration을 입력에 배치 | zero/one/few-shot prompt와 scoring | 입력 문맥의 activation·조건부 출력 분포 |

| QLoRA Guanaco | LLaMA base를 NF4로 저장하고 동결 | OASST1 conversation으로 all-linear BF16 LoRA adapter만 지도 미세조정 | instruction·conversation text→response text | 사전 학습 지식은 동결 base에, 과제 update는 별도 adapter에 위치 |

이 표는 발전 단계를 우열 순으로 놓지 않는다. 고정 특징은 여러 과제가 기반 모델을 공유하기 쉽고 망각 위험이 작다. 전체 미세조정은 적응력이 크지만 작은 자료에서 불안정하거나 사전 학습 지식을 잃을 수 있다. 저순위 adapter는 base를 공유하면서 task-specific update를 별도 artifact로 두지만 layer coverage·rank·storage와 compute dtype·base access라는 새 경계를 만든다. 입력 cue는 가중치 갱신 비용이 없지만 과제 형식과 model scale에 민감하고 초기 GPT-2의 절대 성능은 제한적이었다.

### 파운데이션 모델은 별도의 적응 경로가 아니다

2021년 보고서에서 [[파운데이션 모델]]은 특정 adaptation algorithm이나 model-size 구간이 아니다. 광범위한 자료로 사전 학습되어 여러 하위 과제의 공통 기반으로 적응되는 **역할 범주**다. 보고서가 BERT·GPT-3·CLIP을 함께 예로 든 것은 세 model이 같은 방식으로 적응된다는 뜻이 아니다. 위 표의 feature extraction·full fine-tuning·prompt conditioning·natural-language classifier·동결 백본 사이의 학습된 bridge는 공통 기반을 사용하는 서로 다른 경로다.

보고서 §4.3은 적응을 새 data·prompt로 input을 조건화하거나 일부 또는 전체 parameter를 갱신하는 과정으로 넓게 본다. 선택 조건에는 compute budget, task data와 gradient access가 들어간다. §1.2는 rule·classifier·보완 신호를 결합한 system 구성과 deployment를 model training에서 다시 분리한다.

따라서 ‘사전 학습 지식이 과제에 도착했다’는 주장은 foundation model, adapted model, deployed system 가운데 어느 층에서 성능을 관측했는지 밝혀야 한다. 이 층위를 건너뛰면 base checkpoint의 능력과 retrieval·tool·filter·UI를 포함한 제품의 능력이 한 모델의 속성처럼 합쳐진다.

## 3단계 — 기술과 근거

### ELMo: 지식을 계산해 건넨다

ELMo는 사전 학습 biLM의 입력·내부 층에서 위치별 문맥 표현을 계산한다. 후속 과제는 학습된 scalar weights로 층을 섞고 기존 network의 입력이나 중간 표현에 추가한다. 기반 biLM은 원 대표 설정에서 고정된다.

이 방식의 전이 단위는 모델의 **출력 특징**이다. 후속 과제는 새 표현을 받지만 관계 추론·span 선택·sequence labeling 구조 자체를 새로 학습한다. 따라서 ELMo가 여섯 과제에 쉽게 추가됐다는 것은 하나의 모델이 여섯 출력 형식을 직접 수행했다는 뜻이 아니다.

### ULMFiT: 지식을 영역을 거쳐 다시 쓴다

ULMFiT는 일반 corpus의 AWD-LSTM을 목표 과제 text의 language modeling으로 먼저 적응시킨다. 이후 concat pooling classifier를 붙이고 위층부터 점진적으로 풀며 전체 모델을 지도 미세조정한다.

여기서 전이는 두 번 일어난다.

1. 일반 언어 분포 → 목표 영역의 비표지 text
2. 목표 영역 언어 모델 → 표지 분류 경계

판별적 학습률·점진적 동결 해제·학습률 일정은 사전 지식 보존과 새 과제 적응 사이를 조절한다. ‘사전 학습 뒤 분류’라는 두 단어만으로는 이 중간 영역 적응이 사라진다.

### BERT와 GPT-1: 같은 전체 미세조정, 다른 사전 학습 조건

[[BERT]]와 GPT-1은 과제별 깊은 구조를 줄이고 기반 모델 전체를 미세조정한다는 점에서 닮았다. 그러나 BERT는 [[마스크드 언어 모델링]] encoder가 입력 좌우를 공동 조건으로 사용하고, GPT-1은 causal next-token model이 앞 문맥만 사용한다.

과제 입력도 다르다. BERT는 `[CLS] A [SEP] B [SEP]`와 token·span 출력처럼 encoder representation을 읽는다. GPT-1은 premise·hypothesis·answer 후보를 delimiter가 있는 continuation sequence로 바꾸고 마지막 위치를 분류한다. 두 모델의 전이 인터페이스가 가까워도 사전 학습 목적과 attention graph는 같지 않다.

이 비교는 ‘양방향 이해 모델 대 생성 모델’이라는 성격 분류보다 구체적이다. 둘 다 분류와 QA에 미세조정됐지만 token 표현과 확률 분해의 제약이 다르다.

### GPT-2: 과제를 가중치 밖으로 옮긴다

[[GPT-1과 GPT-2|GPT-2]]의 zero-shot 실험에서는 해당 과제의 표지 training set으로 모델 매개변수를 갱신하지 않았다. 대신 번역쌍 형식, `TL;DR:`, 질문·답 cue와 task별 scoring·decoding을 사용했다.

여기서 과제 적응은 **입력과 평가 절차**로 이동한다. 모델이 언어 모델링 중 본 자연 발생 task 형식이 continuation을 유도한다는 가설이다. 이 변화는 후대 in-context learning의 중요한 전조다.

그러나 GPT-2 결과는 경계도 보여 준다. language modeling·LAMBADA·CBT·Winograd에서는 강했지만 번역·요약·QA의 다수 절대 성능은 지도 모델보다 낮았다. 매개변수를 바꾸지 않았다는 사실과 과제를 높은 품질로 해결했다는 사실은 다르다.

### XLM: 과제 전이에 언어 축을 더한다

[[XLM]]의 XNLI zero-shot은 GPT-2의 “task label 없이 가중치를 고정한다”는 zero-shot과 다르다. XLM은 여러 target 언어의 비표지 text로 encoder를 사전 학습한 뒤 영어 NLI label로 encoder와 classifier를 fine-tune한다. 다른 언어의 test set에서는 target-language NLI label을 쓰지 않지만 fine-tuned 가중치는 그대로 사용한다.

여기서 과제 지식은 영어 label로 매개변수에 들어가고, 언어 사이 이동은 shared vocabulary·Transformer parameter와 multilingual pretraining이 담당한다. 따라서 `target 언어를 보지 않았다`가 아니라 `target 언어의 과제 label을 보지 않았다`고 써야 한다. 사전 학습 언어, supervision 언어, 평가 언어를 분리하지 않으면 서로 다른 zero-shot protocol이 한 단어에 겹친다.

### T5: 과제별 head를 공통 text output으로 옮긴다

[[T5]]는 분류 label, answer, summary와 translation을 모두 decoder target으로 직렬화한다. 같은 encoder–decoder, vocabulary와 token likelihood를 여러 task에 쓰므로 BERT·GPT-1보다 output interface의 공유 범위가 넓다. 그러나 대표 final result는 C4 denoising과 supervised task를 함께 섞은 multi-task pretraining 뒤 대부분 task마다 전체 model을 다시 fine-tuning한 결과다.

T5 task prefix는 input 안에서 task identity를 지정하지만 GPT-2 zero-shot cue와 supervision 조건이 다르다. T5는 labeled example로 prefix와 target mapping을 학습했고 weight도 바꾼다. output이 모두 text여도 GLUE·SQuAD·ROUGE·BLEU metric과 dataset은 남으므로 과제 명세가 완전히 사라진 것도 아니다.

### FLAN: 여러 과제의 감독은 weights에, 현재 과제는 instruction에 둔다

[[지시 미세조정]]은 T5의 supervised text interface와 GPT-3의 inference instruction을 다시 조합한다. 원 FLAN은 62개 dataset을 12개 task cluster로 묶고, 평가 cluster 전체를 제외한 나머지 과제의 instruction–target example로 LaMDA-PT 전체를 미세조정했다. 현재 보류 과제에는 demonstration 없이 instruction·input과 필요한 output options만 제공했다.

따라서 FLAN의 zero-shot은 **현재 task의 label이 weights에 들어가지 않았다**는 뜻이지, 지도 task example을 전혀 쓰지 않았다는 뜻이 아니다. 다과제 감독은 사전에 공통 weights를 바꾸고, inference instruction은 그 weights에서 현재 동작을 조건화한다. GPT-3처럼 weights를 완전히 고정한 prompt-only adaptation도, T5 대표 final recipe처럼 현재 task label로 다시 fine-tuning한 checkpoint도 아니다.

평가 경계도 전이 경로의 일부다. FLAN의 25개 결과는 하나의 universal checkpoint가 아니라 평가 cluster마다 그 cluster를 제외한 별도 checkpoint에서 나왔다. 422M·2B·8B에서는 held-out 성능이 악화되고 68B·137B에서 좋아졌으므로, instruction mixture가 weights에 들어갔다는 절차와 unseen-task 일반화가 항상 좋아진다는 주장을 분리한다.

### GPT-3: demonstration을 순전파 안에 둔다

[[문맥 내 학습]]은 task example을 매개변수 갱신에 쓰지 않고 query와 같은 입력 sequence에 둔다. [[067_GPT-3와 문맥 내 학습]]은 125M–175B의 여덟 모델을 같은 300B token으로 학습한 뒤, instruction만 주는 zero-shot, demonstration 하나를 더하는 one-shot, 보통 10–100개를 넣는 few-shot을 비교했다. 모든 조건에서 가중치는 고정됐다.

여기서 지식이 ‘도착하는’ 위치는 입력 token이 만든 일시적 activation과 그에 조건화된 다음-token 분포다. 그러나 task specification이 없어진 것은 아니다. prompt wording, example과 순서, 2048-token 예산, candidate normalization·scoring과 metric이 새로운 interface를 이룬다. Brown 등도 이 현상이 문맥에서 새 task를 학습하는지, 사전 학습 중 익힌 task를 식별하는지 확정하지 않았다.

### CLIP: class prompt를 분류기 가중치로 바꾼다

[[CLIP]]은 이미지 인코더와 텍스트 인코더를 대조적으로 사전 학습해 두 전역 표현을 같은 점수 공간에 놓는다. [[070_CLIP과 대조적 언어-이미지 사전 학습]]의 zero-shot 분류에서는 대상 자료의 label로 두 인코더를 갱신하지 않는다. 대신 각 후보 class 이름을 `a photo of a {label}` 같은 문장으로 만들고, 정규화된 text embedding을 선형 분류기의 class weight처럼 사용한다. 입력 image embedding과 가장 높은 cosine similarity를 가진 후보가 예측이 된다.

여기서 prompt는 GPT-3처럼 생성 모델의 입력 문맥에서 다음 token 분포를 조건화하지 않는다. **후보 class의 표현과 비교 집합을 합성**한다. 같은 CLIP 특징 위에 몇 개의 표지 예시로 logistic regression을 학습하는 1·2·4·8·16-shot linear probe도 별도 절차다. 따라서 zero-shot과 few-shot의 차이는 demonstration 수가 아니라 대상 자료의 label로 새 classifier weight를 학습했는지에 있다.

CLIP의 가중치가 고정돼도 과제 명세가 사라지지는 않는다. 후보 class 집합, label wording, task별 prompt와 80-template ensemble, cosine score와 metric이 남는다. 또한 zero-shot은 대상 자료의 ImageNet 표지 학습 예제 128만 개로 학습하지 않았다는 뜻이지, 4억 image–text pair에서 해당 개념이나 유사 이미지를 전혀 보지 않았다는 보장이 아니다.

### Flamingo: 동결 백본 사이의 bridge와 문맥을 함께 쓴다

[[Flamingo]]는 대조 목적으로 사전 학습한 NFNet-F6 시각 인코더와 규모별 인과적 언어 모델을 동결하고, 64개 시각 token을 만드는 Perceiver Resampler와 gated cross-attention block을 멀티모달 자료로 학습했다. 가장 큰 variant에서 새 gated block은 약 10B, Resampler는 194M이므로, 이는 고정 특징을 곧바로 prompt에 넣는 절차도 작은 adapter만 붙이는 절차도 아니다. 사전 학습 지식은 동결 백본의 표현과 새 bridge의 weights에 나뉘어 있다.

[[084_Flamingo와 게이트 교차 어텐션 기반 퓨샷 시각-언어 학습]]의 downstream benchmark는 최대 32-shot까지 비교하되 RareAct에는 zero-shot만 보고했다. 이 평가에서는 전체 weights를 다시 고정하고 image/video–text demonstration을 query 앞의 interleaved context에 둔다. Text state는 별도 key/value memory로 남은 시각 token을 gated cross-attention으로 읽어 다음 text를 생성하거나 후보 likelihood를 비교한다. 따라서 GPT-3와 마찬가지로 target-task example은 추론 activation을 조건화하지만, example은 text token만이 아니며 시각 입력이 일반 token sequence에 단순 삽입되는 것도 아니다. Gate도 few-shot마다 새로 학습되는 router가 아니라 사전 학습에서 배운 층별 scalar다.

CLIP과 Flamingo는 서로 다른 encoder·weights·자료를 사용하지만, 둘 다 대조 학습된 시각 표현을 활용한다. CLIP의 prompt는 후보 class embedding과 similarity classifier를 만들고 Flamingo의 prompt는 생성 언어 모델의 조건부 분포를 바꾸므로 그 표현이 도착하는 끝점도 다르다. Flamingo의 open-ended zero-shot도 text-only 예시 두 개로 출력 형식을 제공했고, close-ended zero-shot은 예시 없이 후보 likelihood를 비교했다. RICES support 선택·example 순서·2,048-token 학습 길이·생성 또는 후보 scoring도 남는다. 그러므로 가중치를 고정했다는 사실은 과제 명세나 적응 비용이 사라졌다는 뜻이 아니다.

### 멀티모달 bridge와 parameter update는 서로 다른 두 축이다

[[멀티모달 대규모 언어 모델]]을 비교할 때는 **시각 표현을 언어 계산으로 옮기는 방법**과 **그 경로를 학습할 때 어느 parameter에 gradient가 도착했는지**를 따로 적어야 한다. [[093_멀티모달 LLM과 시각-언어 연결 방식의 분화]]에서 검증한 공개 모델은 두 축이 독립적으로 조합될 수 있음을 보여 준다.

| 시스템 | 표현이 이동하는 bridge | 학습 단계의 update 경계 | downstream·평가에서 다시 확인할 것 |
| --- | --- | --- | --- |
| Frozen | vision encoder가 만든 continuous prefix를 autoregressive LM 입력 앞에 배치 | LM은 동결하고 vision encoder를 학습 | few-shot 예시는 추론 문맥을 바꾸지만 LM weight는 갱신하지 않음 |
| Flamingo | Perceiver Resampler의 visual memory를 삽입된 gated cross-attention이 읽음 | vision encoder·LM은 동결, Resampler·gated block은 학습 | downstream few-shot은 전체 weight를 다시 고정한 문맥 적응 |
| PaLI | ViT patch feature를 pooling 없이 mT5 encoder–decoder의 visual token으로 전달 | 224px 단계는 vision을 동결하고 language 부분을 갱신, 짧은 588px 단계는 전체를 갱신 | COCO·VQAv2 성능은 downstream task fine-tuning 조건 |
| BLIP-2 | 학습 query가 image feature를 압축하는 Q-Former와 projection | 2단계 pretraining에서 image encoder·LLM은 동결 | downstream captioning은 image encoder를 풀 수 있지만 LLM은 동결하는 별도 조건 |
| PaLM-E | encoder·projection의 continuous observation token을 text embedding 열에 interleave | 기본 구성과 562B는 encoder·projection·PaLM을 end-to-end로 갱신 | frozen-PaLM은 기본 설계의 설명이 아니라 비교 조건 |
| LLaVA | CLIP grid feature를 word-embedding 차원으로 옮기는 linear projection | 1단계는 projection만, 2단계는 vision encoder를 동결하고 projection·LLM을 visual instruction tuning으로 갱신 | 평가는 이 지시 적응 checkpoint의 결과 |
| GPT-4V | 외부에 공개된 image·text input→text output interface | 구체적 architecture·model size·training method 비공개 | 행동·배포·위험 자료로 bridge나 update 경로를 역추론하지 않음 |

이 표의 핵심은 prefix·cross-attention·query·projected token이 일렬의 발전 단계라는 것이 아니다. 연속 token을 입력에 넣는다는 표면적 유사성 안에도 Frozen처럼 LM을 고정하는 설계, LLaVA처럼 두 단계에서 LLM까지 갱신하는 설계, PaLM-E처럼 end-to-end로 학습하는 설계가 모두 있다. 반대로 동결 backbone을 쓴다고 해도 Q-Former처럼 별도 표현 병목을 학습할 수 있고, downstream 단계에서 동결 경계가 다시 바뀔 수 있다.

따라서 같은 `image + text → text`라는 입출력 서명은 지식이 이동한 길과 gradient가 흐른 길을 알려 주지 않는다. 또 benchmark 수치는 공통 multimodal pretraining checkpoint, task-specific fine-tuning checkpoint, visual instruction tuning checkpoint, generalist mixture checkpoint 가운데 어느 것을 측정했는지와 함께 읽어야 한다. 기능만 공개된 GPT-4V는 이 두 축의 빈칸을 추측으로 채우지 않는 사례다.

### Shared-core token model은 bridge를 없애기보다 경계를 다시 그린다

[[105_통합 멀티모달 아키텍처의 공유 범위와 입출력 경계]]는 joint embedding·modular bridge·shared encoder-decoder·early-fusion autoregressive model을 ‘통합’ 하나로 묶지 않는다. 과제에 도착하는 사전 학습 지식의 위치가 서로 다르기 때문이다.

| 경로 | 대표 사례 | 사전 학습 지식이 과제에 도착하는 위치 | 남는 modality 경계 |
| --- | --- | --- | --- |
| Joint embedding | CLIP·ImageBind | 후보·query와 비교할 정렬된 vector 좌표계 | Modality별 encoder·projection, 생성 decoder 없음 |
| Modular bridge | Flamingo·BLIP-2·LLaVA | 별도 visual representation을 LM activation으로 옮기는 cross-attention·query·projection | Encoder·bridge·LM과 update 단계 |
| Shared encoder-decoder core | Unified-IO 2 | ViT·AST의 연속 input embedding과 text·action·VQ-GAN output token을 multimodal denoising mixture와 encoder-decoder weights에 축적 | Pretrained ViT·AST는 pretraining 중 동결, image·audio VQ-GAN output tokenizer·decoder 분리 |
| Early-fusion autoregressive core | Chameleon·Emu3 | Interleaved image·text 또는 video token의 next-token distribution | 별도 visual tokenizer; Emu3 공개 post-training weight는 Chat·Gen으로 분리 |
| 제한 공개 native·single-network 공표 | Gemini 1.0·GPT-4o | 공개된 joint training·model I/O 범위까지만 기술 | Gemini pretrained family와 post-trained API·Apps output 차이, tokenizer·bridge·loss·layer와 rollout의 비공개 부분 |

Unified-IO 2는 single encoder-decoder core를 쓰지만 image input용 pretrained ViT, audio input용 AST와 image·audio output용 VQ-GAN tokenizer를 둔다. ViT·AST는 pretraining 동안 동결되고 instruction tuning 끝에서 fine-tuning되므로 ‘from scratch’는 모든 주변 component가 처음부터 공동 학습됐다는 뜻이 아니다. Chameleon과 Emu3도 discrete visual token부터 core Transformer를 공동 학습하지만 raw pixel을 token으로 바꾸는 tokenizer는 별도다. Shared core는 지식이 modality별 bridge 뒤 여러 output direction에 함께 도착하게 만들 수 있어도, 모든 component가 처음부터 끝까지 하나로 학습됐다는 뜻이 아니다.

또한 같은 architecture family가 여러 task를 지원한다는 사실과 한 checkpoint가 모두 지원한다는 사실은 다르다. Emu3의 공개 post-training weight는 understanding용 Chat과 image generation용 Gen으로 갈라지고, Gemini 1.0은 pretrained family report의 native text·image output과 post-trained API·Apps Model Card의 generated text output 범위가 다르며, GPT-4o도 공표한 가능한 입출력과 제품에서 먼저 열린 surface가 달랐다. 따라서 ‘통합’을 적응 경로로 읽을 때는 **tokenizer/encoder가 언제 학습됐는지, shared core에 어떤 loss가 도착했는지, output head와 post-training·release가 어디서 갈라졌는지**를 함께 적는다.

### DALL·E 2: 공유 좌표계를 생성 목표로 바꾼다

[[DALL·E 2]]의 연구 모델 unCLIP은 동결된 CLIP을 분류기나 매 잡음 제거 단계의 외부 채점기로 쓰지 않는다. 먼저 prior가 caption과 CLIP text embedding을 받아 가능한 **CLIP image embedding**을 생성하고, 확산 decoder가 그 image embedding과 선택적 caption을 조건으로 64×64 pixel image를 만든다. 두 확산 upsampler가 이를 256×256과 1,024×1,024로 확대한다.

CLIP의 사전 학습 지식은 여기서 후보 class의 고정 prototype이 아니라 **중간 생성 목표와 decoder의 조건 좌표계**로 도착한다. Prior·decoder·upsampler는 별도로 학습되므로 “CLIP을 동결했다”는 사실이 생성 stack의 새 학습 비용이 없다는 뜻은 아니다. 같은 image embedding을 확률적으로 다시 decoding하거나 embedding을 보간할 수 있다는 성질도, 전역 CLIP 표현이 pixel의 모든 세부를 보존해서가 아니라 의미·style의 일부를 압축하고 decoder가 여러 시각적 실현을 표본화하기 때문에 생긴다.

이 경로는 Flamingo와 방향도 다르다. Flamingo에서는 visual representation이 causal LM의 별도 key/value memory로 들어가 **text**를 생성한다. unCLIP에서는 caption으로 image-side representation을 먼저 만들고 이를 decoder에 넣어 **image**를 생성한다. 두 시스템 모두 고정된 사전 학습 표현과 새 bridge·generator를 결합하지만, 표현의 위치·출력 모달리티·downstream prompt의 역할은 같지 않다.

### Stable Diffusion: 텍스트 표현을 잡음 제거기의 조건 memory로 쓴다

[[Stable Diffusion]] v1은 CLIP image embedding을 생성 상태로 쓰지 않는다. 동결 CLIP ViT-L/14의 **비풀링 text token**이 U-Net 교차 어텐션의 key/value가 되고, U-Net의 공간 feature가 query가 된다. 실제 확산 상태는 사전 학습한 $f=8$ 오토인코더가 만든 64×64×4 공간 latent다. Caption→CLIP image embedding→pixel decoder라는 DALL·E 2 경로와, text token→latent U-Net의 여러 층이라는 Stable Diffusion 경로를 “둘 다 CLIP guidance”로 합치면 조건과 생성 상태를 동시에 잘못 놓는다.

CVPR 2022의 일반 [[잠재 확산 모델]]과 공개 v1도 나눠야 한다. 논문의 text-to-image LDM은 BERT tokenizer와 학습 가능한 조건 Transformer를 U-Net과 함께 최적화했지만, v1은 이미 사전 학습된 CLIP text encoder를 고정했다. 사전 학습 지식이 도착하는 인터페이스는 같은 cross-attention 형식 안에서도 학습 가능한 조건 encoder와 동결 encoder로 달라질 수 있다.

v1의 text encoder와 오토인코더를 고정해도 새 latent U-Net의 대규모 image–text 학습은 남는다. Inference prompt는 가중치를 바꾸지 않지만, token wording·길이·classifier-free guidance scale·sampler가 출력 분포를 바꾼다. 따라서 이 사례는 “고정 encoder→공짜 zero-shot 생성”이 아니라 **고정 text representation, 학습된 conditional generator, 현재 prompt와 sampling rule**의 세 층으로 읽어야 한다.

### 네 시각-언어 경로는 같은 shared embedding의 변형이 아니다

| 시스템 | 동결된 자산 | 새로 학습한 부분 | 표현이 도착하는 위치 | 추론 시 과제 명세 | 출력·점수 |
| --- | --- | --- | --- | --- | --- |
| CLIP zero-shot | image·text encoder | 대상 dataset에서는 없음 | class의 text prototype과 image embedding의 cosine score | 후보 label·prompt template·ensemble | class label |
| Flamingo | 별도 대조 학습 NFNet-F6·causal LM | Perceiver Resampler·gated cross-attention block | Resampler의 visual key/value memory와 LM activation | multimodal demonstration·순서·RICES·decoding | text 또는 후보 likelihood |
| DALL·E 2 unCLIP | CLIP image·text encoder | image-embedding prior·확산 decoder·두 upsampler | 전역 CLIP image-embedding target과 decoder condition | caption·guidance·sampling | image |
| Stable Diffusion v1 | CLIP text encoder·$f=8$ 오토인코더 | latent U-Net·cross-attention | text-token key/value와 64×64×4 공간 latent state | prompt·CFG scale·sampler | image |

네 시스템이 모두 시각·언어 사전 학습 자산을 재사용하더라도, 공유 표현을 어느 쪽에서 만들고 어떤 module이 query를 보내며 무엇을 생성하는지가 다르다. 이 표는 네 연구의 직접 계보를 주장하지 않는다. 각 architecture가 **고정 표현을 분류 prototype·조건 memory·생성 목표·잡음 제거 조건**이라는 서로 다른 interface로 재사용한다는 비교다.

`zero-shot`도 네 행을 하나로 묶는 이름이 아니다. CLIP은 대상 dataset의 label 예제로 encoder·classifier를 갱신하지 않은 분류 protocol이고, Flamingo는 downstream weights를 고정하되 출력 형식 예시·후보 likelihood·RICES가 남는다. DALL·E 2 논문의 MS-COCO zero-shot은 생성 stack을 COCO에 미세조정하지 않은 평가 조건이며, 일반적인 prompt-to-image 사용 전체를 자동으로 zero-shot task transfer라고 부르지는 않는다.

### Codex: 매개변수·prompt·검증기에 과제 정보를 나눈다

[[OpenAI Codex (2021)]]의 연구 계열은 GPT 계열 초기값에서 공개 GitHub Python 코드의 다음-token 예측으로 매개변수를 갱신했다. 연구진은 최대 12B 모델을 1,000억 token 동안 학습했고, 별도의 Codex-S는 올바른 독립 함수와 docstring으로 다시 지도 미세조정했다. GPT 초기화는 수렴을 빠르게 했지만 처음부터 학습한 조건보다 최종 성능을 높이지는 않았다.

평가할 함수의 명세는 signature와 docstring이라는 입력에 남았다. 모델은 하나 또는 여러 후보를 생성하고, HumanEval은 unit test 통과 여부로 기능적 정확성을 판정했다. Codex-12B Table 1의 pass@1은 28.81%, pass@100은 72.31%였지만 두 수치는 같은 사용 경험이 아니다. 큰 $k$는 더 많은 표본 예산과 정답 후보를 알아보는 test oracle을 포함한다. 100개에서 평균 log-probability로 하나만 고른 Codex-S 결과는 44.5%, test를 통과한 후보가 하나라도 있던 비율은 77.5%였다.

따라서 이 사례에서 전이는 코드 분포에 맞춘 **weights**, 함수 합성 분포에 맞춘 **supervised weights**, 현재 문제를 적는 **prompt**, 후보를 검사하는 **external evaluator**로 나뉜다. GPT-3의 in-context learning처럼 가중치를 고정한 채 demonstration만 바꾸는 절차도 아니고, unit test가 모델 내부 지식으로 흡수된 절차도 아니다.

### QLoRA: 기반 지식과 과제 update를 서로 다른 artifact에 둔다

[[QLoRA]]는 instruction tuning의 새로운 objective가 아니라 **어느 parameter를 어떤 memory 표현으로 갱신할지** 정하는 적응 방법이다. [[091_QLoRA와 4비트 양자화 미세조정]]의 Guanaco는 OASST1 conversation을 supervised cross-entropy로 학습했다. 이 data interface는 전체 weights를 미세조정할 때도 사용할 수 있지만, QLoRA에서는 LLaMA base를 NF4로 저장해 동결하고 모든 linear Transformer block에 붙인 BF16 LoRA adapter만 갱신했다.

따라서 `4-bit fine-tuning`이라는 이름도 세 층으로 나눠야 한다. Base는 NF4로 **저장**되고, 사용할 때 BF16으로 역양자화돼 **계산**되며, gradient update는 별도 adapter에만 적용된다. Task supervision은 prompt-only 방식처럼 현재 context에만 남지 않고 adapter weights에 축적되지만, BERT·FLAN의 원 설정처럼 pretrained parameter 전체를 다시 쓰지도 않는다.

이 경계는 실행 가능성과 지식 위치를 함께 바꾼다. 논문은 33B를 단일 24GB consumer GPU, 65B를 단일 48GB professional GPU에서 OASST1으로 미세조정했다. 그러나 hardware envelope가 작아졌다는 사실은 instruction data가 더 적게 필요하다는 뜻이 아니며, NF4+double-quantization QLoRA의 5-shot MMLU 평균 53.1은 같은 LLaMA 규모·data 조건의 BF16 LoRA 53.0과 비교한 결과다. 7B–65B 전체의 full-parameter fine-tuning parity를 입증하지 않는다.

Adapter를 별도 배포할 수 있다는 사실도 base를 없애지 않는다. Guanaco adapter를 실행하려면 당시 신청 승인형 비상업 연구 조건의 LLaMA 1 base가 필요했다. 사전 학습 지식이 base에 남고 task update가 adapter에 놓인다는 계산 경계는 곧 **base artifact, adapter artifact, data와 license를 함께 식별해야 하는 재현 경계**다.

### LoRA 변형: 과제 감독의 위치는 같아도 adapter 내부는 다르다

[[저순위 적응]]의 AdaLoRA·DoRA·VeRA·rsLoRA·LoftQ는 instruction·label·preference처럼 **무엇을 학습할지 정하는 task objective가 아니다.** 같은 supervised data와 loss를 사용해도 동결 base 옆의 update를 어떻게 표현하고 초기화할지가 달라진다.

| 방법 | 바꾸는 adapter 내부 경계 | 바꾸지 않는 것 |
| --- | --- | --- |
| AdaLoRA | 총 rank budget을 SVD형 singular triplet 사이에 재배분 | Task data·loss와 frozen-base 경계 |
| DoRA | Pretrained weight를 magnitude와 direction으로 분해하고 direction에 LoRA 적용 | Task supervision의 위치 |
| VeRA | 동결 random factor matrix 한 쌍을 공유하고 layer별 두 scale만 학습 | Base 지식과 adapter update의 분리 |
| rsLoRA | Rank가 커질 때 scaling을 `α/√r`로 안정화 | Target module과 task objective |
| LoftQ | Quantization residual을 반영해 low-rank factor를 초기화 | 초기화 뒤 quantized base 동결 |

따라서 PEFT 변형의 품질 차이를 “과제 지식이 다른 곳에서 왔다”로 해석해서는 안 된다. 차이는 같은 supervision이 접근할 수 있는 update subspace, layer별 capacity, optimization scale과 시작점에 있다. 이 경계는 재현 장부도 넓힌다. Base·data·loss뿐 아니라 target module, layer별 rank, magnitude vector, shared random seed, rank scaling, quantization bit와 initialization iteration을 기록해야 한다.

또한 trainable parameter 수는 전체 비용의 일부다. VeRA는 layer별 factor를 scale vector로 줄이지만 frozen base·activation·matrix 연산은 남고, DoRA는 학습 중 normalization graph가 추가되지만 최종 weight에 병합할 수 있어 추가 inference latency가 필수는 아니다. Parameter storage, training VRAM·time과 inference graph를 따로 비교해야 한다.

### 지속 사전 학습: 적응 경로에 시간축을 더한다

[[지속 사전 학습]]은 한 목표 영역에서 끝나는 ULMFiT·DAPT와 달리 $D_1,D_2,\ldots,D_T$가 차례로 들어오는 동안 checkpoint를 반복 갱신한다. 새 corpus의 LM loss가 낮아지는 **가소성**, 이전 corpus·과제의 성능을 유지하는 **보존**, 앞선 분포가 뒤의 학습에 주는 **전이**를 단계별로 따로 측정한다. 불변 사실·오래된 사실·새 사실을 나눈 지식 평가도 평균 downstream score와 별도다.

이 경로는 PEFT와 직교한다. 전체 weight나 확장 parameter를 갱신할 수도 있고 LoRA·adapter를 쓸 수도 있지만, 작은 update를 쓴다는 사실만으로 replay·distillation·망각 평가가 생기지는 않는다. 반대로 [[검색 증강 생성]]은 외부 index와 현재 context를 교체하므로 가중치 밖에 최신 자료를 둔다. [[인간 피드백 강화학습|RLHF]]은 지시·선호 행동을 직접 최적화한다. 같은 `post-training`이라는 이름 아래에서도 **비표지 corpus+LM loss**, **지도 응답·선호 objective**, **외부 document retrieval**을 합치지 않는다.

따라서 최신성은 하나의 위치가 아니다. 넓은 분포와 언어 규칙은 base update, task-specific 행동은 adapter나 전체 fine-tuning, 자주 바뀌고 출처가 필요한 사실은 외부 memory에 둘 수 있다. Versioning·A/B test·rollback은 이 선택들의 학습 성질이 아니라 어느 checkpoint와 index 조합을 배포하고 되돌릴지 관리하는 운영 층이다.

### ‘과제 전용 구조가 사라졌다’는 말의 여러 경계

이 연구들을 함께 보면 이 표현도 단계적으로 좁혀야 한다.

- ELMo: 과제 구조는 유지하고 사전 학습 특징을 추가했다.
- ULMFiT: 같은 LM·classifier 구조를 여러 text classification 자료에 재사용했다.
- BERT·GPT-1: 기반 network는 공유하지만 task head와 입력 변환은 남았다.
- GPT-2 zero-shot: task head 학습도 없지만 cue·scoring·decoding 설계는 남았다.
- XLM zero-shot XNLI: 영어 task head·fine-tuning은 남고 target-language label만 사용하지 않았다.
- T5: task-specific head를 공통 decoder로 바꿨지만 prefix·label text·dataset·metric과 task별 fine-tuning은 남았다.
- FLAN: 여러 task의 supervision을 공통 weights에 넣었지만 현재 instruction·OPTIONS·template·metric과 cluster별 평가 checkpoint가 남았다.
- GPT-3 in-context: task-specific weight update는 없지만 instruction·demonstration·context budget·scoring과 metric이 남았다.
- CLIP zero-shot: 대상 자료로 새 classifier를 학습하지 않지만 후보 class·prompt template·ensemble·similarity score와 metric이 남았다.
- Flamingo few-shot: 대상 과제의 weight update는 없지만 사전 학습된 대규모 bridge, multimodal support 선택·순서, text 형식, context 예산, 생성·후보 scoring이 남았다.
- Frozen·PaLI·BLIP-2·PaLM-E·LLaVA: text 출력 인터페이스를 공유해도 continuous prefix·encoder–decoder token·query 병목·observation token·linear projection이 다르고, 시각 encoder·bridge·LM을 갱신하는 단계도 다르다.
- GPT-4V: image-input 기능과 안전 평가는 공개됐지만 bridge·parameter update 경계는 비공개다.
- DALL·E 2 unCLIP: CLIP은 고정됐지만 image-embedding prior·확산 decoder·두 upsampler의 학습과 caption·guidance·sampling 조건이 남았다.
- Stable Diffusion v1: CLIP text encoder와 오토인코더는 고정됐지만 latent U-Net의 학습과 prompt token·CFG scale·sampler·후처리 파이프라인이 남았다.
- Codex·Codex-S: code-specific·function-specific weight update가 있고, docstring·sampling budget·unit-test 또는 ranking 선택이 남았다.
- QLoRA Guanaco: Base 전체 update는 없지만 all-linear LoRA adapter, target rank·scale, NF4 block·BF16 compute, OASST1 selection과 base checkpoint·license가 남았다.
- AdaLoRA·DoRA·VeRA·rsLoRA·LoftQ: Task-specific adapter는 남고, 그 안의 rank allocation·weight coordinates·shared basis·scaling·quantization initialization이 서로 다르다.

과제별 deep architecture가 줄어들어도 과제 명세가 사라지는 것은 아니다. 명세는 label schema, input serialization, prompt, candidate scoring, conditioning path, sampling rule, metric으로 위치를 바꾼다.

### 자료 효율도 서로 다른 분모를 갖는다

ULMFiT의 100개 label 실험, BERT의 작은 task dataset fine-tuning, GPT-2와 CLIP의 zero-shot은 모두 ‘적은 표지 자료’로 묶일 수 있다. 그러나 분모가 다르다.

- 사전 학습 corpus와 계산은 얼마나 사용했는가?
- 목표 영역의 비표지 text는 사용했는가?
- task label은 가중치 갱신에 쓰였는가, 평가에만 쓰였는가?
- input cue·demonstration을 몇 개 제공했는가?
- target 언어의 비표지 text와 task label 가운데 무엇을 사용했는가?
- 공통 pretrained checkpoint 뒤 task별 weight를 따로 만들었는가?
- 다른 task의 instruction–target mixture로 weights를 갱신했으며, unseen 평가를 위해 holdout마다 별도 checkpoint를 만들었는가?
- 후보 class 이름·prompt template·ensemble과 평가 절차를 사람이 얼마나 설계했는가?
- 시각·언어 backbone을 동결했더라도 새 bridge를 어떤 multimodal mixture로 학습했으며, encoder·bridge·LM의 update 경계가 downstream fine-tuning에서 바뀌었는가? 비교하는 수치는 pretraining·task fine-tuning·instruction tuning 중 어느 checkpoint의 것인가?
- 동결된 CLIP이나 오토인코더 뒤 prior·decoder·latent U-Net을 어떤 image–text 자료와 계산으로 학습했으며, 고정 표현은 target·state·condition 가운데 무엇인가?
- 후보를 몇 개 생성하며, 정답을 고르는 test·ranking·사람 검토의 비용은 얼마인가?
- Provider interface가 model-parameter gradient, continuous-input gradient, model output만 반환하는 API 가운데 어디까지 허용하는가?
- Full fine-tuning parameter, adapter parameter와 입력 context token 중 task supervision이 실제로 어디를 바꾸며, base·adapter를 실행하는 storage/compute dtype과 memory는 얼마인가?

표지 예시 수 하나만 비교하면 pretraining data·compute와 task specification 비용을 숨긴다.

## 검증과 한계

### 확인된 사실과 비교 해석

확인된 사실:

- ELMo는 고정 biLM 내부 층의 과제별 가중합을 여섯 기존 task model에 추가했다.
- ULMFiT는 일반 LM·목표 영역 LM·분류기의 세 단계와 안정화 기법을 여섯 text classification 자료에 적용했다.
- BERT와 GPT-1은 작은 task head·input transformation과 전체 model fine-tuning을 사용했다.
- GPT-2는 task-specific parameter update 없이 여러 cue·scoring 방식으로 zero-shot을 평가했다.
- XLM은 target 언어의 비표지 text를 사전 학습에 사용하고 영어 NLI label로 fine-tune한 뒤 target-language label 없이 XNLI를 평가했다.
- T5는 여러 task를 공통 text-to-text interface로 표현했지만 최종 대표 설정에서 task별 supervised fine-tuning을 사용했다.
- FLAN은 다른 task cluster의 instruction–target mixture로 전체 model을 미세조정하고, 보류 cluster에는 demonstration 없이 instruction을 주었다. 평가 cluster마다 별도 checkpoint를 사용했다.
- GPT-3는 zero/one/few-shot 모두 task-specific gradient update 없이 평가됐고, few-shot은 보통 문맥 안에 10–100개 demonstration을 사용했다.
- CLIP zero-shot은 대상 자료의 label로 encoder나 classifier를 학습하지 않고 class prompt의 text embedding을 image embedding과 비교했다. 같은 특징 위의 few-shot 결과는 표지 예시로 logistic regression을 학습한 별도 조건이다.
- Flamingo는 시각·언어 backbone을 동결한 채 Resampler와 gated block을 사전 학습했고, downstream few-shot에서는 전체 weights를 고정한 채 multimodal prompt를 사용했다.
- Frozen은 동결 LM 앞의 continuous image prefix를 학습했다. PaLI는 224px 단계와 588px 단계의 update 경계가 달랐고, BLIP-2는 pretraining에서 두 backbone을 동결했지만 downstream captioning에서 image encoder를 풀 수 있었다.
- PaLM-E의 기본·562B 구성은 encoder·projection·PaLM을 end-to-end로 갱신했고 frozen-PaLM은 별도 비교 조건이었다. LLaVA는 projection-only 정렬 단계 뒤 vision encoder를 동결하고 projection·LLM을 지시 미세조정했다.
- GPT-4 technical report는 image·text input 예시를 제공하지만 구체적 architecture·model size·training method를 공개하지 않았다.
- DALL·E 2의 unCLIP은 동결 CLIP 공간에서 prior가 image embedding을 생성하고 확산 decoder·upsampler가 pixel image를 만들었다. 이 경로는 CLIP gradient guidance가 아니다.
- Stable Diffusion v1은 동결 CLIP의 text token을 latent U-Net 교차 어텐션의 조건으로 사용하고, 오토인코더의 공간 latent에서 확산했다. 일반 LDM 논문의 text conditioner는 별도로 학습되는 Transformer였다.
- Codex는 GPT 계열 모델을 Python 코드 분포로 계속 학습했고, Codex-S는 올바른 독립 함수로 추가 지도 미세조정했다. HumanEval 결과는 표본 수와 unit-test 또는 ranking 선택에 따라 달라졌다.
- QLoRA는 LLaMA base를 NF4로 저장해 동결하고 BF16으로 역양자화해 계산하면서 all-linear LoRA adapter만 갱신했다. Guanaco는 OASST1 9,846개 선택 example의 SFT이며 RLHF가 아니다.
- LoRA 이후 PEFT 변형은 task label 수를 자동으로 줄이지 않는다. 같은 data·loss 아래에서 update의 budget·좌표·basis·scale·초기화를 바꾸며, trainable parameter 감소와 전체 training time·memory 감소를 같은 비율로 간주할 수 없다.
- 지속 사전 학습은 시간·영역 순서의 비표지 corpus에서 LM objective를 이어 학습하고 새 분포 적응·이전 능력 보존·전이를 함께 평가한다. DAPT·TAPT는 이 분포 적응의 토대지만 무기한 stream의 보존을 직접 평가한 설정은 아니다.
- Lifelong pretraining·continual knowledge learning·CPT 연구는 2022년에 공개됐다. 따라서 2025년은 이 문제의 최초 연도가 아니며, LoRA·RAG·RLHF·versioning도 같은 알고리즘의 구성 요소로 자동 합쳐지지 않는다.
- 파운데이션 모델 보고서는 BERT·GPT-3·CLIP을 서로 다른 적응 방식을 가진 공통 기반 사례로 묶고, foundation model을 완성된 system이 아닌 중간 자산으로 구분했다.

비교를 통한 해석:

- 2018–2024년의 변화는 단순히 ‘더 큰 사전 학습’이 아니라 task adaptation이 feature→전체 weights→별도 adapter→context로 갈라지고, 새 corpus가 시간순 base update 또는 교체 가능한 외부 memory로 나뉘며, shared parameter가 언어 경계를 넘고, output head가 공통 text interface로 옮겨진 과정이었다. FLAN은 다른 과제의 supervision과 현재 instruction을 weights 안팎에 나누었고, QLoRA는 base와 task update를 동결 weight·adapter artifact에 나누었다. LoRA 변형들은 그 위치를 다시 옮기기보다 adapter 내부의 allocation·parameterization·sharing·scaling·initialization을 분화했다. 지속 사전 학습은 이 적응을 여러 시점에 반복하며 새·과거 분포를 함께 평가하고, RAG는 최신 자료를 weight 밖에 둔다. GPT-3는 GPT-2의 cue를 여러 demonstration이 들어가는 측정 가능한 in-context 조건으로 확장했으며, CLIP은 prompt를 이미지와 비교할 class representation으로 사용했고, Codex는 code-specific weights와 외부 검증을 결합했다.
- Flamingo는 CLIP의 class-prototype 경로나 GPT-3의 text-only ICL을 단순 연장하지 않는다. 시각 표현은 학습된 bridge를 거쳐 생성 모델에 도착하고, 대상 과제의 example은 multimodal context를 통해 도착하는 두 층의 적응을 결합한다.
- 멀티모달 전이는 **표현 이동 위치**와 **gradient update 범위**의 두 축으로 읽어야 한다. 같은 `image + text → text` interface와 유사한 token 삽입이라도 동결 LM·bridge-only·end-to-end·단계별 update를 자동으로 결정하지 않는다.
- 멀티모달 benchmark는 bridge 설계뿐 아니라 pretraining·task fine-tuning·instruction tuning·generalist mixture의 어느 checkpoint를 측정했는지에 따라 달라진다.
- DALL·E 2와 Stable Diffusion은 서로 다른 사전 학습 CLIP 모델을 서로 다른 interface로 재사용한다. 전자는 image embedding을 prior의 생성 target과 decoder condition으로, 후자는 text token을 latent U-Net의 cross-attention memory로 사용한다. 같은 CLIP 계열 encoder가 등장한다는 사실은 weights·생성 상태·학습 경로가 같다는 뜻이 아니다.
- 모델의 범용성은 task specification의 제거보다 specification 위치의 이동으로 보는 편이 정확하다.
- feature extraction, full fine-tuning, parameter-efficient adapter tuning과 prompting은 서로를 완전히 대체하기보다 계산·자료·gradient access·적응력 조건에 따라 선택되는 인터페이스다.
- 파운데이션 모델은 기존 경로의 종착점이나 새 algorithm이 아니라, 서로 다른 경로를 공통 기반–적응–배포 관계로 읽게 하는 상위 범주다.

### 아직 입증되지 않은 계보

이 자료만으로 다음을 확정할 수는 없다.

- ELMo→ULMFiT→BERT→GPT-2가 하나의 직접 기술 계보를 이룬다는 주장
- 매개변수 적응에서 문맥 적응으로 이동하는 것이 모든 과제의 필연적 종착점이라는 주장
- zero-shot prompting이 fine-tuning보다 보편적으로 자료·계산 효율적이라는 주장
- GPT-2의 수행이 불연속적 창발이며 model size 하나가 원인이라는 주장
- 사전 학습 표현이 사람과 같은 언어 지식 단위로 내부화된다는 주장
- shared multilingual representation이 모든 언어에 같은 품질의 의미 공간을 제공한다는 주장
- T5의 짧은 task prefix가 현대 natural-language instruction following과 unseen-task zero-shot을 직접 입증했다는 주장
- FLAN에서 작은 model의 성능 악화와 큰 model의 개선이 보편적인 instruction-following 창발 임계점이라는 주장
- FLAN의 여러 과제 mixture가 어떤 특정 cluster의 지식을 어떤 보류 과제로 옮겼는지에 대한 인과
- GPT-3의 문맥 내 수행이 새로운 algorithm을 내부에서 학습한 것인지 사전 학습에서 본 task pattern을 식별한 것인지에 대한 단정
- 문맥 내 학습이 모든 과제에서 미세조정보다 정확하거나 자료·계산 효율적이라는 주장
- CLIP의 shared embedding이 일반적인 멀티모달 이해를 보장하거나, natural-language prompt가 임의의 시각 과제를 자동으로 정의한다는 주장
- CLIP의 prompt classifier와 GPT-3의 text ICL이 Flamingo로 직접 이어진 단일 계보라는 주장, 또는 16개 benchmark 결과가 일반적인 멀티모달 추론을 입증한다는 주장
- CLIP zero-shot 분류→Flamingo→DALL·E 2→Stable Diffusion이 하나의 직선적 기술 계보이거나, 네 시스템에서 `embedding`·`cross-attention`·`guidance`가 같은 계산 역할을 한다는 주장
- Frozen→Flamingo→PaLI→BLIP-2→PaLM-E→LLaVA가 하나의 직선적 계보를 이룬다는 주장, 또는 GPT-4V의 외부 행동에서 특정 bridge·update 경계를 역추론할 수 있다는 주장
- DALL·E 2의 CLIP image embedding과 Stable Diffusion의 오토인코더 공간 latent가 같은 잠재 공간이며, 어느 한쪽의 평가가 다른 쪽의 품질·효율·prompt 이해를 입증한다는 주장
- Codex의 짧은 Python 함수 성능이 여러 파일의 소프트웨어 개발·보안·유지보수 능력을 보장하거나, pass@100이 첫 IDE 제안의 정확도와 같다는 주장
- 같은 파운데이션 모델을 사용하는 모든 downstream system에서 결함이 동일한 형태와 크기로 나타난다는 주장
- 파운데이션 모델 자체의 benchmark가 적응 자료·검색·도구·정책·UI를 포함한 완성 system의 성능을 대표한다는 주장
- QLoRA의 weight-memory 절감이 더 적은 task data, 모든 hardware의 더 빠른 학습, 7B–65B full-parameter parity나 base license와 무관한 독립 adapter를 보장한다는 주장
- 특정 LoRA 변형의 제한된 benchmark 우위가 모든 domain shift·생성 LLM·rank budget에서 보편적이거나, 작은 adapter가 기업 채택·비용·환경 효과를 자동으로 보장한다는 주장
- 405M·10B model과 제한된 stream의 지속 사전 학습 결과가 수천억 parameter production model의 빈번한 사실 교체·무중단 배포·장기간 무망각을 보장한다는 주장
- 최신 corpus를 weight에 학습하거나 외부 index를 교체했다는 사실만으로 상충 사실의 판정·출처 추적·오래된 지식 삭제·안전 회귀가 해결된다는 주장

더 정확한 결론은 각 연구가 공통 문제를 다른 경계에 배치했고, 후대 시스템이 이 인터페이스들을 다시 조합한다는 것이다. 현대 모델도 고정 embedding, retrieval feature, parameter-efficient tuning, full fine-tuning, instruction prompt와 tool schema를 함께 쓸 수 있다.
