# 생성은 무엇을 한 단계씩 고르는가 — 파형·이미지 토큰·잠재 잡음

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[concept.자기회귀-생성|자기회귀 생성]], [[concept.잠재-확산-모델|잠재 확산 모델]]<br>
> **읽고 나면:** 파형 표본·이산 이미지 토큰·CLIP 이미지 잠재·연속 잠재 잡음이 만드는 생성 단계, 손실과 평가의 경계를 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 비교 질문과 잠정 결론

생성 모델을 자기회귀와 확산이라는 두 이름만으로 비교하면, 실제로 **무엇을 한 번의 선택 또는 한 번의 갱신으로 삼는지**가 사라진다. [[WaveNet]]은 양자화한 오디오 표본 하나의 범주를 다음 단계에서 고른다. [[DALL·E (2021)]]는 압축된 이미지 격자의 이산 코드 하나씩을 텍스트와 같은 흐름에서 생성한다. DALL·E 2의 unCLIP은 먼저 CLIP 이미지 임베딩을 만들고 여러 확산 단계로 이미지를 복원한다. [[잠재 확산 모델]]은 픽셀 대신 압축 잠재의 잡음을 반복해서 제거한다.

잠정 결론은 **생성 단위가 품질·속도·제어의 한계를 정하는 중요한 인터페이스**라는 것이다. 더 작은 단위가 언제나 더 세밀하거나 더 느린 것은 아니며, 더 압축된 잠재가 언제나 더 빠르거나 더 충실한 것도 아니다. 출력 단위, 한 단계의 연산, 필요한 단계 수, 후처리·후보 선택, 평가 기준을 함께 읽어야 한다.

### 네 장부를 먼저 나눈다

| 장부 | 물어야 할 질문 | 한 단어로 합치면 생기는 오해 |
| --- | --- | --- |
| 표현 | 한 단계에서 다루는 값은 표본·코드·연속 잠재·픽셀 중 무엇인가? | ‘이미지를 직접 만든다’ |
| 생성 절차 | 앞 출력을 조건으로 다음 값을 뽑는가, 잡음을 반복해 갱신하는가? | ‘병렬 생성’ 또는 ‘순차 생성’ |
| 조건과 선택 | text·CLIP 표현·화자 특징은 어디에 들어가며, 후보는 누가 고르는가? | ‘프롬프트를 이해한다’ |
| 평가 | 확률·FID·MOS·사람 선호 중 무엇을 어떤 조건에서 재는가? | ‘더 좋은 생성 모델’ |

이 분석은 자기회귀가 확산보다 낫다는 순위표가 아니다. 각 연구가 실제로 만든 표현과 표본화 절차를 비교해, 같은 ‘생성’이 왜 서로 다른 실패 조건을 갖는지 밝힌다.

## 2단계 — 작동 원리

### 같은 요청에서 달라지는 중간 대상

“부드러운 목소리로 짧은 안내를 들려주고, 옆에는 빨간 자전거 그림을 만든다”는 요청을 생각해 보자. WaveNet 계열의 중심 중간 대상은 시간 순서의 오디오 표본이다. DALL·E 1의 중심 대상은 압축된 이미지 격자의 이산 code다. unCLIP은 텍스트와 닮은 CLIP 이미지 임베딩을 먼저 만들고, LDM은 잡음이 섞인 연속 잠재를 조금씩 깨끗한 잠재로 바꾼다.

최종 결과가 소리·이미지라는 사실은 같아도, model이 직접 확률을 주거나 갱신하는 값은 다르다. 따라서 파형 자체를 출력한다는 말은 이미지의 RGB pixel을 한 번에 내보낸다는 뜻이 아니고, 잠재 확산이 이미지를 만든다는 말은 최종 image decoder가 없다는 뜻도 아니다.

### 생성 단계의 공통점과 차이

자기회귀 방식은 이미 선택한 앞 출력이 다음 선택의 조건이 된다. WaveNet은 앞선 파형 표본에서 다음 256개 μ-law 범주 가운데 하나의 확률분포를 만들었다. DALL·E 1도 텍스트 token 뒤에서 image token을 순차적으로 표본화했다. 정답 전체가 있는 훈련에서는 많은 위치를 함께 계산할 수 있어도, 새 결과를 만들 때는 앞 선택이 다음 조건이 된다.

확산 방식은 처음의 무작위 잡음 또는 잡음 잠재에서 시작해 같은 표현 전체를 여러 단계 갱신한다. 각 단계가 독립된 최종 pixel을 한 번에 확정한다는 뜻은 아니다. Stable Diffusion v1의 reference 설정도 잠재 U-Net을 여러 번 호출한 뒤 마지막 잠재를 decoder로 픽셀 이미지로 바꾼다. 잠재 공간은 한 호출의 공간 비용을 줄이지만, 반복 갱신 자체를 없애지 않는다.

## 3단계 — 기술과 근거

### WaveNet: 파형 표본의 확률을 차례로 고른다

2016년 WaveNet은 16비트 PCM 진폭을 μ-law로 압축해 256개 범주로 양자화하고, 앞 표본들에 조건화한 다음 표본의 categorical distribution을 학습했다. 원시 파형을 다룬다는 말은 스펙트럼 특징을 별도 보코더가 복원하는 대신 최종 파형 표본을 model의 출력 대상으로 삼았다는 뜻이다. 연속 진폭의 확률밀도를 그대로 냈다는 뜻은 아니다.

이 선택은 시간 해상도의 비용을 드러낸다. 원형은 16kHz 음성에서 1초에 약 16,000번의 다음-표본 선택이 필요했다. 팽창 인과 합성곱은 훈련 위치를 병렬 계산하고 수용 영역을 넓혔지만, 실제 표본화의 앞뒤 의존은 남았다. TTS 실험은 언어·음성 특징과 화자 ID에 조건화했으므로, 원형의 직접 파형 생성은 단일 text-to-waveform 시스템이라는 주장과도 구분한다.

### DALL·E 1: 이미지 pixel이 아니라 이산 code를 순차로 고른다

2021년 DALL·E는 256×256 이미지를 32×32 격자, 곧 1,024개의 dVAE code로 바꿨다. 각 위치의 codebook은 8,192개 범주를 가졌으며, 8,192는 한 이미지의 token 수가 아니라 위치 하나에서 고를 수 있는 값의 수다. 이 압축은 Transformer가 픽셀 수보다 훨씬 짧은 시퀀스를 다루게 했지만, 가는 선·글자·고주파 세부를 잃을 수 있는 손실 압축이기도 했다.

이미지 token은 최대 256개의 텍스트 token 뒤에서 디코더 전용 Transformer가 생성했다. 따라서 DALL·E 1은 “text encoder가 의미를 완성하고 image decoder가 그림을 그린다”는 단순한 두 모듈 구조가 아니라, text와 image의 공동 자기회귀 분포다. 대표 비교에서 512개 이미지를 만든 뒤 별도 대조 모델로 문구 적합도를 재순위화한 점도 중요하다. 보이는 최종 한 장은 생성 분포뿐 아니라 후보 수와 선택기의 결과다.

### unCLIP: 중간 이미지 임베딩과 픽셀 복원을 나눈다

DALL·E 2 연구 모델 unCLIP은 text에서 곧바로 이미지 code나 pixel을 만드는 구조가 아니다. 동결 CLIP의 text 표현에서 prior가 조건부 CLIP **이미지** 임베딩을 생성하고, 확산 decoder가 64×64 이미지를 만든 뒤 두 업샘플러가 1,024×1,024까지 높인다. 같은 잠재에 여러 시각적 실현이 대응할 수 있게 의미·스타일의 중간 표현과 최종 세부를 나눈 설계다.

여기서 shared embedding은 생성 결과 그 자체가 아니다. 논문은 text embedding을 image embedding 자리에 바로 넣는 우회보다 prior를 거친 결과가 좋았음을 보고했다. 또한 prior와 기본 decoder의 classifier-free guidance를, 매 단계 외부 CLIP gradient로 부분 이미지를 채점하는 방식과 혼동하지 않는다. ‘CLIP을 쓴 확산’이라는 한 문장만으로는 조건이 들어가는 위치와 후보가 선택되는 위치를 알 수 없다.

### 잠재 확산: 픽셀 대신 손실 압축된 연속 잠재를 반복 갱신한다

LDM은 먼저 오토인코더로 이미지를 잠재 $z$에 압축하고, 그 잠재에 넣은 잡음을 U-Net이 예측·제거하도록 학습한다. Stable Diffusion v1에서 512×512×3 이미지는 64×64×4 잠재로 바뀐다. 공간 위치는 64분의 1, 채널을 포함한 스칼라 수는 48분의 1이지만, 이 수치를 전체 계산이 정확히 그 비율만큼 줄었다는 뜻으로 읽으면 안 된다.

텍스트 조건은 동결 CLIP text encoder의 비풀링 token 표현이 U-Net 교차 attention에 들어가는 형태다. 이는 unCLIP의 CLIP 이미지 embedding prior와 다른 인터페이스다. LDM은 압축률을 높이면 호출당 비용을 줄일 수 있지만 복원 가능한 세부를 잃을 수 있고, 확산 단계 수와 guidance scale은 프롬프트 충실성·다양성·시간의 절충을 다시 만든다.

### 같은 ‘품질’이 아닌 서로 다른 측정

WaveNet은 정해진 문장·언어에서 청취자가 평가한 MOS를 보고했다. DALL·E 1은 MS-COCO 사람 비교, FID와 CUB domain shift를 함께 보였으며, 512개 후보 재순위화 조건이 들어갔다. unCLIP은 GLIDE 및 DALL·E 1과의 사람 선호·FID 비교를 분리했고, LDM은 압축률·과제·guidance 조건별 FID와 처리량을 비교했다.

따라서 WaveNet의 자연스러운 음성과 DALL·E 1의 caption matching, LDM의 MS-COCO FID는 같은 한 줄의 ‘생성 능력’ 점수가 아니다. 출력 양식, 자료 분포, 선택기, 사람 판단 또는 자동 지표가 모두 다르다. 또한 후보를 여러 개 만든 뒤 재순위화하는 pipeline과 단일 sample의 품질을 혼동하면 generator 자체의 기여를 과대평가하게 된다.

## 검증과 한계

### 확인된 사실

- WaveNet 원형은 양자화한 파형 표본의 자기회귀 categorical distribution을 사용했고, 높은 시간 해상도 때문에 순차 표본화 비용이 컸다.
- DALL·E 1은 dVAE의 이산 image code와 text token을 하나의 자기회귀 흐름에서 모델링했으며, 대표 결과에 별도 대조 재순위화가 들어갔다.
- unCLIP은 CLIP image embedding prior, 64×64 확산 decoder와 두 업샘플러를 구분한 계층적 생성 구조였다.
- LDM은 오토인코더 잠재에서 잡음 제거를 반복하며, Stable Diffusion v1은 CLIP token 교차 attention과 특정 sampler·step 설정을 사용한 별도 배포물이다.

### 비교를 통한 해석

출력 단위는 model이 보아야 할 시퀀스 길이·복원 손실·한 단계의 난도와 사용자에게 보이는 제어점을 함께 바꾼다. 이산 token으로 압축한다고 해서 모든 공간 관계가 보존되는 것은 아니고, 연속 latent에서 확산한다고 해서 세부가 자동으로 살아나는 것도 아니다. 생성 방식의 차이는 단순한 속도 순위가 아니라 **어떤 정보를 언제 확정하고 어디에서 잃을 수 있는가**의 차이다.

### 아직 입증되지 않은 계보와 적용 한계

이 네 연구만으로 모든 현대 오디오·이미지 생성이 WaveNet에서 DALL·E를 거쳐 잠재 확산으로 직선 진화했다고 말할 수는 없다. GAN, flow, codec token, 비자기회귀와 다른 확산 설계가 별도로 존재한다. 또한 한 연구의 MOS·FID·사람 선호를 다른 자료·해상도·후보 수·sampler·제품 환경에 일반화하지 않는다.
