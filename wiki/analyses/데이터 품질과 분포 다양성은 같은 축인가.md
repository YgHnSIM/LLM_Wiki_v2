# 데이터 품질과 분포 다양성은 같은 축인가

> [!note] 학습 안내
> **난이도:** 심화<br>
> **선수 지식:** [[말뭉치 기반 학습]], [[Perplexity]]<br>
> **읽고 나면:** 학습 말뭉치의 품질 필터, 영역 범위, sampling weight, 누적 token 노출량과 평가 분포를 분리하고 ‘더 깨끗한 데이터’와 ‘더 다양한 데이터’ 중 무엇이 낫다는 주장의 조건을 확인할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 비교 질문

[[058_GPT-1과 GPT-2의 전이 방식 변화|GPT-2의 WebText]]는 Reddit 이용자의 외부 링크 투표를 수집 출발점으로 삼았다. [[062_T5와 Text-to-Text 통합 프레임워크|T5의 C4]]는 Common Crawl에 언어·형식·중복·금칙어 규칙을 적용했다. [[066_GPT-3와 문맥 내 학습|GPT-3]]는 필터링한 Common Crawl과 더 작고 선별됐다고 본 자료를 비례하지 않는 가중치로 섞었다. [[073_The Pile과 대규모 언어 모델 학습 말뭉치|The Pile]]은 22개 출처의 영역 폭과 component별 반복 횟수를 함께 설계했다. [[077_Chinchilla와 계산 최적 언어 모델 학습|Chinchilla scaling 연구]]는 별도의 MassiveText mixture 위에서 optimizer가 본 누적 token 수 $D$를 늘렸지만, $D$를 고유 문서 수나 품질 점수로 정의하지 않았다.

이 흐름을 ‘데이터 품질이 계속 좋아졌다’는 한 줄 순위로 압축하면 중요한 차이가 사라진다. **품질 필터는 어떤 문서를 남길지 정하고, 분포 다양성은 어떤 영역을 어떤 비율로 보게 할지 정한다. 둘은 상호작용하지만 같은 축은 아니다.**

### 최소한 여섯 장부가 필요하다

| 장부 | 질문 | 한 숫자로 줄일 때 생기는 오류 |
|---|---|---|
| 포함 기준 | 어떤 문서를 제거·통과시키는가? | `clean`을 사실성·안전성·권리까지 모두 검증한 뜻으로 읽음 |
| 고유 자료량 | 중복 제거 뒤 몇 개의 서로 다른 문서·token이 남는가? | Raw byte나 누적 token을 새로운 정보량과 같다고 봄 |
| 분포 범위 | 어떤 언어·영역·장르·집단이 포함되는가? | 출처 수를 대표성이나 균형과 같다고 봄 |
| 노출 가중치 | 포함된 자료를 실제로 얼마나 자주 sampling하는가? | Raw byte·문서 수를 학습 비중과 같다고 봄 |
| 노출 총량 | optimizer가 총 몇 token을 보고 자료를 몇 epoch 반복하는가? | 누적 token $D$를 고유 정보량·품질과 같다고 봄 |
| 평가 조건 | 어느 분포와 metric에서 좋아졌는가? | 특정 benchmark 우위를 보편적 품질로 바꿈 |

중복 제거, benchmark decontamination, 개인정보·권리 검토도 이 장부와 관계하지만 서로 대신하지 않는다. 같은 문서를 두 번 보지 않게 했다고 내용이 사실이 되는 것도 아니고, 사용 조건을 문서화했다고 model loss가 자동으로 낮아지는 것도 아니다.

## 2단계 — 작동 원리

### 필터는 자료를 줄이는 동시에 분포를 바꾼다

원시 영역 $d$에서 나온 문서 $x$의 포함 여부를 $g(x)$, 영역별 sampling weight를 $w_d$라 하자. 실제 학습 노출 분포는 단순화하면 다음처럼 쓸 수 있다.

$$
p_{\mathrm{train}}(x,d) \propto g(x)\,w_d\,p_{\mathrm{raw}}(x\mid d)\,p_{\mathrm{raw}}(d).
$$

Component $d$의 고유 token pool을 $U_d$, 전체 누적 노출을 $D$라 하면 그 component의 기대 노출량은 $Dw_d$, 대략적인 반복 횟수는 다음처럼 분리할 수 있다.

$$
e_d\approx\frac{Dw_d}{U_d}.
$$

필터 $g(x)$는 형식 오류나 중복을 줄일 수 있지만 특정 방언·문체·주제를 더 많이 제거할 수도 있다. $w_d$는 작은 영역을 반복해 보완할 수 있지만 raw collection과 다른 학습 분포를 만든다. 따라서 고유 pool $U_d$, sampling weight $w_d$, 누적 노출 $D$를 따로 기록하지 않고 필터 전후 문서 수만 비교하거나 component 개수만 세면 model이 실제로 본 분포를 알 수 없다.

### ‘품질’은 하나의 속성이 아니다

| 품질이라고 부르는 것 | 가능한 측정 | 그 측정이 보장하지 않는 것 |
|---|---|---|
| 형식·가독성 | 문장 종결, markup·code 비율, 언어 식별 | 사실성·전문성 |
| 중복 감소 | exact·near-duplicate 비율 | 독립 출처 수·평가 무오염 |
| 출처 선별 | community vote, reference corpus 유사도 | 사회 전체 대표성·저자 동의 |
| 과제 적합성 | target-domain loss·accuracy | 다른 영역의 성능 |
| 안전·사실·권리 | 별도 content audit·provenance·license 검토 | 낮은 perplexity |

한 필터가 이 가운데 하나를 개선했다고 나머지까지 함께 개선됐다고 결론 내릴 수 없다. 특히 ‘고품질 출처’라는 이름은 누가 어떤 목적과 proxy로 판단했는지를 함께 기록해야 재검토할 수 있다.

### 다양성도 출처 수보다 넓은 개념이다

영역이 많다는 사실은 각 영역이 균등하거나 목표 사용자를 대표한다는 뜻이 아니다. GPT-3와 The Pile처럼 작은 자료를 의도적으로 더 자주 sampling하면 **지원 범위(support)**와 **노출 질량(probability mass)**이 달라진다. 동일한 22개 component도 epoch weight를 바꾸면 다른 학습 분포가 된다.

다양성의 효과는 평가 분포에도 의존한다. 넓은 mixture는 교차 영역 평균을 개선할 수 있지만 특정 영역에 집중한 자료가 그 영역의 과제에서 더 나을 수 있다. 그러므로 ‘다양할수록 항상 좋다’와 ‘선별할수록 항상 좋다’는 모두 직접 실험보다 강한 주장이다.

### Scaling law의 $D$는 노출 총량이다

Scaling law에서 $D$는 학습 batch를 거치며 model이 본 token의 누적 개수다. 같은 문서를 여러 번 보면 각 노출이 다시 $D$에 더해진다. 따라서 같은 $D$라도 하나는 고유 문서를 넓게 한 번 본 학습일 수 있고, 다른 하나는 작은 선별 자료를 여러 epoch 반복한 학습일 수 있다.

Dense model의 $C\approx6ND$는 model size $N$과 token exposure $D$를 FLOP 장부로 연결하지만, 고유 문서 수·중복·영역·사실성·권리·sampling weight를 별도 변수로 식별하지 않는다. [[077_Chinchilla와 계산 최적 언어 모델 학습|Chinchilla]]의 약 20 tokens/parameter도 특정 MassiveText mixture와 학습 recipe에서 얻은 조건부 근사다. **Compute frontier에서 더 많은 token이 중요했다는 결과는 어떤 $20N$ token 묶음도 서로 동등하다는 결과가 아니다.**

## 3단계 — 기술과 근거

### WebText: community selection은 품질의 대리 지표였다

GPT-2의 WebText는 Reddit post 가운데 karma가 3 이상인 외부 링크 약 4,500만 개를 출발점으로 삼았다. Deduplication과 세부가 공개되지 않은 heuristic cleaning 뒤 preliminary corpus는 약 8백만 문서·40GB text였다. 이 절차는 무차별 web crawl보다 사람이 공유하고 최소한의 지지를 받은 문서를 우선하는 **선택 proxy**였다. 그러나 Reddit 이용자 구성·관심사·언어와 링크 가능한 web이라는 분포를 동시에 도입했다.

GPT-2 논문은 WebText의 효과만 분리하는 같은 규모·같은 model의 corpus ablation을 제공하지 않았다. 따라서 GPT-2의 결과에서 community vote가 독립적으로 성능을 만들었다거나 karma가 객관적 문서 품질을 측정했다고 말할 수 없다.

### C4: heuristic filtering과 domain match가 서로 다른 결과를 냈다

T5 Table 8은 같은 220M baseline과 약 34B-token 사전 학습 protocol에서 745GB C4, 6.1TB unfiltered C4, RealNews-like, WebText-like, Wikipedia와 Wikipedia+Toronto Books Corpus를 비교했다. 여기서 unfiltered C4도 English langdetect는 유지하되 나머지 heuristic filtering을 생략했다. 이 변형은 보고한 일곱 downstream 지표 모두에서 C4보다 낮았다. 이 실험 범위에서는 단순히 더 큰 raw crawl을 쓰기보다 C4의 filtering을 적용한 편이 나았다.

그러나 더 넓은 C4가 모든 과제에서 최고였던 것은 아니다.

| 사전 학습 자료 | 직접 비교에서 두드러진 결과 | 읽을 수 있는 범위 |
|---|---|---|
| C4 | SuperGLUE 71.36 | 여러 English web 영역을 포괄한 기준선 |
| WebText-like | GLUE 84.03 대 C4 83.28 | Reddit-linked subset이 이 집계에서 더 높았음 |
| Wikipedia + TBC | SuperGLUE 73.24 | 도서 영역과 가까운 MultiRC 향상이 큰 몫을 차지함 |
| RealNews-like | ReCoRD exact match 73.72 대 C4 68.16 | 뉴스 영역 일치가 관련 독해 과제에 유리했음 |

Table 8은 품질 필터가 무의미하다는 결과도, 좁은 영역이 보편적으로 낫다는 결과도 아니다. Corpus 크기·내용·반복과 domain match가 함께 달랐으며, 과제에 따라 순위가 바뀐다는 증거다.

### GPT-3: raw pool과 학습 노출량을 의도적으로 다르게 만들었다

GPT-3는 WebText·Wikipedia·web books를 positive reference로 둔 classifier로 Common Crawl을 재표집하고, document-level fuzzy deduplication을 거친 뒤 curated source를 더했다. 이 점수는 factuality나 공정성 점수가 아니라 선택한 reference distribution과의 유사도다.

사전 학습 pool은 filtered Common Crawl 410B, WebText2 19B, Books1 12B, Books2 55B, Wikipedia 3B token으로 약 499B token이었다. 실제 300B-token 학습 mixture의 sampling weight는 각각 60%, 22%, 8%, 8%, 3%로 raw 크기에 비례하지 않았다. 표의 반올림 때문에 합은 101%가 된다.

이 선택으로 WebText2·Books1·Wikipedia 같은 작은 자료는 더 많은 epoch를 노출하고, 큰 Common Crawl은 한 번보다 적게 보았다. 여기서 ‘품질’은 독립적인 scalar가 아니라 Common Crawl filtering, dataset selection과 sampling weight에 구현됐다. Brown 등의 최종 downstream 결과는 이 mixture와 model scale·compute가 함께 작동한 결과이므로 각 데이터 개입의 단독 효과를 식별하지 않는다.

### The Pile: 넓은 mixture는 교차 영역에서 강했지만 모든 metric을 이기지 않았다

The Pile은 22개 component의 825.18 GiB raw data에 1–3 epoch를 배정해 1,254.20 GiB effective mixture를 구성했다. Gao 등은 model 크기와 training data 양의 영향을 줄이기 위해 같은 1.3B architecture를 Pile·CC-100 English·Raw Common Crawl의 약 40GB training subsample에 각각 학습했다.

| 학습 자료 | Pile test BPB | WikiText PPL | LAMBADA PPL | LAMBADA accuracy |
|---|---:|---:|---:|---:|
| The Pile | 0.9433 | 5.59 | 12.78 | 50.1 |
| CC-100 (en) | 1.3293 | 8.27 | 11.78 | 49.7 |
| Raw CC | 1.1275 | 11.75 | 19.84 | 43.8 |

Pile model은 모든 Pile component의 BPB와 WikiText에서 두 Common Crawl model보다 좋았다. 반면 LAMBADA perplexity는 CC-100이 더 낮았고 accuracy 차이는 0.4 point였다. 이 결과는 Pile의 mixture가 해당 protocol에서 교차 영역 적합성을 높였다는 근거지만, 다양성 하나의 효과는 아니다. Component selection·filtering·epoch weight가 함께 달랐고 component별 제거 ablation도 없었다.

### Chinchilla: token 수를 늘려도 mixture 장부는 사라지지 않는다

Hoffmann 등의 Appendix A는 1.4T-token Chinchilla 학습 mixture를 raw 크기와 다른 sampling proportion으로 기록했다.

| MassiveText component | Sampling proportion | 1.4T tokens에서 epoch |
|---|---:|---:|
| MassiveWeb | 45% | 1.24 |
| Books | 30% | 0.75 |
| C4 | 10% | 0.77 |
| News | 10% | 0.21 |
| GitHub | 4% | 0.13 |
| Wikipedia | 1% | 3.40 |

Wikipedia는 전체 비중이 1%여도 작은 corpus라 3.40 epochs 반복됐고, News와 GitHub는 더 큰 corpus라 한 epoch보다 훨씬 적게 노출됐다. 1.4T라는 단일 $D$는 이 component별 support·sampling·repetition 차이를 보여 주지 않는다.

Appendix C의 별도 IsoFLOP 분석은 C4에서 $N/D$ 지수 0.50/0.50, GitHub code에서 0.53/0.47을 얻었다. 다만 저자들은 이 유사성이 **한 epoch를 넘지 않는 조건**에서 성립한다고 제한하고, token 수가 늘수록 data quality가 크게 달라질 수 있으며 고품질 자료의 반복 사용은 후속 연구가 필요하다고 적었다. 이는 MassiveText 하나의 우연일 가능성을 줄이지만, 품질·언어·modality·반복과 무관한 보편 20:1을 입증하지 않는다.

### 다섯 연구를 같은 장부에 놓으면 보이는 것

| 연구 | 포함 기준 | 분포·가중 설계 | 직접 확인한 것 | 확인하지 못한 것 |
|---|---|---|---|---|
| WebText | Reddit karma 기반 link selection | Reddit-linked web | 수집 경로와 GPT-2 평가 | selection proxy의 독립 인과 |
| C4 | English·형식·중복 등 heuristic filtering | broad web와 좁은 대안 corpus 비교 | unfiltered 열세와 과제별 domain match | 보편적인 단일 corpus 순위 |
| GPT-3 | filtered CC와 curated source | raw 크기에 비례하지 않는 300B-token mixture | 실제 source weight·epoch 장부 | data choice별 단독 기여 |
| The Pile | component별 수집·처리 | 22개 영역과 epoch weight | 1.3B·40GB protocol의 cross-domain 우위와 mixed LAMBADA | diversity·filter·weight의 독립 효과 |
| Chinchilla | MassiveText 6-component mixture | sampling proportion과 1.4T-token epoch | C4·GitHub의 1-epoch 미만 유사 지수와 최종 mixture 장부 | 임의의 $20N$ token 동등성·반복의 보편 효과 |

따라서 실무적으로 유용한 질문은 ‘품질이냐 다양성이냐’가 아니라 **어떤 필터 뒤에 얼마의 고유 자료가 남았고, 어느 분포를 어떤 가중치와 총량으로 노출했으며, 어느 평가 분포에서 무엇이 개선됐는가**다.

## 검증과 한계

### 확인된 사실

- WebText는 Reddit karma 3 이상 외부 링크를 출발점으로 삼고 deduplication·heuristic cleaning을 거쳤으며, community selection과 web coverage를 동시에 바꿨다.
- T5 Table 8에서 unfiltered C4는 C4보다 모든 보고 지표가 낮았지만, 더 좁은 corpus가 domain-aligned 과제에서 C4를 앞선 사례도 있었다.
- GPT-3와 The Pile은 raw 자료 크기와 다른 sampling weight·epoch를 사용했다.
- The Pile의 40GB 비교는 동일한 1.3B architecture를 사용했지만 Pile의 component selection·filtering·weight를 서로 분리하지 않았다.
- Chinchilla의 $D$는 누적 token 노출량이며, Appendix A의 MassiveText component는 1.4T tokens에서 0.13–3.40 epochs로 서로 다르게 반복됐다. Appendix C의 C4·GitHub 유사 scaling은 한 epoch 미만이라는 조건을 가졌다.

### 비교를 통한 해석

다섯 연구를 함께 읽으면 filtering은 단순한 정제가 아니라 **분포 변환**이고, diversity는 단순한 출처 개수가 아니라 **가중된 support 설계**이며, token count는 고유 정보량이 아닌 **누적 노출 장부**라는 관점을 얻는다. ‘품질’이라는 말을 쓰려면 형식·중복·출처 proxy·과제 적합성·사실·안전·권리 가운데 어느 속성을 뜻하는지 밝혀야 한다.

또한 dataset 평가는 target use distribution과 함께 설계해야 한다. 교차 영역 평균, 특정 도메인 task, 사실성·안전성·권리 준수는 다른 평가 장부이며 한 metric으로 대체할 수 없다.

### 아직 입증되지 않은 인과

이 비교는 WebText→C4→GPT-3 mixture→The Pile→Chinchilla가 하나의 선형 진보 계보를 이룬다고 주장하지 않는다. 논문마다 model architecture·tokenizer·training budget·목표와 평가가 달라 결과 수치를 하나의 leaderboard로 합칠 수 없다.

또한 다섯 자료는 모든 언어·문화·법적 조건에 대한 최적 mixture를 정하지 않는다. 높은 downstream 점수가 저자 동의·사실성·안전성·대표성을 보장하지 않으며, 더 많은 domain이 언제나 특정 과제 성능을 높인다는 일반 법칙도 제공하지 않는다. 반복 token이 새로운 고유 token과 같은 효과를 낸다거나 data quality와 무관하게 보편적인 20:1이 성립한다는 인과도 확인하지 않았다.
