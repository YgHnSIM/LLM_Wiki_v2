# 공개 가중치와 재현 가능성은 같은 축인가

> [!note] 학습 안내
> **난이도:** 심화<br>
> **선수 지식:** [[파운데이션 모델]], [[The Pile]], [[HELM]], [[BLOOM]], [[LLaMA 1]]<br>
> **읽고 나면:** 문서·data·code·model weight·평가 출력의 공개 범위를 나누고, 검사·변형·재배포·재실행·재학습·의사 결정 참여가 왜 서로 다른 접근 축인지 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 비교 질문

[[074_The Pile과 대규모 언어 모델 학습 말뭉치|The Pile]]은 대규모 학습 자료와 구성 code를 공개했지만 project-level license가 원문 각각의 권리 상태를 하나로 만들지는 않았다. [[076_파운데이션 모델 보고서와 AI 생태계|파운데이션 모델 보고서]]는 이미 훈련된 model의 재사용이 후속 개발 비용을 낮출 수 있는 동시에 model 접근, 적응 compute와 engineering expertise가 새 장벽이 될 수 있다고 지적했다. [[082_BLOOM과 공개 접근 다국어 LLM|BLOOM]]은 문서·weight·Apache 2.0 code·ROOTS 일부 접근을 결합했지만 각 artifact의 조건과 실행 비용은 달랐다. [[089_LLaMA 1과 제한적 공개 가중치 연구 배포|LLaMA 1]]은 논문과 신청 승인형 weight 접근을 결합했지만, 비상업 연구 license와 case-by-case 심사를 두어 BLOOM의 공개 접근과도 다른 법적·절차적 경계를 만들었다. [[079_HELM과 다차원 언어 모델 평가|HELM]]은 scenario와 prompt·completion을 남겨 결과 감사를 돕지만, 평가한 폐쇄형 API의 내부 weight나 미래 version을 고정하지 못한다.

이 다섯 사례를 함께 읽으면 답은 명확하다. **가중치 접근은 검사 가능성과 변형 가능성을 크게 넓힐 수 있지만, 법적 접근·재배포 권리·실행 계산·학습 재현과 같은 축은 아니다.** 재현하려는 대상이 학습인지, 특정 checkpoint의 추론인지, 한 평가 run인지에 따라 필요한 data·code·환경·계산·version 기록이 달라진다.

### ‘열려 있다’보다 먼저 목적어와 동사를 적는다

`오픈`이라는 한 단어에는 서로 다른 질문이 겹친다.

| 목적어 | 물어야 할 동사 | 확인할 조건 |
| --- | --- | --- |
| 문서·model card | 읽고 검토할 수 있는가 | 공개 범위, version, 누락된 설계 판단 |
| Training data | 조사·재구성·재배포할 수 있는가 | 원천별 권리, consent, 접근 심사, snapshot |
| Code·환경 | 실행하고 수정할 수 있는가 | license, dependency·hardware version, 설정·seed |
| Model weight | 신청·다운로드·검사·변형·재배포할 수 있는가 | 접근 심사, 사용 목적, 파생물·재배포 조건, 저장·memory 요구량 |
| 평가 산출물 | score에서 prompt·completion으로 내려갈 수 있는가 | scenario, adaptation, metric, query 시각·model version |
| 개발 과정 | 의제와 규칙을 함께 정할 수 있는가 | 참여 경로, 의사 결정권, compute 배분, 책임 구조 |

공개 URL이 있다는 사실은 이 동사 전부에 자동으로 `예`라고 답하지 않는다. 반대로 완전한 재학습이 어렵다는 이유만으로 공개 weight가 제공하는 독립적 probing·fine-tuning·오류 분석의 가치가 사라지는 것도 아니다.

## 2단계 — 작동 원리

### 재현 대상마다 필요한 교집합이 다르다

**추론 재실행**은 같은 checkpoint, tokenizer·inference code, decoding 설정, 입력과 계산 자원이 있어야 비교할 수 있다. **평가 재실행**은 여기에 scenario data, prompt 구성, adaptation 절차, metric 구현과 model version 기록이 더 필요하다. **학습 재현**은 training data snapshot과 순서·가중치, architecture, optimizer, hyperparameter, distributed system, random seed와 충분한 compute까지 요구한다.

이를 한 개의 점수 대신 조건 집합으로 쓰면 다음과 같다.

$$
R_t = D_t \cap C_t \cap E_t \cap H_t \cap B_t
$$

여기서 $R_t$는 대상 $t$의 재현 조건, $D_t$는 data, $C_t$는 code·configuration, $E_t$는 software·hardware environment, $H_t$는 실행 가능한 계산 자원, $B_t$는 weight·output·log 같은 기준 artifact다. 어느 한 항목의 공개는 다른 항목의 결손을 대신하지 않는다. 이 식은 재현 여부를 자동 판정하는 metric이 아니라, 빠진 조건을 기록하기 위한 장부다.

### 축 사이의 대표적인 비대칭

- Weight를 받을 수 있어도 training data를 같은 snapshot으로 얻지 못하면 **변형은 가능하지만 학습 재현은 불완전**할 수 있다.
- Data와 code를 받을 수 있어도 필요한 cluster가 없으면 **법적 접근은 있어도 실행 접근은 없을** 수 있다.
- Prompt와 completion을 볼 수 있어도 API 제공자가 내부 model을 바꾸면 **과거 결과는 감사할 수 있지만 같은 model의 재질의는 불가능**할 수 있다.
- 수천 명이 협업 공간에 참여해도 compute allocation과 최종 release rule을 누가 정했는지 모르면 **참여 규모와 거버넌스 권한을 같게 셀 수 없다.**

## 3단계 — 기술과 근거

### The Pile: project license와 원문 권리는 다른 층이다

The Pile 논문과 datasheet는 22개 component, 처리 방법, raw·effective size와 위험을 상세히 기록했다. Datasheet는 dataset을 MIT License로 배포했다고 설명한다. 동시에 Books3를 비롯한 구성요소의 저작권, host terms, PII와 저자 동의가 균일하지 않으며 규모 때문에 모든 document를 전수 확인할 수 없다고 적었다.

따라서 project-level license는 연구자가 배포자가 제시한 조건을 확인하게 하지만, 수집된 모든 underlying work의 권리를 새로 통일하는 장치로 읽을 수 없다. 이 구분은 재현성에도 직접 영향을 준다. 뒤에 원천 접근 조건이 바뀌거나 특정 component를 재배포할 수 없다면 같은 이름의 corpus를 받더라도 동일 snapshot을 재구성하기 어려울 수 있다.

The Pile을 공개했다는 사실은 corpus 구성과 data 변수를 더 잘 조사하게 한다. 그러나 같은 자료로 학습한다는 것만으로 model 재현이 끝나지 않는다. Tokenizer, component weight, document order, architecture, optimizer, seed와 compute가 달라지면 다른 실험이다.

### 파운데이션 모델 보고서: 접근 확대와 자원 집중은 공존한다

파운데이션 모델 보고서는 model을 처음부터 다시 훈련하지 않고 여러 과제에 적응시키는 구조가 비용을 나눌 기회를 만든다고 설명한다. 그러나 §4.4의 공정한 비교 조건에는 적응 data, model access와 compute가 함께 들어간다. §1.3과 §5.6은 대규모 사전학습 능력과 핵심 model 접근이 소수 산업 조직에 집중될 수 있다는 문제를 별도로 다룬다.

이는 `weight를 받았다`와 `연구 조건이 평등해졌다` 사이의 간격을 보여 준다. 공개 weight는 base model 개발자가 아니어도 내부 activation 조사나 fine-tuning을 시도하게 할 수 있다. 하지만 checkpoint를 저장·실행할 hardware, 적응 data와 engineering expertise가 집중돼 있다면 가능한 연구의 폭은 집단마다 다르다. 접근성은 artifact의 법적 상태뿐 아니라 **적응 가능한 자원**까지 포함해 평가해야 한다.

### BLOOM: 한 model 안에서도 공개 조건이 네 갈래로 나뉜다

BLOOM은 다음 층을 하나의 연구 프로젝트에서 함께 제시했다.

| 층 | 확인된 공개 범위 | 재현 장부에서 남는 조건 |
| --- | --- | --- |
| 문서 | Architecture, 학습·평가, model card 성격의 기록과 협업 과정 | 모든 시행착오·환경 상태가 한 문서에 완전히 보존됐는지 별도 확인 필요 |
| Weight | 완성 checkpoint와 일부 중간 artifact에 접근 가능 | RAIL의 이용·재배포 제한, 저장·memory·inference compute |
| Code | 학습·실행 code를 Apache 2.0으로 공개 | Dependency·driver·distributed runtime와 hardware 조건 |
| ROOTS data | 구성·data card와 gated인 큰 초기 subset, source별 release 전략 | 전체 text의 단일 자유 license가 없고 동일 snapshot 재구성에 권리·접근 차이 존재 |

RAIL은 `Data`를 license 대상에서 제외하고, Model과 파생물에는 Attachment A의 use-based restriction과 재배포 고지 의무를 둔다. 이용 제한은 아무 조건 없는 재배포와 다르지만, checkpoint의 검사·허용된 변형 가능성을 없애는 것도 아니다. `open weights`, `open-source code`, `open data`를 한 단어로 합치면 이 차이가 사라진다.

실행 장벽은 수치로도 드러난다. BLOOM 최종 학습은 Jean Zay의 A100 80GB GPU 384개에서 진행됐고 1,082,990 GPU-hours가 보고됐다. 공개 artifact는 exact retraining의 정보 장벽을 낮추지만 이 계산량을 모든 연구자에게 배분하지 않는다. 공공 HPC를 이용한 국제 협업은 기업 외부의 대규모 학습 가능성을 보여 준 사례이면서, 국가급 계산 allocation이라는 집중된 기반에도 의존한 사례다.

### LLaMA 1: 신청할 수 있다는 것과 공개로 받는다는 것은 다르다

LLaMA 1 논문은 7B·13B·33B·65B model의 architecture, data mixture, token 수, optimizer와 평가를 기록했다. Meta의 release 공지는 가중치를 **비상업 연구 license**로 배포하고, 학계 연구자, 정부·시민사회·학술 기관 소속 연구자 및 산업 연구소의 신청을 case-by-case로 심사한다고 밝혔다. 따라서 LLaMA 1은 가중치 수준의 연구 접근을 제공했지만, 누구나 약정 없이 다운로드·상업 이용·재배포할 수 있는 release로 분류해서는 안 된다.

BLOOM과 LLaMA 1을 `weight가 있다`는 공통점만으로 묶으면 실제 차이가 사라진다.

| 질문 | BLOOM | LLaMA 1 |
| --- | --- | --- |
| 법적·절차적 접근 | Checkpoint에 직접 접근하되 RAIL의 use restriction을 따름 | 신청·승인 후 비상업 연구 license로 접근 |
| 검사 | 외부 연구자가 weight·model card·논문·code를 함께 검토 가능 | 승인된 연구자는 weight를 검사하고 공개 논문의 설계 설명과 비교 가능 |
| 변형 | RAIL이 허용하는 범위의 fine-tuning·파생 model 연구 | 승인·license 범위 안의 비상업 적응 연구 |
| 재배포 | Model·파생물은 RAIL 제한과 고지 의무를 따름 | 일반 재배포 권리를 주는 공개 release가 아님 |
| 실행 compute | 176B checkpoint를 실행할 memory·accelerator가 필요 | 논문은 13B 추론이 단일 V100에서 가능하다고 보고하지만 model size와 용도에 따라 자원이 달라짐 |
| 학습 재현 | ROOTS·code·학습 문서가 있어도 release 가능 범위와 1,082,990 GPU-hours·실행 환경을 맞춰야 함 | 논문이 mixture·hyperparameter를 제공해도 정확한 corpus snapshot·전체 pipeline·실행 환경과 65B의 1,022,362 GPU-hours가 필요 |

실행 비용은 같은 LLaMA 1 안에서도 추론과 학습을 갈라놓는다. 논문은 13B model을 단일 V100에서 추론할 수 있다고 설명한다. 그러나 Table 15의 65B 학습량은 1,022,362 GPU-hours이며, 전체 개발 과정은 1,015 tCO2eq로 추정됐다. 작은 checkpoint의 추론 실행 가능성을 전체 사전학습의 재현 가능성으로 확장할 수 없다.

또한 version 경계를 고정해야 한다. 논문 §4의 `LLaMA-I`는 명령 미세조정을 시험한 제한적 실험이지, LLaMA 1 base 가중치 전체가 chat·RLHF model이었다는 뜻이 아니다. 이후 출시된 Llama 2의 상업 이용 조건과 release 방식도 LLaMA 1에 소급해 적용하지 않는다. 각 version의 base·instruction-tuned model과 license를 별도 artifact로 기록해야 한다.

### ROOTS와 BigScience: data governance는 access control보다 넓다

ROOTS는 구성 data의 언어·출처와 처리 과정을 문서화하고, native speaker 참여와 data governance를 corpus 설계의 일부로 다뤘다. 큰 초기 공개분은 gated access와 윤리 헌장 동의를 요구했고, 원천별 license·release 조건을 따랐다. 이 장치는 무차별 download와 다른 책임 구조를 만든다.

그러나 gate가 있다는 사실만으로 원 저자 동의, 언어 공동체 대표성과 모든 downstream harm이 해결됐다고 결론 내릴 수 없다. 반대로 gate 때문에 corpus 문서화와 공동 심의의 가치가 사라지는 것도 아니다. 거버넌스는 `파일을 받을 수 있는가`뿐 아니라 **누가 포함·제외 기준과 release rule을 정하고, 이의를 제기하며, 자원을 배분하는가**를 묻는 별도 축이다.

### HELM: 출력 감사와 model 재현을 구분한다

HELM은 task·domain·language로 scenario를 정하고, adaptation과 metric을 표준화하며, score뿐 아니라 원시 prompt·completion을 공개했다. 이 구조는 결과표의 한 점에서 실제 입력·출력으로 내려가 오류와 측정 방식을 검사하게 한다. 같은 scenario와 metric을 공개 구현으로 재실행하거나 새로운 model에 적용할 통로도 제공한다.

하지만 HELM은 open model, 제한적 API와 closed-access model을 함께 평가했다. 비공개 API는 평가 기간에도 바뀔 수 있었고 제공자별 version 기록도 일관되지 않았다. Query 시각과 알려진 version을 남겨도, 제공자가 과거 내부 checkpoint를 공개하지 않으면 외부 연구자가 그 model 자체를 복원할 수 없다. **공개된 원시 출력은 과거 run의 감사 기록이지, mutable service의 실행 파일이 아니다.**

따라서 평가 재현은 적어도 두 수준으로 나눠야 한다.

1. **절차 재현:** 같은 scenario·prompt·metric code를 다시 실행한다.
2. **관측 재현:** 같은 model version과 조건에서 같은 분포의 응답을 얻는다.

HELM은 첫 번째 수준의 장벽을 크게 낮추고 과거 관측을 남겼다. 폐쇄형 API에 대해서는 두 번째 수준을 독립적으로 보장하지 못한다.

### 다섯 자료를 함께 읽을 때 얻는 실무 규칙

연구 artifact를 공개하거나 사용할 때는 최소한 다음 문장을 완성해야 한다.

- **접근:** 누가 어떤 절차와 license로 무엇의 어느 version까지 받을 수 있다.
- **검사:** 접근 자격을 얻은 사람이 어떤 내부 정보와 행동을 조사할 수 있다.
- **변형:** 어떤 artifact를 어떤 조건에서 바꿔 파생물을 만들 수 있다.
- **재배포:** 원본과 파생물에 어떤 license·use restriction·source-specific right가 적용된다.
- **재현:** 추론·평가·학습 가운데 무엇을 어떤 tolerance로 반복하려는지 정한다.
- **실행:** 필요한 storage, memory, accelerator time과 전문성을 기록한다.
- **거버넌스:** 포함 기준, 접근 심사, model release와 compute 배분을 누가 결정했는지 기록한다.

이 일곱 문장을 채우면 `오픈인가 아닌가`라는 이분법보다 무엇이 실제로 가능하고 무엇이 빠졌는지 재검토하기 쉬워진다.

## 검증과 한계

### 확인된 사실

- The Pile 자료는 project-level MIT 배포 표기와 underlying component의 저작권·ToS·동의 차이를 함께 기록한다. 공개 corpus라는 이름만으로 모든 원문의 권리 상태가 같아지지 않는다.
- 파운데이션 모델 보고서는 model 재사용의 비용 분담 가능성과 model access·적응 compute·expertise의 집중 위험을 함께 제시한다.
- BLOOM의 weight, Apache 2.0 code와 ROOTS data는 서로 다른 조건으로 공개됐다. RAIL은 Data를 대상에서 제외하고 Model·파생물의 이용 제한과 재배포 고지 의무를 정한다.
- BLOOM 최종 학습에는 A100 80GB GPU 384개와 1,082,990 GPU-hours가 사용됐다. Artifact 공개가 이 계산 자원을 자동 배분하지 않는다.
- LLaMA 1 공식 배포는 비상업 연구 license와 case-by-case 신청 심사를 사용했다. 이는 논문 공개와 가중치 수준 접근이 있었다는 뜻이지, 무조건적 공개 download·상업 이용·재배포가 허용됐다는 뜻이 아니다.
- LLaMA 1 논문은 13B의 단일 V100 추론 가능성과 65B 학습의 1,022,362 GPU-hours를 함께 보고했다. 전체 개발 탄소 발자국 추정치는 1,015 tCO2eq였다.
- LLaMA-I는 LLaMA 1 논문의 제한적 명령 미세조정 실험이며, LLaMA 1 base release나 후속 Llama 2와 같은 artifact·version으로 다루면 안 된다.
- HELM은 scenario·adaptation·metric과 prompt·completion을 공개했지만, 폐쇄형 API의 내부 checkpoint를 공개하거나 미래에도 같은 version을 유지하게 만들지는 못했다.

### 비교를 통한 해석

다섯 자료를 함께 놓으면 공개성은 단일 선이 아니라 **법적·절차적 접근, 검사 가능성, 변형 가능성, 재배포 권리, 재현 조건, 실행 자원과 거버넌스 참여의 벡터**로 보는 편이 설명력이 높다. 가중치 접근은 이 벡터의 여러 값을 개선할 수 있지만 모두를 최대로 만들지는 않는다. 특히 BLOOM의 RAIL 조건 직접 접근과 LLaMA 1의 신청 승인형 비상업 접근은 둘 다 weight-level 연구를 가능하게 하지만, 누가 받고 어디까지 다시 나눌 수 있는지에서 다르다.

이 관점에서 재현 가능성도 `예/아니오` 하나가 아니다. 고정 checkpoint의 추론을 다시 돌리는 일, 평가 절차를 다시 실행하는 일, 같은 관측을 얻는 일과 사전학습을 다시 수행하는 일은 서로 다른 증거를 요구한다. 특히 closed API의 raw output 공개는 감사 가능성을 높이지만 model identity를 고정하지 않고, open weight는 model identity를 고정하지만 원 data·compute가 없으면 training lineage를 완전히 재현하지 못한다.

### 아직 입증되지 않은 계보와 인과

이 비교는 The Pile이 파운데이션 모델 보고서를 직접 낳았거나, 그 보고서가 BLOOM·HELM·LLaMA 1을 단선적으로 설계하게 했다는 계보를 주장하지 않는다. 다섯 프로젝트는 일부 연구 공동체와 문제의식을 공유하지만 직접 영향에는 명시적인 설계 기록·인용과 참여자 증언이 더 필요하다. LLaMA 1이 후속 개방형 model 생태계를 직접 유발했다는 광범위한 인과도 이 자료만으로는 입증하지 않는다.

또한 가중치 접근이 항상 더 안전하거나 더 공정한 model을 만든다는 인과, RAIL의 이용 제한이 실제 오용을 줄였다는 효과, gated data·weight access가 권리·대표성·오용 문제를 해결했다는 결과는 현재 근거로 확인되지 않는다. BigScience의 큰 참여 규모가 의사 결정권과 보상을 균등하게 분배했다거나, Meta의 신청 심사가 연구 접근성과 위험 완화를 얼마나 개선했다거나, HELM의 공개 결과가 모든 model provider의 투명성을 높였다는 광범위한 사회적 효과도 별도 연구가 필요하다.

마지막으로 exact retraining만을 재현성의 유일한 기준으로 삼지 않는다. 제한된 compute에서 weight·code·output을 사용해 독립 검증을 수행하는 가치와, 원 실험을 처음부터 같은 조건으로 반복하는 가치는 모두 중요하지만 서로 다른 성취다.
