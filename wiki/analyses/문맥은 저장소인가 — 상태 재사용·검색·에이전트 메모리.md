# 문맥은 저장소인가 — 상태 재사용·검색·에이전트 메모리

> [!note] 학습 안내
> **난이도:** 심화<br>
> **선수 지식:** [[긴 문맥 언어 모델]], [[검색 증강 생성]]<br>
> **읽고 나면:** 상태 재사용·입력 문맥·검색 색인·에이전트 memory를 갱신, 접근, 학습, 근거 추적의 네 축으로 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 비교 질문과 잠정 결론

`memory`라는 말은 모델이 과거 정보를 다시 쓴다는 공통점을 가리키지만, 그 정보가 **어디에 남는지**, **누가 바꾸는지**, **다음 답에서 어떻게 선택되는지**까지 같다는 뜻은 아니다. [[046_메모리 네트워크와 외부 지식 접근|Memory Network]]의 사실 슬롯, [[Transformer-XL]]의 이전 은닉 상태, 긴 문맥의 입력 token, [[검색 증강 생성|RAG]]의 passage 색인, [[LLM 에이전트]]의 event log·vector store는 모두 서로 다른 state carrier다.

잠정 결론은 간단하다. **문맥은 답을 만들 때 읽는 입력이고, 저장소는 그 입력 후보 또는 상태를 세션 밖까지 보존하는 장치다.** 다만 이 둘은 이분법이 아니다. Transformer-XL은 이전 계산의 표현을 제한된 상태로 넘기고, RAG는 외부 문서를 다음 입력으로 만들며, 에이전트는 실행 흔적을 저장했다가 다음 prompt에 다시 넣는다. 이들은 모두 과거를 다시 쓰지만, 갱신 비용과 오류가 생기는 위치가 다르다.

### 비교에 필요한 네 질문

어떤 시스템이 `memory`를 쓴다고 말할 때는 다음 네 질문을 함께 적어야 한다.

1. **보존:** 무엇을 남기는가? 원문 사실, token, 은닉 벡터, 검색용 embedding, 실행 log 가운데 무엇인가?
2. **갱신:** 새 사실을 넣거나 고칠 때 model weight를 다시 학습해야 하는가, index·파일·prompt만 바꾸면 되는가?
3. **접근:** 다음 답은 전체를 직접 읽는가, 점수화·검색·요약으로 일부만 고르는가?
4. **근거:** 사용자가 어떤 원자료·상태·실행 결과가 답에 들어갔는지 확인할 수 있는가?

이 질문은 “긴 문맥이 RAG를 대체한다” 또는 “에이전트가 경험으로 학습한다” 같은 넓은 문장을 구체적인 설계 판단으로 바꾼다.

## 2단계 — 작동 원리

### 같은 질문을 다섯 방식으로 처리하는 최소 예

예를 들어 정책 문서의 연락처가 바뀌었다고 하자. 다음 질의는 “현재 담당자는 누구인가?”다. 다섯 방식은 모두 답을 바꿀 수 있지만, 바뀌는 장소와 실패 지점이 다르다.

| 방식 | 과거 정보가 남는 곳 | 새 연락처를 반영하는 직접 작업 | 답이 틀릴 수 있는 대표 지점 |
| --- | --- | --- | --- |
| Memory Network | 문장·사실 슬롯 | 새 슬롯을 쓰거나 후보 구성을 고친다 | 질문 표현이 새 슬롯을 고득점으로 찾지 못한다 |
| Transformer-XL | 제한 길이의 이전 은닉 상태 | 현재 처리 흐름에 새 token을 넣는다 | 상태 길이를 넘었거나 표현이 필요한 세부를 잃었다 |
| 긴 문맥 | 이번 요청의 입력 token | 최신 문서를 prompt에 포함한다 | 긴 입력 안의 위치를 못 찾거나 여러 사실을 잘못 결합한다 |
| RAG | 문서와 검색 색인 | 문서를 embedding·indexing해 index를 교체한다 | retriever가 근거 passage를 후보에서 빼버린다 |
| 에이전트 memory | log·파일·vector store·요약 | state를 기록·정정하고 다음 prompt에 다시 넣는다 | 오래된 기록을 재주입하거나 권한 없는 상태를 사용한다 |

여기서 `새 연락처를 반영했다`는 말은 모두 같은 수준의 최신성을 뜻하지 않는다. 긴 문맥에는 문서를 매 요청 넣어야 하고, RAG는 새 문서의 분할·embedding·색인 구축이 필요하며, agent state는 어느 기록을 신뢰하고 폐기할지 정책이 필요하다. 어느 방식도 자료가 있다는 사실만으로 올바른 답을 보장하지 않는다.

### 정보가 답까지 오는 공통 경로

다섯 방식은 대체로 `보존 → 후보 형성 → 선택 또는 주의 → 답 생성`의 순서를 공유한다. 차이는 후보 형성의 위치다. 긴 문맥은 후보 원자료를 먼저 입력에 넓게 넣고 model 내부 attention이 관련 위치를 찾아야 한다. RAG는 retriever가 먼저 corpus를 좁히고 generator가 선택 passage를 읽는다. agent는 이전 실행의 state를 어떤 prompt·tool call에 다시 넣을지 orchestrator가 정한다.

그러므로 저장 장치의 용량과 답에 실제로 쓰이는 정보량도 다르다. 긴 문맥의 명목 길이는 수용 한도일 뿐이다. [[098_백만 토큰 문맥 모델의 명목 길이와 유효 활용 경계|긴 문맥]]에서 정리한 수용·계산·접근·사용 경계 중 마지막 둘을 통과해야 입력 속 사실이 답에 기여한다. RAG에서도 같은 문제가 retriever의 후보 재현율과 generator의 근거 사용으로 나뉘어 나타난다.

## 3단계 — 기술과 근거

### 외부 슬롯: Memory Network는 사실을 고르고 답했다

2014년 MemNN의 일반 틀은 입력을 표현하는 I, 메모리를 갱신하는 G, 메모리에서 출력 특징을 만드는 O, 응답을 만드는 R을 분리했다. 원 텍스트 구현은 문장을 새 빈 슬롯에 저장하고, 질문과 supporting fact의 점수를 매겨 최대 두 개를 hard `argmax`로 선택했다. 이 방식의 장점은 어떤 문장이 선택됐는지 볼 수 있다는 점이다.

하지만 슬롯에 문장이 있다는 것과 그 문장이 답의 충분한 근거라는 것은 다르다. 원형은 supporting-fact 라벨이 있는 강한 감독과 통제된 합성 세계에 기대었고, 대규모 QA에서는 기존 후보의 재순위화에 가까웠다. 따라서 이 구조는 “외부 저장이 있으면 지식이 자동 갱신된다”가 아니라, **저장 단위·질문 표현·후보 선택을 함께 설계해야 한다**는 이른 사례로 읽는 편이 정확하다.

### 은닉 상태: Transformer-XL은 저장소가 아니라 제한된 계산 이력이다

Transformer-XL은 이전 세그먼트의 은닉 상태 일부를 다음 세그먼트의 key·value용 memory로 재사용한다. 과거 상태에는 stop-gradient가 걸리므로 새 세그먼트의 손실은 그 과거 계산까지 역전파되지 않는다. 또한 길이 $M$은 제한돼 있으며, 원문 전체나 임의의 오래된 사건을 무기한 보존하는 database가 아니다.

이 메커니즘은 긴 문서를 외부에서 검색하는 방식과 목적이 다르다. 주된 이득은 고정 세그먼트 경계 때문에 생기던 문맥 단편화와 중복 계산을 줄이는 데 있다. 현재 query가 여전히 `memory + 현재 상태`의 dense attention을 계산하고, 과거의 원문 locator를 사용자가 그대로 검사할 수 있는 것도 아니다. 같은 `memory`라는 이름을 붙여도 **계산 표현의 재사용**과 **검사 가능한 지식 저장**은 다른 기능이다.

### 입력 문맥과 검색 색인: 어느 단계에서 증거를 좁히는가

긴 문맥은 후보 자료를 prompt에 그대로 넣어 retrieval 이전의 누락을 줄인다. 그러나 길이를 받는 것, 계산하는 것, 필요한 위치에 접근하는 것, 여러 사실을 사용해 근거 충실한 답을 내는 것은 별도 경계다. 위치별 long-context 평가가 가운데 정보의 활용 저하를 보고한 사실도, 입력 용량이 곧 균일한 접근을 뜻하지 않음을 보여 준다.

반대로 2020년 RAG는 Wikipedia passage 색인에서 DPR로 top-$K$ 후보를 찾고 BART generator가 이를 조건으로 답을 만들었다. 색인을 호환되는 새 문서로 교체하면 weight를 다시 학습하지 않고 출력이 달라질 수 있다. 그러나 retriever가 관련 passage를 놓치면 뒤 generator는 그 문서를 읽을 기회가 없고, 검색된 passage가 생성된 모든 주장을 지지한다는 보장도 없다.

따라서 긴 문맥과 RAG의 차이는 단순히 “내부 대 외부”가 아니다. 전자는 **후보를 먼저 넓게 보존한 뒤 내부 선택에서 실패할 수 있고**, 후자는 **후보를 먼저 좁힌 뒤 검색 누락에서 실패할 수 있다.** 한 책의 710K 전체 문맥과 4K TF-IDF 문맥을 비교한 Gemini 1.5 실험은 이런 경로의 한 조건부 사례일 뿐, 모든 corpus·질문·비용 조건에서 어느 한쪽이 우세하다는 증거는 아니다.

### 실행 state: 에이전트 memory는 학습이 아니다

에이전트는 대화 기록, observation, 파일, code, vector database, 요약, 실패 feedback을 state로 보존하고 다음 attempt의 prompt 또는 tool 입력으로 다시 넣을 수 있다. Reflexion처럼 언어로 된 feedback을 episodic memory에 저장해 retry하는 방식은 같은 model weight를 바꾸지 않는다. 이는 fixed model의 다음 조건을 바꾸는 **verbal reinforcement**이지 online fine-tuning이나 reinforcement learning이 아니다.

이 차이는 운영상 중요하다. state를 고치면 즉시 다음 시도에 반영할 수 있지만, 오래된 요약·잘못된 observation·prompt injection도 계속 재주입될 수 있다. Weight update는 더 지속적인 행동 변화를 만들 수 있으나, 자료 선택·목적함수·회귀와 drift 평가가 필요한 별도 학습 절차다. “경험을 기억했다”는 문장만으로 어느 변화가 일어났는지 판단해서는 안 된다.

### 갱신성과 근거성은 한 축이 아니다

새 정책 문서를 빨리 반영하기에는 RAG index·agent file·긴 prompt가 weight 재학습보다 유리할 수 있다. 하지만 빨리 바꿀 수 있다는 사실이 출처가 명확하다는 뜻은 아니다. RAG의 검색 기록은 provenance 후보를 보여 주지만 claim-level citation의 정확성은 별도 평가가 필요하다. agent의 실행 log도 action trace를 남길 수 있지만, 그 action이 사용자의 목표·권한·최신 문서에 맞았는지는 policy와 postcondition 검사에 달려 있다.

반대로 원문을 모두 prompt에 넣으면 검색 단계의 탈락은 줄일 수 있지만, 어느 위치가 실제로 답을 결정했는지는 여전히 자동으로 드러나지 않는다. **갱신 비용, 접근 성공, 답의 충실성, 사용자가 검증할 수 있는 흔적은 서로 다른 장부**다.

## 검증과 한계

### 확인된 사실

- 원 MemNN은 외부 슬롯과 hard supporting-fact 선택을 사용했고, 후속 soft attention 변형·RAG와 같은 구현은 아니었다.
- Transformer-XL은 제한된 과거 은닉 상태를 재사용하며, stop-gradient로 세그먼트 사이 gradient를 끊었다.
- 원 RAG는 parametric model과 non-parametric index를 구분했고, document encoder·index를 고정한 채 question encoder와 generator를 학습하는 범위를 가졌다.
- 긴 문맥의 최대 길이는 수용 한도이며, 위치별 접근·여러 증거의 사용·근거 충실성에는 별도 평가가 필요하다.
- Reflexion형 episodic memory는 weight를 갱신하지 않는 retry loop로 제시됐다.

### 비교를 통한 해석

이 자료들을 함께 읽으면 `memory`를 단일 능력으로 측정하는 대신, **보존 형식·갱신 주체·선택 단계·검사 흔적**을 따로 기록하는 편이 재사용 가능하다. 특히 시스템 설계에서는 “최신 문서를 반영할 수 있는가?”와 “그 문서가 답을 지지했음을 보여 줄 수 있는가?”를 같은 질문으로 묶지 않는 것이 좋다.

### 아직 입증되지 않은 계보와 적용 한계

MemNN의 memory hop이 Transformer-XL의 recurrence나 현대 agent memory의 직접 조상이라는 계보는 이 자료만으로 입증되지 않는다. 모두 과거 정보를 다시 쓰지만, 표현·학습·실행 환경이 다르다. 또한 긴 문맥과 RAG의 상대 성능은 corpus 분포, chunking, retriever, 질문 유형, 비용, model과 평가 기준에 따라 달라진다. 이 글은 보편적인 우열이 아니라 실패 위치를 비교한다.
