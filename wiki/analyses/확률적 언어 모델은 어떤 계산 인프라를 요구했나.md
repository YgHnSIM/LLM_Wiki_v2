# 확률적 언어 모델은 어떤 계산 인프라를 요구했나

> [!note] 학습 안내
> **난이도:** 입문 → 중급<br>
> **선수 지식:** 없음 — corpus, count table, sparse storage, hidden state, dynamic programming, decoding search와 distributed query를 작은 숫자부터 정의한다.<br>
> **읽고 나면:** N-gram·HMM의 확률식이 corpus scan·count·smoothing·dynamic programming·hypothesis search라는 workload를 만드는 과정을 설명하고, 100만 단어 corpus에서 2조 token 분산 language model까지 data·storage·training·serving 지표를 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 확률식은 혼자 실행되지 않는다

[[001_섀넌의 N-gram 모델]]은 언어열을 확률적 source로 다루는 문제를 열었다. 실제 system을 만들려면 확률 기호 $P(w\mid h)$를 계산할 자료와 절차가 필요하다.

1. Text·speech를 machine-readable corpus로 만든다.
2. Token·acoustic feature를 정하고 sequence를 읽는다.
3. N-gram count나 HMM expected count를 누적한다.
4. Sparse event에 확률을 배분하고 parameter를 저장한다.
5. 입력마다 수많은 candidate path·sentence를 score하고 일부를 남긴다.
6. Held-out loss·perplexity·word error rate·translation score로 결과를 평가한다.

확률 모델의 발전은 수학적 estimator만의 역사가 아니다. Corpus format, storage, dynamic programming, search, CPU와 network가 함께 만든 실행 능력의 역사다.

### “큰 language model”의 크기는 시대마다 달랐다

1960년대 Brown Corpus의 약 100만 word는 digital computer로 실제 language sample을 반복 분석할 수 있게 한 중요한 자료였다. 1987년 Katz 논문은 sparse 3-gram을 IBM real-time speech recognizer의 language-model component로 구현했다. 2007년 Google 연구진은 13 million에서 2 trillion token까지 5-gram을 분산 처리하고 최대 300 billion n-gram을 serving했다.

세 규모를 같은 “parameter 수”로만 놓으면 핵심을 잃는다.

| 규모 축 | 세는 것 | 병목 |
| --- | --- | --- |
| Corpus | 읽은 token·utterance·sentence pair | 수집·정제·scan·I/O |
| Model | 저장한 n-gram·HMM state·transition·probability | memory·disk·partition |
| Training | count·expected count·정규화 반복 | CPU time·temporary storage |
| Decoding | 한 입력에서 조회·확장한 hypothesis | latency·network·search 폭 |
| Evaluation | held-out token·utterance·sentence와 metric | 비교 조건·domain 차이 |

Data가 커져도 모두 model에 남지 않으며, model이 커져도 한 request가 전부를 읽는 것은 아니다.

### 가장 작은 구체적 예: 가능한 표와 관측된 표

Vocabulary $V=\{\text{나는},\text{밥},\text{먹는다},\text{잔다}\}$에서 trigram의 가능한 조합은

$$
|V|^3=4^3=64
$$

개다. Corpus가 `나는 밥 먹는다`와 `나는 밥 먹는다`, `나는 잔다` 세 sentence뿐이라면 실제로 관측한 trigram은 훨씬 적다. `나는 밥 먹는다` count는 2이고, `나는 밥 잔다`는 0이다.

가능한 64칸을 모두 dense array로 저장할 수도 있지만 vocabulary가 50,000이면 가능한 trigram은

$$
50{,}000^3=125{,}000{,}000{,}000{,}000
$$

개다. 대부분 관측되지 않으므로 실제 system은 보통 관측 tuple과 count만 저장하는 **sparse table**을 쓴다. Sparse storage는 없는 event를 삭제하는 결정과 같다. 따라서 미관측 확률을 어떻게 복원할지 [[Smoothing]]과 backoff가 필요하다.

## 2단계 — 작동 원리

### N-gram training은 scan·sort·aggregate다

Order $n$의 language model은 token sequence를 길이 $n$의 window로 훑는다. 각 history $h$와 next token $w$의 count $C(h,w)$를 누적하고

$$
\hat P(w\mid h)=\frac{C(h,w)}{C(h)}
$$

로 상대빈도를 계산할 수 있다. Corpus token 수를 $D$라 하면 한 order의 window를 만드는 일은 대략 $O(D)$지만, count를 정렬·병합하고 여러 order를 저장하는 비용이 추가된다.

Vocabulary 크기를 $|V|$라 할 때 theoretical table은 $|V|^n$으로 폭증한다. 실제 model size는 관측된 distinct n-gram 수 $M_n$에 더 가깝다.

$$
M_n\le \min(D,|V|^n)
$$

$D$가 커지면 새로운 n-gram이 계속 생기지만 증가율은 corpus 중복, domain과 vocabulary cutoff에 달려 있다. 따라서 token 수를 두 배로 했다고 model byte가 정확히 두 배가 되지는 않는다.

### Backoff는 sparse lookup의 control flow다

[[019_Katz 백오프와 희소 데이터 확률 추정]]은 저빈도 관측 count를 할인해 probability mass를 남기고, 긴 history에서 event를 보지 못했으면 짧은 history로 내려간다.

Lookup 흐름은 다음과 같다.

1. Trigram $(w_{t-2},w_{t-1},w_t)$이 table에 있는지 찾는다.
2. 있으면 discounted probability를 반환한다.
3. 없으면 history별 backoff weight를 곱하고 bigram을 찾는다.
4. Bigram도 없으면 unigram distribution으로 내려간다.

이 과정은 수학적으로 probability를 재분배하면서 system 관점에서는 hash·sorted array·trie 같은 index를 여러 번 조회하는 branching workload다. Accuracy만 아니라 lookup latency와 model memory가 decoder의 처리량을 좌우한다.

### HMM은 지수적인 path 열거를 부분 결과 재사용으로 바꾼다

[[013_은닉 마르코프 모델과 통계적 음성 인식]]의 HMM은 관측되지 않는 state가 전이하고 각 state가 acoustic observation을 방출한다고 본다. State 수가 $S$, time step이 $T$이면 가능한 state sequence는 단순히 $S^T$개다.

Forward algorithm은 time $t$와 state $j$까지 오는 모든 path의 probability 합을 $\alpha_t(j)$에 저장한다.

$$
\alpha_t(j)=b_j(o_t)\sum_{i=1}^{S}\alpha_{t-1}(i)a_{ij}
$$

Dense transition이면 $O(TS^2)$ time과 한두 time slice의 $O(S)$ working memory로 계산할 수 있다. 예를 들어 $T=100$, $S=100$이면 가능한 path는 $100^{100}$개지만 recurrence의 transition score는 대략 $100\cdot100^2=1{,}000{,}000$개다.

Dynamic programming이 문제를 “공짜”로 만든 것은 아니다. State 수·observation dimension·mixture 수가 늘고 vocabulary search와 합쳐지면 계산량은 다시 커진다.

### 합·최대·기대 count는 서로 다른 workload다

HMM에서 비슷한 표를 사용해도 질문은 다르다.

- **Forward:** 모든 state path probability를 더해 observation likelihood를 구한다.
- **Viterbi:** 합 대신 maximum과 backpointer를 저장해 최고 path 하나를 찾는다.
- **Baum–Welch:** forward·backward 결과로 transition·emission의 expected count를 누적하고 parameter를 재추정한다.

[[최고 경로와 기대 통계, 백오프]]가 설명하듯 최고 path, path sum, expected statistics와 unseen-event backoff는 서로 바꿀 수 없다. Training과 decoding이 같은 model을 읽어도 temporary state, 반복 횟수와 output contract가 다르다.

### Speech recognition은 model score와 hypothesis search를 결합한다

Continuous speech에서는 acoustic frame마다 가능한 state·word가 갈라진다. Pronunciation lexicon, acoustic model과 language model 점수를 결합해 partial hypothesis를 확장하고, 가능성이 낮은 후보를 beam pruning으로 버린다.

Beam을 좁히면 빠르지만 정답 path를 일찍 제거할 수 있다. Beam을 넓히면 더 많은 후보를 보지만 CPU·memory가 늘어난다. Model의 probability quality와 search approximation을 분리해 기록해야 한다.

### Distributed N-gram은 memory lookup을 network protocol로 바꾼다

2007년 Brants 등의 system은 n-gram probability를 여러 server에 partition하고 machine-translation decoder가 필요한 lookup을 batch로 보냈다. 한 query마다 모든 worker에 broadcast하지 않고 필요한 n-gram을 가진 worker에 접근했다.

Network round-trip이 candidate마다 일어나면 latency가 감당되지 않는다. Decoder는 한 round에서 필요한 n-gram을 모아 1,000개나 10,000개 단위 request로 보내고 응답 뒤 score·pruning을 계속했다. 이때 language model은 local table이 아니라 **networked serving system**이 된다.

## 3단계 — 기술과 근거

### Machine-readable corpus가 만든 반복 가능한 count

Francis와 Kučera의 Brown Corpus manual은 1961년 미국 편집 산문에서 고른 500개 sample과 약 100만 word를 digital computer용 표준 corpus로 조직했다. 이는 “영어 전체”가 아니라 sampling frame·genre·시기·encoding이 고정된 dataset이다.

Corpus가 machine-readable하다는 것은 같은 counting program을 다시 실행할 수 있다는 뜻이다. 동시에 tag·token boundary·오탈자·sampling choice가 count에 들어간다. 더 많은 text가 자동으로 더 대표적인 language model을 만드는 것은 아니다.

### HMM과 통계적 speech recognition이 묶은 pipeline

Baum 계열의 재추정은 finite-state probabilistic model의 parameter learning을 수학적으로 구성했다. Jelinek의 1976년 종합은 speaker·acoustic processor modeling, statistical parameter estimation, hypothesis search와 likelihood computation을 하나의 continuous-speech recognition 문제 안에 놓았다.

이 결합에서 model training과 recognizer execution은 다르다. Training은 많은 observation에서 count·expected count를 누적한다. Recognition은 한 utterance에서 candidate path를 search한다. 같은 parameter file을 사용해도 throughput·latency 요구가 다르다.

### Katz: 희소성 처리와 real-time component

Katz의 1987년 연구는 sparse m-gram probability estimation을 IBM real-time speech recognizer의 language-model component에 적용했다. 확인되는 범위는 이 구현과 논문 안의 perplexity 비교다.

Backoff는 unseen event 문제를 줄였지만 모든 긴 context를 저장하거나 의미를 표현하지 않는다. Count cutoff·discount table·backoff weight를 준비하는 offline 비용과 recognizer가 probability를 조회하는 online 비용도 구분해야 한다.

### 2007년 2조 token model의 숫자를 분리해 읽기

Brants 등은 5-gram training data를 13 million에서 2 trillion token까지 늘렸다. 가장 큰 web 조건의 Table 2는 다음을 보고했다.

| 항목 | 가장 큰 web 조건 |
| --- | ---: |
| Training token | 약 1.8 trillion |
| Vocabulary | 16 million |
| 저장된 n-gram | 300 billion |
| Served LM size | 약 1.8 TB |
| Stupid Backoff training | 1,500 machines에서 약 1일 |
| Kneser–Ney 예상 training | 1,500 machines에서 약 1주라 판단해 실험 제외 |

Decoder 예에서는 평균 22-word sentence마다 약 23 network round, 약 150,000 n-gram을 요청했다. Batch당 평균 network latency 35 ms로 distributed LM 때문에 약 0.8초가 추가됐다. Quality 일부를 양보하고 약 10,000 n-gram으로 줄이면 batch latency를 7 ms 수준으로 낮출 수 있었다.

이는 “1,500대면 모든 것이 실시간”이라는 결과가 아니다. Training wall-clock, served bytes, 한 sentence의 request 수와 network latency가 각각 다른 병목임을 보여 준다.

### 단순한 smoothing도 시스템 선택이다

이 연구의 Stupid Backoff는 큰 data에서 싸게 계산하기 위한 score rule이며 normalized probability distribution을 만들지 않는다. 그래서 저자들은 이 score의 perplexity를 보고하지 않고 5-gram coverage와 translation BLEU를 함께 봤다.

더 정교한 Kneser–Ney가 작은 data에서 우수해도 2 trillion token 조건에서는 estimated training cost 때문에 제외됐다. Algorithm 선택은 수학적 quality만이 아니라 data scale·machine 수·deadline·serving integration과 함께 결정됐다.

### 이 본편의 측정 장부

| 항목 | 기록 |
| --- | --- |
| 작업 | Corpus n-gram counting·smoothing, HMM likelihood·decoding·re-estimation, speech·translation hypothesis scoring |
| 규모 | Token $D$, vocabulary $|V|$, distinct n-gram $M_n$, state $S$, sequence $T$, hypothesis·machine 수 |
| 결과 계약 | Normalized next-word probability 또는 명시적 score, observation likelihood, 최고 state·word path, held-out recognition·translation 결과 |
| 시스템 경계 | Corpus preparation·offline training·model storage·network serving·decoder search·evaluation을 분리 |
| 고정 조건 | Tokenization·domain·vocabulary cutoff·n, HMM topology·feature, smoothing·beam, hardware·machine 수와 test set |
| 지표 | Count·coverage·perplexity·WER·BLEU, CPU time·wall-clock·model byte·query 수·network round·latency |

같은 “language model size”도 token, distinct n-gram과 byte 가운데 무엇을 뜻하는지 밝혀야 한다. Perplexity, WER와 BLEU도 서로 다른 result contract라 직접 환산할 수 없다.

### N-gram에서 LLM으로 옮겨진 병목과 바뀐 병목

[[N-gram 모델]]은 surface tuple별 count를 sparse하게 저장한다. Neural language model은 embedding과 shared weight로 context 사이에 parameter를 공유한다. 그러나 corpus scan, batch, checkpoint, distributed communication과 serving latency라는 system 질문은 사라지지 않았다.

현대 LLM에서 lookup table 대부분은 dense tensor operation으로 바뀌었고 training은 gradient·optimizer state를 저장한다. N-gram distributed server의 network query와 modern accelerator collective는 둘 다 communication이지만 message, synchronization과 consistency contract가 다르다. 직접 계보보다 **계산을 partition할 때 data locality와 latency가 다시 나타난다**는 비교가 안전하다.

## 검증과 한계

- **직접 영향:** Katz backoff가 IBM speech recognizer에 구현됐고, Brants 등의 distributed language model이 machine-translation hypothesis search에 직접 통합됐다는 점은 각 원문이 확인한다.
- **가능 조건:** Machine-readable corpus, 더 큰 storage와 CPU cluster는 더 많은 count·candidate를 처리할 수 있게 했다. 이 조건만으로 좋은 tokenization·smoothing·search나 대표성 있는 data가 생기지는 않는다.
- **병행 맥락:** HMM speech recognition과 N-gram language modeling은 한 recognizer에서 결합될 수 있지만 HMM state transition·emission과 word history table은 다른 확률 변수와 독립 가정을 가진다.
- **후대 유추:** Sparse n-gram serving과 modern LLM serving을 data locality·batch·latency 축으로 비교하는 것은 시스템 분석이다. 동일한 model architecture나 software lineage를 뜻하지 않는다.

2007년 논문의 “large language model”은 최대 5-gram sparse model을 뜻한다. 오늘날 neural LLM의 parameter count와 같은 단위가 아니다. 1.8 TB model size를 neural weight 1.8 TB와 같은 계산량으로 해석할 수도 없다.

Reported machine 수와 time은 당시 implementation·hardware·data·smoothing에 한정한다. Energy·cost·failure rate가 직접 보고되지 않았으므로 추정하지 않는다. Brown Corpus와 web corpus의 token 수 차이도 quality나 representativeness의 순위를 자동으로 정하지 않는다.

## 학습 확인

1. Vocabulary 50,000의 모든 trigram을 dense하게 저장하는 방식과 관측 n-gram만 sparse하게 저장하는 방식의 비용·확률 문제를 설명하라.
2. HMM의 forward, Viterbi와 Baum–Welch가 같은 state table을 사용하면서도 output과 temporary computation이 다른 이유는 무엇인가?
3. 새 distributed language model 보고서에서 corpus token, model byte, training wall-clock, request latency와 task metric을 각각 찾아 별도 장부로 적어라.

다음에는 sparse table·CPU cluster에서 dense matrix·GPU·CUDA·deep-learning framework로 workload와 programming interface가 어떻게 바뀌었는지 살핀다.

횡단 연결 [[N-gram에서 LLM으로]]은 이 본편의 sparse count·Katz back-off에서 출발해 NPLM·Word2Vec·RNN·seq2seq·Transformer까지 **예측 과업과 표현 학습의 결과 계약이 바뀐 중간 단계**를 잇는다.
