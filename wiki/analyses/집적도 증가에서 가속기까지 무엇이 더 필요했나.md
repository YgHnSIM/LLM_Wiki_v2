# 집적도 증가에서 가속기까지 무엇이 더 필요했나

> [!note] 학습 안내
> **난이도:** 입문 → 중급<br>
> **선수 지식:** 없음 — 집적도, transistor scaling, power wall, memory wall, parallelism과 domain specialization을 작은 시간 예산부터 정의한다.<br>
> **읽고 나면:** Moore의 1965년 관찰을 CPU 속도나 LLM 성능의 법칙으로 바꾸지 않고, 더 많은 transistor가 실제 accelerator 성능이 되려면 전력·memory·병렬 프로그래밍·특화 설계가 왜 필요했는지 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 더 많은 component는 더 빠른 프로그램과 같은 문장이 아니다

Moore의 1965년 글은 집적 회로에서 **component당 비용이 최소가 되는 집적 수준**과 시간에 따른 component 수 증가를 관찰하고 전망했다. 현대에 흔히 말하는 “CPU 속도는 일정 주기로 두 배가 된다”는 문장과 같지 않다. Component를 더 넣을 수 있어도 다음 조건을 풀지 못하면 실제 program은 그 비율만큼 빨라지지 않는다.

1. 각 transistor를 허용 전력 안에서 얼마나 빠르게 switching할 수 있는가
2. 동시에 쓸 수 있는 병렬 작업을 algorithm과 program이 제공하는가
3. 연산 장치에 data를 충분히 빨리 공급할 memory hierarchy가 있는가
4. 특정 workload에 유용한 arithmetic·dataflow를 architecture가 제공하는가
5. Compiler·library·runtime이 그 hardware를 실제 operation으로 사용할 수 있는가
6. 전체 service의 품질·지연·비용 계약을 만족하는가

따라서 집적도 증가는 **자원 가능성**이고, accelerator는 그 자원을 특정 workload의 실현 성능과 효율로 바꾸는 설계다. 둘 사이에는 자동 변환이 없다.

### 100이라는 시간 예산으로 보는 병목 이동

가상 program의 전체 시간이 100이고, 그중 연산이 80, memory 대기가 20이라고 하자. 연산 장치만 정확히 2배 빨라지면 연산 시간은 40이 되지만 memory 20은 그대로다.

$$
T_{\text{new}}=\frac{80}{2}+20=60
$$

전체 speedup은 2가 아니라 다음과 같다.

$$
S=\frac{T_{\text{old}}}{T_{\text{new}}}
=\frac{100}{60}
\approx 1.67
$$

연산을 더 가속할수록 바뀌지 않은 memory·communication·serial work의 비중이 커진다. 이 설명용 숫자는 특정 processor의 benchmark가 아니라 **부분 가속을 전체 가속으로 오해하지 않는 법**을 보여 준다.

## 2단계 — 작동 원리

### 1. 집적도와 device scaling

집적도(density)는 일정 면적에 넣는 component 수다. 집적도가 늘면 더 많은 execution unit, register, cache와 control logic를 넣을 여지가 생긴다. 그러나 회로가 실제로 동작하려면 voltage, current, 열과 fabrication 조건을 함께 만족해야 한다.

Dennard 등의 1974년 scaling model은 transistor의 치수와 전압 등을 함께 축소하는 조건 아래 작은 MOSFET의 성질을 분석했다. 흔히 **Dennard scaling**이라고 부르는 요지는 단순히 transistor가 작아진다는 사실이 아니라, 전기장과 전력 밀도를 통제하는 동시 scaling 규칙이다. 이 조건이 영원히 유지된다는 자연 법칙이 아니다.

### 2. 단일 core 속도에서 병렬 자원으로

Clock과 instruction-level parallelism만 계속 높이기 어려워지면 새 transistor를 여러 core와 execution lane에 배분하는 선택이 중요해진다. 2006년 Berkeley 보고서는 power, instruction-level parallelism과 conventional architecture의 한계를 지적하고, parallelism을 연구·programming의 중심 문제로 다뤘다.

병렬 hardware만 늘려도 program이 자동으로 나뉘지는 않는다. Data dependence, synchronization, load balance와 communication을 표현하는 programming model이 필요하다. 같은 transistor 예산도 cache, general-purpose core, vector lane 또는 matrix unit에 어떻게 배분하느냐에 따라 잘하는 workload가 달라진다.

### 3. 연산과 memory의 속도 차이

Memory wall은 processor가 arithmetic을 끝내는 속도와 main memory에서 data를 가져오는 속도의 격차 때문에 전체 실행이 memory access에 지배될 수 있다는 문제다. Cache는 자주 쓰는 값을 가까이 두지만 working set이 cache보다 크거나 접근이 불규칙하면 miss와 data movement가 남는다.

이 때문에 peak operations per second는 필요한 data가 execution unit에 제때 도착할 때만 의미가 있다. [[메모리 계층과 데이터 이동]]은 HBM·cache·SRAM, bandwidth, latency와 재사용을 완전히 설명한다.

### 4. CUDA가 많은 core를 programmable throughput으로 바꾸기

GPU는 많은 arithmetic lane을 가졌지만, 범용 계산 workload가 이를 사용하려면 실행과 memory를 표현할 interface가 필요했다. CUDA는 thread를 block과 grid로 조직하고 block 안의 shared memory와 synchronization을 제공했다. Programmer는 독립 작업을 thread에 배치하고 data locality를 설계할 수 있게 됐다.

CUDA는 transistor 수 증가의 자동 결과가 아니다. 같은 시대의 device density를 **throughput-oriented parallel machine**으로 배치한 architecture와 이를 노출한 software model의 결합이다.

### 5. TPU가 domain specialization으로 자원을 다시 배분하기

TPU는 범용 CPU의 모든 동작을 같은 비중으로 빠르게 하는 대신, production neural-network inference의 matrix multiply와 low-precision arithmetic에 큰 면적을 배분했다. Jouppi 등의 2017년 분석은 65,536개 8-bit multiply-accumulate unit과 28 MiB on-chip memory를 포함한 설계를 실제 datacenter inference workload와 99백분위 response-time constraint에서 평가했다.

이 선택은 높은 arithmetic density와 data reuse를 얻는 대신 지원 operation·자료형·programming flexibility를 제한한다. [[가속기와 행렬 계산]]은 CPU·GPU·TPU를 속도 서열이 아니라 parallel unit·memory path·precision·utilization으로 비교한다.

## 3단계 — 기술과 근거

### 집적도 관찰에서 accelerator까지의 여섯 전환

| 전환 | 새로 가능해진 것 | 자동으로 보장되지 않은 것 |
| --- | --- | --- |
| Moore 1965의 component 집적 전망 | 같은 회로 면적·비용에서 더 복잡한 기능을 넣을 여지 | CPU clock, program speed, model quality |
| Dennard scaling model | 특정 동시 scaling 조건에서 작은 transistor의 동작·전력 밀도 분석 | Scaling 조건의 영구 지속, system energy 감소 |
| Power·ILP 한계와 parallel shift | 여러 core·lane에 transistor 예산을 배분 | Sequential program의 자동 speedup |
| Memory wall | Arithmetic peak와 data 공급을 별도 병목으로 측정 | Cache만으로 모든 workload 해결 |
| CUDA GPU | Throughput hardware를 thread·block·memory model로 프로그램 | 모든 algorithm의 GPU 효율 |
| TPU specialization | Neural inference의 matrix workload에 arithmetic·memory를 집중 | 모든 model·operation·service에서 우월함 |

이 표의 연결은 “첫 행이 마지막 행을 직접 낳았다”는 계보가 아니다. 시대별로 **남는 병목이 설계 목표를 어떻게 바꾸었는가**를 비교한 것이다.

### 여섯 항목 측정 장부

| 항목 | 이 연결고리에서 기록할 것 |
| --- | --- |
| 작업 | Transistor circuit, CPU program, parallel kernel, neural inference 중 무엇을 실행했는지 구분한다. |
| 규모 | Component·transistor, core·thread, matrix shape, chip·host와 request 수를 각각 기록한다. |
| 결과 계약 | 같은 program output, 허용 수치 오차, model quality, 99백분위 latency 가운데 무엇을 만족해야 하는지 밝힌다. |
| 시스템 경계 | Device circuit, chip, host 또는 datacenter service 중 어디까지 시간·전력을 포함했는지 적는다. |
| 고정 조건 | Process node, voltage, frequency, memory, precision, software, batch와 workload 중 무엇을 같게 뒀는지 적는다. |
| 지표 | Component density, clock, operations/s, bandwidth, latency, energy와 cost를 서로 대리값으로 쓰지 않는다. |

“두 배”라는 숫자를 읽을 때 첫 질문은 **무엇의 두 배인가**다. Component 수, peak arithmetic, kernel throughput, end-to-end latency와 time-to-quality는 서로 다른 분자·분모와 시스템 경계를 가진다.

### 가상 speedup 예를 일반화하기

전체 시간을 가속 대상 $T_a$와 나머지 $T_r$로 나누고, 대상만 $k$배 빠르게 하면 새 시간은 다음과 같다.

$$
T_{\text{new}}=\frac{T_a}{k}+T_r
$$

이는 정의에서 나온 산술식이다. 실제 system에서 $T_a$와 $T_r$이 고정된다는 보장은 없다. 더 빠른 kernel이 batch·memory traffic·scheduling을 바꾸면 두 부분도 함께 변할 수 있으므로 profile을 다시 측정해야 한다.

## 검증과 한계

### 인과를 네 종류로 감사한다

| 인과 표지 | 이 문서에서 허용하는 주장 |
| --- | --- |
| 직접 영향 | CUDA와 TPU 논문은 각각 throughput-oriented GPU programming과 neural inference를 위한 domain-specific 설계 목표를 직접 설명한다. Moore의 글이 이 두 설계를 지시했다는 직접 문헌 근거는 제시하지 않는다. |
| 가능 조건 | 더 높은 집적도와 transistor scaling은 더 많은 core·memory·matrix unit을 chip에 넣을 물리적 여지를 넓혔다. 이것만으로 GPU·TPU·LLM이 필연적으로 나오지는 않는다. |
| 병행 맥락 | Power·ILP 한계, memory wall과 parallel computing 전환은 같은 실제 성능 문제를 서로 다른 system 층에서 다뤘다. 모든 연구가 하나의 공동 roadmap을 따랐다고 쓰지 않는다. |
| 후대 유추 | Moore → Dennard → wall → CUDA → TPU라는 여섯 칸과 100→60 예는 이 위키가 여러 1차 자료를 함께 읽어 만든 회고적 설명이다. |

### 금지하는 단일 원인 문장

“무어의 법칙이 GPU를 만들었다”, “무어의 법칙이 LLM을 낳았다”, “transistor가 늘어서 AI가 두 배씩 좋아졌다”는 문장은 이 근거들로 지지되지 않는다. 집적도는 model architecture, training data, optimization, software stack, memory system, parallel execution과 evaluation contract를 대신하지 않는다.

또한 다음을 한 순위로 합치지 않는다.

- Moore의 최소 비용점 component 수와 processor transistor count
- Device transistor scaling과 system-level power
- Peak arithmetic과 memory-bound kernel 시간
- GPU kernel throughput과 TPU datacenter inference
- Hardware efficiency와 model quality

Semiconductor 공급망, fabrication yield, packaging, interconnect, 냉각, 전력망, 자본 비용과 환경 영향은 중요한 조건이지만 이 연결고리의 범위 밖이다.

## 학습 확인

1. Moore의 1965년 관찰이 “CPU 또는 LLM 성능이 일정 주기로 두 배가 된다”는 명제와 다른 이유를 설명하라.
2. 전체 시간 100에서 연산 80만 2배 가속할 때 새 시간 60과 speedup 약 1.67이 되는 과정을 계산하고, memory 비중이 어떻게 달라지는지 말하라.
3. 새 AI chip이 “10배 빠르다”고 주장한다. 작업·규모·결과 계약·시스템 경계·고정 조건·지표를 채우고 peak arithmetic, kernel, model step, end-to-end service 중 어느 경계인지 판정하라.

시대순으로는 [[언어와 계산을 기계적 절차로 만들다]]에서 programmable machine의 층을 확인하고, [[행렬곱 가속은 딥러닝을 어떻게 현실화했나]]를 거쳐 [[연산보다 데이터 이동이 비싸질 때]]에서 바뀐 병목을 이어 읽는다.
