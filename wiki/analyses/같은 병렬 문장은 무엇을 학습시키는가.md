# 같은 병렬 문장은 무엇을 학습시키는가

> [!note] 학습 안내
> **난이도:** 심화<br>
> **선수 지식:** [[통계적 기계 번역]], [[신경망 기계 번역]], [[XLM]]<br>
> **읽고 나면:** 같은 병렬 문장쌍이 IBM SMT·seq2seq NMT·TLM에서 서로 다른 관측값·예측 목표·정렬 신호가 되는 이유를 설명할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 비교 질문과 잠정 결론

[[022_IBM 통계적 기계 번역과 데이터 기반 전환]], [[045_Sequence-to-Sequence 학습과 신경 기계 번역]], [[062_XLM과 교차 언어 사전 학습]]은 모두 두 언어로 된 대응 문장을 사용한다. 그러나 `원문–번역문 pair를 쓴다`는 공통점만으로 같은 학습 문제라고 할 수는 없다. 한 pair에서 **무엇을 이미 아는 값으로 두고, 무엇을 맞혀야 할 값으로 두며, 어떤 대응을 숨은 구조로 두는지**가 다르기 때문이다.

- IBM 통계 번역에서는 문장쌍은 관측되지만 단어별 대응은 잠재 정렬이다.
- seq2seq 신경 번역에서는 원문을 조건으로 번역문의 다음 token들을 직접 예측한다.
- XLM의 TLM에서는 두 문장을 한 encoder 문맥으로 묶고 양쪽의 가린 token을 복원한다. 한쪽 문장 전체를 다른 쪽의 자기회귀 출력으로 만들지는 않는다.

따라서 병렬 자료는 그 자체로 `번역 정답`이나 `정렬 신호`라는 한 가지 의미를 갖지 않는다. **목적 함수가 pair 안에 예측 경계를 어디에 놓는지**에 따라 번역 매개변수 추정 자료, target sequence supervision, 교차 언어 표현 정렬 문맥으로 역할이 달라진다.

### 비교할 세 질문

1. **관측값은 무엇인가?** 문장쌍, 원문, 번역문, masked token 가운데 학습기에 주어진 값은 무엇인가?
2. **예측값은 무엇인가?** 단어 대응의 기대 통계, 다음 번역 token, 양쪽 언어의 masked token 가운데 무엇에 loss를 거는가?
3. **직접 사용 목적은 무엇인가?** 번역 후보의 점수화, 번역문 생성, 공유 encoder 사전 학습 가운데 어디에 결과를 쓰는가?

이 세 질문은 자료 이름보다 학습 신호의 실제 위치를 더 정확하게 드러낸다.

## 2단계 — 작동 원리

### 한 문장쌍이 세 학습 문제로 바뀌는 과정

영어 `the cat sleeps`와 프랑스어 `le chat dort`가 대응 문장으로 주어졌다고 하자.

| 접근 | 관측된 값 | 따로 주어지지 않은 값 | 직접 예측·추정하는 것 | 학습 결과의 직접 용도 |
| --- | --- | --- | --- | --- |
| IBM SMT | 영어·프랑스어 문장쌍 | 단어 위치별 정렬 | 번역·정렬·왜곡 등 확률과 잠재 정렬의 기대 통계 | 번역 후보 점수화와 탐색 |
| seq2seq NMT | 원문 $x$와 참조 번역문 $y$ | 명시적 단어 정렬 | $x$와 앞선 참조 token을 조건으로 한 다음 target token | 번역문 자기회귀 생성 |
| XLM TLM | 이어 붙인 두 문장과 가리지 않은 token | 명시적 단어 정렬 | 양쪽 문장에서 가린 token | 교차 언어 shared encoder 사전 학습 |

IBM 모형은 문장 전체의 대응을 이용하지만 어느 단어가 어느 단어에서 생성됐는지는 직접 받지 않는다. seq2seq는 target 문장 순서를 token별 정답으로 사용하지만, 별도 정렬 label은 요구하지 않는다. TLM은 두 문장을 모두 양방향 문맥으로 사용하며 어느 쪽이든 일부 token을 가려 복원한다.

### ‘정답’이라는 말이 가리는 차이

세 방법 모두 corpus에 기록된 실제 token을 학습 신호로 사용한다. 그러므로 TLM만 정렬 신호이고 SMT·NMT만 정답을 쓴다고 이분법적으로 나누는 것도 부정확하다. 차이는 token이 존재하느냐가 아니라 **어떤 조건부 분포를 맞추도록 배치되느냐**에 있다.

- SMT의 문장쌍은 번역 확률을 추정하는 관측 자료이며 단어 정렬은 합산하거나 근사하는 잠재 변수다.
- NMT의 target 문장은 위치별 생성 label로 직접 들어간다.
- TLM의 두 문장은 서로의 복원 문맥이 되고, loss는 선택된 masked position에만 놓인다.

같은 pair를 보더라도 한쪽 전체를 출력 sequence로 정했는지, 양쪽 일부를 공동 복원하게 했는지에 따라 학습된 interface가 달라진다.

## 3단계 — 기술과 근거

### IBM SMT: 문장은 맞춰져 있고 단어 정렬은 숨어 있다

IBM 연구의 pipeline에서는 먼저 Hansard 같은 이중 언어 문서에서 대응 문장쌍을 구성했다. Brown·Lai·Mercer의 1991년 연구는 문장 길이를 단서로 1:1뿐 아니라 삭제·삽입·분할·병합을 포함한 문장 alignment를 찾았다. 이 단계에서 만들어진 **sentence pair**와, 뒤의 IBM Models가 추정한 **word alignment**를 같은 정답으로 보아서는 안 된다.

Brown 등의 생성 방향 표기에서 관측된 영어 문장 $e$가 프랑스어 문장 $f$를 만들 확률은 가능한 단어 정렬 $a$를 합해 계산한다.

$$
P(f\mid e)=\sum_a P(f,a\mid e)
$$

정렬 label이 없기 때문에 EM은 현재 매개변수 아래 각 $a$의 사후확률을 구해 단어쌍·위치·생성도 등의 기대 계수를 누적한다. Models 1·2에서는 가능한 정렬의 합을 정확히 계산할 수 있지만 Models 3–5에서는 유력 정렬 주변의 근사가 필요했다. 여기서 pair는 `이 두 문장이 번역 관계다`라는 관측이고, 어느 위치가 대응하는지는 모형이 추정하는 숨은 구조다.

### seq2seq NMT: target 문장이 생성 label이 된다

초기 seq2seq NMT는 원문 $x$를 읽어 얻은 표현을 조건으로 target 문장 $y$의 확률을 직접 매개변수화했다.

$$
\mathcal{L}_{\mathrm{NMT}}
=-\sum_{t=1}^{T}\log p_\theta(y_t\mid y_{<t},x)
$$

훈련에서는 참조 prefix $y_{<t}$를 입력하는 teacher forcing으로 각 target token에 cross-entropy loss를 건다. Sutskever 등의 2014년 대표 모형은 별도의 attention이나 word-alignment label 없이 고정 벡터를 통해 이 조건부 생성을 학습했다.

같은 2014년의 모든 RNN Encoder–Decoder가 완결된 sentence-level 번역기로 쓰인 것은 아니다. Cho 등의 대표 실험은 source phrase에서 target phrase의 조건부 점수를 학습한 뒤 그 점수를 기존 구 기반 SMT의 추가 특징으로 넣었다. 이 분석의 `seq2seq NMT` 행은 Sutskever식 직접 문장 생성을 가리키며, encoder–decoder라는 구조 이름만으로 최종 system role까지 같다고 보지 않는다.

뒤의 Bahdanau attention은 target token을 만들 때 source 위치별 연속 가중치를 계산했다. 기능적으로 입력–출력 대응을 보여 주지만 IBM식 이산 정렬 label이나 EM의 잠재 변수와 같은 연산은 아니다. attention weight도 translation loss 안에서 간접 학습되며 정렬의 정답으로 별도 제공되지 않았다.

### TLM: 두 문장이 서로의 masked-token 문맥이 된다

XLM은 병렬 문장쌍을 이어 붙이고 두 언어 양쪽에서 token을 선택한 뒤, corrupted pair 전체의 문맥으로 원 token을 복원하는 Translation Language Modeling(TLM)을 사용했다. 선택된 token은 MLM과 같이 80%는 `[MASK]`, 10%는 무작위 token으로 바뀌고 10%는 그대로 남는다. 이어 붙인 sequence를 $z=[x;y]$, 선택 위치 집합을 $M$, 실제 encoder 입력을 $\tilde z=\operatorname{corrupt}(z,M)$이라 하면 목적은 다음처럼 쓸 수 있다.

$$
\tilde z=\operatorname{corrupt}(z,M),\qquad
\mathcal{L}_{\mathrm{TLM}}
=-\sum_{i\in M}\log p_\theta(z_i\mid \tilde z)
$$

이는 $x$를 읽고 $y$ 전체를 왼쪽에서 오른쪽으로 생성하는 $p(y\mid x)$가 아니다. $y$의 token이 가려지면 $x$와 가리지 않은 $y$가 복원 문맥이 되고, $x$의 token이 가려지면 반대 방향의 문맥도 사용된다. 명시적 단어 정렬 label 없이 full attention이 두 문장을 오갈 수 있어 번역쌍은 shared encoder에 강한 교차 언어 대응 신호를 준다.

XLM의 `MLM+TLM` 설정은 monolingual MLM batch와 parallel TLM batch를 교대로 학습했다. TLM이 CLM 뒤의 필수 단계이거나 번역 decoder를 훈련하는 목적은 아니다. monolingual MLM만으로도 XNLI 전이가 가능했고, MLM 71.5와 MLM+TLM 75.1의 차이는 해당 설정에서 parallel data와 TLM objective를 함께 추가한 결과다. 이 3.6%p 차이만으로 TLM의 보편적 정렬 품질이나 objective만의 순수 인과 효과가 입증되지는 않는다.

### 같은 ‘alignment’가 가리키는 서로 다른 층위

| 표현 | 정렬되는 단위 | 정렬이 놓이는 위치 | 별도 정렬 label |
| --- | --- | --- | --- |
| sentence alignment | 두 언어의 문장·구간 | corpus 구축·전처리 | 문서 순서·길이 등으로 추정·검토 |
| IBM word alignment | source·target 단어 위치 | 번역 생성 모형의 이산 잠재 변수 | 없음 |
| NMT attention | target 시점과 source hidden state | translation network 내부의 연속 가중치 | 없음 |
| TLM cross-lingual context | 두 문장의 token 표현 | shared encoder의 masked reconstruction | 없음 |

네 경우는 모두 언어 사이 대응을 다루지만 교환 가능한 이름이 아니다. 특히 `IBM alignment가 attention으로 바뀌고 다시 TLM이 됐다`는 직선 계보는 기능적 유사성만으로 입증할 수 없다.

### 병렬 자료의 비용도 목적과 함께 읽어야 한다

IBM SMT와 지도 NMT는 번역기를 직접 학습하기 위해 대응 문장쌍에 의존한다. XLM은 monolingual MLM만으로도 shared multilingual encoder를 만들 수 있고, TLM은 parallel pair가 있는 언어에 추가하는 objective다. 원 XLM 실험의 TLM pair는 한쪽이 모두 영어였으므로 모든 언어쌍 사이에 직접 병렬 자료가 있었던 것도 아니다.

따라서 다음 두 문장은 동시에 참이다.

- 같은 형식의 병렬 자료도 목적 함수에 따라 번역 모형이나 표현 모형의 서로 다른 supervision이 될 수 있다.
- pair의 품질·domain·언어 연결 구조가 다르면 `같은 양의 병렬 자료`라는 숫자만으로 세 방법의 효율과 성능을 비교할 수 없다.

이 비교의 재사용 가능한 결론은 **data type이 task를 결정하지 않고, prediction target과 attention·mask 경계가 data의 학습 역할을 결정한다**는 것이다.

## 검증과 한계

### 확인된 사실

- IBM SMT의 학습 자료는 sentence-aligned pair였지만 Models 1–5의 word alignment는 관측 label이 아니라 잠재 변수였다.
- 2014년 seq2seq NMT는 원문을 조건으로 target sequence의 token likelihood를 최대화했다.
- 초기 Sutskever seq2seq에는 attention이 없었고, Bahdanau식 soft alignment는 뒤의 translation loss 안에서 연속적으로 학습됐다.
- XLM TLM은 병렬 문장 양쪽의 masked token을 공동 문맥으로 복원했으며, MLM과 TLM batch를 교대로 학습했다.
- XLM의 monolingual MLM 설정도 교차 언어 전이를 보였으므로 parallel data가 multilingual transfer의 유일한 조건은 아니었다.

### 비교를 통한 해석

- 병렬 문장쌍의 의미는 저장 형식보다 목적 함수의 예측 경계로 정의하는 편이 정확하다.
- SMT의 잠재 대응 추정, NMT의 조건부 생성, TLM의 표현 정렬은 같은 자료에서 서로 다른 supervision을 꺼내는 세 방식이다.
- `정렬`이라는 공통어를 sentence preparation, latent variable, attention weight, representation sharing으로 분해하면 서로 다른 시대의 모형을 직접 계보로 과장하지 않고 비교할 수 있다.

### 아직 입증되지 않은 계보와 일반화

- IBM word alignment가 신경망 attention이나 TLM으로 직접 변형됐다는 역사적 인과는 이 논문들의 기능적 유사성만으로 확인되지 않는다.
- TLM이 모든 언어·과제에서 monolingual MLM보다 낫거나 지도 번역 목적을 대체한다는 결론은 나오지 않는다.
- 어느 목적이 같은 양의 병렬 자료를 가장 효율적으로 사용한다는 보편 순위도 corpus·언어쌍·model size·evaluation을 통제하지 않고는 정할 수 없다.
- 실제 비교 문헌의 corpus는 Hansard·WMT·XLM의 영어 중심 병렬 자료로 서로 다르므로, 동일 data를 세 목적에 넣은 통제 실험처럼 읽을 수 없다.
- 표현이 더 잘 정렬됐다는 사실만으로 번역 충실성·생성 품질·target-language task 성능이 모두 같은 폭으로 좋아진다고 볼 수 없다.
