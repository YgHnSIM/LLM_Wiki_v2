# 언어와 계산을 기계적 절차로 만들다

> [!note] 학습 안내
> **난이도:** 입문 → 중급<br>
> **선수 지식:** 없음 — 명제, switch, 상태, tape, instruction, program과 확률적 message source를 이 문서 안에서 정의한다.<br>
> **읽고 나면:** 불 대수·relay circuit·Turing machine·저장 프로그램·확률 언어 모형이 각각 무엇을 표현했는지 설명하고, 이들을 하나의 직접 계보로 과장하지 않으면서 현대 LLM의 token·program·parameter·출력 확률과 비교할 수 있다.

## 1단계 — 먼저 잡을 핵심

### “기계가 읽는 언어”는 한 종류가 아니다

계산의 역사에서 **기호를 쓴다**는 말은 적어도 네 가지를 가리킨다.

| 기호 체계 | 표현하는 것 | 기계적 처리의 질문 |
| --- | --- | --- |
| 논리식 | 참·거짓 조건의 관계 | 같은 조건을 더 단순한 식이나 circuit으로 바꿀 수 있는가 |
| 상태 전이표 | 현재 상태와 읽은 기호에 따른 다음 동작 | 정해진 절차를 한 단계씩 모호함 없이 실행할 수 있는가 |
| 저장된 instruction | 실제 장치가 가져와 해석할 operation과 operand | 배선을 다시 만들지 않고 다른 작업으로 바꿀 수 있는가 |
| 확률분포 | 가능한 다음 message symbol의 불확실성 | 어떤 기호가 얼마나 예측 가능하고 효율적으로 부호화되는가 |

이 네 층은 모두 기호를 다루지만 같은 언어가 아니다. 논리식은 조건을 기술하고, transition table과 program은 동작을 지시하며, 확률분포는 가능한 message 사이의 불확실성을 나타낸다.

### 핵심 전환은 “지능”보다 표현과 실행 계약이었다

[[기계 이전의 계산은 어떻게 능력이 되었나]]에서 인간 계산자는 작업표를 읽고 중간값을 썼다. 19세기 중반부터 20세기 중반까지의 여러 연구는 이 실행 계약을 서로 다른 방향으로 더 엄밀하게 만들었다.

1. George Boole은 논리 관계를 기호와 대수적 연산으로 다룰 수 있게 했다.
2. [[클로드 섀넌]]은 논리식과 relay의 open/closed 연결을 대응시켜 circuit 분석·합성 문제로 바꿨다.
3. [[앨런 튜링]]은 유한한 상태와 instruction table을 읽는 추상 machine으로 “기계적으로 계산한다”의 경계를 연구했다.
4. EDVAC 보고서는 instruction과 수치 자료, 중앙 제어와 memory를 실제 전자식 장치의 구성 문제로 옮겼다.
5. Shannon의 1948년 통신 이론은 message symbol을 확률적 source의 출력으로 다뤘다.

이는 한 사람이 다음 사람에게 완성품을 넘긴 단선적 발명 목록이 아니다. 논리의 대수화, 계산 가능성, switching circuit, stored program과 확률적 통신은 서로 다른 문제에서 발전했고 일부가 후대 computer system 안에서 만났다.

### 가장 작은 구체적 예: 조건을 circuit으로 옮기기

두 switch $X,Y$가 닫혔을 때 1, 열렸을 때 0인 전도 변수 $c_X,c_Y\in\{0,1\}$을 정의하자. 두 switch를 **직렬**로 연결하면 둘 다 닫혀야 전류가 흐른다.

$$
c_{\mathrm{series}}=c_Xc_Y
$$

**병렬**로 연결하면 적어도 하나가 닫히면 흐른다.

$$
c_{\mathrm{parallel}}=1-(1-c_X)(1-c_Y)
$$

예를 들어 $(c_X,c_Y)=(1,0)$이면 직렬 출력은 0, 병렬 출력은 1이다. 식과 circuit이 같은 truth table을 내면, 조건을 실제 switch network로 구현했다고 말할 수 있다.

Shannon의 1938년 원문은 **hindrance**를 $X=0$이면 closed, $X=1$이면 open으로 두고 series를 $+$, parallel을 곱셈으로 표기했다. 위 식은 전도가 1인 현대적 설명용 표기다. 0과 1의 의미를 확인하지 않고 식만 복사하면 AND와 OR을 뒤바꿀 수 있다.

## 2단계 — 작동 원리

### 논리식을 물리적 연결로 번역한다

논리식은 “A이고 B”, “A이거나 B가 아니다” 같은 조건을 기호 연산으로 만든다. Relay는 전기 신호로 접점을 열거나 닫는 switch다. Shannon의 방법에서는 circuit을 방정식으로 나타내고, 식을 단순화한 뒤 대응하는 relay 연결을 다시 그릴 수 있다.

이 번역에는 세 층이 있다.

1. **의미 선택:** 0과 1이 open/closed 가운데 무엇을 뜻하는지 정한다.
2. **구조 대응:** series·parallel·보수 접점이 어떤 대수 연산과 같은 결과를 내는지 정한다.
3. **합성:** 원하는 입력–출력 조건을 식으로 쓰고 같은 truth table을 내는 circuit을 만든다.

식이 짧다고 실제 circuit이 언제나 가장 빠르거나 가장 싸다는 뜻은 아니다. 접점 수, relay 지연, fan-out, 고장 가능성과 배선 제약은 별도 물리 비용이다.

### Turing machine은 계산 절차의 최소 부품을 분리한다

Turing의 1936년 machine은 실제 제품 설계도가 아니라 **유한한 규칙으로 수행 가능한 계산의 범위**를 연구하는 추상 모형이다. 필요한 부품은 다음과 같다.

- 칸으로 나뉜 tape와 유한한 symbol alphabet
- 현재 한 칸을 읽고 쓸 수 있는 head
- 유한한 내부 상태 집합
- 현재 상태와 읽은 symbol에서 쓸 symbol, 이동 방향, 다음 상태를 고르는 instruction table

현대 표기로 한 transition을 다음처럼 쓸 수 있다.

$$
\delta(q,s)=(q',s',m),\qquad m\in\{L,N,R\}
$$

$q$는 현재 state, $s$는 현재 읽은 symbol이다. $s'$를 쓰고 왼쪽·정지·오른쪽 가운데 $m$만큼 움직인 뒤 $q'$로 바뀐다. 이 tuple 하나가 전체 계산은 아니다. 현재 조건과 일치하는 rule을 반복 적용한 trace가 계산이다.

설명용으로 첫 bit를 뒤집고 멈추는 table은 다음과 같다.

| 현재 state | 읽은 symbol | 쓸 symbol | 이동 | 다음 state |
| --- | --- | --- | --- | --- |
| $q_0$ | 0 | 1 | N | halt |
| $q_0$ | 1 | 0 | N | halt |

입력이 0이면 한 step 뒤 1, 입력이 1이면 한 step 뒤 0이다. 이 작은 예는 현대적 halt 표기를 쓴 편집부 예이며 Turing 논문의 특정 machine table을 옮긴 것이 아니다.

### Machine의 기술(description)도 symbol sequence가 된다

Turing은 각 machine의 instruction table을 표준 기호열과 description number로 부호화했다. 그러면 **universal machine** $U$는 다른 machine $M$의 기술 $\langle M\rangle$과 입력 $x$를 받아 $M$의 동작을 모사할 수 있다.

$$
U(\langle M\rangle,x)=M(x)
$$

중요한 전환은 한 물리 장치가 원래부터 모든 답을 품었다는 데 있지 않다. 실행할 규칙을 기호 자료로 표현해 바꾸면 같은 실행 원리가 여러 절차를 해석할 수 있다는 데 있다. 계산 가능한 모든 함수가 효율적이라는 뜻도 아니다. 같은 결과를 계산해도 time과 space 비용은 machine과 encoding에 따라 크게 다를 수 있다.

### 저장 프로그램은 추상적 기술을 장치의 빠른 memory로 옮긴다

EDVAC 보고서는 자동 digital computing system을 central arithmetic part(CA), central control(CC), memory(M), input(I), output(O)으로 나눴다. 특히 memory가 instruction material, 중간 결과, 표와 초기·경계 조건을 기억해야 한다고 설명하고, 가능한 한 하나의 memory organ과 교환 가능한 부분으로 다루려 했다.

간단한 stored-program 예를 보자.

| address | 저장 내용 | 해석 |
| ---: | --- | --- |
| 0 | `LOAD 4` | address 4의 값 3을 accumulator로 가져온다 |
| 1 | `ADD 5` | address 5의 값 5를 더한다 |
| 2 | `STORE 6` | 결과 8을 address 6에 쓴다 |
| 4 | `3` | data |
| 5 | `5` | data |

Program counter가 0, 1, 2를 따라 instruction을 가져오면 같은 arithmetic unit이 instruction의 순서에 따라 다른 일을 한다. Instruction과 data가 모두 memory에 놓일 수 있어도 **역할은 자동으로 같아지지 않는다**. 현재 control이 어느 bit pattern을 operation으로 해석하는지, 어느 것을 operand로 읽는지가 다르다.

### 확률적 language source는 “무슨 동작을 하라”가 아니다

Shannon의 1948년 discrete source는 유한한 symbol 집합에서 message를 차례로 낸다. 영어는 문자나 단어의 빈도와 앞선 symbol에 따른 조건부확률을 가진 source로 근사할 수 있다. [[001_섀넌의 N-gram 모델]]과 [[N-gram 모델]]은 이 층을 자세히 설명한다.

$$
p(w_{1:T})=\prod_{t=1}^{T}p(w_t\mid w_{<t})
$$

이 식은 다음 symbol의 불확실성을 분해한다. Turing machine의 $\delta$처럼 실행할 instruction을 지정하지 않고, 가능한 다음 token에 확률을 배정한다. 현대 LLM은 이 분포를 neural network로 계산하지만, sampling된 token을 다시 입력으로 넣는 실행 절차와 model이 예측한 확률분포는 여전히 구분해야 한다.

## 3단계 — 기술과 근거

### Boole과 Shannon: 기호논리에서 switching network로

Boole의 1854년 저작은 논리 명제를 대수적 기호와 방정식으로 다루는 체계를 전개했다. 1938년 Shannon은 relay·switch network를 방정식으로 표현하고 그 계산법이 symbolic logic의 proposition calculus와 정확히 대응한다고 설명했다. 원문의 목표는 “digital computer를 한 번에 발명”하는 것이 아니라 원하는 operating characteristic를 만족하는 network를 분석하고, 더 적은 접점으로 합성하는 방법을 찾는 것이었다.

따라서 역사적 연결은 두 단계로 말해야 한다. 논리 관계를 대수식으로 조작할 수 있다는 기반은 switching circuit을 수학적으로 기술할 수 있게 했다. 그러나 abstract logic 자체가 relay의 지연·전력·고장·제조 문제를 해결하지는 않는다.

### Turing: 가능한 절차와 불가능한 판정을 함께 정의하다

Turing은 제한된 인간 계산자의 동작을 tape, scanned symbol, 유한한 m-configuration과 표로 추상화했다. §§5–7에서는 machine table을 standard description과 number로 만들고, 이 기술을 tape에 둔 universal machine을 구성했다.

이 결과는 “한 machine이 여러 program을 실행한다”는 programmability의 이론적 핵심을 보여 준다. 동시에 논문의 Entscheidungsproblem 결과는 기계적 절차로 풀 수 없는 판정 문제가 있음을 보인다. Universal은 무한한 속도나 모든 질문의 해결을 뜻하지 않는다.

### EDVAC: instruction 전달 비용을 architecture 문제로 만들다

1945년 EDVAC 보고서 §1.2는 장치에 문제의 numerical information뿐 아니라 exhaustive instruction을 제공해야 한다고 썼다. §§2.2–2.9는 arithmetic, control, memory, input과 output의 기능을 나눴다. Memory 항목에는 계산 중간값뿐 아니라 instruction과 함수 table도 포함된다.

이는 문제를 바꿀 때마다 물리 배선 전체를 새로 구성하는 비용을, memory에 부호화한 instruction을 입력·저장·가져오는 비용으로 옮긴다. 다만 stored-program 개념을 von Neumann 개인의 단독 발명으로 확정할 수는 없다. 보고서는 Moore School의 집단 설계 맥락에서 나왔고, abstract universal machine, 실제 EDVAC 설계, 처음 작동한 stored-program machine은 서로 다른 “최초” 기준이다.

### Shannon 1948: message를 가능한 symbol 선택으로 재정의하다

Shannon은 communication의 핵심을 가능한 message 집합에서 실제 message가 선택되고 channel을 거쳐 재현되는 문제로 두었다. 의미론은 그 engineering problem의 직접 측정 대상에서 분리하고, 불확실성을 bit와 entropy로 측정했다. 영어의 letter·word approximation은 앞선 symbol을 더 고려할수록 통계적 구조가 어떻게 나타나는지 보여 줬다.

이 작업은 relay 논문과 저자가 같지만 같은 결과는 아니다. 1938년 논문은 switch network의 논리적 분석·합성, 1948년 논문은 source·channel·noise·encoding과 확률적 message 구조를 다룬다. 현대 language model은 후자의 확률적 질문을 이어 받으면서 전자의 digital circuit과 stored-program machine 위에서 실행된다.

### 이 본편의 측정 장부

| 항목 | 기록 |
| --- | --- |
| 작업 | 논리 조건을 circuit으로 합성하기, machine rule을 단계 실행하기, instruction을 memory에서 실행하기, 다음 message symbol의 분포를 계산하기 |
| 규모 | 논리 variable·접점 수, state·symbol·rule 수, instruction·memory word 수, alphabet·context·sequence 길이 |
| 결과 계약 | 같은 truth table, 정한 tape 출력·정지 조건, instruction 순서에 맞는 수치 결과, 합이 1인 다음 symbol 분포 |
| 시스템 경계 | abstract algebra와 machine, relay circuit, arithmetic·control·memory·I/O 장치, source–channel–receiver를 각각 분리 |
| 고정 조건 | 0·1 의미, alphabet·encoding, 초기 state·tape, instruction set·word layout, source 분포와 관측 context |
| 지표 | 식·접점·rule 수, step·space, program 교체 비용, memory 용량·접근, bit/s·entropy·오류율 |

이 장부에서 rule 수와 실행 시간, memory 용량과 message entropy는 서로 바꿔 쓸 수 없다. “더 적은 기호”도 circuit contact 감소, program byte 감소, message 압축에서 각각 다른 결과 계약을 갖는다.

### LLM에서 다시 만나는 네 층

현대 LLM system에서는 이 역사의 층들이 함께 보인다.

- Token ID와 tensor는 bit pattern으로 저장되고 digital logic circuit에서 계산된다.
- Model architecture를 구현한 program과 실행 graph가 operation 순서를 정한다.
- Weight는 학습된 수치 data이며 instruction과 같은 것이 아니다.
- Model은 context가 주어졌을 때 다음 token의 확률분포를 낸다.
- Runtime은 program·weight·KV cache·입출력 token을 memory 계층 사이로 이동시킨다.

[[LLM을 만든 수학]]에서 $W$와 $b$는 계산에 사용되는 parameter이고, 행렬곱·softmax·SGD는 그 값을 처리하는 operation이다. 둘 다 memory의 bit로 저장될 수 있다는 이유로 parameter를 program이라고 부르면 역할을 놓친다. 반대로 model이 생성한 token을 다음 step의 입력으로 되먹이는 control flow를 보지 않으면 autoregressive generation을 정적인 확률표로 오해한다.

### CS_WIKI와 함께 읽기

[CS_WIKI의 「First Draft of a Report on the EDVAC」](https://yghnsim.github.io/CS_Wiki/sources/first-draft-of-a-report-on-the-edvac/)는 EDVAC 설계, Moore School의 집단 기여와 Manchester Baby·EDSAC의 서로 다른 최초 기준을 더 자세히 다룬다. 현재 문서는 그 architecture를 계산·언어 표현의 역사와 잇되, CS_WIKI의 문서를 현재 위키의 근거 레지스트리 대신 사용하지 않는다.

## 검증과 한계

- **직접 영향:** Shannon은 1938년 원문에서 relay circuit의 방정식 계산법과 symbolic logic의 proposition calculus가 대응한다고 명시했다. 이 문서가 직접 영향으로 분류하는 가장 강한 연결이다.
- **가능 조건:** 논리의 대수화, switching element, 빠른 memory와 instruction encoding은 programmable digital computer가 구현될 수 있는 조건을 넓혔다. 어느 하나만으로 stored-program computer나 LLM이 필연적으로 나오지는 않는다.
- **병행 맥락:** Turing의 1936년 computability와 Shannon의 1938년 circuit synthesis는 가까운 시기의 연구지만 서로 다른 질문과 추상 수준을 가진다. 이 문서는 직접 협업이나 단일 계보를 주장하지 않는다.
- **후대 유추:** Universal machine의 description, stored program의 instruction, LLM runtime의 code·weight·token을 한 표에서 비교하는 것은 현대의 분석이다. 세 대상을 역사 행위자가 같은 용어로 이해했다는 뜻이 아니다.

Turing machine의 무한 tape는 실제 memory 용량 주장이 아니다. 실제 computer와 LLM은 유한한 memory·time·energy·context window에서 작동한다. Formal universality가 특정 algorithm을 빠르게 실행하거나 benchmark를 잘 풀거나 신뢰할 만한 답을 보장하지도 않는다.

Shannon이 communication engineering에서 semantics를 측정 경계 밖에 둔 것은 의미가 존재하지 않거나 중요하지 않다는 철학적 결론이 아니다. 또한 다음-token prediction이 언어의 모든 구조와 인간의 이해를 완전히 설명한다는 결론도 1948년 근거에서 나오지 않는다.

## 학습 확인

1. 논리식, Turing transition table, stored instruction, 다음-token 확률분포가 각각 무엇을 표현하는지 한 문장씩 구분하라.
2. $U(\langle M\rangle,x)=M(x)$가 “모든 문제를 빠르게 푼다”는 뜻이 아닌 이유를 설명하라.
3. 새 LLM 실행 사례에서 program, weight, input token, 중간 state와 output distribution을 찾아 서로 바꿔 부르면 안 되는 이유를 적어라.

다음에는 이론적으로 명시된 학습 규칙이 실제 자료·memory·연산 장치에서 왜 바로 규모화되지 못했는지, 초기 기계번역·퍼셉트론·ADALINE의 결과 계약과 병목으로 확인한다.
