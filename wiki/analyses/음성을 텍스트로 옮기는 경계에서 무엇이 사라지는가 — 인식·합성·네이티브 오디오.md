# 음성을 텍스트로 옮기는 경계에서 무엇이 사라지는가 — 인식·합성·네이티브 오디오

> [!note] 학습 안내
> **난이도:** 중급<br>
> **선수 지식:** [[자동 음성 인식]], [[WaveNet]]<br>
> **읽고 나면:** ASR→언어 모델→TTS 파이프라인과 음성 입력·출력을 함께 학습했다고 공표된 모델을 정보 경로·평가·공개 범위로 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 비교 질문과 잠정 결론

말을 듣고 답하는 시스템에서 텍스트는 매우 유용한 중간 표현이다. 단어열은 검색·언어 모델·번역·감사 기록에 쓰기 쉽다. 그러나 전사된 단어열은 원 음성의 모든 특성을 그대로 보존하지 않는다. 억양, 웃음, 발화 속도, 겹친 화자, 배경음, 말 끊김과 시간 정렬은 전사 목적과 평가 방식에 따라 남거나 버려질 수 있다.

[[041_심층 신경망 음향 모델과 DNN-HMM 전환|DNN-HMM]]은 음향 특징에서 HMM 상태 점수를 만들고 발음 사전·언어 모델·decoder가 단어열을 탐색하는 모듈식 경로였다. [[Whisper]]는 30초 log-Mel 음향 특징에서 여러 특수 token과 텍스트를 생성하는 encoder-decoder로 전사·X→English 번역을 묶었다. [[WaveNet]]은 반대 방향에서 언어·음성 특징에 조건화해 파형 표본을 생성했다. GPT-4o는 text·vision·audio를 하나의 신경망에서 end-to-end로 학습했다고 공표했지만, modality interface의 내부 세부는 공개하지 않았다.

잠정 결론은 **텍스트 중간층을 없애는 일이 곧 모든 음성 정보를 보존하거나 더 안전한 대화를 보장하는 것은 아니다**라는 것이다. 정보 경로, 실제 model I/O, 사용자에게 배포된 기능, 채점하는 oracle을 따로 기록해야 한다.

### ‘사라진다’는 말의 정확한 뜻

이 글에서 무엇이 사라진다는 말은, 원 음성이 물리적으로 파괴된다는 뜻이 아니다. 중앙 언어 모델 또는 다음 모듈이 **직접 조건으로 받는 표현에서 어떤 신호가 빠질 수 있는가**를 뜻한다. 애플리케이션이 원 오디오를 별도로 저장하거나, TTS가 화자·운율 조건을 따로 받으면 일부 신호는 다른 경로로 남을 수 있다. 문제는 그 경로와 검증 기준을 명시하지 않은 채 “음성 대화”라고 한 단어로 묶는 데 있다.

## 2단계 — 작동 원리

### 한 발화가 지나가는 두 경로

전통적 음성 대화 경로를 단순화하면 다음과 같다.

```text
audio → ASR → text → 언어 모델 → text → TTS → audio
```

ASR은 음성에서 단어열을, 언어 모델은 단어열에서 답을, TTS는 답과 음성 조건에서 새 파형을 만든다. 이 구조에서는 중앙 언어 모델이 ASR text에 명시되지 않은 억양·화자·웃음·환경음을 직접 읽지 못한다. 반대로 모듈마다 WER, 답의 사실성, MOS처럼 다른 지표를 붙이고 오류 위치를 나누기 쉽다.

GPT-4o에 대해 OpenAI가 공표한 고수준 경로는 text·vision·audio를 한 신경망에서 end-to-end로 학습한 native audio model이다. 이 공표는 기존 3-model voice pipeline보다 낮은 audio response latency와, text 중간층에만 남기기 어려운 음향 신호를 직접 입출력으로 다룰 가능성을 설명한다. 하지만 공개되지 않은 tokenizer·encoder·codec·decoder·attention·loss를 임의로 채워 넣을 수는 없다.

### 같은 ‘정확도’가 아닌 세 평가 층

| 층 | 질문 | 대표 지표 또는 근거 | 통과해도 남는 문제 |
| --- | --- | --- | --- |
| 인식 | 말한 단어열을 맞혔는가? | WER, 전사 오류 분석 | 억양·화자·정서·권한을 이해했다는 보장은 없음 |
| 합성 | 출력 음성이 자연스럽고 조건에 맞는가? | MOS, 청취자 비교 | 말한 내용의 사실성·안전성은 별도 문제 |
| 대화 system | 입력 음성을 바탕으로 적절하고 안전하게 반응했는가? | speech-to-speech 평가·red teaming·latency 조건 | 실제 사용자 환경·모든 언어·모든 위험을 보장하지 않음 |

따라서 낮은 WER, 높은 MOS, 빠른 응답 시간을 하나의 ‘음성 지능’ 점수로 합치면 실패 위치를 잃는다.

## 3단계 — 기술과 근거

### DNN-HMM: 음성에서 단어열로 가는 모듈식 분업

2012년 DNN-HMM 전환에서 깊은 신경망은 GMM 음향 모델을 대체해 인접 음향 프레임으로 문맥 의존 HMM 상태의 점수를 냈다. HMM 전이, 발음 사전, 언어 모델과 decoder는 단어열 탐색에 남았다. 이는 DNN이 HMM을 모두 없앤 end-to-end 사건이 아니라, 음향 모델의 한 부분을 바꾼 hybrid pipeline이었다.

이 경로의 이점은 분명하다. 음향 점수, 발음 제약, 언어 prior와 탐색을 분리해 어떤 곳에서 오류가 났는지 검사할 수 있다. 반면 중앙 언어 모델이 보는 것은 decoder가 선택한 단어열이다. 발화의 강세나 배경의 경고음이 text field로 표현되지 않았다면, 다음 text-only 모듈은 그 신호를 조건으로 쓰지 못한다. 낮은 WER도 발화 의미 이해나 화자·환경의 완전한 모델링을 뜻하지 않는다.

### WaveNet: 텍스트 답을 다시 음성으로 만드는 일은 별도다

WaveNet은 양자화한 파형 표본의 다음 값 분포를 생성했다. TTS에서는 음소·음절·단어 수준의 언어·음성 특징과 화자 ID가 조건으로 들어갔으며, 원시 파형을 출력 대상으로 삼았다고 해서 입력 text만으로 모든 음성 특성을 스스로 추론한 것은 아니다.

이 사례는 text와 audio 사이의 비대칭을 보여 준다. 동일한 문장도 화자·속도·억양에 따라 여러 파형으로 실현될 수 있다. TTS는 text가 정하지 않는 부분을 화자 조건·음향 특징·확률 표본화로 채워야 한다. WaveNet의 MOS는 이 음성 합성 품질을 특정 청취 조건에서 재는 지표이지, 입력 문장의 사실성이나 대화 상대를 이해했다는 지표가 아니다.

### Whisper: 음향 특징에서 텍스트 token으로 통합하지만 음성 전체를 보존하지는 않는다

Whisper는 16kHz 오디오를 30초 log-Mel spectrogram으로 바꾸고, Transformer encoder-decoder가 언어 식별·전사·X→English 번역·무음·타임스탬프를 특수 token과 text token으로 출력하게 했다. DNN-HMM의 명시적 HMM 상태·발음 사전·별도 언어 모델은 이 구조 안에서 보이지 않지만, 원시 파형을 그대로 넣는 것도 아니며 장문은 30초 창을 옮겨 가며 처리한다.

Whisper의 WER은 전사 결과의 문자열 오류를 측정한다. 논문은 텍스트 정규화기가 일부 자료에서 WER를 크게 낮출 수 있음을 기록했고, 30초 창의 잘못된 전사·타임스탬프가 다음 창에 전파될 수 있다고 설명한다. 전사가 정확해도 화자 분리, 운율의 의미, 정서, 개인정보 보호, 실시간 지연은 별도 과제다. 특히 음성 번역은 2022년 원 연구에서 X→English 방향이므로 임의 언어 쌍의 대화 번역으로 확대하지 않는다.

### GPT-4o: native audio 공표가 확인하는 것과 비공개인 것

OpenAI는 2024년 5월 GPT-4o를 text·vision·audio를 한 신경망에서 end-to-end로 학습한 모델로 공표했다. 또한 기존 GPT-3.5 voice pipeline의 2.8초, GPT-4 pipeline의 5.4초와 대비해 audio input에 대한 최저 232ms·평균 320ms model response latency를 제시했다. 이는 text를 거치는 3-model 경로와 다른 입출력·지연 주장이다.

하지만 이 수치는 network·device·streaming을 포함한 모든 대화의 보장치가 아니며, 하나의 공통 tokenizer나 별도 음성 codec·encoder·decoder가 전혀 없다는 뜻도 아니다. 발표 당일 제품 surface에는 text·image input과 text output이 먼저 있었고, native audio·realtime API·video·native image 기능은 이후 단계적으로 배포됐다. model capability, launch surface와 후속 rollout을 같은 날짜의 기능으로 쓰지 않는다.

GPT-4o System Card의 speech-to-speech 평가도 중요하다. 일부 평가는 audio를 입력하고 audio를 출력했지만, 내용 채점에서 TTS와 transcriber를 거쳐 text oracle을 사용했다. 그러므로 text 중간층을 피한 model이라도 **평가가 무엇을 텍스트로 환원했는지** 따로 적어야 한다. 음향의 자연스러움·감정·화자 특성·안전성은 text benchmark 정확도만으로 측정되지 않는다.

## 검증과 한계

### 확인된 사실

- DNN-HMM은 DNN 음향 상태 점수와 HMM·발음 사전·언어 모델·decoder를 결합한 hybrid 구조였다.
- WaveNet TTS는 직접 파형을 생성했지만 언어·음성 특징과 화자 조건을 사용했고, MOS는 정해진 청취 평가의 자연스러움 지표였다.
- Whisper는 30초 log-Mel 입력에서 자기회귀 text token을 생성하며, 전사·X→English 번역·언어 식별·타임스탬프를 한 형식에 넣었다.
- GPT-4o는 native audio를 포함한 end-to-end single-network training을 공표했지만 modality별 내부 interface는 공개하지 않았다.
- GPT-4o의 공식 speech 평가에는 audio 입출력을 text로 변환해 채점하는 절차가 포함됐다.

### 비교를 통한 해석

텍스트 중간층은 정보 손실만 만드는 장애물이 아니라, 어휘 기반 검색·감사·모듈별 교체와 오류 진단을 가능하게 하는 인터페이스다. 반대로 native audio의 가치는 text가 표현하지 않은 신호를 직접 조건으로 다룰 수 있는 가능성에 있지만, 그 가능성은 실제 model interface·평가·배포와 안전 통제의 근거로 확인해야 한다. 모듈을 합친다고 자동으로 더 많은 음성 의미를 안전하게 보존하는 것은 아니다.

### 아직 입증되지 않은 계보와 적용 한계

이 자료는 GPT-4o의 내부 구조가 WaveNet 또는 Whisper를 직접 계승했다는 증거가 아니다. 또한 native audio model이 모든 언어·억양·장애 접근성·감정 이해·고위험 상담에서 text pipeline보다 우수하다는 비교도 제공하지 않는다. 공개된 latency와 system card 평가는 model·prompt·snapshot·평가 변환기에 조건화된 결과다.
