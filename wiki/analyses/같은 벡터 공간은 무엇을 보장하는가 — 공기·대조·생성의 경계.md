# 같은 벡터 공간은 무엇을 보장하는가 — 공기·대조·생성의 경계

> [!note] 학습 안내
> **난이도:** 심화<br>
> **선수 지식:** [[concept.단어-임베딩|단어 임베딩]], [[concept.clip|CLIP]]<br>
> **읽고 나면:** LSA·Word2Vec·GloVe·CLIP·unCLIP의 벡터가 무엇을 가깝게 하도록 학습됐는지와, 유사도·분류·생성의 경계를 구분할 수 있다.

## 1단계 — 먼저 잡을 핵심

### 비교 질문과 잠정 결론

벡터 공간(vector space)은 대상을 숫자 좌표로 나타내 거리나 내적을 계산하게 하는 표현 공간이다. 그러나 “같은 공간에 있다”는 말은 적어도 세 가지를 뜻할 수 있다. 하나의 차원 수를 맞췄다는 뜻, 서로의 유사도를 직접 점수화할 수 있다는 뜻, 같은 token 흐름에서 생성한다는 뜻이다. 이들은 서로 따라오지 않는다.

[[잠재 의미 분석]]은 단어와 문서를 저차원 좌표에서 비교해 검색을 돕는다. [[Word2Vec]]는 [[GloVe]]와 함께 단어가 어떤 문맥에 나타나는지에서 정적 단어 표현을 학습한다. [[CLIP]]은 별도 이미지·텍스트 encoder의 출력을 대조 학습해 짝인 image-text를 가깝게 두고, 후보 class text와 이미지의 유사도로 분류한다. DALL·E 2의 unCLIP은 같은 CLIP 좌표계를 쓰지만 text embedding을 image embedding 자리에 바로 넣지 않고 prior와 diffusion decoder를 추가한다.

잠정 결론은 **공유 좌표가 보장하는 것은 정해진 목적 아래의 비교 가능한 점수이지, 동일한 의미 구조·자유 생성·원인 이해가 아니다**라는 것이다. 무엇이 유사해야 하는지, 어떤 후보 집합에서 비교하는지, 그 벡터 뒤에 decoder가 있는지를 함께 적어야 한다.

### 먼저 구분할 네 층

| 층 | 질문 | 예 |
| --- | --- | --- |
| 관측 단위 | 어떤 것을 벡터로 바꾸는가? | 단어, 문서, 이미지, caption |
| 학습 신호 | 무엇을 가까이·예측 가능하게 만드는가? | 공기, 주변 단어, image-text 짝 |
| 읽는 연산 | 벡터로 무엇을 하는가? | 검색, 유사도, 후보 분류, 조건화 |
| 생성 경계 | 벡터에서 새 결과를 만들려면 무엇이 더 필요한가? | decoder, prior, sampler, output tokenizer |

같은 차원 수만 맞춰도 두 표현이 같은 의미를 갖는 것은 아니다. 반대로 다른 encoder가 내놓은 표현이라도 대조 목적이 있으면 특정 후보 집합에서 비교할 수 있다.

## 2단계 — 작동 원리

### ‘빨간 자전거’를 서로 다르게 담는 최소 예

`빨간 자전거`라는 말이 있는 문서, 그 문장을 둘러싼 단어, 자전거 사진, 그 사진을 설명한 caption을 생각해 보자. LSA는 단어-문서 공기 행렬을 줄여 문서와 질의의 숨은 축을 비교한다. Word2Vec는 `자전거`의 주변 단어를 예측하거나 주변 단어에서 중심 단어를 예측하며 단어 type 벡터를 학습한다. GloVe는 `자전거`와 `빨간`이 다른 단어들과 함께 나타나는 비율 관계를 맞춘다.

CLIP은 사진 encoder와 caption encoder가 만든 두 벡터의 유사도를 높인다. 이때 `빨간 자전거` 문장은 사진의 정확한 pixel 배열을 담은 벡터가 아니라, 후보 사진 또는 후보 class text와 비교할 수 있게 만든 표현이다. 사진을 새로 만들려면 그 표현을 픽셀 또는 다른 시각 표현으로 옮기는 별도 생성 경로가 필요하다.

### 점수화와 생성은 다른 인터페이스다

검색과 제로샷 분류에서는 벡터와 후보 집합이 먼저 있다. LSA는 질의와 문서를 같은 저차원 기준에서 비교하고, CLIP은 이미지 벡터와 미리 준비한 class text 벡터를 비교한다. 어느 후보가 가장 가까운지를 고르는 일은 이미 있는 후보 사이의 판정이다.

생성은 후보 집합 밖의 새 image·text·audio를 만들기 위해 분포와 decoder가 필요하다. unCLIP의 prior는 text 조건에서 가능한 CLIP **image** embedding을 만들고, diffusion decoder와 upsampler가 그 표현을 이미지로 복원한다. 즉 CLIP의 shared space는 생성 경로의 인터페이스가 될 수 있지만, 그 공간만으로 생성기가 되지는 않는다.

## 3단계 — 기술과 근거

### LSA: 단어와 문서를 검색 가능한 저차원 좌표로 옮긴다

LSI/LSA는 term-by-document 행렬을 특이값 분해(SVD)로 낮은 차원의 근사로 바꾼다. 질의도 같은 잠재 축으로 fold-in해 문서와 비교할 수 있으므로, 정확한 단어가 겹치지 않아도 비슷한 공기 패턴을 가진 문서를 찾는 데 쓸 수 있다. 여기서 ‘공유’는 단어·문서를 검색 연산에서 비교할 수 있게 한 좌표계라는 뜻이다.

그 좌표가 문장의 모든 관계·사실·원인을 보존한다는 뜻은 아니다. 차원 수와 절단 방식은 설계 선택이며, LSI의 retrieval 결과는 MED·CISI 같은 정해진 자료와 평가 조건에서 읽어야 한다. LSA가 이후 분산 표현과 문제의식을 공유해도, Word2Vec의 예측 목적과 같은 모델이라고 볼 수는 없다.

### Word2Vec와 GloVe: 단어 표현도 같은 목표가 아니다

Word2Vec의 CBOW와 Skip-gram은 중심 단어와 주변 단어의 예측 관계를 학습한다. 자주 함께 나타나는 단어가 비슷한 표현을 얻을 수 있지만, 학습의 직접 목표는 주어진 window에서 조건부 예측을 잘하는 것이다. 일반적으로 쓰는 단어 벡터와 출력 쪽 문맥 벡터가 모두 존재한다는 점도, ‘단어 하나에 완결된 의미 좌표 하나’라는 단순한 그림을 경계하게 한다.

GloVe는 전역 단어-단어 공기 행렬의 비율 관계를 가중 회귀로 맞춘다. 따라서 기존 [[계수 기반과 예측 기반 단어 표현은 얼마나 다른가]]가 비교하듯, 두 방식은 자료에서 단어 관계를 얻는다는 공통점이 있어도 통계 집계와 목적함수가 다르다. 어느 쪽도 단어가 실제 세계의 대상을 하나로 지시하거나, 문맥마다 달라지는 의미를 자동으로 분리한다고 보장하지 않는다.

### CLIP: image-text 쌍의 비교 공간을 학습한다

CLIP은 image와 text를 각각 encoder로 벡터화하고, 한 batch의 실제 짝은 높은 점수, 나머지 조합은 낮은 점수를 갖도록 양방향 대조 손실을 학습한다. 두 벡터는 정규화된 내적으로 비교된다. 여기서 ‘같은 공간’은 이미지 하나와 문장 하나를 직접 비교해, 배치 또는 후보 class 안에서 어느 짝이 더 맞는지 점수화할 수 있다는 뜻이다.

이 구조가 곧 cross-encoder식 token-level 융합이나 open-ended visual question answering은 아니다. 제로샷 분류에서도 model은 미리 제공한 class text와 prompt template 사이에서 이미지를 비교한다. class 후보, wording, prompt ensemble이 바뀌면 결과도 달라질 수 있다. `shared embedding`을 일반적인 멀티모달 이해의 동의어로 쓰면, 목표와 평가 범위를 잃는다.

### unCLIP: 가까운 좌표와 교환 가능한 표현은 다르다

unCLIP은 동결 CLIP의 text·image representation을 공통 좌표계로 사용한다. 그러나 논문은 text embedding을 image embedding 자리에 그대로 넣는 우회가, text 조건 image embedding prior를 거친 전체 모델보다 낮은 결과를 냈다고 보고했다. 같은 공간에서 가깝다는 사실이 두 representation을 그대로 교환할 수 있게 만들지는 않았다는 실험적 근거다.

prior는 caption에 어울리는 image embedding의 분포를 만들고, diffusion decoder는 그 embedding을 바탕으로 저해상도 이미지를 생성한 뒤 upsampler가 해상도를 높인다. 이 계층은 표현 사이의 유사도, 조건부 image representation 생성, pixel 복원이라는 세 작업을 분리한다. CLIP을 ‘이미지를 만드는 벡터’라고 부르기보다, 생성 stack이 사용할 수 있는 비교·조건화 인터페이스로 한정하는 편이 정확하다.

### 공통 차원·공통 sequence·공통 semantics를 섞지 않는다

[[105_통합 멀티모달 아키텍처의 공유 범위와 입출력 경계|통합 멀티모달 아키텍처]]가 지적하듯, modality별 feature를 같은 hidden width로 projection하는 일, image와 text token을 같은 attention sequence에 넣는 일, discrete token을 한 생성 목적 아래 예측하는 일은 각각 다르다. ImageBind처럼 modality별 encoder·projection을 joint embedding에 정렬하는 구조는 retrieval·classification에 쓸 수 있지만, 자체적인 open-ended generator를 뜻하지 않는다.

따라서 `공유 공간`이라는 말 뒤에는 최소한 encoder가 몇 개인지, 학습 자료가 어떤 pair인지, score가 어떤 후보 집합에서 계산되는지, output decoder가 무엇인지가 따라야 한다. 차원이 같거나 cosine similarity를 계산할 수 있다는 사실만으로 동일한 개념 구조, 물리적 인과 이해, 모든 modality 방향의 생성이 확인되는 것은 아니다.

## 검증과 한계

### 확인된 사실

- LSI/LSA는 term-by-document 행렬의 저차원 근사와 질의 fold-in을 이용해 검색을 평가했다.
- Word2Vec은 문맥 예측, GloVe는 전역 공기 통계의 가중 회귀를 통해 정적 단어 표현을 학습했다.
- CLIP은 별도 image·text encoder를 대칭 대조 목적에서 정렬하고, prompt로 만든 후보 class vector와 이미지의 유사도로 제로샷 분류를 수행했다.
- unCLIP은 frozen CLIP 좌표계를 쓰되 text-to-image embedding prior와 diffusion decoder를 별도로 두었다.
- joint embedding, shared core, common token sequence와 product interface는 서로 다른 통합 주장이다.

### 비교를 통한 해석

벡터 공간의 유용성은 ‘의미를 모두 담았다’는 선언보다 **어떤 비교·검색·분류·조건화 연산을 허용하는가**로 설명하는 편이 낫다. 이 관점에서는 LSA의 문서 검색, Word2Vec·GloVe의 단어 관계, CLIP의 후보 짝 맞히기, unCLIP의 생성 조건이 연속된 한 역사라기보다 서로 다른 문제에 맞춘 재사용 가능한 인터페이스로 보인다.

### 아직 입증되지 않은 계보와 적용 한계

이 자료는 LSA가 CLIP의 직접 조상이라거나, 단어 임베딩의 유추 성능이 cross-modal grounding을 낳았다는 계보를 입증하지 않는다. 또한 CLIP·unCLIP의 결과를 모든 caption, 언어, 데이터 분포, 이미지 생성 제품의 품질로 확대하지 않는다. 벡터가 가깝다는 관측은 선택한 자료·목적·후보 집합에서의 점수 관계이며, 인간의 의미 이해나 인과 모델의 증거는 별도로 필요하다.

## 학습 확인

### 확인 질문

1. LSA의 query–document 비교와 CLIP의 image–class text 비교는 각각 어떤 후보 집합에서 어떤 일을 수행하는가?
2. Word2Vec의 문맥 예측과 GloVe의 전역 공기 회귀를 같은 ‘단어 의미 학습’으로만 부르면 어떤 차이가 사라지는가?
