# 1단계 문서 학습 구조 가이드

이 문서는 `wiki/**/*.md`의 기술 내용을 삭제하지 않고, 독자가 정의에서 작동 원리와 근거로 점진적으로 이동하도록 본문 구조를 통일하는 기준이다. frontmatter 스키마, 근거 레지스트리, raw 불변성, 링크와 Git 경계는 `AGENTS.md`가 계속 최상위 규칙이다. 이 가이드는 그 규칙을 바꾸지 않고 본문 H1 아래의 학습 순서만 표준화한다.

## 1. 구조 감사 결과

2026-07-21 구조 개편 시작 시점의 243개 Markdown 문서에서 ATX 헤딩을 집계했다. 아래 수치는 변환 전 기준선이다.

| page_type | 문서 수 | H2 합계 | H2 중앙값 | H2 범위 | 서로 다른 H2 | H3 합계 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `source` | 59 | 637 | 11 | 5–15 | 372 | 17 |
| `concept` | 135 | 797 | 6 | 3–12 | 460 | 11 |
| `entity` | 29 | 104 | 3 | 2–6 | 43 | 0 |
| `analysis` | 17 | 186 | 11 | 6–15 | 144 | 14 |
| `meta` | 3 | 110 | 6 | 5–99 | 108 | 0 |
| **합계** | **243** | **1,834** | — | — | **1,108** | **42** |

추가로 확인한 기준선 상태는 다음과 같다.

- 모든 문서의 마지막 H2는 `## 관련 항목`이다.
- 비메타 240개 문서는 모두 `## 출처`를 한 번 가진다. 메타 3개는 현재 `## 출처`가 없다.
- `source` 59개는 모두 `## 핵심 문장`을 가지며 54개는 `## 검증 정정`을 가진다.
- `concept`에는 `## 한계` 35개, `## 강점과 한계` 6개가 있지만 나머지는 한계가 다른 절에 섞여 있다.
- `analysis`는 사실·해석·미확인 계보의 구분 방식이 여러 이름으로 흩어져 있다.
- Obsidian callout은 아직 없고, 이 문서가 정하는 다섯 개 새 학습 H2도 아직 없다.
- 수식을 포함한 문서는 `source` 31개, `concept` 40개, `analysis` 8개이며 `entity`에는 없다.
- `wiki/log.md`의 날짜별 기록 98개가 각각 H2여서 메타 H2 수와 고유 제목 수를 크게 늘린다.
- 기준선에는 `reference` 문서가 없다. 앞으로 생기면 `source` 규칙을 따르되 정규 번호 ingest가 아니라는 출처 성격을 분명히 한다.

이 분포는 내용이 빈약하다는 뜻이 아니다. 현재 H2가 문서마다 개별 논점을 직접 표현해 탐색에는 유용하지만, 독자가 정의·원리·근거·한계를 어느 순서로 읽어야 하는지 예측하기 어렵다는 뜻이다. 따라서 기존 논점 제목을 없애지 않고 H3로 보존하는 방식이 적합하다.

## 2. 절대 보존 규칙

첫 구조 변환의 바닥 조건은 **기존 기술 내용의 무손실 보존**이다. 쉬운 설명과 검증 경계를 보강할 수 있지만, 기존의 조건·근거·한계를 요약 과정에서 잃어서는 안 된다.

1. frontmatter 필드를 삭제하지 않는다. `updated`는 실제 구조 편집일로 갱신하되, 단순 이동만으로 `id`, `title`, `verification`, `artifacts`, `evidence`, `related` 등의 의미를 바꾸지 않는다. H1, 모든 사실 주장, 직접 인용, 표, 수식, 코드, 목록, URL, locator와 위키 링크도 삭제하지 않는다.
2. 기존 H2는 의미가 드러나는 H3로 보존한다. 기존 H3는 그 아래 H4로 내린다. 현재 문서에는 H4 이하가 없으므로 이 원칙으로 기존 계층을 잃지 않는다.
3. 기술적으로 같은 문장이 반복되면 근거 범위를 다시 확인한 뒤 합칠 수 있다. 단, 서로 다른 조건이나 시기의 주장을 같은 문장으로 뭉개지 않는다.
4. 한 절에 원리와 한계가 섞여 있으면 문단 단위로 나누어 옮길 수 있지만, 문장 일부를 잘라 의미나 조건을 바꾸지 않는다.
5. raw artifact는 읽기만 하며 수정하지 않는다. raw 오류·결손·과장은 `## 검증과 한계` 아래에서 기존 근거와 함께 보존한다.
6. `verification`, `evidence`, `artifacts`, `related`는 본문 이동만으로 바꾸지 않는다. 새 주장을 추가할 때만 근거와 상태를 재판정한다.
7. 비메타 문서는 `## 출처`의 항목과 locator를 그대로 보존하고 정확히 한 번 둔다. 메타 문서는 기존 규칙대로 `## 출처`와 frontmatter `evidence` 요구에서 제외한다.
8. `## 관련 항목`은 계속 모든 Markdown 문서의 마지막 H2다. 링크를 기계적으로 상호화하거나 늘리지 않는다.

## 3. 표준 본문 골격

H1 바로 다음에 `학습 안내` callout을 두고, callout 앞뒤에 별도의 도입 문단을 두지 않는다. 기존 H1 아래의 도입 문단은 `1단계`로 옮긴다.

```markdown
# {frontmatter title과 같은 제목}

> [!note] 학습 안내
> **난이도:** 입문·중급·심화 중 주 독자에게 맞는 한 단계를 쓴다.<br>
> **선수 지식:** 필요한 경우에만 기존 문서 0–2개를 연결한다. 없으면 “없음”으로 쓴다.<br>
> **읽고 나면:** 독자가 설명하거나 구분할 수 있게 되는 것을 한 문장으로 쓴다.

## 1단계 — 먼저 잡을 핵심

### 한 문장 정의 또는 결론

### 왜 중요한가

### 이 문서의 범위

## 2단계 — 작동 원리

### 문제와 입력

### 처리 흐름 또는 논증 구조

### 결과와 읽는 법

## 3단계 — 기술과 근거

### {기존 기술 논점 1}

### {기존 기술 논점 2}

### 실험·사례·역사적 근거

## 검증과 한계

### 확인된 사실

### 검증 정정과 해석의 경계

### 적용 범위와 남은 한계

## 학습 확인

### 확인 질문

1. 정의 또는 핵심 결론을 묻는다.
2. 작동 순서나 인과 관계를 묻는다.
3. 필요할 때 근거가 보장하지 않는 것을 묻는다.

### 다음 문서

- [[다음 문서]] — 지금 생긴 다음 질문과 이 문서가 답하는 이유를 한 문장으로 쓴다.

## 출처

{기존 출처와 locator를 보존한다.}

## 관련 항목

{기존의 큐레이션된 링크를 보존한다.}
```

이 골격은 비메타 문서에 적용하며, 일곱 H2 제목과 순서는 고정한다. H3는 문서 내용에 맞게 선택하며 빈 H3를 채우기 위해 내용을 만들지 않는다. `2단계`가 절차형 주제가 아니라면 “작동”을 계산 절차로만 해석하지 말고, 개념이 대상을 구분하는 방식, 인물의 연구가 문제를 바꾼 방식, 분석의 비교 논리가 결론에 도달하는 방식으로 쓴다. 메타 문서는 초보자 학습 경로·시대별 진입점·선수 관계를 중심으로 목적에 맞는 H2를 사용한다.

### 학습 안내 callout 규칙

- 세 줄을 기본으로 하고 각 줄은 한 문장으로 쓴다.
- `난이도`는 수식의 유무가 아니라 문서를 이해하는 데 필요한 개념 수와 추론 깊이로 정한다.
- `선수 지식`은 실제 선행 지식만 연결한다. 선행 문서가 없으면 “없음”으로 쓴다.
- `읽고 나면`은 “이 문서를 읽는다”가 아니라 독자가 읽은 뒤 설명하거나 구분할 수 있는 것을 적는다.
- callout에는 새 수치, 긴 정의, 수식, 출처 목록이나 결론의 모든 예외를 넣지 않는다.

## 4. 기존 절의 무손실 이동표

| 기존 내용의 기능 | 새 위치 | 처리 원칙 |
| --- | --- | --- |
| H1 뒤 도입, `핵심 요약`, `핵심 문장`, 정의, 왜 중요한가 | `1단계` | 문장과 목록을 보존한다. 핵심 문장이 여러 개면 `### 핵심 문장`으로 둔다. |
| 짧은 역사적 위치 | `1단계` | 현재 개념을 잡는 데 필요한 1–2단락만 둔다. 상세 연표와 선행 연구는 `3단계`로 보낸다. |
| 구조, 구성, 입력·출력, 학습, 추론, 계산 흐름, 논증 단계 | `2단계` | 독자가 순서나 의존 관계를 따라갈 수 있게 기존 H2를 H3로 내린다. |
| 수식, 알고리즘 변형, 모델별 차이, 실험 조건·결과, 연표, 후대 사용, 현대 모델과의 관계 | `3단계` | 표·수식·조건·연도·수치를 그대로 보존하고 논점별 H3를 유지한다. |
| `검증 정정`, `원문 상태`, `범위와 한계`, `한계`, `강점과 한계`, 논쟁 상태 | `검증과 한계` | 사실, 비교 해석, 미확인 계보와 적용 한계를 H3로 분리한다. |
| `확인된 사실과 비교 해석` 계열 | `검증과 한계` | 기존의 `확인된 사실`·`해석`·`입증되지 않은 계보` 하위 구분을 유지한다. |
| 기존 `출처` | `출처` | 항목, URL, locator, 소스 노트 링크를 삭제하거나 축약하지 않는다. |
| 기존 `관련 항목` | 마지막 `관련 항목` | 기존 링크를 보존하며 자동 상호 링크를 만들지 않는다. |

분류가 애매하면 다음 질문을 사용한다.

- “무엇인가, 왜 중요한가?”에 답하면 `1단계`다.
- “어떤 입력이나 전제에서 어떤 중간 단계를 거쳐 무엇이 나오는가?”에 답하면 `2단계`다.
- “정확한 식, 변형, 수치, 연도, 사례와 문헌은 무엇인가?”에 답하면 `3단계`다.
- “어디까지 확인됐고 무엇을 보장하지 않는가?”에 답하면 `검증과 한계`다.

## 5. 유형별 권장 하위 구조

다음 H3는 권장안이며, 실제 자료에 없는 내용을 채우는 체크리스트가 아니다.

### source와 reference

- `1단계`: `핵심 문장`, `역사적 위치`, `원자료가 제기한 문제`.
- `2단계`: `문제 설정`, `입력과 표현`, `학습·추론 또는 논증 흐름`, `출력의 의미`.
- `3단계`: 기존 모델·알고리즘별 절, 수식, 자료와 평가 조건, 결과, 연표, 직접 확인되는 후속 사용.
- `검증과 한계`: `원문 상태`, `검증 정정`, 측정 범위, 영역 이동, 후대 계보의 직접성.
- source의 raw 서사와 외부 1차 자료가 충돌하면 외부 근거에 따른 정정을 보존하고 raw를 고치지 않는다.
- reference는 정규 번호 소스인 것처럼 쓰지 않으며, 기존 주장 보강에 필요한 범위만 다룬다.

### concept

- `1단계`: 최초 정의, 핵심 직관, 구분해야 할 인접 개념, 위키에서 중요한 이유.
- `2단계`: 구성 요소, 입력–상태–출력, 학습과 추론의 차이, 간단한 예시.
- `3단계`: 정식 수식, 변형, 계산 비용, 역사적 형성, 관련 모델·과제와의 정확한 관계.
- `검증과 한계`: 가정, 실패 조건, 장단점, 흔한 오해와 용어 범위.
- 관계 중심으로 흩어진 기존 절은 없애지 않는다. 원리를 설명하는 관계는 `2단계`, 역사·비교·후대 연결은 `3단계`의 H3로 옮긴다.

### entity

- `1단계`: 누구인지, 이 위키에서 다루는 역할, 생애 전체가 아닌 문서의 근거 범위.
- `2단계`: 당시 문제, 인물의 접근, 연구 결과와 연구 관행에 준 변화. 사람 자체가 “작동한다”고 쓰지 않는다.
- `3단계`: 검증된 연구·시스템·논문별 기여, 연대, 공동 연구자와 자료 기반.
- `검증과 한계`: 단독 발명 귀속, 공저자·선행 연구 누락, 후대 영향의 과장, 확인되지 않은 전기 정보.
- 인물의 업적을 모델의 보편적 성공이나 분야 전체의 전환과 동일시하지 않는다.

### analysis

- `1단계`: 비교 질문, 잠정 결론, 비교 대상과 축.
- `2단계`: 자료를 함께 읽는 논리, 공통 파이프라인, 비교표와 사례를 읽는 순서.
- `3단계`: 대상별 상세 비교, 반례, 실제 적용 원칙, 사용한 자료별 근거.
- `검증과 한계`: `확인된 사실`, `비교를 통한 해석`, `아직 입증되지 않은 계보`를 분리한다.
- `verification: partial`인 이유가 해석적 합성에 있다면, 사실이 불확실하다는 뜻으로 흐리지 말고 어느 문장이 합성 판단인지 밝힌다.

### meta

- 메타 문서는 고정된 비메타 3단계 H2 골격의 적용 대상이 아니다.
- `overview`는 현재 범위와 상태보다 먼저 초보자 독서 경로, 시대별·주제별 진입점, 난이도에 따른 읽기 방법을 제시한다.
- `index`는 유형·근거 수·링크를 읽는 법을 짧게 설명하고 기존 source·reference·entity·concept·analysis 목록을 보존한다.
- `log`는 기록의 역할과 날짜·작업 유형·검증 결과를 읽는 법을 안내하되 기존 날짜별 H2와 앵커를 보존한다.
- 집계 기준일, 생성 값과 수동 서술의 차이, 알려진 미해결 상태를 분명히 적는다.
- 메타 문서는 기존 규칙대로 `## 출처`와 비어 있지 않은 frontmatter `evidence` 요구에서 제외된다.

## 6. 문장과 용어 규칙

### 문장 길이와 문단

- 문장 하나에는 중심 주장 하나를 둔다. 기본 상한은 약 35어절 또는 한글 90자이며, 조건·결과·예외가 세 겹 이상이면 둘로 나눈다.
- 2–4문장을 한 문단으로 묶는다. 긴 문단은 주장, 근거, 해석의 경계에서 나눈다.
- 연도·수치·성능을 쓸 때 같은 문장이나 바로 다음 문장에 자료, 평가 조건, 단위와 지표를 함께 적는다.
- “혁명”, “최초”, “직접 이어졌다”, “완전히 해결했다”는 1차 근거와 비교 범위가 있을 때만 쓴다.
- 글머리표는 병렬 항목에만 사용한다. 서로 인과적으로 이어지는 설명은 번호 목록이나 문단으로 쓴다.
- 굵은 글씨는 한 문단의 핵심 대비나 새 용어에만 사용하며 문장 전체를 연속해서 강조하지 않는다.

### 용어의 최초 정의

- 본문 첫 등장에서는 `한국어 용어(English term, 약어)` 순서로 정의하고 이후에는 한 가지 짧은 표기를 일관되게 쓴다. 예: `확률적 문맥 자유 문법(Probabilistic Context-Free Grammar, PCFG)`.
- 정의 대상이 기존 페이지라면 최초 정의에서 `[[페이지|표시명]]`으로 연결한다. 링크가 정의를 대신하지 않도록 현재 문서에 한 문장 정의도 남긴다.
- 같은 약어가 다른 뜻을 가질 수 있거나 번역이 고정되지 않았으면 문서에서 선택한 의미와 범위를 밝힌다.
- 원 논문의 용어와 후대 표준 용어가 다르면 시기를 표시해 둘을 섞지 않는다.
- 새 alias나 개념 페이지는 검색 편의를 이유로 기계적으로 만들지 않는다. 독자의 다음 질문에 독립적으로 답할 가치가 있을 때만 만든다.

## 7. 수식과 기술 세부 배치

1. 직관과 계산 순서를 보여 주는 최소 수식은 `2단계`에 둔다. 완전한 목적함수, 변형, 유도, 복잡도와 평가식은 `3단계`에 둔다.
2. 구조 이동 중에는 수식의 기호·연산자·첨자·괄호를 고치지 않는다. 수식 오류 수정은 원 근거와 대조하는 별도 내용 편집이다.
3. 수식 앞 문장에서 무엇을 계산하는지 말하고, 처음 나온 모든 기호를 수식 직전이나 직후에 정의한다.
4. 수식 뒤에는 결과를 자연어 한 문장으로 해석하고, 성립 조건이나 독립 가정을 함께 적는다.
5. 짧은 기호는 인라인 수식으로, 분수·곱·합·여러 줄 계산은 블록 수식으로 쓴다. 한 문단에 새 블록 수식을 연속으로 셋 이상 두지 않고 사이에 해설을 둔다.
6. 실험 결과 식에는 자료 분할, 지표, 비교 기준을 붙인다. 확률, 점수, 유사도와 신뢰도를 같은 값처럼 부르지 않는다.
7. 수식만 callout이나 `1단계`에 복사하지 않는다. 핵심은 먼저 말로 설명하고 정식 표현으로 내려간다.

## 8. 학습 확인과 다음 문서

### 확인 질문

- 문서마다 2–3개를 둔다.
- 첫 질문은 정의·핵심 결론, 둘째는 작동 흐름·비교 논리를 묻는다. 셋째 질문을 둘 때는 근거가 보장하지 않는 범위를 묻는다.
- 질문은 본문만으로 답할 수 있어야 하며, 출처 목록의 사소한 서지 정보를 암기하게 하지 않는다.
- 답을 덧붙일 때는 각 답을 1–2문장으로 쓰고 답이 있는 H3를 함께 가리킨다. 본문에 없는 새 사실을 정답에서 처음 제시하지 않는다.

### 다음 문서

- 한 문서에서 다음 링크는 최대 2개다. 짧은 2문서 순차 경로 또는 기본 경로 하나와 분기 경로 하나로 제시한다.
- 각 링크 뒤에 “왜 다음인가”를 한 문장으로 쓴다. 단순히 제목이 비슷하다는 이유로 선택하지 않는다.
- 다음 문서는 현재 문서가 남긴 질문을 실제로 이어 받아야 한다. source에서 관련 concept, concept에서 상세 source나 analysis, entity에서 대표 source, analysis에서 반례·적용 문서로 잇는 경로를 우선한다.
- 존재하는 문서 또는 `red-links.yml`에 의도적으로 등록된 링크만 사용한다.
- `다음 문서`는 독서 안내이고 `related`는 큐레이션된 관계다. 중요한 경로라면 frontmatter `related`와 마지막 `## 관련 항목`에도 일관되게 반영하되 자동 상호화하지 않는다.
- 같은 페이지를 선행 지식과 다음 문서에 동시에 두지 않는다.

## 10. 적용 후 검수

### 문서별 수동 검사

- 비메타 문서의 H1 바로 뒤에 `> [!note] 학습 안내`가 정확히 한 번 있는가.
- 고정 H2 일곱 개가 정해진 순서로 정확히 한 번씩 있는가.
- 기존 도입 문단, H2/H3, 표, 수식, 목록, 인용, URL과 링크가 모두 새 위치에 있는가.
- 사실, 해석, 미확인 계보와 한계가 분리됐는가.
- 2–3개의 학습 질문 모두에 본문만으로 답할 수 있는가.
- 다음 문서가 실제 후속 질문을 이어 가며 링크가 해소되는가.
- `## 출처`가 비메타에서 정확히 한 번이고 `## 관련 항목`이 마지막 H2인가.
- frontmatter의 `title`과 H1, `updated`, `verification`, `evidence`, `related`가 실제 변경과 일치하는가.

### 저장소 검사

구조 변환 배치마다 다음 순서로 확인한다.

```powershell
npm run sync:index
npm run lint:wiki
npm run build:site
npm run check:site
npm run test
```

마지막에는 `npm run verify`로 같은 회귀 검사를 한 번 더 통과시킨다. 사이트에서 callout, 목차의 H2/H3 계층, 표, KaTeX 수식, 긴 source와 analysis, `overview`, `index`, `log`의 앵커를 대표 표본으로 직접 확인한다. 구조 전환 때문에 첫 본문 단락이 달라지면 `sync:index`가 만든 한 줄 설명도 내용상 적절한지 검토한다.

이 검수는 형식 통과로 끝나지 않는다. 기존 기술 주장이나 조건이 빠지지 않았는지, 요약 과정에서 인과가 강해지지 않았는지, 같은 설명이 불필요하게 중복됐는지까지 원문 diff로 확인해야 한다.
