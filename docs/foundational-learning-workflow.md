# 비전공자 기초 학습형 문서 종합 워크플로

이 문서는 LLM Wiki v2의 문서를 단순히 쉬운 말로 요약하는 수준을 넘어, 비전공자가 숨은 선수 지식 없이 문제의 배경부터 기술적 표현과 근거까지 단계적으로 이해할 수 있게 작성·개정하는 절차를 정한다. 독자의 나이를 특정하지 않으며, 목표는 **기초에서 전문적 이해까지 설명이 끊기지 않는 누적 학습형 문서**다.

`AGENTS.md`가 스키마·근거·raw·링크·Git 경계의 최상위 규칙이고, `docs/learning-structure-style-guide.md`가 고정 H2와 문장 배치를 정한다. 이 워크플로는 그 구조 안에서 선수 지식, 구체적 예, 수식, 근거와 학습 경로를 어떤 순서로 설계하고 검수할지를 정한다.

## 1. 적용 범위와 완료 목표

다음 작업에는 이 워크플로를 적용한다.

- 새 source·reference·entity·concept·analysis 문서를 작성할 때
- 기존 문서의 설명, 수식, 예시 또는 학습 경로를 실질적으로 고칠 때
- 여러 문서가 공통으로 요구하는 기초 개념을 보강할 때
- `overview.md` 같은 메타 문서에 비전공자용 학습 경로를 만들 때
- 새 정규 소스를 공개하며 연결된 concept·entity·analysis를 갱신할 때

문서는 독자가 본문을 읽고 다음을 할 수 있을 때 학습 관점에서 완료된 것으로 본다.

1. 이 주제가 필요해진 문제와 배경을 자기 말로 설명한다.
2. 본문에 등장하는 핵심 용어를 다른 미정의 전문용어 없이 설명한다.
3. 가장 작은 예에서 입력·중간 과정·출력을 순서대로 따라간다.
4. 핵심 수식의 모든 기호와 연산을 읽고 숫자를 넣어 결과를 재현한다.
5. 수식의 어느 부분이 정의·가정의 귀결이고 어느 부분이 설계 선택인지 구분한다.
6. 방법이 보장하는 것, 보장하지 않는 것과 실패 조건을 설명한다.
7. 확인된 사실, 편집부의 설명용 예시, 비교를 통한 해석을 구분한다.

짧고 쉬운 요약만 추가했거나 전문용어를 다른 전문용어로 바꿔 말한 상태는 완료가 아니다.

## 2. 편집 원칙

### 2.1 문제에서 출발한다

정의나 수식을 먼저 제시하지 않는다. 먼저 당시 또는 현재 무엇이 어려웠는지, 기존 방법이 어디서 막혔는지, 새 개념이 어떤 질문에 답하려 했는지를 설명한다. 역사적 배경은 근거가 있는 사실과 교육을 위한 문제 재구성을 구분한다.

### 2.2 선수 지식을 숨기지 않는다

독자가 알아야 하는 개념을 “기본적이다”, “잘 알려져 있다”, “간단히 알 수 있다”로 넘기지 않는다. 핵심 논리를 이해하는 데 필요한 용어·수학·역사 배경을 먼저 목록화하고, 정의한 뒤 사용한다.

### 2.3 링크가 정의를 대신하지 않는다

기존 기초 페이지로 연결하더라도 현재 문서에 그 개념의 역할을 2–5문장으로 설명한다. 더 깊은 유도와 다양한 사례는 기준 개념 페이지가 담당한다. 같은 긴 설명을 여러 문서에 복제하지 않는다.

### 2.4 예에서 추상화로 올라간다

작은 숫자, 짧은 문장, 적은 수의 벡터처럼 독자가 손으로 따라갈 수 있는 사례를 먼저 완결한다. 그 뒤 사례의 각 요소를 일반 기호로 바꾸고 실제 모델로 확장한다. 예시는 직관만 주는 비유와 실제 계산 가능한 예를 구분한다.

### 2.5 수식을 압축된 결론으로 방치하지 않는다

수식은 문제, 요구 조건, 기호, 항, 연산, 계산 예, 성립 가정, 대안과 실패 조건을 포함한 설명 단위다. “공식은 다음과 같다”만으로 수식을 도입하지 않는다.

### 2.6 쉬운 설명과 정확성을 맞바꾸지 않는다

기술 조건·수치·수식·근거·한계를 삭제해 문장을 쉽게 만들지 않는다. 직관은 앞 단계에, 정식 표현과 근거는 뒤 단계에 둔다. 비유를 사용하면 비유가 설명하지 못하는 범위를 같은 절에서 밝힌다.

### 2.7 문서와 페이지를 기계적으로 늘리지 않는다

공통 선수 개념이 여러 문서에서 반복되거나 독립적인 다음 질문에 답할 가치가 있을 때만 기준 개념 페이지를 만들거나 보강한다. 한 문서 안의 짧은 정의로 충분하면 새 페이지를 만들지 않는다.

## 3. 기초 지식 체계와 학습 경로

### 3.1 기초 개념 축을 먼저 세운다

개별 문서를 고치기 전에 여러 문서가 공통으로 의존하는 개념을 찾는다. 대표 축은 다음과 같지만, 실제 페이지 생성 여부는 기존 문서와 근거를 감사한 뒤 결정한다.

- 언어와 데이터: 기호, 문자, 단어, 토큰, 문장, 시퀀스, 말뭉치, 문맥, 빈도
- 수학: 비율, 함수, 확률, 조건부확률, 로그, 벡터, 행렬, 가중합, 미분
- 기계학습: 모델, 매개변수, 학습과 추론, 손실함수, 최적화, 일반화
- 신경망: 뉴런, 층, 활성화 함수, 임베딩, 순환, 어텐션
- 검증: 데이터 분할, 기준선, 평가 지표, 재현성, 상관과 인과

기초 페이지는 용어 사전이 아니라 후속 문서가 실제로 재사용할 수 있는 설명을 제공해야 한다. 정의, 필요 배경, 최소 예, 작동 원리, 정식 표현, 한계와 다음 문서를 갖춘다.

### 3.2 선수 관계를 세 등급으로 나눈다

대상 문서의 핵심을 이해하는 데 필요한 항목을 다음처럼 분류한다.

| 등급 | 판정 | 처리 |
| --- | --- | --- |
| 필수·국소 | 짧은 설명만 있으면 현재 문서를 따라갈 수 있음 | 현재 문서에서 2–5문장으로 정의하고 필요하면 기준 페이지로 연결 |
| 필수·독립 | 자체 예와 원리 설명이 필요한 큰 개념 | 먼저 기준 개념 페이지를 보강하고 `학습 안내`와 본문에서 연결 |
| 선택·심화 | 핵심 직관에는 필요 없지만 정식 유도나 변형에 필요함 | `3단계`에서 정의하고 심화 경로로 분리 |

필수 선수 문서와 현재 문서가 서로를 선수 지식으로 요구하는 순환 경로를 만들지 않는다. 순환이 발견되면 더 기초적인 공통 설명을 분리하거나 한쪽 문서에 국소 설명을 보강한다.

### 3.3 경로는 의존 관계순으로 만든다

폴더명, 공식 소스 번호 또는 시대순만으로 학습 순서를 정하지 않는다. 예를 들어 다음처럼 개념 의존 관계를 우선한다.

```text
빈도와 비율
→ 확률
→ 조건부확률
→ 언어 모델
→ N-gram
→ 데이터 희소성
→ 분산 표현과 임베딩
→ 신경 언어 모델
→ 어텐션
→ Transformer
→ 대규모 언어 모델
```

`overview.md`에는 시작점과 분기점을 설명하고, 각 비메타 문서의 `학습 확인`에는 현재 문서가 남긴 실제 다음 질문을 받는 문서를 최대 2개 연결한다.

## 4. 문서 한 편을 작성·개정하는 순서

### 4.1 작업 상태와 범위를 먼저 확인한다

1. `git status --short --branch`로 현재 브랜치와 기존 변경을 확인한다.
2. 대상 문서와 연결된 source·concept·entity·analysis, frontmatter evidence와 raw artifact를 확인한다.
3. raw는 읽기만 하고 수정하지 않는다.
4. 이번 작업이 구조 이동, 설명 보강, 사실 정정, 수식 교정 중 무엇인지 구분한다.
5. 새 사실이나 새 수식 해석을 추가한다면 재확인 가능한 외부 근거와 locator가 있는지 확인한다.

### 4.2 원문과 기존 문서를 처음부터 끝까지 읽는다

부분 검색 결과만으로 설명을 쓰지 않는다. 다음 항목을 별도 작업 메모로 추출한다.

- 저자나 문서가 실제로 다룬 문제
- 입력, 처리, 출력과 평가 방식
- 핵심 주장과 이를 지지하는 근거
- 모든 전문용어, 약어와 기호
- 독자가 알아야 할 수학 개념과 역사적 배경
- 원문이 직접 말한 것과 후대의 해석
- 현재 설명에서 생략되거나 순환 정의된 부분
- 모든 핵심 수식과 수식 사이의 의존 관계

### 4.3 선수 지식 감사를 수행한다

각 전문용어와 수식에 대해 다음 질문을 순서대로 확인한다.

1. 이 항목이 처음 등장하기 전에 정의됐는가?
2. 정의를 이해하려면 또 다른 미정의 용어가 필요한가?
3. 현재 문서의 핵심을 이해하는 데 필수인가?
4. 2–5문장으로 국소 설명할 수 있는가?
5. 여러 문서가 반복해서 의존하는 독립 개념인가?
6. 기존 기준 페이지가 있다면 충분한 예와 원리를 제공하는가?
7. 선수 문서와 현재 문서 사이에 순환이 생기지 않는가?

감사 결과에 따라 국소 설명, 기존 기초 페이지 보강, 새 기초 페이지 후보, 선택 심화 항목으로 나눈다. 새 페이지 후보는 독립적인 학습 질문과 충분한 근거가 있을 때만 실제로 만든다.

### 4.4 설명의 논리 사다리를 설계한다

본문을 쓰기 전에 다음 한 줄 경로를 먼저 만든다.

```text
문제의 배경 → 필요한 기초 → 가장 작은 예 → 단계별 작동 → 일반 원리 → 정식 수식 → 실제 근거 → 한계
```

이 경로에서 한 단계라도 다음 단계의 미정의 개념을 미리 요구하면 순서를 다시 설계한다.

### 4.5 `1단계`에서 배경과 기초를 세운다

- 개념이 필요해진 문제와 기존 접근의 한계를 먼저 설명한다.
- 필수 선수 개념을 현재 문맥에서 정의한다.
- 핵심 아이디어를 전문용어와 수식 없이 먼저 말한다.
- 일상 비유를 사용했다면 대응하는 요소와 대응하지 않는 요소를 함께 밝힌다.
- 연도·수치·성능보다 독자가 다음 단계에서 추적할 문제 구조를 먼저 잡게 한다.

### 4.6 `2단계`에서 가장 작은 예를 완결한다

1. 입력을 구체적으로 제시한다.
2. 각 처리 단계를 번호로 나눈다.
3. 단계마다 값이나 상태가 어떻게 변하는지 보여 준다.
4. 결과를 계산하고 자연어로 해석한다.
5. 예의 요소를 일반 기호와 연결한다.
6. 예가 실제 자료인지 편집부가 만든 설명용 예인지 명시한다.

설명용 예는 새로운 역사적 사실이나 성능 근거처럼 쓰지 않는다. 실제 시스템보다 단순화했다면 무엇을 생략했는지 밝힌다.

### 4.7 `3단계`에서 정식 표현과 근거로 확장한다

- 앞 단계의 자연어와 예를 정식 용어·기호에 하나씩 대응시킨다.
- 핵심 수식마다 6장의 수식 해설 프로토콜을 적용한다.
- 원 논문의 표기와 위키 표기가 다르면 대응 관계를 밝힌다.
- 실제 데이터, 실험 조건, 모델 변형, 연대와 locator를 보존한다.
- 현대적 재해석을 원 저자의 표현처럼 쓰지 않는다.

### 4.8 `검증과 한계`에서 이해의 경계를 세운다

다음을 분리한다.

- 근거로 직접 확인된 사실
- 설명을 위해 단순화한 예와 비유
- 여러 자료를 함께 읽어 얻은 비교 해석
- 아직 입증되지 않은 계보 또는 인과
- 수식이 성립하는 가정과 정의되지 않는 경계값
- 방법이 실패하거나 성능이 떨어지는 조건
- 흔한 오해와 과도한 의인화

### 4.9 `학습 확인`에서 재구성 능력을 확인한다

질문은 2–3개를 기본으로 하되 단순 용어 암기에 머물지 않는다.

1. 문제와 핵심 개념을 자기 말로 설명하게 한다.
2. 작은 입력으로 작동 과정이나 수식을 재현하게 한다.
3. 필요하면 가정, 대안 또는 실패 조건을 구분하게 한다.

자기 학습 문서에서는 각 질문에 1–2문장의 답과 답을 확인할 H3를 제공하는 것을 권장한다. 답에서 본문에 없던 사실을 처음 제시하지 않는다.

### 4.10 메타데이터와 연결을 정합하게 만든다

- 새 주장과 정정에 맞춰 evidence와 locator를 재판정한다.
- 실제 사용한 raw만 artifacts에 둔다.
- 중요한 선수·후속 관계는 본문, `related`, `관련 항목`에서 의미가 일치하게 큐레이션한다.
- 모든 링크를 상호화하지 않는다.
- 새 기초 문서나 제목 변경이 있으면 index·overview·log를 갱신한다.

## 5. 표준 본문 설계안

고정 H2는 `docs/learning-structure-style-guide.md`를 그대로 따른다. 아래 H3·H4는 내용이 있을 때 선택해서 쓰며 빈 절을 채우기 위해 내용을 만들지 않는다.

```markdown
# 제목

> [!note] 학습 안내
> **난이도:** 입문·중급·심화<br>
> **선수 지식:** 실제로 필요한 문서 0–2개 또는 없음<br>
> **읽고 나면:** 독자가 설명·계산·구분할 수 있는 결과

## 1단계 — 먼저 잡을 핵심

### 이 개념이 필요해진 문제
```

## 6. 핵심 수식 해설 프로토콜

핵심 수식은 독자가 결과를 재현하고 식의 형태가 나온 이유를 설명할 수 있을 정도로 해설한다. 반복 사용되는 보조식은 기준 수식으로 연결할 수 있지만, 현재 문서에서 새로 등장하는 기호와 현재 역할은 다시 정의한다.

### 6.1 먼저 수식의 역할을 판정한다

| 역할 | 반드시 설명할 질문 |
| --- | --- |
| 정의식 | 무엇을 새로 정의하며 왜 이 정의가 유용한가? |
| 유도식 | 어떤 가정·정리·대수 규칙에서 각 줄이 나오는가? |
| 확률식 | 표본공간·조건·분포·정규화는 무엇인가? |
| 목적·손실함수 | 무엇을 오류로 보고 왜 그 항에 벌점을 주는가? |
| 갱신식 | 무엇을 어느 방향으로 얼마나 바꾸는가? |
| 구조·변환식 | 입력과 출력의 자료형·shape가 어떻게 바뀌는가? |
| 평가식 | 어떤 자료와 기준을 어떤 단위로 비교하는가? |

### 6.2 수식 전에 문제와 요구 조건을 쓴다

수식이 계산할 질문을 자연어 한 문장으로 적고, 결과가 만족해야 할 성질을 밝힌다. 예를 들면 확률은 0과 1 사이이고 후보 전체의 합이 1이어야 한다. 가중 평균은 각 값의 기여도를 반영해야 하며, 손실은 예측과 정답의 차이를 학습 가능한 하나의 값으로 바꿔야 한다.

요구 조건이 실제로 필수인지, 연구자가 선택한 설계 목표인지 구분한다.

### 6.3 모든 기호와 연산자의 역할을 정의한다

핵심 수식에는 필요에 따라 다음 표를 둔다.

| 기호 | 현재 문서에서의 의미 | 종류·shape | 값의 범위·단위 | 값의 출처 |
| --- | --- | --- | --- | --- |
| 예: `x_t` | 시점 `t`의 입력 표현 | 길이 `d`인 벡터 | 실수 | 입력 자료에서 계산 |
| 예: `W` | 입력을 다른 공간으로 바꾸는 가중치 | `m × d` 행렬 | 실수 | 학습되는 매개변수 |
| 예: `η` | 한 번의 갱신 크기를 조절하는 학습률 | 스칼라 | 보통 양수 | 사람이 정하는 하이퍼파라미터 |

다음 사항을 생략하지 않는다.

- 스칼라·벡터·행렬·텐서 중 무엇인지
- 각 축이 배치·시간·토큰·특징·층·헤드 중 무엇인지
- 아래첨자와 위첨자의 의미
- 합을 취하는 인덱스와 남는 인덱스
- 입력, 관측값, 학습 매개변수, 중간값, 하이퍼파라미터의 구분
- 확률·점수·거리·유사도·로짓처럼 값의 해석이 다른 양의 구분
- `=`, `≈`, `∝`, `∼`가 각각 같은 값, 근사, 비례, 분포에서의 표본 추출 중 무엇을 뜻하는지

### 6.4 수식을 한 항씩 만든다

완성된 식을 먼저 보여 주더라도 곧바로 구성 과정을 되짚는다.

1. 가장 단순한 입력과 원하는 출력의 관계를 쓴다.
2. 첫 항이 어떤 정보를 담는지 설명한다.
3. 다음 항이 왜 필요한지 설명한 뒤 추가한다.
4. 더하기·곱하기·나누기·합·정규화가 각각 어떤 역할을 하는지 말한다.
5. 변형 줄마다 사용한 대수 법칙, 확률 법칙 또는 미분 법칙을 이름과 함께 설명한다.
6. 행렬식은 각 단계의 shape를 써서 연산 가능성과 출력 크기를 확인한다.
7. 확률식은 전체 합 또는 적분이 1이 되는지 확인한다.

“정리하면”, “자명하게”, “간단히 알 수 있다”로 중간 단계를 생략하지 않는다.

### 6.5 연산을 선택한 이유를 설명한다

연산 이름만 풀이하지 말고 현재 수식에서 그 연산이 필요한 이유를 밝힌다.

| 연산 | 설명해야 할 핵심 |
| --- | --- |
| 더하기·합 | 독립 항의 기여, 전체 비용 또는 후보 전체를 왜 누적하는가? 어떤 축을 없애는가? |
| 곱하기 | 결합, 조건부 연쇄, 가중치 적용 또는 스케일 조절 중 어떤 역할인가? |
| 나누기 | 비율, 평균, 정규화 또는 단위 변환 중 무엇인가? 분모가 0이면 어떻게 되는가? |
| 내적 | 대응 성분의 곱을 더한 값이 왜 현재 목적의 관련도나 투영으로 쓰이는가? 다른 유사도도 가능한가? |
| 행렬곱 | 어떤 선형 결합을 한 번에 수행하며 입력·출력 공간이 어떻게 바뀌는가? |
| 지수함수 | 왜 양수화하거나 큰 차이를 강조해야 하는가? 값 폭주를 어떻게 다루는가? |
| 로그 | 왜 곱을 합으로 바꾸거나 작은 확률을 안정적으로 다뤄야 하는가? 로그의 밑이 결과 해석에 어떤 영향을 주는가? |
| 정규화 | 어떤 합·평균·분산을 기준으로 값을 비교 가능하게 만드는가? |
| 미분·그래디언트 | 무엇에 대한 변화율이며 부호가 어느 방향의 변화를 뜻하는가? |
| 기대값 | 어느 확률분포 아래 어떤 값의 평균을 구하는가? 실제로 어떻게 추정하는가? |
| 최대·argmax | 가장 큰 값 자체와 그 위치를 왜 구분하는가? 미분 불가능성이 문제가 되는가? |

### 6.6 숫자를 넣어 처음부터 끝까지 계산한다

- 독자가 손으로 따라갈 수 있는 작은 값을 쓴다.
- 입력값과 선택 이유를 먼저 제시한다.
- 모든 중간값을 표시하고 반올림 시점과 자릿수를 밝힌다.
- 벡터·행렬은 연산 전후 shape와 대응 성분을 보여 준다.
- 계산 결과를 원래 문제의 언어로 다시 해석한다.
- 경계값, 0, 같은 값, 매우 큰 값 가운데 의미 있는 하나를 추가로 시험한다.
- 설명용 숫자를 실제 실험 결과나 출처의 수치처럼 쓰지 않는다.

### 6.7 필연성과 선택을 판정한다

각 핵심 수식에는 다음 구분을 명시한다.

| 판정 | 의미 |
| --- | --- |
| 정의 | 개념의 뜻을 정하기 위해 선택한 표현 |
| 수학적 귀결 | 밝힌 가정과 정리에서 논리적으로 도출됨 |
| 통계적 귀결 | 특정 분포·독립성·추정 기준 아래에서 도출됨 |
| 요구 성질을 만족하는 선택 | 양수, 합 1, 미분 가능성 같은 목표를 만족하도록 선택 |
| 계산 가능한 근사 | 정확한 계산이 어렵거나 비싸서 사용 |
| 공학적 선택 | 속도, 메모리, 수치 안정성 또는 학습 용이성 때문에 사용 |
| 역사적 관례 | 여러 가능한 표기나 방법 중 널리 정착함 |

“이렇게 쓸 수밖에 없다”는 말은 가정에서 유일하게 도출됨을 보였을 때만 쓴다. 대안이 있으면 최소 하나를 제시하고, 현재 식을 선택했을 때 얻는 이점과 잃는 성질을 설명한다.

### 6.8 성립 조건과 실패 조건을 확인한다

- 분모가 0이거나 로그 입력이 0 이하일 때 정의되는가?
- 값이 매우 크거나 작을 때 overflow·underflow가 생기는가?
- 독립성, 정상성, 선형성 같은 가정이 필요한가?
- 미관측 자료나 분포 밖 입력에서 어떻게 달라지는가?
- 근사식과 정확한 식의 차이가 언제 커지는가?
- 최적화 목표가 실제 평가 목표와 일치하는가?

필요하면 smoothing, clipping, 작은 상수, log-sum-exp, 정규화 같은 보완책을 소개하되, 보완책이 원 문제를 전부 해결한다고 쓰지 않는다.

### 6.9 반복 수식은 설명 책임을 나눈다

같은 수식의 완전한 유도는 가장 적합한 concept 문서 한 곳에 둔다. source·analysis에서 다시 사용할 때는 현재 논점에 필요한 기호, 입력·출력과 해석을 다시 설명하고 완전한 유도 문서로 연결한다. 링크만 남기고 현재 수식의 역할을 생략하지 않는다.

## 7. 수식 해설의 최소 예: N-gram 상대빈도

다음 식은 문맥 `h`가 주어졌을 때 다음 항목 `w`의 확률을 관측 빈도로 추정한다.

$$
P(w\mid h)=\frac{C(h,w)}{C(h)}.
$$

### 7.1 질문과 기호

질문은 “문맥 `h`가 나타난 경우들 가운데 다음 항목이 `w`였던 비율은 얼마인가?”다.

| 기호 | 의미 | 종류·범위 |
| --- | --- | --- |
| `h` | 이미 주어진 앞 문맥 | 한 개 이상의 토큰으로 이루어진 시퀀스 |
| `w` | 다음 위치의 후보 토큰 | 어휘 집합의 원소 |
| `C(h,w)` | `h` 바로 뒤에 `w`가 나온 횟수 | 0 이상의 정수 |
| `C(h)` | `h`가 다음 토큰을 가질 수 있는 위치에 나온 전체 횟수 | 0 이상의 정수 |
| `P(w\mid h)` | `h`가 주어졌을 때 `w`가 나올 추정 확률 | 0 이상 1 이하의 스칼라 |

### 7.2 왜 나누는가

비교 대상은 말뭉치의 모든 단어가 아니라 `h`가 관측된 경우들이다. `h`가 20번 나타났고 그중 8번 다음 항목이 `w`였다면 다음처럼 계산한다.

$$
P(w\mid h)=\frac{8}{20}=0.4.
$$

분모 `C(h)`는 후보별 횟수를 같은 기준으로 바꾸고 확률 합을 1로 만든다. 가능한 다음 토큰을 임시 기호 `w'`로 순회하면 다음이 성립한다.

$$
C(h)=\sum_{w'}C(h,w').
$$

따라서 `C(h)>0`일 때 모든 후보의 추정 확률을 더하면 1이다.

$$
\sum_{w'}P(w'\mid h)
=\sum_{w'}\frac{C(h,w')}{C(h)}
=\frac{C(h)}{C(h)}
=1.
$$

두 번째 줄은 모든 항이 같은 분모를 가지므로 분자를 먼저 더한 것이고, 세 번째 줄은 후보별 횟수의 합이 문맥의 전체 횟수라는 앞선 정의를 사용한 것이다.

### 7.3 어디까지 필연적인가

이 상대빈도 식은 `h` 뒤의 관측을 같은 범주형 분포에서 얻은 표본으로 보고 최대우도 기준을 사용하면 도출된다. 그 가정과 기준 안에서는 자연스러운 추정값이지만 가능한 유일한 확률 추정법은 아니다. `C(h,w)=0`이면 확률을 0으로 주고 `C(h)=0`이면 식 자체가 정의되지 않는다. 평활화, back-off와 베이지안 추정은 이런 문제를 다르게 처리하는 대안이다.

이 예에서 필요한 설명 단위는 기호 번역, 비율의 직관, 합이 1이 되는 계산, 통계적 가정, 대안과 실패 조건까지다. 다른 핵심 수식도 해당 수식의 역할에 맞춰 같은 깊이로 설명한다.

## 9. 근거와 설명용 내용의 경계

1. 역사적 사실, 성능, 연도, 발명·영향 주장은 evidence와 locator로 확인한다.
2. 편집부가 만든 숫자 예시는 “설명용 예”로 표시하고 실제 실험 결과처럼 인용하지 않는다.
3. 원문에 없는 수식 유도는 사용한 수학 규칙과 출발 가정을 밝힌다.
4. 원 논문의 표기를 바꾸면 원 기호와 위키 기호의 대응표를 둔다.
5. 등식, 근사식, 비례식과 경험적 경향을 서로 바꾸어 쓰지 않는다.
6. 수학적 유사성을 역사적 영향 관계의 증거로 사용하지 않는다.
7. 비유는 작동 원리를 보조할 뿐 모델이 인간처럼 이해·기억·판단한다는 근거가 아니다.
8. 새 설명이 기존 evidence 범위를 넘으면 근거를 추가하거나 verification을 재판정한다.

## 10. 전체 문서군을 개편하는 순서

### 10.1 1차 — 선수 지식과 수식 감사

- 먼저 `npm run learning:audit`를 실행한다. 이 명령은 `docs/foundational-learning-audit.md`에 비메타 문서 수, 난이도·선수 지식 표기, 블록 수식 수, 서술 본문 유입 링크와 새 학습 구조 표지를 기록한다. 이 보고서는 후보 우선순위를 좁히는 기계적 기준선이며, 교육적 가치나 숨은 선수 지식의 최종 판정은 아니다.
- 모든 비메타 문서의 `선수 지식`, 최초 전문용어와 핵심 수식을 목록화한다.
- 미정의 용어, 순환 선수 관계, 계산 예가 없는 수식과 표기 충돌을 찾는다.
- 여러 문서가 반복해서 요구하는 기초 개념을 우선순위 후보로 모은다.

### 10.2 2차 — 기초 개념 축 완성

- 후속 의존 문서가 많은 기초 페이지부터 보강한다.
- 개념별로 배경, 최소 예, 핵심 수식, 한계와 다음 경로를 완성한다.
- 기초 페이지 자체가 더 어려운 미정의 개념을 선행 요구하지 않는지 다시 확인한다.

### 10.3 3차 — 연결된 학습 경로 개편

- 폴더나 번호가 아니라 하나의 질문을 잇는 문서 묶음으로 작업한다.
- 한 경로의 concept를 먼저 보강하고 연결된 source·entity·analysis를 갱신한다.
- `overview.md`와 각 문서의 다음 문서 안내를 함께 갱신한다.

### 10.4 4차 — 수식 중심 재검토

- 블록 수식이 있는 문서를 다시 감사한다.
- 핵심 수식과 보조식을 구분하고 기준 유도 문서를 정한다.
- 기호표, shape, 숫자 예, 연산 이유, 필연성·선택, 실패 조건이 빠진 곳을 보강한다.
- 사이트에서 긴 수식, 표, 모바일 폭과 KaTeX 렌더링을 확인한다.

### 10.5 5차 — 신규 ingest에 상시 적용

정규 소스 처리에서는 번역·raw 보존과 외부 근거 검증 뒤, 공개 위키를 쓰기 전에 선수 지식 감사를 수행한다. 필요한 기초 문서를 먼저 보강하고 source와 연결 문서를 작성한 뒤 수식 게이트와 전체 검증을 통과시킨다. 이 변경은 해당 공식 번호의 단일 `ingest` 커밋에 포함한다.

내용 보강만 수행하는 작업은 관련 경로를 하나의 의미 있는 범위로 묶고 `content: short_topic` 커밋을 사용한다. 일정한 문서 수를 채우기 위해 범위를 기계적으로 정하지 않는다.

## 11. 품질 게이트

### 11.1 선수 지식 게이트

- 핵심 용어가 사용되기 전에 정의돼 있다.
- 정의가 다른 미정의 전문용어에 기대지 않는다.
- 필수 선수 개념은 현재 문서에도 최소 설명이 있다.
- 선수 문서와 다음 문서가 순환하지 않는다.

### 11.2 설명 게이트

- 문제의 배경과 개념의 필요성이 먼저 나온다.
- 독자가 끝까지 따라갈 수 있는 완결된 최소 예가 있다.
- 입력·중간 과정·출력이 구분된다.
- 비유의 대응 범위와 한계가 함께 적혀 있다.
- 전문용어를 쉬운 말로 바꾸면서 기술 조건을 삭제하지 않았다.

### 11.3 수식 게이트

- 수식이 답하는 질문과 요구 조건이 먼저 설명된다.
- 모든 기호, 인덱스, 값의 종류·shape·범위·출처가 정의된다.
- 각 항과 핵심 연산의 역할이 설명된다.
- 유도에서 건너뛴 대수·확률·미분 단계가 없다.
- 숫자를 넣은 계산을 독자가 재현할 수 있다.
- 결과가 원래 문제의 언어로 해석된다.
- 필연적인 부분, 가정에 따른 귀결, 근사와 설계 선택이 구분된다.
- 최소 한 가지 대안과 실패·경계 조건이 설명된다.

### 11.4 근거 게이트

- 사실, 설명용 예, 해석과 미확인 계보가 구분된다.
- 새 사실 주장에는 evidence와 locator가 있다.
- 원문의 표기·범위와 후대 표준을 혼동하지 않는다.
- raw를 수정하지 않았고 artifact 해시가 유지된다.

### 11.5 학습 확인 게이트

- 독자가 정의를 자기 말로 설명하는 질문이 있다.
- 예나 수식을 재현하는 질문이 있다.
- 필요하면 가정·대안·한계를 구분하는 질문이 있다.
- 질문의 답을 본문에서 찾을 수 있다.
- 다음 문서가 현재 남긴 질문을 실제로 이어 받는다.

### 11.6 저장소와 사이트 게이트

일반 내용 작업은 다음 검사를 수행한다.

```powershell
npm run learning:audit
npm run learning:audit:check
npm run sync:index
npm run lint:wiki
npm run build:site
npm run check:site
npm run test
npm run verify
```

정규 소스 ingest는 같은 공식 번호로 다음 검사까지 수행한다.

```powershell
npm run source:ready -- NNN
```

자동 검사는 설명의 교육적 완결성, 수식의 논리적 필연성이나 비유의 정확성을 대신 판정하지 못한다. 원문 diff, 수동 계산 재현, 대표 사이트 렌더와 학습 질문의 답 가능성을 사람이 검토한다.

## 12. 완료 정의

다음 항목을 모두 만족해야 작업을 완료한다.

- [ ] 대상 문서와 원 근거를 처음부터 끝까지 읽었다.
- [ ] 숨은 선수 지식과 순환 정의를 감사했다.
- [ ] 필요한 기초 개념을 현재 문서와 기준 페이지에서 설명했다.
- [ ] 문제에서 예, 원리, 수식과 근거로 이어지는 논리 사다리가 끊기지 않는다.
- [ ] 핵심 수식이 6장의 해설 프로토콜과 수식 게이트를 통과한다.
- [ ] 사실·설명용 예·해석·한계를 구분했다.
- [ ] 학습 확인과 다음 문서가 실제 이해와 경로를 시험한다.
- [ ] frontmatter, evidence, artifacts, related, index·overview·log가 변경과 일치한다.
- [ ] 자동 검사와 수동 내용·수식·사이트 검수를 통과했다.
- [ ] 관련 없는 사용자 변경을 포함하지 않고 올바른 Git 경계와 커밋 접두사를 지켰다.

이 가운데 하나라도 충족하지 못하면 형식 lint가 통과해도 기초 학습형 문서 작업은 완료되지 않은 것이다.
