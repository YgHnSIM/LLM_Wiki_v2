# Whisper와 대규모 약지도 다국어 음성 인식 해설

## 1. 한눈에 보기

- 핵심 주제: 68만 시간의 웹 음성-텍스트 쌍으로 학습한 단일 Transformer가 전사, 영어 번역, 언어 식별, 음성 없음 판정을 함께 수행하도록 만든 방법
- 등장 배경: 깨끗한 단일 벤치마크에 맞춘 모델은 실제 환경에서 쉽게 무너졌고, 자기지도 음성 인코더는 실제 전사를 위해 별도의 미세조정된 디코더가 필요했다.
- 가장 중요한 아이디어: 새로운 음성 전용 구조를 발명하기보다, 크고 다양한 약지도 데이터와 토큰화된 다중 과제 인터페이스를 결합해 분포 밖 일반화를 노렸다.
- 이후 LLM/NLP에 남긴 영향: 자연어 생성에 쓰이던 encoder-decoder Transformer와 제어 토큰을 음성 처리의 공통 인터페이스로 사용함으로써 음성과 텍스트를 하나의 조건부 생성 문제로 다루는 실용적 선례를 만들었다.

> 이 문서는 `087_Whisper Large-Scale Multilingual Speech Recognition with Transformer Architecture.md`의 번역문을 이해하기 위한 해설입니다. 원문을 반복하기보다 공식 논문과 모델 카드를 바탕으로 구조, 작동 흐름, 평가의 의미, 흔한 오해를 보완합니다.

## 2. 핵심 요약

Whisper는 OpenAI가 2022년에 공개한 범용 음성 인식 모델 계열이다. 연구의 핵심 질문은 특정 데이터셋마다 미세조정하지 않고도 여러 언어와 실제 녹음 환경에서 견고하게 작동하는 음성 시스템을 만들 수 있는가였다. 연구진은 인터넷에서 수집한 약 68만 시간의 음성-텍스트 쌍을 자동 필터링하고, 이를 영어 전사, 다국어 전사, 비영어 음성의 영어 번역 등으로 함께 학습했다. 입력 음성은 30초 구간의 log-Mel spectrogram으로 바뀐 뒤 Transformer 인코더를 통과하고, 자기회귀 Transformer 디코더가 언어·과제·타임스탬프를 나타내는 특수 토큰과 텍스트 토큰을 순서대로 생성한다. 논문의 강한 결과는 모든 정제 벤치마크에서 최고 점수를 냈다는 데 있지 않고, 대상 데이터셋으로 별도 미세조정하지 않은 zero-shot 조건에서 여러 분포에 걸쳐 비교적 안정적인 성능을 냈다는 데 있다. 동시에 언어별 데이터 양에 따라 성능 격차가 컸고, 존재하지 않는 문장을 생성하는 환각, 긴 음성에서의 반복과 정렬 실패 같은 한계도 남았다. 따라서 Whisper는 “음성 인식이 해결되었다”는 선언이 아니라, 모델 구조의 복잡성보다 데이터의 규모·다양성·과제 표현 방식이 견고성에 얼마나 큰 영향을 주는지를 보여 준 사례로 읽는 편이 정확하다.

- 무엇을 다루는가: 대규모 약지도 학습을 이용한 다국어 자동 음성 인식(ASR)과 X→English 음성 번역
- 어떤 문제를 해결하려 했는가: 언어·도메인·잡음 조건마다 별도 모델과 미세조정이 필요한 파편화된 음성 처리 체계
- 어떤 방식이 새로웠는가: 68만 시간 규모의 다양한 웹 데이터와 여러 음성 과제를 하나의 토큰 시퀀스로 통합한 학습 형식
- 결과적으로 무엇을 바꾸었는가: 특정 벤치마크 최고점보다 분포 밖 zero-shot 견고성을 음성 모델 평가의 중심 질문으로 끌어왔다.

## 3. 역사적 배경

Whisper 이전에도 음성 인식은 이미 심층 신경망, 종단간 학습, Transformer를 빠르게 받아들이고 있었다. 한 흐름은 wav2vec 2.0 같은 자기지도 학습으로 막대한 비라벨 음성에서 좋은 음향 표현을 배우는 것이었다. 그러나 당시의 대표적 자기지도 방식은 실제 단어열을 출력하려면 대상 데이터셋의 전사 자료로 디코더를 미세조정해야 했다. 다른 흐름은 여러 감독 데이터셋을 합쳐 도메인 견고성을 높이는 것이었지만, 공식 논문이 예로 든 SpeechStew의 합계는 5,140시간으로 웹 규모 비라벨 음성보다 훨씬 작았다.

Whisper는 이 간극을 “비라벨 음성을 더 잘 표현하는 인코더”가 아니라 “웹에 이미 존재하는 잡음 많은 음성-텍스트 쌍으로 인코더와 디코더를 함께 사전 학습한다”는 방향으로 메웠다. 공식 논문은 이를 대규모 **약지도 학습(weak supervision)**으로 규정한다. 데이터는 사람이 전부 새로 검수한 정답지가 아니므로 품질이 낮지만, 환경·화자·언어·주제의 폭은 훨씬 넓다. 이 교환을 감수하면서 자동 필터링, 중복 제거, 언어 일치 검사, 저품질 출처의 수동 제거를 결합했다.

- 이전 접근법: 단일 데이터셋에 맞춘 지도 학습, 여러 단계의 음향·언어 모델 파이프라인, 자기지도 음성 인코더 뒤의 과제별 미세조정
- 당시의 한계: 벤치마크 내부에서는 낮은 오류율을 내도 억양, 잡음, 전화 음질, 전문 용어 같은 분포 변화에서 성능이 크게 떨어질 수 있었다.
- 이 주제가 필요했던 이유: 실제 배포 환경의 모든 언어와 녹음 조건에 대해 별도 정답 데이터와 모델을 유지하는 방식은 비용이 크고 확장하기 어려웠다.

이 문제 설정과 수치는 [Whisper 공식 논문 §1–2](https://arxiv.org/abs/2212.04356)에 근거한다.

## 4. 핵심 개념 해설

### 4.1 약지도 데이터: “자동 전사 68만 시간”이 아니다

Whisper의 학습 자료는 인터넷에서 이미 음성과 텍스트가 짝지어진 자료를 모은 것이다. 공식 논문 기준 전체 약 68만 시간 가운데 약 43만 8천 시간은 영어 음성과 영어 전사, 11만 7천 시간은 비영어 음성과 같은 언어 전사, 12만 5천 시간은 비영어 음성과 영어 번역의 쌍이다. 중요한 점은 연구진이 기존 ASR로 68만 시간을 새로 전사한 것이 아니라는 사실이다. 오히려 기계가 만든 듯한 전사문은 문장 부호·대소문자·표기 양상의 휴리스틱을 이용해 가능한 한 제거했다. 음성 언어와 텍스트 언어가 다르고 텍스트가 영어인 쌍은 X→English 번역 자료로 분류했다.

여기서 **약지도**란 라벨이 전혀 없다는 뜻이 아니다. 텍스트 라벨은 있지만, 사람이 같은 규약으로 정밀 검수한 학술 데이터셋보다 정렬 오류, 누락, 잘못된 언어 판정, 품질 편차가 크다는 뜻이다. 규모는 잡음을 평균화하고 다양한 조건을 보여 주는 장점이 있지만, 데이터 오류와 편향도 함께 학습시킨다.

### 4.2 입력에서 텍스트까지: 30초 음성을 조건으로 한 언어 모델

원래 Whisper 계열의 기본 흐름은 다음과 같다.

1. 음성을 16 kHz로 다시 샘플링한다.
2. 25 ms 창과 10 ms 간격으로 80채널 log-magnitude Mel spectrogram을 만든다.
3. 두 층의 작은 합성곱 stem이 시간축을 압축하고, 사인 위치 임베딩을 더한다.
4. Transformer 인코더가 전체 음향 특징을 문맥화한다.
5. Transformer 디코더가 앞서 생성한 텍스트 토큰과 인코더 출력을 함께 보며 다음 토큰을 자기회귀적으로 예측한다.
6. BPE 토큰을 글자로 복원해 전사문, 영어 번역문, 타임스탬프를 얻는다.

따라서 Whisper는 파형을 곧바로 문자로 바꾸는 마법 상자가 아니다. 고정된 음향 특징 추출, 합성곱 전처리, Transformer 인코딩, 교차 주의를 포함하는 autoregressive decoding이 이어지는 **조건부 언어 모델**이다. 논문은 의도적으로 검증된 encoder-decoder Transformer를 사용해, 개선의 원인이 새로운 구조인지 데이터 규모인지 혼동하지 않도록 했다. 원래 모델 계열은 Tiny 39M, Base 74M, Small 244M, Medium 769M, Large 1.55B 매개변수로 확장된다. 세부 구조는 [공식 논문 §2.2와 표 1](https://arxiv.org/abs/2212.04356)에 제시되어 있다.

### 4.3 특수 토큰이 만드는 다중 과제 인터페이스

동일한 음성에도 “들린 언어 그대로 적기”와 “영어로 번역하기”라는 서로 다른 답이 가능하다. Whisper는 이 일대다 문제를 별도 출력 헤드로 나누기보다 디코더의 토큰 시퀀스로 지정한다.

- `<|startoftranscript|>`: 출력 시작
- 언어 토큰: 감지하거나 지정한 입력 언어
- `<|transcribe|>` 또는 `<|translate|>`: 같은 언어 전사인지 영어 번역인지 지정
- `<|notimestamps|>` 또는 시간 토큰: 타임스탬프 출력 여부와 구간 경계
- `<|nospeech|>`: 해당 구간에 음성이 없다고 판정
- `<|endoftranscript|>`: 출력 종료

이 설계의 의의는 여러 과제를 “텍스트 다음 토큰 예측”이라는 한 인터페이스로 바꾼 데 있다. 다만 Whisper의 `translate`는 임의의 목표 언어로 번역하는 기능이 아니라 **비영어 음성을 영어 텍스트로 옮기는 X→English 번역**이다. 프랑스어 음성을 한국어로 직접 번역하는 모델로 이해하면 안 된다.

### 4.4 구체적인 작동 예

30초 이하의 한국어 회의 음성에 “오늘 배포 일정을 다시 확인하겠습니다”라는 발화가 있다고 하자.

- `transcribe` 과제를 선택하면 디코더는 한국어 언어 토큰과 전사 토큰에 조건화되어 한국어 문장을 생성한다.
- `translate` 과제를 선택하면 같은 음향 표현을 조건으로 영어 문장을 생성한다.
- 타임스탬프 모드에서는 20 ms 단위로 양자화된 시작·끝 시간 토큰을 텍스트 사이에 끼워 넣는다.
- 30초를 넘는 파일은 모델이 한 번에 모두 읽지 않는다. 추론 코드가 30초 창을 이동시키고, 이전 창의 텍스트와 예측된 시간 토큰을 이용해 다음 구간을 이어 붙인다.

이 때문에 긴 음성의 품질은 신경망 가중치만이 아니라 beam search, 온도 fallback, 반복 감지, 무음 임계값, 이전 텍스트 조건화 같은 디코딩 규칙에도 좌우된다. 공식 저장소의 `transcribe()`가 전체 파일을 30초 이동 창으로 처리한다는 설명은 [Whisper README](https://github.com/openai/whisper)에, 긴 음성용 휴리스틱은 [공식 논문 §4.5](https://arxiv.org/abs/2212.04356)에 정리되어 있다.

### 4.5 무엇을 어떻게 평가했는가

전사는 주로 단어 오류율(WER)로 평가한다.

\[
\mathrm{WER}=\frac{S+D+I}{N}
\]

여기서 \(S\)는 치환, \(D\)는 삭제, \(I\)는 삽입 오류 수이며 \(N\)은 정답 단어 수다. 문장부호나 숫자 표기처럼 의미가 같아도 표면 형식이 다르면 WER가 커질 수 있으므로 Whisper 논문은 자체 텍스트 정규화를 적용했다. 저자들도 이 정규화가 Whisper의 출력 양식에 과적합될 위험을 명시했다. 음성 번역은 BLEU, 언어 식별은 정확도로 평가했다.

논문의 영어 결과를 “모든 곳에서 SOTA”로 요약하면 핵심을 놓친다. LibriSpeech test-clean의 zero-shot 성능은 당시 최고 기록보다 낮았지만, LibriSpeech에 맞춰 학습한 비교 모델보다 여러 다른 영어 데이터셋에서 오류가 훨씬 덜 증가했다. 다국어에서도 MLS에서는 강했지만 VoxPopuli에서는 여러 선행 모델보다 뒤졌다. 즉 중요한 주장은 최고점 하나가 아니라 **대상 데이터셋 미세조정 없이 여러 분포에 걸친 견고성**이다.

## 5. 원문의 논리 구조

원문은 대략 다음 흐름으로 전개됩니다.

1. 기존 음성 인식은 언어·과제·음향 조건별로 모델과 파이프라인이 갈라져 실제 환경의 다양성을 다루기 어렵다고 문제를 제기한다.
2. 해법의 중심을 복잡한 새 구조가 아니라 크고 다양한 다국어·다중 과제 데이터에 둔다.
3. log-Mel 입력을 받는 Transformer encoder-decoder와 과제를 지정하는 특수 토큰 형식을 설명한다.
4. 단일 모델이 전사, X→English 번역, 언어 식별을 수행하고 여러 실제 조건에서 견고하다고 주장한다.
5. 공개된 모델의 활용성과 함께 계산 비용, 언어별 격차, 데이터 불투명성, 긴 음성 처리 같은 한계를 논한다.

이 흐름을 읽을 때는 원문의 포괄적 표현과 공식 연구 결과의 범위를 구분해야 한다. “다국어”, “번역”, “최고 수준”, “오픈 소스”는 각각 지원 언어별 품질, 영어 방향 번역, 평가 데이터셋별 차이, 공개된 산출물 범위를 확인해야 정확해진다.

## 6. 왜 중요한가

Whisper의 역사적 가치는 Transformer를 음성에 처음 적용했다는 데 있지 않다. 2022년 이전에도 음성 Transformer와 종단간 ASR은 존재했다. 더 중요한 점은 다음 세 요소를 하나의 재현 가능한 시스템으로 결합한 데 있다.

- **사전 학습의 출력까지 포함했다.** 음향 인코더만 사전 학습한 뒤 과제별 디코더를 붙이는 대신, 텍스트 생성 디코더도 대규모 약지도 자료로 함께 학습해 바로 사용할 수 있게 했다.
- **분포 밖 평가를 전면에 놓았다.** 특정 벤치마크 훈련 분할에 적응하지 않고 여러 공개 데이터셋에 적용해, 실제 배포에서 중요한 견고성을 별도 능력으로 다뤘다.
- **파이프라인의 여러 결정을 토큰으로 통합했다.** 언어, 전사·번역, 타임스탬프, 무음을 하나의 디코더 어휘 안에 넣어 같은 가중치와 인터페이스를 재사용했다.
- **모델 가중치와 추론 코드를 공개했다.** 개발자가 고성능 ASR을 직접 실행하고 변형할 수 있는 기반을 제공했다. 다만 학습 데이터와 완전한 학습 코드는 공개 범위에 포함되지 않았다는 점도 함께 기억해야 한다.

이 사례는 “구조가 단순하면 시스템도 단순하다”는 뜻이 아니다. 학습 데이터 수집·필터링과 긴 음성 디코딩에는 상당한 규칙과 운영 설계가 들어간다. 단순성은 신경망 본체의 상대적 단순성을 가리킨다.

## 7. 현대 LLM과의 연결

- **조건부 자기회귀 생성**: GPT가 앞선 텍스트를 조건으로 다음 토큰을 생성하듯, Whisper 디코더도 앞선 텍스트와 음향 인코더 상태를 조건으로 다음 토큰을 생성한다. 차이는 Whisper가 양방향 음향 인코더와 교차 주의를 쓰는 encoder-decoder 구조라는 점이다.
- **제어 토큰과 과제 통합**: 언어·전사·번역 토큰은 서로 다른 과제를 하나의 생성 인터페이스로 바꾼다. 이는 오늘날 멀티태스크 모델의 control token이나 프롬프트와 닮았지만, 자연어 지시를 따르도록 instruction tuning한 것과 동일하지는 않다.
- **웹 규모 약지도 사전 학습**: 깨끗하지만 좁은 데이터보다 크고 다양한 자료로 먼저 학습해 zero-shot 일반화를 얻으려는 전략은 대규모 언어 모델의 사전 학습과 문제의식을 공유한다. 다만 Whisper에는 텍스트와 시간 정렬이라는 추가 잡음원이 있다.
- **멀티모달 인터페이스**: 음성을 텍스트 토큰 생성의 조건으로 바꾸면서 음성 이해 결과를 요약·검색·대화 같은 언어 시스템의 후속 단계에 연결하기 쉬워졌다. 이것이 곧 Whisper 자체가 범용 대화형 LLM이라는 뜻은 아니다.
- **평가의 이동**: 단일 데이터셋 내부의 최저 WER보다 미세조정 없이 다른 억양·도메인·녹음 환경으로 옮겨 갔을 때의 성능을 중시한 점은 현대 foundation model 평가의 분포 밖 일반화 문제와 직접 닿아 있다.

Whisper를 “오디오용 GPT”라고만 부르면 encoder-decoder 구조, 음향 전처리, 타임스탬프 토큰, 약지도 정렬 자료라는 중요한 차이가 사라진다. 더 정확한 설명은 **음향 인코더에 조건화된 다중 과제 autoregressive text decoder**다.

## 8. 한계와 비판적 관점

### 8.1 모델 자체의 한계

- 기술적 한계: 긴 음성은 30초 이동 창과 여러 휴리스틱에 의존하므로 정렬 드리프트, 반복, 구간 누락이 누적될 수 있다. 원래 구조는 저지연 스트리밍 전용 모델이 아니다.
- 이론적 한계: 대규모 데이터와 성능의 상관은 강하지만, 규모 자체가 어떤 언어 지식과 음향 불변성을 만들었는지 완전한 인과 설명을 제공하지 않는다.
- 실용적 한계: 큰 모델의 계산·메모리 요구량, 언어별 품질 격차, 전문 도메인별 오류를 배포 전에 따로 평가해야 한다.
- 안전 한계: 모델은 음성에 없는 그럴듯한 텍스트를 생성할 수 있다. 공식 모델 카드는 이를 hallucination으로 명시하며, 고위험 의사결정 용도를 권하지 않는다.
- 공정성 한계: 같은 언어 안에서도 억양·방언과 화자 집단에 따라 오류율이 다를 수 있고, 저자들은 언어별 전사 성능이 해당 언어 학습량과 강하게 연관된다고 보고했다.

이 한계들은 [Whisper 공식 모델 카드](https://github.com/openai/whisper/blob/main/model-card.md)의 Performance and Limitations 및 Broader Implications에 근거한다.

### 8.2 흔한 오해 바로잡기

| 오해 | 공식 자료에 가까운 설명 |
|---|---|
| 68만 시간을 기존 ASR이 자동 전사했다. | 인터넷에 이미 존재한 음성-텍스트 쌍을 수집했으며, 기계 생성 전사로 보이는 자료는 오히려 휴리스틱으로 제거하려 했다. |
| 90개가 넘는 언어에서 모두 잘 작동한다. | 학습 언어 목록과 실질적으로 강한 언어 수는 다르다. 공식 모델 카드는 강한 ASR 결과를 약 10개 언어에서 강조하고, 저자들은 언어별 데이터 양과 오류율의 큰 격차를 보고한다. |
| 원하는 두 언어 사이를 모두 번역한다. | 원래 Whisper의 음성 번역 과제는 X→English다. 같은 언어 전사는 다국어로 가능하지만 임의 목표 언어 번역 모델은 아니다. |
| 모든 음성 인식 벤치마크에서 SOTA였다. | 일부 과제에서는 최고 수준이거나 경쟁적이었지만, 깨끗한 영어 데이터와 일부 다국어 벤치마크에서는 더 좋은 선행 모델이 있었다. 핵심은 zero-shot 분포 밖 견고성이다. |
| 한 모델이 화자 분리까지 완성된 파이프라인으로 처리한다. | 논문은 전사·번역·언어 식별·무음·타임스탬프를 통합했다. 화자 분리(diarization)는 기본 공개 모델의 검증된 핵심 과제가 아니다. |
| 학습 데이터와 학습 코드까지 모두 공개되었다. | 공식 발표의 공개 범위는 모델 가중치와 추론 코드다. 데이터셋과 완전한 학습 파이프라인은 공개되지 않았다. |
| “zero-shot”은 처음 보는 언어도 같은 품질로 처리한다는 뜻이다. | 논문에서 zero-shot은 주로 평가 대상 데이터셋의 훈련 자료로 별도 미세조정하지 않았다는 뜻이다. 그 언어가 사전 학습에 없었다는 뜻은 아니다. |

### 8.3 오늘날 관점에서 다시 볼 점

원문은 Whisper의 영향과 성능을 다소 포괄적으로 서술한다. 공식 논문은 더 신중하다. 다국어 ASR에서 텍스트 정규화 때문에 직접적인 SOTA 주장을 경계했고, VoxPopuli에서 선행 모델보다 뒤진 결과도 보고했다. 또한 공개 저장소가 널리 쓰였다는 사실과 원래 연구가 모든 실제 사용 사례를 검증했다는 주장은 구분해야 한다. 의료·법률·채용처럼 오류가 큰 피해로 이어지는 환경에서는 도메인별 WER뿐 아니라 누락, 환각, 화자·방언별 격차를 별도로 측정하고 사람이 검토하는 절차가 필요하다.

## 9. 용어 정리

| 용어 | 설명 |
|---|---|
| 자동 음성 인식(ASR) | 음성 파형을 같은 언어의 문자 전사로 바꾸는 과제 |
| 음성 번역 | 음성을 다른 언어의 텍스트로 바꾸는 과제. 원래 Whisper에서는 X→English 방향 |
| 약지도 학습 | 라벨이 존재하지만 정밀 검수된 정답보다 잡음과 불확실성이 큰 자료로 학습하는 방식 |
| log-Mel spectrogram | 시간에 따른 주파수 에너지를 사람의 청각 척도에 가깝게 압축해 로그값으로 표현한 음향 특징 |
| encoder-decoder Transformer | 인코더가 입력 전체를 표현하고 디코더가 그 표현에 주의를 주며 출력 토큰을 순서대로 만드는 구조 |
| cross-attention | 디코더의 현재 상태가 음향 인코더의 어느 위치를 참고할지 계산하는 주의 메커니즘 |
| BPE | 자주 함께 나타나는 문자 조각을 토큰으로 묶어 열린 어휘를 다루는 부분단어 토큰화 방식 |
| task token | 전사·번역 같은 원하는 동작을 디코더에 알려 주는 특수 토큰 |
| timestamp token | 30초 창 안의 시작·끝 시간을 20 ms 간격으로 나타내는 토큰 |
| zero-shot 평가 | 해당 평가 데이터셋의 훈련 분할로 모델을 별도 미세조정하지 않고 바로 평가하는 방식 |
| WER | 치환·삭제·삽입 오류 합계를 정답 단어 수로 나눈 전사 오류율 |
| 환각(hallucination) | 입력 음성에 실제로 존재하지 않는 그럴듯한 문장을 모델이 생성하는 현상 |
| 화자 분리(diarization) | “무엇을 말했는가”가 아니라 “누가 언제 말했는가”를 구분하는 별도 과제 |

## 12. 짧은 결론

Whisper는 새 음성 전용 구조 하나로 역사를 바꾼 모델이라기보다, 검증된 Transformer encoder-decoder에 웹 규모 약지도 데이터와 토큰화된 다중 과제 인터페이스를 결합해 **미세조정 없는 분포 밖 견고성**을 실용 수준으로 끌어올린 사건이다. 동시에 그 성과는 언어별 불균형, 환각, 긴 음성 디코딩의 취약성, 비공개 학습 자료라는 조건 위에 서 있다. 따라서 Whisper의 유산은 “ASR의 완성”보다 “좋은 사전 학습 데이터, 출력 인터페이스, 평가 분포를 함께 설계해야 범용성이 생긴다”는 교훈에 있다.

공식 근거는 Alec Radford 외, [*Robust Speech Recognition via Large-Scale Weak Supervision*](https://arxiv.org/abs/2212.04356), [OpenAI Whisper 공식 저장소](https://github.com/openai/whisper), [Whisper 공식 모델 카드](https://github.com/openai/whisper/blob/main/model-card.md)다.
