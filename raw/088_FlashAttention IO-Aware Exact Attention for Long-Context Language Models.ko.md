# FlashAttention: 긴 문맥 언어 모델을 위한 I/O 인지형 정확 어텐션
원본 출처: https://mbrenndoerfer.com/writing/flashattention-io-aware-exact-attention-long-context-language-models

---

2022년에 등장한 FlashAttention을 종합적으로 살펴본다. I/O를 고려한 어텐션 계산이 2~4배의 속도 향상과 5~10배의 메모리 절감을 가능하게 한 방식, 타일링과 온라인 소프트맥스로 메모리 복잡도를 이차에서 선형으로 줄인 기법, 하드웨어를 고려한 GPU 최적화, 그리고 효율적인 트랜스포머 아키텍처와 긴 문맥 언어 모델에 남긴 지속적인 영향을 알아본다.

## 2022년: FlashAttention

스탠퍼드를 비롯한 여러 기관의 연구진이 2022년에 선보인 [FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)은 I/O를 고려한 정확한 어텐션 계산을 통해 긴 문맥의 학습과 추론을 훨씬 빠르고 메모리 효율적으로 만들면서 [어텐션 메커니즘](/writing/attention-mechanism-intuition-soft-lookup-weights-context-vectors)의 효율성에 획기적 진전을 이뤘다. 메모리 접근 패턴을 최소화하면서 어텐션을 계산하는 이 알고리즘의 혁신적 접근은 훨씬 긴 시퀀스를 처리하는 [트랜스포머](/writing/transformer-attention-is-all-you-need) 모델의 학습과 배포를 가능하게 했고, 대규모 언어 모델의 확장 가능성을 근본적으로 바꾸었다.

2022년 무렵 트랜스포머 모델은 언어 AI의 지배적인 아키텍처가 되었지만, 시퀀스 길이에 따라 어텐션 메커니즘의 메모리 복잡도가 이차적으로 늘어난다는 중대한 한계가 있었다. 이 때문에 긴 시퀀스를 다루는 모델을 학습하거나 배포하는 일은 감당하기 어려울 만큼 비쌌다. 표준 어텐션 구현은 모든 중간 결과를 고대역폭 메모리에 저장해 과도한 메모리 접근을 일으켰고, 계산 속도를 늦추며 모델이 실질적으로 처리할 수 있는 시퀀스 길이를 제한했다. 연구자들이 문서 이해, 장문 생성, 장시간 대화 같은 응용을 위해 더 긴 문맥을 추구하면서 이 병목은 갈수록 심각해졌다.

[FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)의 성공은 밑바탕의 모델 설계를 바꾸지 않고도 알고리즘 혁신으로 기존 아키텍처의 효율을 크게 높일 수 있음을 보여 주었다. 이 연구는 메모리 접근 패턴과 하드웨어 최적화를 세심하게 고려하면 수치적으로 정확한 어텐션 계산을 유지하면서도 최대 2~4배의 속도 향상과 5~10배의 메모리 절감을 얻을 수 있음을 보였다. 이 돌파구는 이후 여러 어텐션 메커니즘의 발전에 영향을 주고 긴 문맥 언어 모델의 새로운 능력을 가능하게 했으며, FlashAttention을 효율적인 딥러닝 알고리즘 역사에서 중요한 이정표로 자리매김시켰다.

## 문제

[트랜스포머](/writing/transformer-attention-is-all-you-need) 모델에서 어텐션을 계산하던 전통적인 방식은 표준 행렬 곱셈 연산에 의존했는데, 특히 시퀀스가 길어질수록 메모리 사용량과 계산 비용이 컸다. [어텐션 메커니즘](/writing/attention-mechanism-intuition-soft-lookup-weights-context-vectors)은 중간 결과를 메모리에 저장해야 했으므로 시퀀스 길이에 대해 이차 메모리 복잡도를 보였다. 길이가 \(n\)인 시퀀스를 처리할 때 표준 어텐션은 \(n \times n\) 어텐션 행렬을 저장해야 했고, 메모리 사용량은 시퀀스 길이의 제곱에 비례해 늘어났다. 이런 한계 때문에 시퀀스가 길어질수록 메모리 요구량이 빠르게 증가해 긴 시퀀스 모델을 학습하거나 배포하기가 어려웠다.

실제 사례로 8,000개 토큰으로 이뤄진 문서를 처리한다고 생각해 보자. 표준 어텐션은 8,000 × 8,000 행렬을 저장해야 하므로 query, key, value 행렬까지 고려하기도 전에 어텐션 가중치만으로 250MB가 넘는 메모리를 소비한다. 연구자들이 문서 이해와 장문 생성을 위해 지원하려 했던 16,000개 이상의 토큰 시퀀스에서는 메모리 요구량이 감당하기 어려운 수준이 되어 가용 GPU 메모리를 넘어서는 경우가 많았다.

게다가 표준 어텐션 계산은 현대 하드웨어에 맞게 최적화되지 않아 계산 자원을 비효율적으로 사용했다. 전통적 구현은 느린 전역 메모리에서 더 빠른 공유 메모리와 레지스터까지, 메모리 계층의 서로 다른 수준 사이에서 데이터를 반복적이고 비효율적으로 옮겼다. 메모리 접근에는 지연 시간과 대역폭 비용이 따르는데, 순진한 어텐션 구현은 불필요한 메모리 전송을 많이 일으켰다. 따라서 메모리가 충분한 상황에서도 GPU가 실제 계산보다 데이터 전송을 기다리는 데 많은 시간을 쓰면서 연산이 느려졌다.

[어텐션 메커니즘](/writing/attention-mechanism-intuition-soft-lookup-weights-context-vectors)의 메모리 병목은 이 분야에 큰 영향을 미쳤다. 연구자들이 긴 문서를 이해하고 생성하거나, 장시간 대화의 문맥을 유지하거나, 책이나 연구 논문 전체를 처리하는 모델을 학습하는 능력이 제한되었다. 더 정교한 응용을 위해 긴 문맥을 추구하면서 이 한계는 긴 문맥 언어 모델의 발전을 막는 주요 장애물 가운데 하나가 되었다.

## 해결책

[FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)은 어텐션 계산을 I/O 인지형이고 메모리 효율적인 방식으로 다시 설계해 이런 한계를 해결했다. 알고리즘은 입력을 블록 단위로 처리하고 타일링과 재계산 같은 기법을 사용해, 정확한 어텐션 계산을 유지하면서 메모리 사용량을 최소화했다. 이 접근은 메모리 복잡도를 시퀀스 길이에 대한 이차에서 선형으로 줄여 훨씬 긴 시퀀스를 처리하는 모델의 학습과 배포를 가능하게 했다.

FlashAttention의 핵심 혁신은 타일링을 사용해 어텐션 계산을 블록 단위로 처리함으로써 수치적 정확성을 유지하면서 메모리 요구량을 줄인 데 있었다. 알고리즘은 입력을 더 작은 블록으로 나누고 온라인 소프트맥스와 온라인 어텐션 같은 기법으로 각 블록의 어텐션을 따로 계산해 정확한 결과를 유지했다. 전체 어텐션 행렬을 한꺼번에 계산하는 대신 query와 key를 타일로 처리하면서 어텐션 점수를 점진적으로 계산하고, 최종 출력에 필요한 정보만 저장했다.

이 타일링 접근은 입력 시퀀스를 블록으로 나누고 어텐션 계산을 블록별로 처리하는 방식으로 작동했다. 각 query 블록에 대해 알고리즘은 key 블록을 순회하며 어텐션 점수를 점진적으로 계산했다. 핵심 통찰은 [소프트맥스](/writing/multinomial-logistic-regression-complete-guide-mathematical-foundations-python-implementation)와 어텐션 계산을 위한 온라인 알고리즘을 사용하면 전체 어텐션 행렬을 저장하지 않고도 수치적으로 정확한 결과를 유지할 수 있다는 것이었다. [온라인 소프트맥스](/writing/flashattention-algorithm-memory-efficient-gpu-tiling) 알고리즘은 새로운 어텐션 점수가 계산될 때 소프트맥스 [정규화](/writing/normalization-feature-scaling-min-max-machine-learning-guide) 계수를 점진적으로 계산할 수 있게 했고, 온라인 어텐션 계산은 중간 점수를 저장하지 않고도 어텐션으로 가중한 값을 누적할 수 있게 했다.

알고리즘의 아키텍처는 현대 GPU 아키텍처와 메모리 계층을 고려하도록 설계되었다. FlashAttention은 공유 메모리, 레지스터 블로킹, 메모리 병합 접근 같은 기법으로 계산 효율을 극대화하고 메모리 접근 오버헤드를 최소화했다. 구현은 느린 메모리 접근 횟수를 줄이기 위해 GPU 메모리의 여러 수준, 즉 전역 메모리와 공유 메모리, 레지스터 사이의 데이터 이동을 세심하게 관리했다. 자주 접근하는 데이터를 빠른 공유 메모리와 레지스터에 유지함으로써 순진한 구현보다 훨씬 효율적으로 어텐션을 계산할 수 있었다.

알고리즘은 수치적으로 안정적이고 정확하게 설계되어 결과가 표준 어텐션 계산과 동일하도록 했다. 수치적 차이가 모델의 학습과 배포에 영향을 줄 수 있으므로 이는 매우 중요했다. FlashAttention이 사용한 [온라인 소프트맥스](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)와 어텐션 알고리즘은 표준 어텐션과 같은 수치적 성질을 유지하되 더 메모리 효율적인 순서로 계산하도록 세심하게 설계되었다.

## 구현과 학습

[FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)의 학습 과정에는 몇 가지 핵심 구성 요소가 있었다. 이 알고리즘은 기존 [트랜스포머](/writing/transformer-attention-is-all-you-need) 아키텍처에 통합할 수 있는 사용자 정의 CUDA 커널로 구현되었다. 구현은 자동 미분과 gradient checkpointing 같은 기법을 사용해 새로운 [어텐션 메커니즘](/writing/attention-mechanism-intuition-soft-lookup-weights-context-vectors)으로 효율적으로 학습할 수 있게 했다. 또한 기존 학습 프레임워크와 호환되고 표준 어텐션을 바로 대체할 수 있도록 설계되었다.

사용자 정의 CUDA 커널 구현은 FlashAttention의 성공에 결정적이었다. 연구진은 저수준 GPU 코드를 작성해 고수준 프레임워크에서는 불가능한 방식으로 메모리 접근 패턴을 최적화할 수 있었다. 커널은 지연 시간을 최소화하고 처리량을 극대화하도록 전역 메모리와 공유 메모리, 레지스터 사이의 데이터 이동을 세심하게 조율했다. 이런 하드웨어 수준 최적화가 FlashAttention을 혁신적으로 만든 극적인 효율 향상을 가능하게 했다.

구현은 자동 미분 프레임워크와의 호환성을 유지해 [FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)을 학습 파이프라인에서 매끄럽게 사용할 수 있게 했다. [역방향 패스](/writing/backpropagation-algorithm-deep-learning-neural-networks)도 비슷한 타일링과 재계산 기법으로 최적화해 순방향과 역방향 계산 모두 메모리 효율 개선의 혜택을 받도록 했다. 학습 중 메모리 사용량을 더 줄이기 위해 gradient checkpointing 기법도 통합했으며, 그 결과 더 긴 시퀀스를 학습에서 처리할 수 있었다.

바로 대체할 수 있는 방식으로 알고리즘을 설계한 점은 도입에 매우 중요했다. 연구자와 실무자는 코드베이스나 학습 파이프라인의 다른 부분을 수정하지 않고도 기존 모델의 표준 어텐션을 FlashAttention으로 바꿀 수 있었다. 이런 통합 편의성과 큰 폭의 효율 개선이 결합되면서 연구계와 산업계에 빠르게 도입되었다.

## 성능과 영향

[FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)은 표준 어텐션 계산보다 최대 2~4배 빠르고 메모리를 5~10배 적게 사용하는 큰 폭의 효율 개선을 달성했다. 이런 개선은 이전 접근법의 2K~4K 토큰 한계와 비교해 최대 16K 토큰 길이의 시퀀스로 모델을 학습할 수 있게 했다. 또한 메모리 효율이 높아져 같은 하드웨어에서 더 큰 모델을 학습하고 계산 자원을 더 효율적으로 사용할 수 있었다.

FlashAttention의 성공은 I/O 인지형 어텐션 알고리즘의 몇 가지 핵심 장점을 보여 주었다. 첫째, 메모리 효율 덕분에 이전보다 훨씬 긴 시퀀스로 모델을 학습하고 배포할 수 있었다. 예전에는 수천 개 토큰만 처리하던 모델이 이제 문서 전체, 긴 대화, 그 밖의 확장된 문맥을 처리할 수 있었다. 둘째, 계산 효율 덕분에 같은 하드웨어에서 더 큰 모델을 학습할 수 있었다. 연구자들은 절약한 메모리로 모델 크기나 [배치 크기](/writing/stochastic-gradient-descent-neural-network-optimization)를 늘려 학습 효율과 모델 성능을 모두 개선할 수 있었다.

셋째, 알고리즘의 정확한 계산은 결과가 표준 어텐션과 같도록 해 효율을 높이면서도 모델 품질을 유지했다. 이는 연구자들이 수치적 차이가 모델에 영향을 줄까 걱정하지 않고 [FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)을 도입할 수 있다는 뜻이어서 매우 중요했다. 이 알고리즘은 정확도나 모델 동작의 절충 없이 더 빠르고 메모리 효율적인 계산이라는 모든 이점을 제공했다.

알고리즘의 능력은 긴 시퀀스 처리가 필요한 긴 문맥 언어 모델과 응용에 큰 영향을 미쳤다. FlashAttention은 문서 전체, 긴 대화, 그 밖의 장문 콘텐츠를 다루는 모델의 개발을 가능하게 해 문서 분석, 장문 [질의응답](/writing/ibm-watson-jeopardy-open-domain-question-answering-nlp-information-retrieval), 대화형 AI 같은 응용의 새로운 가능성을 열었다. 이전에 몇 쪽의 텍스트만 처리하던 모델이 연구 논문이나 책 전체, 긴 멀티턴 대화를 다룰 수 있게 되면서 [트랜스포머](/writing/transformer-attention-is-all-you-need) 기반 언어 모델의 잠재적 응용 범위가 크게 넓어졌다.

## 한계와 과제

[FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)은 메모리 효율을 크게 개선했지만 어텐션 기반 모델의 모든 한계를 없애지는 못했다. 알고리즘은 메모리 복잡도를 이차에서 선형으로 줄였지만 계산 복잡도는 시퀀스 길이에 대해 여전히 이차였다. 100,000개 토큰에 가까운 매우 긴 시퀀스에서는 메모리 효율적 구현을 사용해도 계산 비용이 감당하기 어려울 수 있었다.

사용자 정의 CUDA 커널 구현은 효율 개선을 가능하게 했지만 유지보수와 이식성 문제도 만들었다. 서로 다른 GPU 아키텍처와 CUDA 버전에 맞춰 코드를 세심하게 유지해야 했다. 최적화가 NVIDIA GPU 아키텍처와 메모리 계층에 특화되어 있었기 때문에 FlashAttention을 새로운 하드웨어 플랫폼이나 다른 가속기로 이식하려면 상당한 엔지니어링 노력이 필요했다.

또한 타일링 접근은 표준 어텐션보다 구현을 복잡하게 만들었다. [FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)은 바로 대체할 수 있도록 설계되었지만, 사용자 정의 아키텍처나 특수 학습 파이프라인에 통합할 때는 추가 작업이 필요하기도 했다. 온라인 소프트맥스와 온라인 어텐션 알고리즘은 수치적으로 정확하지만 표준 구현보다 디버깅하거나 수정하기 어려울 수 있었다.

이 알고리즘은 특정 과제에서 나타나는 어텐션 메커니즘의 근본적 한계도 해결하지 않았다. 예를 들어 매우 긴 문맥 전체에 걸친 전역 추론이 필요한 과제는 [효율적 어텐션](/writing/attention-complexity-quadratic-scaling-memory-efficient-transformers)을 사용해도 여전히 어려움을 겪을 수 있었다. 이차 계산 복잡도가 실용적인 시퀀스 길이를 제한할 수 있기 때문이다. 어떤 응용은 표준 어텐션의 유연성을 일부 희생하더라도 긴 문맥을 더 효율적으로 처리하는 다른 아키텍처에서 이점을 얻을 수 있었다.

## 유산과 영향

[FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)의 성공은 이후 여러 어텐션 메커니즘의 발전에 영향을 주고 어텐션 효율의 새로운 기준을 세웠다. 이 알고리즘의 접근은 다른 [효율적 어텐션](/writing/attention-complexity-quadratic-scaling-memory-efficient-transformers) 구현의 본보기가 되었고, 그 성능 벤치마크는 새로운 어텐션 메커니즘을 위한 표준 [평가 지표](/writing/history-rouge-meteor-evaluation-metrics)가 되었다. 또한 하드웨어를 고려한 알고리즘 설계의 가치를 보여 주면서 다른 효율적 [트랜스포머](/writing/transformer-attention-is-all-you-need) 알고리즘의 개발에도 영향을 주었다.

알고리즘의 오픈 소스 공개는 세계의 연구자와 개발자가 이를 사용할 수 있게 해 빠른 도입과 후속 개발을 가능하게 했다. 구현 코드가 공개되면서 다른 이들이 이 연구를 토대로 특정 응용이나 하드웨어에 특화된 버전을 개발할 수 있었다. 이 개방형 접근은 효율적 어텐션 메커니즘과 관련 분야의 연구·개발을 가속했으며, 이후 여러 연구가 FlashAttention의 기법과 통찰을 직접 토대로 삼았다.

FlashAttention은 기존 아키텍처의 효율을 높이는 데 알고리즘 혁신이 중요하다는 사실도 보여 주었다. 메모리 접근 패턴과 하드웨어 최적화를 세심하게 고려하면 밑바탕의 모델 아키텍처를 바꾸지 않고도 효율을 크게 높일 수 있음을 입증했다. 이 통찰은 아키텍처 변경보다 알고리즘 개선이 더 큰 이득을 주는 경우도 있음을 연구자들이 인식하게 하면서 이후 여러 딥러닝 효율화 알고리즘의 발전에 영향을 주었다.

긴 시퀀스를 효율적으로 처리하는 능력은 다른 긴 문맥 AI 시스템의 발전에도 영향을 미쳤다. 효율적 알고리즘으로 더 긴 시퀀스를 가능하게 한다는 발상은 현대 AI 시스템의 표준 접근이 되었고, 장문 콘텐츠를 처리해야 하는 더 정교한 응용을 뒷받침했다. 이 원칙은 검색 증강 생성 시스템부터 긴 문맥 언어 모델까지, 긴 시퀀스를 처리할 수 있는 여러 후속 시스템의 개발에 영향을 주었다.

[FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)의 성공은 현대 AI 시스템에서 하드웨어 인식 알고리즘 설계가 얼마나 중요한지도 부각했다. 현대 GPU 아키텍처를 위한 최적화는 구체적인 하드웨어 능력을 활용하는 알고리즘을 설계할 가치가 있음을 보여 주었다. 이 통찰은 효율 개선에 알고리즘과 하드웨어 양쪽에 대한 깊은 이해가 필요한 경우가 많다는 인식과 함께, 특정 하드웨어 플랫폼에 최적화된 이후 여러 알고리즘의 발전에 영향을 주었다.

알고리즘의 영향은 어텐션 메커니즘을 넘어 딥러닝과 AI의 다른 영역까지 이어졌다. 효율 개선은 더 긴 시퀀스를 처리하는 더 큰 모델의 학습과 배포를 가능하게 해 새로운 응용과 능력을 열었다. 메모리 효율에 대한 접근도 신경망 학습과 배포의 다른 계산 병목에 적용되는 패턴과 기법을 확립하면서 다른 딥러닝 효율화 알고리즘의 발전에 영향을 주었다.

[FlashAttention](/writing/flashattention-algorithm-memory-efficient-gpu-tiling)은 알고리즘 혁신이 기존 아키텍처의 효율을 크게 높일 수 있음을 보여 준, 어텐션 메커니즘과 효율적 딥러닝 알고리즘 역사에서 중요한 이정표다. I/O 인지형 계산, 메모리 효율, 하드웨어 최적화를 비롯한 혁신은 어텐션 효율의 새로운 기준을 세웠다. 이 연구는 이후 여러 어텐션 메커니즘의 발전에 영향을 주고 긴 문맥 언어 모델의 새로운 능력을 가능하게 하며, AI 기술을 진전시키는 알고리즘 혁신의 힘을 보여 주었다.
