# 서브워드 토큰화와 FastText 해설

## 1. 한눈에 보기

이 글은 단어를 더 이상 쪼개지 않는 원자처럼 다룰 때 생기는 희귀어·미등록어 문제와, 이를 완화하는 FastText의 문자 n-gram 합성을 설명한다. 핵심 아이디어는 한 단어의 벡터를 그 단어 내부 문자 조각들의 벡터 합으로 만드는 것이다. 다만 원문은 FastText와 BPE·SentencePiece를 하나의 연속 계보처럼 서술한다. 실제로는 **한 단어 벡터를 내부 특징으로 합성하는 방법**과 **모델에 들어가는 토큰열 자체를 서브워드로 바꾸는 방법**을 구분해야 한다.

## 2. 핵심 요약

- 기본 Skip-gram은 어휘 항목마다 독립적인 입력 벡터를 두므로 단어 내부 철자와 형태를 직접 공유하지 않는다.
- Bojanowski 등의 방법은 단어 경계 기호를 붙인 길이 3–6의 문자 n-gram과 단어 자체를 이용해 입력 표현을 합성한다.
- 훈련에서는 중심 단어의 n-gram 벡터 합과 문맥 단어의 출력 벡터로 점수를 계산하고 negative sampling 목적을 최적화한다.
- 훈련에 없던 단어는 단어별 벡터 없이도 이미 학습된 문자 n-gram 벡터를 합해 표현할 수 있다.
- 문자 조각은 형태소 분석 결과가 아니다. 표면 철자를 공유할 뿐 의미와 형태 경계를 보장하지 않는다.
- FastText의 합성은 입력 단어열을 쪼개지 않지만 BPE는 토큰열의 단위와 길이를 바꾼다.
- FastText 단어 벡터 논문의 정식 출판은 TACL 2017년이다. 2016년은 논문 제출·초기 공개 시기와 겹치지만 출판 연도를 그대로 대체하지 않는다.

## 3. 역사적 배경

word2vec의 Skip-gram은 국소 문맥 예측으로 단어 벡터를 효율적으로 학습했지만, 기본형에서는 각 word type이 독립적인 입력 벡터를 갖는다. 같은 어근이나 접사를 공유해도 그 구조가 매개변수에 직접 반영되지는 않는다. 형태가 풍부한 언어와 희귀어에서는 관측이 여러 굴절형으로 흩어지는 문제가 컸다.

이 문제를 다루는 연구는 FastText 하나에서 갑자기 시작되지 않았다. 형태소 특징, 문자 기반 신경망, 문자 n-gram의 합과 같은 선행 접근이 있었다. Bojanowski 등은 이를 Skip-gram with negative sampling의 단순하고 빠른 구조에 결합해 9개 언어의 단어 유사도·유추와 언어 모형 초기화에서 평가했다. TACL 논문은 2016년 제출을 거쳐 2017년 출판되었다.

한편 Sennrich·Haddow·Birch는 ACL 2016에서 압축 알고리즘 BPE를 신경 기계 번역의 단어 분절에 적용했다. 이 작업은 고정 크기 어휘와 가변 길이 문자열로 희귀어 번역을 다루었다. FastText 논문도 관련 연구에서 Sennrich 등의 서브워드 번역을 언급하지만, 이것만으로 FastText가 BPE의 직접 원인이라고 말할 수는 없다. 두 연구는 비슷한 희소성 문제를 서로 다른 모델 인터페이스에서 다룬 병행 흐름에 가깝다.

## 4. 핵심 개념 해설

단어 w에 경계 기호 `<`, `>`를 붙이고 길이 3–6의 문자 n-gram 집합 G_w를 만든다. 논문은 완전한 단어를 나타내는 특별한 항목도 집합에 넣는다. 각 n-gram g에 벡터 z_g를 두면 중심 단어와 문맥 단어 c의 점수는 다음처럼 쓸 수 있다.

$$
s(w,c)=\sum_{g\in G_w} z_g^\top v_c
$$

여기서 v_c는 문맥 단어의 출력 벡터다. 따라서 기본 Skip-gram의 독립 입력 벡터 u_w가 여러 공유 subword 벡터의 합으로 바뀐다. 훈련 중 관측된 단어는 단어 자체의 특별 벡터와 문자 n-gram 벡터를 함께 쓰고, OOV 단어는 단어별 특별 벡터 없이 문자 n-gram들만으로 근사할 수 있다.

모든 문자 n-gram을 별도 항목으로 저장하면 메모리가 커지므로 논문 구현은 FNV-1a hash로 n-gram을 K=2,000,000개의 bucket에 사상했다. 서로 다른 n-gram이 같은 bucket에 들어가는 충돌이 가능하며, 이는 메모리를 제한하는 대가다.

BPE는 다른 방식이다. 처음에는 단어를 문자 열로 놓고 가장 자주 나타나는 인접 symbol pair를 반복해서 합친다. merge 횟수가 어휘 크기를 조절한다. 자주 나타나는 문자열은 긴 단위나 완전한 단어로 남고, 드문 단어는 짧은 조각으로 분절된다. 모델은 이 조각들을 별도 시퀀스 위치로 받는다.

## 5. 원문의 논리 구조

원문은 다섯 단계로 전개된다.

1. 원자적 단어 임베딩이 희귀어·OOV·형태 풍부 언어에서 겪는 문제를 제시한다.
2. 문자 n-gram 벡터의 합으로 단어 표현을 만드는 FastText의 해법을 설명한다.
3. Skip-gram과 negative sampling을 유지하면서 subword 매개변수를 공유하는 훈련 구조를 소개한다.
4. 분류·개체명 인식·검색·다언어·소셜 미디어 응용 가능성과 정적 임베딩의 한계를 나열한다.
5. 이 통찰을 BPE·SentencePiece·Transformer 토큰화로 이어지는 유산으로 서술한다.

1–3단계는 FastText 단어 벡터 논문의 핵심과 대체로 맞는다. 4단계의 개별 응용 성능은 이 글이 직접 제시한 실험 근거가 아니며, 5단계는 공통 문제의식과 직접 계보를 구분해 읽어야 한다.

## 6. 왜 중요한가

FastText의 중요한 기여는 OOV를 하나의 미지 토큰으로 뭉개는 대신 철자 구조에서 표현을 계산할 수 있게 한 것이다. 공유되는 접사·어근 비슷한 문자열이 여러 단어에서 반복 학습되므로 희귀 단어도 더 빈번한 조각의 신호를 빌릴 수 있다. 복잡한 형태 분석기 없이 구현할 수 있고 기본 Skip-gram의 효율을 상당 부분 유지한다는 점도 실용적이었다.

더 넓게 보면 이 연구는 표현 단위가 미리 주어진 자연적 사실이 아니라 모델 설계 선택임을 드러낸다. 단어를 하나의 ID로만 볼 수도 있고, 내부 특징의 합으로 볼 수도 있고, 시퀀스의 여러 토큰으로 분해할 수도 있다. 무엇을 공유하느냐에 따라 희소성, 어휘 크기, 시퀀스 길이, 의미 구별 능력의 trade-off가 달라진다.

## 7. 현대 LLM과의 연결

현대 LLM도 대개 고정된 유한 어휘를 사용하고 입력 문자열을 여러 subword 또는 byte 계열 token으로 바꾼다. 이 선택은 희귀 문자열을 더 작은 단위로 표현하고 어휘 크기를 제한한다는 점에서 FastText와 문제의식을 공유한다. 그러나 계산 구조는 다르다.

- FastText는 먼저 단어 경계를 정한 뒤 문자 n-gram을 내부 특징으로 합쳐 **하나의 정적 단어 벡터**를 만든다.
- BPE·WordPiece·Unigram 계열 tokenizer는 문자열을 **여러 token position**으로 분절한다.
- Transformer는 각 token의 초기 lookup embedding을 문맥에 따라 반복 갱신해 **문맥화 표현**을 만든다.

원문 마지막의 “현대 방법은 토큰화와 임베딩을 공동 학습한다”는 표현은 일반화가 지나치다. 널리 쓰이는 많은 파이프라인에서는 tokenizer 어휘·규칙을 말뭉치에서 먼저 학습하거나 고정한 뒤 언어 모형 embedding을 훈련한다. end-to-end tokenizer 연구가 따로 존재하지만 모든 Transformer의 표준 절차는 아니다.

SentencePiece도 하나의 분절 목적 함수와 동일한 말이 아니다. 원 논문은 raw sentence에서 직접 훈련·인코딩하고 normalized text를 복원할 수 있는 tokenizer/detokenizer 틀이며 BPE와 Unigram model 등을 지원한다. “SentencePiece=BPE”로 바꾸어 읽지 않는다.

## 8. 한계와 비판적 관점

첫째, 문자 n-gram은 형태소가 아니다. `where`의 `her`처럼 우연히 다른 단어와 같은 문자열이 포함될 수 있으며, hash collision까지 더해져 같은 매개변수를 공유한다고 의미 관계가 보장되지는 않는다.

둘째, OOV 벡터를 계산할 수 있다는 것과 그 의미를 이해한다는 것은 다르다. 새 단어가 알려진 접사와 어근 비슷한 철자를 공유하면 도움이 되지만, 철자가 불투명한 이름·다른 문자 체계·새 개념은 정보가 부족하다. 문맥에 따라 뜻이 바뀌는 다의어 문제도 정적 벡터에는 그대로 남는다.

셋째, 원문의 응용 사례 중 개체명 인식·정보 검색·콘텐츠 조정 성능은 FastText 단어 벡터 논문 자체의 직접 실험 범위를 넘어선다. 원 논문의 핵심 평가는 9개 언어의 유사도·유추, 자료량·n-gram 길이 분석, 일부 언어 모형 초기화다. 응용 가능성과 논문에서 입증된 결과를 분리해야 한다.

넷째, 형태가 풍부한 언어에서 이점이 크다는 경향도 언어별 tokenizer, 문자 정규화, 말뭉치와 과제에 따라 달라진다. 한국어에서는 완성형 음절을 문자로 볼지 정규화해 자모 단위로 볼지에 따라 n-gram 공유가 크게 바뀐다. Unicode 정규화는 부수적 전처리가 아니라 표현 단위를 결정하는 선택이다.

다섯째, BPE도 OOV를 무조건 없애지 않는다. 기본 alphabet 또는 byte fallback이 입력의 모든 symbol을 포괄하는 설정에서는 임의 문자열을 표현할 수 있지만, 문자 어휘가 제한되거나 normalization 과정에서 정보가 사라지면 unknown 처리가 남을 수 있다. 또한 어휘를 줄이면 시퀀스가 길어지는 비용이 생긴다.

## 9. 용어 정리

- **OOV**: 훈련·모델 어휘집에 등록되지 않은 항목. 문자열을 표현할 수 없음과 의미를 잘 추정하지 못함은 다른 문제다.
- **문자 n-gram**: 연속된 n개의 문자 조각. FastText에서는 여러 길이의 조각을 bag으로 사용한다.
- **경계 기호**: 단어 시작과 끝을 표시해 접두·접미 위치를 내부 문자열과 구분하는 기호다.
- **hash bucket**: 여러 n-gram을 고정 수의 벡터 슬롯에 사상해 메모리를 제한하는 장치다. 충돌이 가능하다.
- **FastText word vectors**: 문자 n-gram 합을 이용하는 정적 단어 표현 방법이다.
- **fastText classifier**: bag-of-words·n-gram과 선형 분류를 효율적으로 학습하는 같은 프로젝트의 별도 기능·논문이다.
- **BPE**: 빈번한 인접 symbol pair를 반복 병합해 가변 길이 단위를 만드는 알고리즘이다. 원래 압축 기법이었고 NMT word segmentation에 적응되었다.
- **SentencePiece**: raw text에서 subword model을 훈련하고 encoding·decoding하는 언어 독립적 도구·틀이다.
- **정적 임베딩**: 문맥과 무관하게 word type마다 같은 벡터를 쓰는 표현이다.
- **문맥화 표현**: 같은 token도 주변 문맥에 따라 다른 hidden state를 갖는 표현이다.

2. 형태소 경계를 몰라도 문자 n-gram이 유용한 이유와, 바로 그 단순함이 실패를 만드는 경우는 무엇인가?

5. 한국어에서 음절·자모·byte 가운데 어느 단위를 기본 alphabet으로 삼느냐가 희귀어 공유에 어떤 차이를 만들까?
6. FastText와 BPE의 공통점을 ‘서브워드’라는 말보다 더 정확한 축으로 표현한다면 무엇인가?

## 12. 짧은 결론

FastText는 Skip-gram의 중심 단어 표현을 문자 n-gram 벡터의 합으로 바꾸어 희귀어와 미관측어가 더 빈번한 철자 조각의 통계를 공유하게 했다. 이 아이디어는 단어를 원자적 ID로만 볼 필요가 없음을 선명하게 보여주지만, BPE처럼 입력 시퀀스를 분절하는 토큰화와는 다른 기술이다. 두 흐름을 제대로 연결하려면 “서브워드를 쓴다”에서 멈추지 말고, 조각이 **한 벡터의 특징인지 여러 시퀀스 토큰인지**를 먼저 물어야 한다.
