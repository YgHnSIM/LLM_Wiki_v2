# 레스크 알고리즘과 문맥 기반 단어 의미 중의성 해소 해설

## 1. 한눈에 보기

- 핵심 주제: 사전의 뜻풀이와 주변 단어의 뜻풀이가 공유하는 어휘를 세어 문맥에 맞는 단어 의미를 고르는 지식 기반 중의성 해소 방법
- 등장 배경: 기계 판독형 사전을 계산 자원으로 활용할 수 있게 되고, 규칙을 단어별로 일일이 만드는 방식의 확장성 한계가 분명해지던 1980년대
- 가장 중요한 아이디어: 서로 양립하는 의미들은 같은 주제 영역의 단어를 뜻풀이에서 공유할 가능성이 높으므로, 뜻풀이 중첩을 의미 선택의 점수로 쓸 수 있다.
- 이후 LLM/NLP에 남긴 영향: 레스크는 오늘날에도 재현 가능한 지식 기반 기준선으로 유용하며, 문맥과 후보 의미의 적합도를 비교한다는 문제 설정은 현대의 글로스 임베딩 기반 방법과도 비교할 수 있다.

> 이 문서는 `017_Lesk Algorithm Word Sense Disambiguation & the Birth of Context-Based NLP.md`의 번역문을 이해하기 위한 해설이다. 번역문을 되풀이하기보다 1986년 실제 구현, 단순화 레스크, 적응형·확장 계열을 구분하고, 원문에 섞여 있는 연대·복잡도·현대 신경망과의 계보 주장을 비판적으로 읽는 기준을 제시한다.

## 2. 핵심 요약

마이클 레스크의 공개 논문은 1986년 SIGDOC에 실린 「Automatic Sense Disambiguation Using Machine Readable Dictionaries: How to Tell a Pine Cone from an Ice Cream Cone」이다. 원 논문의 실제 구현은 구절의 각 단어를 한 번씩 처리했다. 현재 단어의 각 후보 의미 뜻풀이를 주변 단어들의 모든 후보 의미 뜻풀이와 비교하고, 중첩 점수가 가장 큰 의미를 골랐다. 이미 고른 의미만 남기고 다른 단어를 재평가하는 `settling`은 미래 선택지로 남겼으며, 문장 전체의 의미 조합을 전수 탐색하지 않았다. 이 방법은 별도의 단어별 규칙을 만드는 대신 기계 판독형 사전을 계산 자원으로 재활용했다. 오늘날 흔히 소개되는 ‘목표 단어의 뜻풀이와 원문 문맥 단어를 직접 비교하는 절차’는 후대의 단순화 레스크다. 원 구현은 대상 후보 수·주변 단어 수·그 단어들의 후보 수·뜻풀이 길이가 모두 관계하는 중첩 비교를 반복했지만, 논문은 점근 복잡도나 실행 시간을 정식 보고하지 않았다. 따라서 전역 조합 탐색이라고 할 수도, 단순 선형이라고 할 수도 없다. 2002년 배너지와 페더슨의 `Adapted Lesk`는 WordNet의 관계를 따라 관련 글로스를 추가하고 더 긴 중첩 문자열에 높은 점수를 주어 희소한 정확 일치 문제를 완화했다. 임베딩과 문맥 언어 모델은 의미 유사도를 더 풍부하게 표현하지만, 원 레스크와 같은 알고리즘이거나 그 직접적인 확장이라고 단정할 근거는 없다.

- 무엇을 다루는가: 단어 의미 중의성 해소, 기계 판독형 사전, 뜻풀이(gloss), 어휘 중첩, 문맥, 후보 의미 비교
- 어떤 문제를 해결하려 했는가: 한 단어가 여러 사전 의미를 가질 때 주변 단어와 가장 일관된 의미를 자동으로 선택하는 문제
- 어떤 방식이 새로웠는가: 사람이 만든 뜻풀이를 의미적 특징으로 간주하고, 뜻풀이 사이의 실제 단어 중첩을 계산 가능한 선택 기준으로 삼았다.
- 결과적으로 무엇을 바꾸었는가: 사전 기반 WSD를 위한 간단한 기준선을 제공했고, 이후 WordNet 관계 확장·말뭉치 가중치·벡터 유사도를 결합한 여러 변형의 비교점이 됐다.

## 3. 역사적 배경

확인 가능한 1차 출판 기록은 1983년이 아니라 1986년이다. [ACM DOI 기록](https://doi.org/10.1145/318723.318728)은 논문을 SIGDOC ’86, pp. 24–26으로 수록하고, [마이클 레스크의 출판 목록](https://www.lesk.com/mlesk/pub.html)도 같은 제목과 1986년 6월 토론토 발표를 제시한다. 원문은 ‘1986년 논문이지만 1983년 무렵 개발됐다’고 서술하지만, 이 앞선 개발 연대를 뒷받침하는 별도 출처는 제공하지 않는다. 따라서 역사적 기준점은 1986년 공개 논문으로 잡고, 1983년은 추가 근거가 필요한 주장으로 읽는 편이 안전하다.

레스크 이전에도 단어 의미 중의성 해소 연구와 문맥 활용은 존재했다. 레스크의 구체적인 공헌은 WSD 자체를 처음 발명한 데 있다기보다, 기계 판독형 사전의 뜻풀이를 비교 가능한 데이터로 전환한 간결한 지식 기반 절차에 있다. 이 점에서 ‘문맥 기반 NLP의 탄생’이라는 원문 제목은 역사적 사실을 엄밀히 한정한 명칭이라기보다 중요성을 강조하는 수사에 가깝다. 또한 레스크의 방법은 확률을 추정하거나 말뭉치에서 매개변수를 학습하지 않으므로, 사전과 텍스트를 사용한다는 이유만으로 통계 학습 알고리즘이라 부르기는 어렵다.

- 이전 접근법: 수작업 어휘 규칙, 통사 제약, 선택 제약, 분야 지식 등을 이용해 불가능하거나 덜 그럴듯한 의미를 제거하는 방법
- 당시의 한계: 단어별 규칙 작성 비용, 사전 뜻풀이의 짧은 길이, 의미 구분의 세밀도 차이, 정확히 같은 어휘가 드물게 겹치는 문제
- 레스크가 필요했던 이유: 이미 구축된 어휘 자원을 이용하면서도 문맥에 따라 후보 의미를 자동으로 순위화할 재현 가능한 절차가 필요했다.

## 4. 핵심 개념 해설

### 4.1 1986년 구현과 단순화 레스크

1986년 구현은 구절의 각 단어를 한 번씩 처리했다. 현재 단어의 후보 의미 하나를 고르면, 그 뜻풀이를 주변 단어들의 모든 후보 의미 뜻풀이와 비교해 중첩을 합산했다. 그런 다음 점수가 가장 큰 현재 단어의 의미를 선택했다. 선택 결과로 다른 단어를 다시 평가하지도, 모든 단어의 의미 조합을 전역적으로 탐색하지도 않았다. 반면 단순화 레스크는 보통 하나의 목표 단어만 중의성 해소한다. 목표 단어의 후보 글로스 각각을 실제 주변 문맥과 비교해 겹치는 단어가 가장 많은 의미를 고른다. 두 방식은 어휘 중첩을 이용하지만, 비교 대상과 처리 절차가 다르다.

### 4.2 글로스 중첩과 탐색 비용

글로스는 사전이나 WordNet에 붙은 짧은 뜻풀이 또는 설명문이다. 가장 단순한 점수는 두 글로스에 공통으로 나타나는 어휘를 세어 만든다. 1986년 논문의 출력 예시는 `burned`와 `burning`을 `burn`으로 다룬 듯하지만, 논문은 토큰화·불용어 제거·어간 처리 절차를 정식으로 명세하지 않았다. 실제 구현의 비교량은 현재 단어의 후보 의미 수, 주변 단어 수, 그 단어들의 후보 의미 수, 뜻풀이 길이에 따라 달라진다. 논문은 점근 복잡도나 실행 시간을 보고하지 않았으므로 선형이나 지수라고 단정할 수 없다. 모든 단어의 의미 조합을 전수 탐색한다면 조합 수가 후보 수의 곱으로 커지지만, 1986년 실제 구현은 그런 전역 탐색을 사용하지 않았다. 단순화 레스크는 목표 단어의 각 후보 글로스를 표면 문맥과 직접 비교한다.

### 4.3 정확 일치, 의미 관계, 벡터 유사도

원형의 점수는 실제로 같은 문자열이 뜻풀이에 나타나는지를 본다. "water"와 "river"가 의미상 가깝다는 이유만으로 점수가 생기지는 않는다. 원문의 낚시 예에서 두 단어를 ‘의미적 이웃’으로 묶는 단계는 정확 일치만 사용하는 원 알고리즘을 넘어선다. [배너지와 페더슨의 2002년 Adapted Lesk](https://www.d.umn.edu/~tpederse/Pubs/cicling2002-b.pdf)는 WordNet 관계를 따라 관련 개념의 글로스를 추가해 비교 재료를 늘린다. 더 후대의 임베딩 방법은 벡터 사이 유사도로 동의어나 관련어를 가까이 다룰 수 있다. 이 세 층위는 각각 정확 어휘 중첩, 지식망을 이용한 글로스 확장, 학습된 연속 표상에 해당하며 서로 바꿔 쓸 수 있는 이름이 아니다.

## 5. 원문의 논리 구조

원문은 대체로 다음 순서로 논지를 전개한다.

1. 다의어가 기계 번역·정보 검색·음성 합성·질의응답에서 일으키는 문제를 제시한다.
2. 주변 문맥과 사전 정의의 어휘 중첩을 이용한다는 레스크의 핵심 직관을 소개한다.
3. 단순화 절차와 이웃 단어의 정의까지 비교하는 원형을 설명하고, `bank` 예로 작동 방식을 보여 준다.
4. 사전 품질, 희소한 중첩, 짧은 문맥, 가까운 의미, 비유와 관용구라는 한계를 정리한다.
5. WordNet 기반 적응형 레스크, 통계 가중치, 통사 정보, 임베딩과 현대 문맥 모델을 후속 흐름으로 연결한다.

이 구조는 입문 설명으로는 명료하지만, 원 알고리즘과 후대 변형의 기능을 한 사례 안에서 섞어 설명하는 부분이 있다. 특히 정확한 단어 중첩이 0인 예에서 곧바로 의미적 이웃을 이용하는 설명으로 넘어가므로, 독자는 어느 단계가 원형이고 어느 단계가 확장인지 구분해야 한다.

## 6. 왜 중요한가

레스크의 역사적 가치는 복잡한 언어 지식을 모두 형식화하지 않고도 기존 사전에서 계산 가능한 신호를 끌어낸 데 있다. 알고리즘은 정의 문장을 사람이 읽는 설명에서 기계가 비교할 수 있는 어휘 집합으로 바꿨다. 또한 성능이 제한적이어도 입력 자원, 전처리, 점수 규칙을 명시하면 재현 가능한 지식 기반 기준선이 된다는 연구 방법론적 가치를 보여 준다. 새 모델이 정말 문맥 의미를 포착하는지 확인할 때, 단순한 글로스 중첩보다 얼마나 좋아지는지를 비교하면 개선의 출처를 더 분명하게 볼 수 있다.

특히 중요한 점은 다음과 같다.

- 외부 어휘 지식을 WSD에 사용하는 간단하고 해석 가능한 계산 틀을 제공했다.
- 정확 일치가 실패하는 사례를 통해 형태 정규화, 관계 확장, 통계 가중치, 의미 유사도 같은 후속 개선 지점을 명확히 드러냈다.
- ‘문맥이 의미 선택의 증거를 제공한다’는 일반 원리와 ‘중첩 횟수로 그 증거를 측정한다’는 특정 구현을 구분해 생각하게 한다.

## 7. 현대 LLM과의 연결

현대 문맥 언어 모델은 같은 표면 단어라도 주변 토큰에 따라 서로 다른 은닉 표상을 만든다. 이는 단어마다 고정된 사전 항목 하나를 택하는 레스크의 출력과 다르지만, 후보 의미를 판단할 때 문맥이 중요하다는 문제의식은 공유한다. 글로스 기반 신경망 WSD에서는 목표 단어가 든 문맥과 후보 의미 설명을 각각 인코딩한 뒤 적합도를 비교하기도 한다. 이 경우 구조적 유사성은 더 크지만, 점수는 실제 단어 중첩이 아니라 학습된 표현과 훈련 목표에서 나온다.

- 문맥 임베딩: 같은 단어의 표상을 주변 문장에 따라 바꾸므로 의미 차이를 암묵적으로 담을 수 있다.
- 글로스 인코딩: 후보 의미의 정의를 신경망 입력으로 넣어 문맥 표상과 직접 비교할 수 있다.
- 사전 의미와 생성 모델: GPT 같은 모델은 보통 매 토큰마다 사전의 의미 번호를 명시적으로 선택하지 않으므로, 문맥에 민감한 생성과 사전 기반 WSD를 같은 과제로 보면 안 된다.

따라서 BERT 기반 WSD를 ‘학습된 레스크’라고 부르는 것은 직관을 설명하는 비유로는 쓸 수 있지만 기술적 동일성이나 직접 계보를 뜻하지 않는다. 레스크는 고정된 외부 뜻풀이와 이산적 중첩 점수를 사용한다. 트랜스포머는 대규모 말뭉치에서 매개변수를 학습하고, 문맥 전체에 조건화된 연속 표상을 계산한다.

## 8. 한계와 비판적 관점

레스크 계열의 가장 직접적인 한계는 사전이 실제 문맥과 같은 어휘를 써야 점수가 생긴다는 점이다. 전처리로 형태 차이를 줄일 수는 있지만 동의어, 상식, 담화 맥락, 화용 의도까지 자동으로 얻지는 못한다. 사전마다 의미 구분의 수와 경계가 다르므로 ‘정답 의미’ 자체도 자원에 종속된다. 1986년 구현은 전역 조합 탐색을 하지 않았지만, 현재 단어의 각 후보 글로스를 주변 단어들의 모든 후보 글로스와 반복 비교하므로 사전의 의미 수와 문맥 폭이 커질수록 비교량도 늘어난다.

- 기술적 한계: 짧은 글로스와 문맥에서는 0점 동률이 잦고, 원 구현의 다중 글로스 비교를 단순 선형이라고 일반화할 근거도 제시되지 않았다.
- 이론적 한계: 문맥은 의미 선택의 증거이지만 문맥만이 의미를 ‘결정한다’고 단정하면 세계 지식, 화자 의도, 장르와 담화 구조를 빠뜨린다.
- 실용적 한계: 사전의 범위·편향·의미 세분도에 성능이 좌우되며, 분야가 바뀌면 적합한 정의와 관계가 부족할 수 있다.
- 오늘의 관점에서 다시 봐야 할 점: 현대 WSD의 성능 향상 폭, 훈련 예 수, 1980년대 실제 응용 범위, 천 단어 처리 시간 같은 원문의 수치는 근거가 제시되지 않았으므로 독립 자료 없이 확정적 사실로 인용하면 안 된다.

원문이 레스크에서 분포 의미론, Word2Vec, BERT, GPT로 이어지는 직접적인 발전 계보를 제시하는 부분도 주의해야 한다. 이 방법들은 모두 문맥을 활용하지만, 사용하는 데이터와 목적 함수, 표상, 출력 단위가 다르다. 공통된 직관이나 비교 가능한 문제 설정이 곧 직접적인 역사적 영향이나 기술적 후손 관계를 증명하지는 않는다.

## 9. 용어 정리

| 용어 | 설명 |
|---|---|
| 단어 의미 중의성 해소(WSD) | 문맥에 나타난 단어가 후보 사전 의미 가운데 어느 의미로 쓰였는지 판별하는 과제 |
| 다의성(polysemy) | 하나의 단어 형태가 서로 관련되거나 구별되는 여러 의미를 지니는 현상 |
| 글로스(gloss) | 사전이나 WordNet이 한 의미에 붙인 짧은 뜻풀이 또는 설명문 |
| 어휘 중첩(lexical overlap) | 두 텍스트에 동일한 단어나 구절이 함께 나타나는 정도 |
| 단순화 레스크(Simplified Lesk) | 목표 단어의 각 후보 글로스를 실제 주변 문맥과 비교하는 단일 목표 중심 변형 |
| 적응형 레스크(Adapted Lesk) | 2002년 Banerjee·Pedersen이 WordNet 관계와 관련 글로스를 이용해 비교 범위를 넓힌 변형 |
| 확장 글로스 중첩(Extended Gloss Overlaps) | 2003년 후속 연구가 관련 개념의 글로스를 이용해 의미 관련도를 계산한 방법 |
| 의미 세분도(sense granularity) | 사전이 단어 의미를 얼마나 잘게 나누어 별도 항목으로 구별하는지를 나타내는 정도 |

3. 문맥 임베딩이 용법 차이를 잘 표현한다는 사실과, 사전에 정의된 의미 번호를 정확히 선택한다는 사실은 어떻게 다른가?

## 12. 최종 결론

레스크 알고리즘은 단어 의미 중의성 해소를 처음 만든 방법이나 현대 문맥 모델의 직접적인 원형이라기보다, 기계 판독형 사전의 뜻풀이 중첩을 이용해 문맥에 맞는 의미를 고르는 명료한 1986년 지식 기반 알고리즘으로 자리매김하는 편이 정확하다. 실제 구현은 현재 단어의 각 후보 글로스를 주변 단어들의 모든 후보 글로스와 비교해 그 단어의 의미를 한 번 선택했으며, 문장 전체의 의미 조합을 전역 탐색하지 않았다. 널리 알려진 단순화 버전은 목표 글로스와 실제 문맥을 직접 비교한다. 희소한 정확 일치와 반복 비교 비용, 사전 의존성은 뚜렷한 약점이지만, 바로 그 약점이 WordNet 관계 확장과 통계 가중치, 벡터 유사도 같은 후속 연구의 필요성을 선명하게 만들었다. 현대 LLM과 연결할 때에는 ‘문맥 적합도를 계산한다’는 넓은 공통점은 인정하되, 알고리즘·학습 방식·역사적 계보가 같다는 과도한 결론은 피해야 한다.
