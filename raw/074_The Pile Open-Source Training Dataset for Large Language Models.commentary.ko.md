# The Pile과 공개 LLM 학습 데이터 해설

## 1. 한눈에 보기

- 핵심 주제: 서로 다른 22개 영어 텍스트 구성요소를 결합해 대규모 언어 모델 사전 학습과 교차 영역 평가에 사용하도록 공개한 EleutherAI의 The Pile
- 등장 배경: GPT-3 이후 모델과 컴퓨팅뿐 아니라 대규모 학습 자료의 수집·정제·문서화가 재현 가능한 LLM 연구의 핵심 장벽으로 드러난 상황
- 가장 중요한 아이디어: 웹 문서 하나에 의존하지 않고 학술 문서, 도서, 코드, 법률, 대화 등 의도적으로 다른 영역을 혼합하며 구성과 처리 과정을 공개한 것
- 이후 LLM/NLP에 남긴 영향: GPT-Neo·GPT-J·GPT-NeoX와 후속 공개 모델 연구에 공통 데이터 기반을 제공하고, 데이터 구성·편향·라이선스·문서화를 모델 설계와 같은 수준의 연구 문제로 부각한 것

> 이 문서는 `073_The Pile Open-Source Training Dataset for Large Language Models.md`의 번역문을 이해하기 위한 해설입니다. 원문을 반복하기보다 The Pile 논문이 직접 보고한 구성과 평가, 원문이 넓게 해석한 대중화 효과, 그리고 공개 접근성과 저작권·라이선스 적합성을 구분해서 읽는 기준을 정리합니다.

## 2. 핵심 요약

The Pile은 EleutherAI가 대규모 언어 모델 학습을 위해 만든 825.18 GiB 규모의 영어 텍스트 말뭉치다. 논문은 2020년 12월 31일 arXiv에 처음 제출되었고, 2021년 자료로 널리 알려졌다. 데이터는 Pile-CC, PubMed Central, Books3, OpenWebText2, arXiv, GitHub, FreeLaw 등 22개 구성요소를 합친 것이며, 그중 14개는 논문이 새 언어 모델링 데이터셋으로 소개했다. 모든 구성요소를 똑같이 한 번씩 사용하는 단순 합집합이 아니라, Wikipedia처럼 품질이 높다고 판단한 일부 자료에 최대 세 번까지 더 큰 학습 가중치를 주는 혼합물이었다. 연구진은 Pile로 학습한 GPT-2 규모 모델이 Raw Common Crawl과 CC-100으로 학습한 비교 모델보다 Pile의 각 구성요소에서 낮은 손실을 보이고 일부 하위 평가에서도 개선됨을 보고했다. 그러나 825 GiB라는 크기만으로 GPT-3와 같은 모델을 재현할 수 있다는 뜻은 아니며, 매개변수 규모·토큰 수·컴퓨팅·최적화와 평가 조건이 함께 필요하다. 또한 “오픈 소스”와 “모든 텍스트가 하나의 허용적 라이선스로 재배포된다”는 말은 같지 않다. The Pile은 구성 코드와 문서, 데이터 접근을 공개했지만 구성요소별 권리와 이용 조건이 달랐고, 연구진도 저자 동의·편향·분할 간 중복 가능성을 별도 쟁점으로 기록했다.

- 무엇을 다루는가: The Pile의 22개 구성요소, 가중 혼합, 큐레이션·문서화와 공개 LLM 연구에 미친 영향
- 어떤 문제를 해결하려 했는가: 폐쇄형 학습 데이터 때문에 모델 비교·재현·교차 영역 연구가 어려웠던 문제
- 어떤 방식이 새로웠는가: 방대한 Common Crawl 하나가 아니라 의도적으로 고른 전문 영역 자료를 섞고, 구성 코드와 데이터 분석을 함께 공개한 방식
- 결과적으로 무엇을 바꾸었는가: 공개 모델 개발의 데이터 준비 비용을 낮추고, 학습 데이터 자체를 감사·평가·설계할 수 있는 연구 대상으로 만들었다.

## 3. 역사적 배경

GPT-2와 GPT-3는 웹 규모 사전 학습과 모델 확장이 범용 언어 능력을 크게 높일 수 있음을 보여 주었다. 그러나 모델 가중치나 API 접근과 별개로, 어떤 문서를 어떤 비율로 골라 학습했는지는 재현하기 어려웠다. Common Crawl은 누구나 구할 수 있었지만 HTML 잔재, 중복, 스팸과 품질 편차가 컸다. 연구 집단이 각자 필터와 혼합 비율을 만들면 모델 성능 차이가 모델 때문인지 데이터 때문인지 분리하기 어려웠다.

EleutherAI는 공개 GPT 계열 모델을 만들려면 학습 코드와 컴퓨팅뿐 아니라 반복 사용할 수 있는 대규모 데이터 기반이 필요하다고 보았다. The Pile은 원시 웹 자료의 양만 늘리기보다 학술·전문 자료를 의도적으로 더하고 각 구성요소를 문서화했다. 논문은 Pile을 학습 집합이면서 여러 영역에서 언어 모델 손실을 측정하는 교차 영역 벤치마크(benchmark)로도 제안했다.

- 이전 접근법: 비공개 혼합 데이터, 원시 Common Crawl 중심 말뭉치, 좁은 영역의 소규모 학술 데이터셋
- 당시의 한계: 데이터 수집·필터가 재현되지 않았고, 서로 다른 자료로 학습한 모델 사이의 성능 원인을 비교하기 어려웠음
- 이 주제가 필요했던 이유: 공개 모델 공동체가 동일한 대규모 자료와 구성 코드를 사용하고, 데이터 영역별 성능과 편향을 직접 조사할 기반이 필요했음

원문은 당시 컴퓨팅 자원이 점점 더 접근 가능해지고 데이터가 “주된 장벽”이었다고 설명한다. 이는 EleutherAI의 문제의식을 보여 주지만, 2021년에도 수십억 매개변수 모델의 학습 컴퓨팅은 큰 장벽이었다. The Pile이 데이터 준비의 한 장벽을 낮춘 것과 전체 LLM 개발 비용을 대중화한 것은 구분해야 한다.

## 4. 핵심 개념 해설

### 4.1 22개 구성요소와 가중 혼합

The Pile은 하나의 균일한 출처가 아니라 성격이 다른 22개 하위 데이터셋의 혼합물이다. 큰 비중을 차지한 Pile-CC는 Common Crawl에서 필터링한 웹 자료이고, PubMed Central과 arXiv는 과학 문서, GitHub는 코드, FreeLaw는 법률, Stack Exchange와 Hacker News는 질의응답과 토론을 제공했다. Books3와 BookCorpus2는 긴 서사 텍스트를 포함했다.

중요한 것은 원시 바이트(byte) 크기와 실제 학습 표본 비중이 다르다는 점이다. 연구진은 품질이 높다고 판단한 일부 구성요소를 한 Pile 에폭(epoch) 안에서 두세 번 보도록 가중했다. 따라서 “22개 자료를 모았다”는 사실만으로 학습 분포를 알 수 없으며, 각 구성요소의 원시 크기, 가중치와 반복 횟수를 함께 봐야 한다. 이 선택은 모델이 무엇을 자주 보고 어떤 영역에 강해지는지에 직접 영향을 준다.

### 4.2 825GB, 825.18 GiB와 학습 규모

원문은 읽기 쉽게 825GB라고 쓰지만 원 논문의 정확한 표기는 825.18 GiB다. 1 GiB는 $2^{30}$바이트이고 1 GB는 $10^9$바이트이므로 단위는 동일하지 않다. 논문 제목의 “800GB”도 둥글게 표현한 이름이며, 보고값을 인용할 때는 825.18 GiB라고 적는 편이 정확하다.

저장 용량은 모델이 실제로 본 토큰(token) 수와도 같지 않다. 토크나이저(tokenizer)에 따라 같은 바이트가 다른 수의 토큰이 되고, 구성요소 가중치와 에폭 수에 따라 문서를 여러 번 볼 수 있다. 그래서 “GPT-3와 비슷한 바이트 규모”만으로 같은 학습량이나 성능이 보장되지 않는다. 데이터 규모, 토큰 예산, 모델 크기, 컴퓨팅 예산과 최적화가 함께 성능을 결정한다.

### 4.3 큐레이션, 중복 제거와 문서화

The Pile은 출처마다 별도의 수집·정제 절차를 사용했고, Pile-CC에는 OpenWebText2를 양성 예시로 삼은 분류 필터를 적용했다. 코드와 LaTeX 같은 구조를 살리는 처리도 중요했다. 연구진은 문서 중복을 줄이기 위해 노력했지만, 원 논문은 학습·검증·시험 분할 사이에 같은 문서가 남았을 가능성을 명시했다. 따라서 “중복 제거를 적용했다”와 “완전히 중복이 없다”는 서로 다른 주장이다.

또한 연구진은 우려되는 모든 내용을 제거하기보다 일부는 분석하고 문서화해 사용자가 판단하도록 하는 방침을 택했다. 성별·종교·인종 표현의 공기 관계, 비속어, 저자 동의와 공개 자료 재사용을 조사했지만, 이는 편향이나 유해 자료를 제거했다는 뜻이 아니다. 데이터 문서화(data documentation)는 위험 완화의 출발점이지 자동 해결책이 아니다.

## 5. 원문의 논리 구조

원문은 대략 다음 흐름으로 전개됩니다.

1. 독점 학습 데이터가 공개 LLM 연구와 모델 비교를 가로막았다는 문제를 제기한다.
2. 22개 출처를 결합한 825GB 공개 데이터셋 The Pile을 해결책으로 소개한다.
3. 다양성, 표준 형식, 필터링, 중복 제거, 문서화와 라이선스 검토를 핵심 설계로 설명한다.
4. GPT-Neo·GPT-J, 재현 연구, 영역별 데이터 효과와 편향 연구에 미친 영향을 서술한다.
5. 품질 편차, 영어 중심 구성, 최신성, 법적 복잡성과 유지 관리 한계를 짚고 공개 데이터 문화의 유산을 전망한다.

이 서사를 읽을 때는 원 논문이 직접 보고한 **데이터 구성과 비교 실험**, 이후 모델·연구에서 확인된 **활용 사례**, “경쟁의 장을 평평하게 했다”와 같은 **사회적 평가**를 분리해야 한다.

## 6. 왜 중요한가

The Pile의 가장 중요한 변화는 데이터셋을 모델 학습 뒤에 숨는 보조 자원이 아니라 공개적으로 검토할 수 있는 연구 산출물로 만든 데 있다. 어떤 영역을 골랐고 어느 비율로 반복했는지 기록하면 모델 성능과 실패를 데이터 구성과 연결해 질문할 수 있다. 또한 같은 말뭉치를 사용하는 여러 모델은 데이터라는 큰 변수를 통제해 아키텍처와 학습 절차를 더 직접적으로 비교할 수 있다.

특히 중요한 점:

- 전문·학술·코드 자료를 의도적으로 섞어 Common Crawl 중심 모델의 영역 공백을 보완하려 했다.
- 구성 코드, 구성요소 통계와 우려 사항을 공개하여 외부 연구자가 데이터 혼합을 검사하고 변형할 수 있게 했다.
- GPT-Neo, GPT-J와 GPT-NeoX 같은 공개 모델 계열에 실제 학습 기반을 제공해 데이터 공개가 모델 공개와 연결되는 선례를 만들었다.

다만 동일한 데이터셋만으로 완전한 재현성이 생기지는 않는다. 토크나이저, 자료 순서, 난수 시드(seed), 옵티마이저(optimizer), 배치(batch) 구성, 컴퓨팅 정밀도와 체크포인트(checkpoint) 선택도 결과를 바꾼다. The Pile은 재현의 중요한 한 축을 공개했지만 전체 실험 조건을 자동으로 같게 만들지는 않는다.

## 7. 현대 LLM과의 연결

The Pile 이후 공개 LLM 연구는 모델 가중치뿐 아니라 학습 토큰, 혼합 비율, 필터, 중복 제거와 데이터 계보(data provenance)를 함께 공개하려는 방향으로 발전했다. 현대 데이터셋은 더 큰 규모와 더 많은 언어를 다루고, 품질 점수나 개인 정보·저작권 정책을 더 명시적으로 적용하는 경우가 많다.

- 컴퓨팅 최적 학습(compute-optimal training): Chinchilla 계열 스케일링 연구는 고정된 컴퓨팅에서 모델 크기뿐 아니라 충분한 학습 토큰이 중요함을 강조했다. 이는 825 GiB라는 저장 크기보다 실제 토큰 예산과 반복 정책을 보게 한다.
- 데이터 혼합과 영역 능력(data mixture and domain capability): 코드·수학·과학 자료의 비중은 해당 영역 성능을 바꿀 수 있다. 현대 모델도 사전 학습 혼합과 후반부 영역별 어닐링(annealing)을 설계 변수로 사용한다.
- 데이터 거버넌스(data governance): 구성요소의 출처, 권리, 동의, 삭제 요청과 개인 정보 처리는 모델 성능과 별개의 운영 요건이다. “웹에서 접근 가능함”은 “어떤 목적으로든 재사용 허용됨”과 같지 않다.
- 공개 평가와 감사(audit): 자료가 공개되면 데이터 오염(contamination), 암기, 편향과 출처별 성능을 외부에서 조사할 수 있다. 반대로 원문 텍스트를 대규모로 재배포하면 권리 침해와 민감 정보 노출 위험도 커질 수 있다.

이 계보는 The Pile의 구성을 그대로 유지해야 한다는 뜻이 아니다. 후속 공개 말뭉치는 The Pile이 보여 준 투명성을 계승하면서 언어 다양성, 라이선스 명확성, 중복 제거와 문서화를 개선하는 방향으로 설계될 수 있다.

## 8. 한계와 비판적 관점

원문은 The Pile의 법적 준수와 법적 명확성을 다소 강하게 표현한다. 실제로는 구성요소마다 원 자료의 라이선스와 이용 조건이 달랐고, Hugging Face 데이터셋 카드도 전체 라이선스를 단일 허용 라이선스가 아닌 `other`로 표시한다. Books3처럼 저작권 있는 도서의 제3자 수집본을 포함한 구성요소는 특히 공개 접근, 호스트(host)의 이용 조건, 저작권자의 허락을 서로 구분해 검토해야 한다. 큐레이션되었다는 말도 모든 문서가 수작업으로 검증되거나 동료 심사를 거쳤다는 뜻은 아니다. 예를 들어 arXiv에는 심사 전 논문이 포함되고, 웹·코드 구성요소에는 자동 필터의 판단이 적용되었다.

- 기술적 한계: 구성요소 간·분할 간 중복이 완전히 제거되지 않았을 수 있고, 품질 필터는 스팸을 줄이는 동시에 특정 문체·집단을 과도하게 배제할 수 있다.
- 이론적 한계: 특정 말뭉치에서 낮은 언어 모델링 손실(language-modeling loss)이 사실성, 안전성, 공정성 또는 일반적인 “이해”를 곧바로 의미하지 않는다.
- 실용적 한계: 825.18 GiB의 저장·전처리·학습에는 여전히 큰 인프라가 필요하며, 정적 자료이므로 최신 지식은 포함하지 못한다.
- 오늘날 관점에서 다시 봐야 할 점: 공개 데이터와 오픈 소스라는 이름만으로 상업적 재사용, 저자 동의나 모든 구성요소의 적법성이 일괄 보장되지는 않는다. 실제 사용자는 구성요소별 권리와 관할법을 검토해야 한다.

대표성도 제한적이다. The Pile은 명시적으로 영어 중심 말뭉치였고, 공개적으로 쉽게 구할 수 있는 과학·기술·인터넷 자료의 분포를 크게 반영했다. 따라서 여러 언어와 문화에 대한 균형 잡힌 세계 표본이라기보다, 특정 수집 경로와 큐레이터의 품질 판단이 만든 학습 분포다. 데이터의 다양성은 절대적 속성이 아니라 어떤 모집단과 비교하는지에 따라 달라진다.

## 9. 용어 정리

| 용어 | 설명 |
|---|---|
| The Pile | EleutherAI가 22개 영어 텍스트 구성요소를 결합해 공개한 825.18 GiB 규모의 언어 모델 학습·평가 말뭉치 |
| 구성요소(component) | Pile-CC, arXiv, GitHub, Books3처럼 서로 다른 출처와 처리 절차를 가진 하위 데이터셋 |
| 데이터 혼합(data mixture) | 여러 구성요소를 어떤 비율과 반복 횟수로 학습에 제시할지 정한 분포 |
| 가중치·에폭(epoch) | 일부 구성요소를 한 번보다 자주 표본화해 실제 학습 비중을 원시 크기와 다르게 만드는 설정 |
| 중복 제거(deduplication) | 같은 문서나 매우 비슷한 텍스트가 반복 학습·평가되지 않도록 찾아 제거하는 과정 |
| 데이터 계보(data provenance) | 텍스트가 어디서 왔고 어떤 수집·필터·변환과 권리 조건을 거쳤는지에 관한 기록 |
| GiB | $2^{30}$바이트를 뜻하는 이진 단위로, $10^9$바이트인 GB와 값이 다름 |

## 12. 짧은 결론

The Pile은 825.18 GiB의 영어 텍스트를 22개 출처에서 모은 것 자체보다, 구성과 가중치, 처리 코드, 영역별 통계와 우려 사항을 공개해 LLM 학습 데이터를 공동 검토의 대상으로 만든 점에서 중요한 이정표다. 이 자원은 GPT-Neo·GPT-J·GPT-NeoX 계열과 공개 데이터 연구를 촉진했지만, 크기만으로 GPT-3 재현을 보장하지 않았고 중복·편향·영어 중심성·저자 동의와 구성요소별 권리 문제도 남겼다. The Pile의 지속적인 교훈은 “공개된 큰 데이터”가 끝이 아니라, 출처·혼합·품질·권리·대표성을 함께 문서화하고 검증하는 데이터 거버넌스가 모델 개발의 핵심이라는 데 있다.
