# 에이전트형 AI 시스템의 추론·계획·도구 사용 해설

## 1. 한눈에 보기

- 핵심 주제: 언어 모델을 반복 실행하는 제어 루프에 목표, 상태, 도구, 메모리, 종료 조건과 안전 장치를 결합해 여러 단계의 일을 수행하는 시스템
- 등장 배경: 한 번의 프롬프트와 응답만으로는 검색, 파일 수정, 코드 실행처럼 관찰과 행동을 번갈아 해야 하는 과제를 끝내기 어려웠던 상황
- 가장 중요한 아이디어: 모델의 한 번짜리 답을 곧바로 실행하는 것이 아니라, `관찰 → 판단 → 허가된 행동 → 결과 확인 → 상태 갱신`을 제한된 횟수만큼 반복한다.
- 이후 LLM/NLP에 남긴 영향: 모델 자체의 점수뿐 아니라 실행 틀, 도구 권한, 상태 관리, 비용, 실패 복구와 사람의 감독을 하나의 시스템으로 평가하게 했다.

> 이 문서는 `104_Agentic AI Systems Autonomous Agents with Reasoning, Planning, and Tool Use.md`의 번역문을 이해하기 위한 해설입니다. 원문이 제시하는 일반 구조는 살리되, “2024년에 에이전트형 AI가 등장했다”는 연대와 자율성·학습·산업 채택에 관한 넓은 주장은 연구가 실제로 확인한 범위와 분리해 읽습니다.

## 2. 핵심 요약

에이전트형 AI 시스템(agentic AI system)은 대개 새로운 단일 모델이라기보다 언어 모델을 의사결정 구성 요소로 사용하는 **응용 시스템**이다. 시스템은 목표와 현재 상태를 모델에 제공하고, 모델이 답변·도구 호출·추가 질문 같은 다음 행동을 제안하면, 실행기가 권한과 형식을 검사한 뒤 행동을 수행하고 결과를 다시 관찰로 돌려준다. 계획은 목표를 하위 과제로 나누는 표현이며, 추론은 다음 행동을 고르는 계산 과정이고, 도구 사용은 외부 세계에 읽기나 쓰기 효과를 내는 별도의 실행 경계다. 메모리도 모델 안에 저절로 생기는 영속 기억이 아니라 대화 기록, 작업 상태, 데이터베이스와 검색기를 연결한 애플리케이션 계층인 경우가 대부분이다. 이 구조는 검색, 코딩, 데이터 처리처럼 중간 결과를 확인하며 고쳐야 하는 작업을 자동화할 가능성을 넓혔다. 그러나 한 단계의 오류가 다음 단계 입력이 되어 누적되고, 도구 호출에는 실제 부작용이 있으므로 신뢰성은 모델의 문장 생성 능력만으로 보장되지 않는다. 또한 2024년은 이 발상의 기원이 아니라 제품화와 평가가 빠르게 확산된 시기로 보는 편이 정확하다. ReAct, Toolformer, LangChain, Auto-GPT 같은 선행 연구와 구현은 2022–2023년에 이미 추론-행동 루프와 도구 연결을 구체화했다.

- 무엇을 다루는가: 목표 지향 제어 루프, 계획, 도구 호출, 상태·메모리, 피드백, 평가와 안전
- 어떤 문제를 해결하려 했는가: 여러 시스템을 오가며 중간 결과에 따라 다음 행동을 바꿔야 하는 일을 사람이 매번 프롬프트로 지휘해야 했던 문제
- 어떤 방식이 새로웠는가: LLM의 자연어 추론과 구조화된 도구 인터페이스를 반복 실행 런타임에 결합해 범용적인 디지털 작업 흐름을 만들었다.
- 결과적으로 무엇을 바꾸었는가: “모델이 답을 아는가?”에서 “시스템이 제한된 권한과 비용 안에서 목표를 재현 가능하고 안전하게 달성하는가?”로 평가 단위를 넓혔다.

## 3. 역사적 배경

목표를 가진 소프트웨어 에이전트, 계획기, 행동-관찰 루프는 LLM보다 수십 년 앞선 AI 연구 주제다. 고전적 에이전트 연구는 환경을 관찰하고 정책에 따라 행동하며 상태 변화에 대응하는 구조를 다뤘고, 로봇공학·강화학습·워크플로 자동화도 이미 계획, 실행, 피드백과 안전 제약을 연구해 왔다. 따라서 “수동적인 AI 도구에서 능동적인 에이전트로의 최초 전환”을 2024년의 단일 돌파구로 놓으면 긴 계보가 사라진다.

LLM 기반 계보에서는 몇 가지 흐름이 합쳐졌다. 2022년의 chain-of-thought prompting은 복잡한 문제를 중간 언어 단계로 풀어내는 방법을 널리 알렸지만, 그 자체로 외부 환경에 행동하지는 않았다. 2022년 10월 공개되고 ICLR 2023에 실린 [ReAct](https://openreview.net/forum?id=WE_vluYUL-X)는 언어적 추론 흔적과 과제별 행동을 번갈아 생성해 지식 질의와 ALFWorld·WebShop 같은 제한된 환경에서 계획을 갱신하는 방식을 실험했다. 이는 현대적인 에이전트 루프의 직접적인 선행 사례지만, 모든 업무에서 장기 계획을 안정적으로 수행한다는 증명은 아니다.

[Toolformer](https://proceedings.neurips.cc/paper_files/paper/2023/hash/d842425e4bf79ba039352da0f658a906-Abstract-Conference.html)는 NeurIPS 2023에서 소수의 시범을 바탕으로 계산기, 질의응답, 검색, 번역, 달력 등 다섯 종류의 API 호출을 학습 데이터에 삽입하고, 모델이 호출 시점·도구·인수를 고르게 하는 자기지도 학습을 보였다. 이 연구는 도구 선택을 모델 가중치에 학습시키는 근거이지, 영속 메모리나 범용 계획기, 임의 API에 대한 안전한 자율 실행을 함께 검증한 연구는 아니다.

개발 생태계도 2024년보다 앞섰다. [LangChain 저장소](https://github.com/langchain-ai/langchain)는 2022년 10월에 만들어져 모델, 검색기, 도구와 실행 단계를 조합하는 공통 인터페이스를 제공했고, [Auto-GPT 저장소](https://github.com/Significant-Gravitas/AutoGPT)는 2023년 3월에 공개되어 목표를 반복적으로 하위 과제로 나누고 도구를 호출하는 실험적 자율 에이전트를 대중에게 각인시켰다. 저장소의 존재와 인기는 구현·채택의 역사에는 중요한 자료지만, 연구 논문처럼 정확도나 안전성을 통제된 조건에서 입증하는 근거는 아니다.

2024년에는 AgentBench, WebArena, SWE-bench처럼 상호작용·웹·코딩 환경에서 긴 실행을 재현하려는 평가가 본격화되고, 상용 모델의 function calling 및 다양한 오케스트레이션 도구가 널리 결합되었다. 그러므로 2024년의 의미는 **발명**보다 **평가, 제품화와 생태계 확산**에 가깝다.

- 이전 접근법: 고전 계획·에이전트 아키텍처, 강화학습, 규칙 기반 워크플로, 단일 턴 LLM 호출
- 당시의 한계: LLM 응답과 실제 시스템 행동 사이의 연결, 장기 작업 상태, 오류 복구, 범용적인 도구 인터페이스가 응용마다 따로 구현됐다.
- 이 주제가 필요했던 이유: 언어로 주어진 목표를 실행 가능한 작은 행동으로 바꾸고, 각 결과를 관찰해 다음 행동을 수정하는 공통 런타임이 필요했다.

## 4. 핵심 개념 해설

### 4.1 에이전트 루프와 종료 조건

에이전트의 최소 단위는 한 번의 “생각”이 아니라 반복되는 상태 전이다. 목표를 $g$, 시점 $t$의 작업 상태를 $s_t$, 환경 관찰을 $o_t$라고 하면, 모델 또는 별도 제어기는 다음 행동 $a_t$를 제안하고 실행 결과로 새 관찰과 상태를 얻는다.

$$
a_t = \pi_\theta(g, s_t, o_t), \qquad s_{t+1} = U(s_t, a_t, o_{t+1})
$$

실제 시스템에서는 이 식 사이에 중요한 경계가 더 들어간다.

1. 사용자의 목표와 허용 범위를 명시한다.
2. 모델이 최종 답변, 추가 질문, 도구 호출, 중단 중 하나를 제안한다.
3. 정책 계층이 도구 이름, 인수 스키마, 자격 증명, 권한, 비용과 위험도를 검사한다.
4. 실행기가 격리된 환경에서 허가된 행동만 수행한다.
5. 도구의 성공·실패·부분 결과를 구조화된 관찰로 반환한다.
6. 작업 상태와 필요한 기록을 갱신한다.
7. 성공 조건, 실패 조건, 시간·토큰·비용 한도, 사람 승인 지점 중 하나에 닿으면 종료한다.

이 중 3·4·7단계는 언어 모델의 “추론 능력”이 아니라 시스템 설계다. 모델이 `send_email` 같은 문자열을 생성했다는 사실과 이메일이 실제로 발송되었다는 사실도 다르다. 실행 권한, 재시도와 중복 방지, 사용자 확인, 감사 로그가 있어야 텍스트 제안을 통제 가능한 행동으로 바꿀 수 있다.

### 4.2 계획, 추론과 도구 사용은 서로 다른 층이다

**계획**(planning)은 목표를 하위 목표와 행동 순서로 나타내고 선행 조건, 의존성, 자원과 실패 경로를 관리하는 일이다. 처음에 전체 계획을 세우는 방식도 있고, 매 관찰 뒤 다음 한두 단계만 다시 고르는 방식도 있다. 변하는 웹 페이지나 실패 가능한 API에서는 완성된 장기 계획을 고수하기보다 짧은 계획과 재계획을 결합하는 편이 현실적이다.

**추론**(reasoning)은 관찰과 목표에서 다음 판단을 도출하는 넓은 과정이다. Chain-of-thought 같은 출력은 모델이 중간 단계를 언어로 표현하게 해 성능을 높일 수 있지만, 그 문장이 내부 계산의 충실한 기록이나 정답의 증명이라고 가정할 수는 없다. 그럴듯한 설명과 실행 가능한 계획을 구분하려면 도구 결과, 형식 검사, 단위 테스트와 환경의 성공 조건이 필요하다.

**도구 사용**(tool use)은 외부 능력을 호출하는 인터페이스다. 모델에는 보통 함수 이름, 설명과 JSON 같은 인수 스키마가 주어지고, 실제 네트워크·파일·데이터베이스 접근은 별도 실행기가 맡는다. 검색처럼 읽기 전용인 도구와 결제·삭제·발송처럼 되돌리기 어려운 쓰기 도구는 같은 권한으로 취급하면 안 된다. 최소 권한, 허용 목록, 비밀 정보 분리, 입력·출력 검증, 타임아웃, 속도 제한과 고위험 행동의 사람 승인이 도구 계층의 핵심이다.

ReAct는 추론과 행동을 교대로 배치하는 한 가지 **제어 패턴**이고, Toolformer는 API 호출 표기를 학습 데이터와 다음 토큰 예측에 통합하는 한 가지 **학습 방법**이다. 둘을 모든 에이전트가 반드시 갖추는 단일 표준 아키텍처처럼 합치면 안 된다.

### 4.3 메모리, 자율성, 적응을 구분하기

에이전트의 “메모리”는 적어도 세 층으로 나뉜다.

- 단기 문맥: 현재 모델 호출에 포함된 최근 대화, 도구 결과와 scratchpad
- 작업 상태: 완료 단계, 열린 파일, 실패 횟수, 체크포인트와 승인 상태를 담는 상태 기계나 작업 그래프
- 장기 기억: 이후 실행에서 검색할 수 있도록 데이터베이스, 문서 저장소나 벡터 색인에 보존한 사실과 요약

모델의 문맥 창이 길다고 해서 영속 메모리가 생기는 것은 아니며, 외부 저장소가 있다고 해서 필요한 기억이 정확히 검색되는 것도 아니다. 오래되거나 잘못된 기록, 다른 사용자의 데이터 혼입, 검색 문서의 prompt injection과 개인정보 보존 기간을 별도로 관리해야 한다.

자율성도 이분법이 아니라 권한의 단계다. 시스템은 계획만 제안할 수도 있고, 모든 행동 전 승인을 받을 수도 있으며, 읽기 전용 도구만 자동 실행하거나, 제한된 sandbox 안에서 일정 시간 자율 루프를 돌 수도 있다. 무엇을 스스로 결정하는지, 어떤 자원에 접근하는지, 언제 사람에게 넘기는지를 함께 적어야 “자율 에이전트”라는 말이 의미를 가진다.

마지막으로 **적응**과 **학습**은 다르다. 같은 실행 안에서 실패 결과를 보고 계획을 바꾸는 것은 문맥 내 적응이다. 다음 실행을 위해 메모리를 저장하는 것은 상태 갱신이다. 모델 가중치를 바꾸는 온라인 학습이나 강화학습은 데이터 수집, 보상 정의, 훈련, 검증과 배포를 포함한 별도 파이프라인이다. 원문처럼 피드백 루프가 곧 경험을 통한 지속 학습을 보장한다고 쓰면 이 세 층이 섞인다.

## 5. 원문의 논리 구조

원문은 대략 다음 흐름으로 전개됩니다.

1. 2024년에 수동적 언어 모델에서 능동적 에이전트로 패러다임이 바뀌었다고 문제를 설정한다.
2. 단일 턴 모델에는 주도성, 외부 도구, 여러 단계의 계획, 영속 상태와 피드백 적응이 부족했다고 설명한다.
3. 추론 엔진, 계획 모듈, 도구 모듈, 메모리와 피드백 루프를 에이전트형 시스템의 해결책으로 제시한다.
4. 코딩, 연구, 개인 비서, 의료, 교육과 업무 자동화를 대표 응용으로 열거한다.
5. 오류 누적, 비용, 불확실한 적응, 평가와 안전 문제를 한계로 인정한 뒤 2024년을 장기적인 설계 전환점으로 평가한다.

이 흐름은 구성 요소를 익히는 개론으로는 유용하다. 다만 “구성 요소가 존재한다”에서 “사람 개입 없이 안정적으로 복잡한 목표를 달성했다”로 넘어가는 부분에는 구체적인 시스템, 실험 조건, 성공률과 배포 근거가 빠져 있다. 독자는 아키텍처 설명, 가능한 응용, 입증된 성능을 서로 다른 주장 층으로 읽어야 한다.

## 6. 왜 중요한가

에이전트형 접근이 중요한 까닭은 언어 모델의 출력 공간을 텍스트에서 **통제된 소프트웨어 행동**으로 넓혔기 때문이다. 검색 결과를 읽고, 코드를 고치고, 테스트 실패를 다시 관찰하는 작업은 한 번의 생성보다 반복적인 환경 상호작용에 가깝다. 에이전트 루프는 이 과정을 공통 구조로 만들고, 모델을 검색기·컴파일러·브라우저·데이터베이스 같은 결정론적 도구와 결합할 수 있게 한다.

또 하나의 변화는 실패 책임을 더 정확히 나누게 했다는 점이다. 최종 과제 실패는 기반 모델의 지식 부족뿐 아니라 잘못된 도구 설명, 검색 실패, 상태 손실, 권한 거부, 종료 판정, 환경 변화나 평가기의 오류에서 생길 수 있다. 따라서 모델 교체만으로 해결할 수 없는 시스템 공학 문제가 분명해졌다.

특히 중요한 점:

- 모델 능력과 실행 scaffold의 능력을 분리해 설계하고 비교하게 했다.
- 최종 답의 정확도 외에 경로 효율, 도구 오류, 비용, 부작용과 사람 개입 횟수를 평가 대상으로 만들었다.
- 권한, 감사, 중단, 복구와 승인 같은 운영 통제를 AI 제품의 중심 설계 문제로 끌어왔다.
- 사람은 반복 실행을 위임할 수 있지만, 목표와 성공 기준, 위험 허용 범위와 책임 주체를 더 명확히 정해야 한다.

## 7. 현대 LLM과의 연결

- **Chain-of-thought와 ReAct:** Chain-of-thought는 한 응답 안의 중간 언어 단계를, ReAct는 추론과 환경 행동의 교대를 강조한다. 현대 에이전트는 여기에 도구 결과의 구조화, 재시도 예산, checkpoint와 사람 승인 지점을 더한다.
- **Function calling과 structured outputs:** 모델이 자유 형식 문장 대신 도구 이름과 인수를 스키마에 맞춰 내도록 하면 파싱 오류를 줄일 수 있다. 그러나 스키마 적합성은 행동의 의미, 권한이나 안전성을 보증하지 않는다.
- **RAG와 메모리:** 검색 증강 생성은 외부 문서를 읽어 현재 판단을 보완하는 방법이고, 에이전트 메모리는 작업 상태와 과거 기록을 저장·검색하는 더 넓은 운영 개념이다. 둘 다 검색 품질과 출처 추적, prompt injection 방어가 필요하다.
- **RLHF·Constitutional AI와 런타임 통제:** 정렬 훈련은 모델이 유해한 요청을 거절하거나 지시를 따르는 경향을 바꿀 수 있다. 하지만 실제 파일 삭제나 송금 권한은 학습된 성향이 아니라 접근 제어, 정책 엔진과 사람 승인으로 제한해야 한다.
- **Auto-GPT와 LangChain:** 두 프로젝트는 반복 루프와 구성 요소 연결을 개발자에게 널리 보인 역사적 구현이다. 저장소의 인기나 기능 목록은 생태계 확산의 증거이지, 장기 자율 작업의 신뢰성·안전성에 대한 실험적 보증은 아니다.
- **Agent MLOps:** 모델·프롬프트·도구 스키마·정책 버전을 함께 기록하고, 실행 trace, 비용, 지연, 실패 원인과 부작용을 관측해야 한다. Canary 배포, 회귀 평가와 rollback도 필요하다. 이 운영 계층은 “추론 엔진+메모리+도구”라는 개념도에 자동으로 포함되지 않는다.

현재의 에이전트 제품은 흔히 완전 자율 시스템보다 **제한된 권한의 협업형 실행기**에 가깝다. 사람이 목표를 정하고 중요한 변경을 승인하며, 시스템은 검색·편집·검증 같은 반복 단계를 맡는 형태가 신뢰성과 효용의 균형을 잡기 쉽다.

## 8. 한계와 비판적 관점

원문의 가장 큰 문제는 역사, 기술 가능성, 시제품 시연과 안정적인 채택을 한 서사로 묶는다는 점이다. 다음 구분이 필요하다.

| 원문의 넓은 주장 | 근거에 맞춘 해석 |
|---|---|
| 에이전트형 AI가 2024년에 등장했다 | 고전 에이전트 연구는 훨씬 오래됐고, LLM 기반 ReAct·LangChain·Auto-GPT·Toolformer도 2022–2023년에 공개됐다. 2024년은 평가와 제품화가 두드러진 시기다. |
| 이전 LLM은 외부 시스템과 상호작용할 수 없었다 | 기반 모델 단독에는 실행 권한이 없지만, API·plugin·function calling과 별도 실행기를 붙인 시스템은 2024년 이전에도 가능했다. 이는 모델과 응용 scaffold의 경계다. |
| 피드백 루프가 경험으로부터 학습시킨다 | 결과를 다음 프롬프트에 넣어 재계획하는 것, 장기 메모리를 갱신하는 것, 가중치를 온라인 훈련하는 것은 서로 다른 메커니즘이다. |
| 코딩·연구·의료·교육에서 성공이 입증됐다 | 제한된 시연과 benchmark 성공은 가능성을 보이지만, 장기간의 실제 배포에서 정확성·안전성·책임을 일반적으로 입증하지는 않는다. 특히 연구 논문 제출이나 환자 관리의 전면 자율화 주장은 별도 근거가 필요하다. |
| 안전한 실행 환경이 자율 배포를 가능하게 했다 | Sandbox는 피해 범위를 줄이는 한 수단일 뿐이다. 네트워크, 비밀 정보, 사회공학, 권한 상승, 외부 부작용과 잘못된 목표까지 자동으로 해결하지 않는다. |

1차 자료가 확인한 범위도 제한적이다.

- [ReAct](https://openreview.net/forum?id=WE_vluYUL-X)는 지식 질의와 몇 개의 상호작용 환경에서 추론-행동 교대의 효과를 보였다. 임의의 업무 환경, 무제한 실행이나 고위험 행동의 안전성을 검증하지 않았다.
- [Toolformer](https://proceedings.neurips.cc/paper_files/paper/2023/hash/d842425e4bf79ba039352da0f658a906-Abstract-Conference.html)는 다섯 종류의 간단한 API에 대한 자기지도 도구 학습을 평가했다. 복합 워크플로 오케스트레이션, 영속 메모리나 접근 제어를 다룬 범용 에이전트 논문은 아니다.
- [WebArena](https://proceedings.iclr.cc/paper_files/paper/2024/hash/4410c0711e9154a7a2d26f9b3816d1ef-Abstract-Conference.html)는 재현 가능한 웹 환경을 만들었지만, 논문 당시 최고 GPT-4 기반 에이전트의 종단 간 성공률은 14.41%로 인간의 78.24%보다 크게 낮았다. 이는 2024년의 가능성과 함께 당시 신뢰성 격차도 보여 준다.
- [AgentBench](https://openreview.net/forum?id=zAdUB0aCTQ)는 여덟 환경에서 LLM을 에이전트로 평가하고 모델 간 큰 성능 차이를 보고했다. 특정 scaffold와 환경에서 얻은 점수를 “일반 자율성” 하나의 수치로 볼 수는 없다.
- [SWE-bench](https://openreview.net/forum?id=VTF8yNQM66)는 실제 GitHub 이슈와 테스트를 사용해 코딩 과제를 더 현실적으로 만들었고, 초기 논문은 강한 모델도 대부분의 이슈를 해결하지 못했음을 보였다. “복잡한 기능을 최소 개입으로 구현했다”는 일반화보다 훨씬 좁고 엄격한 근거다.
- Auto-GPT와 LangChain의 공식 저장소는 기능과 공개 시점을 확인하는 1차 자료다. 그러나 공개 저장소의 별 수, 다운로드나 사례 소개는 통제 실험의 성공률, 안전성 또는 산업 전반의 채택률을 대신하지 못한다.

- 기술적 한계: 장기 실행에서 오류가 누적되고, 환경 관찰이 불완전하며, tool output이나 웹 콘텐츠를 통한 prompt injection, 잘못된 인수, 중복 실행, 상태 손실과 무한 루프가 생길 수 있다.
- 이론적 한계: 자연어로 그럴듯한 계획을 출력하는 능력과 미래 상태를 정확히 예측하는 계획 능력은 같지 않다. “주도성”이나 “의도” 같은 인간적 표현은 실제 정책과 권한을 가릴 수 있다.
- 실용적 한계: 여러 번의 모델 호출과 도구 왕복은 지연과 비용을 키운다. 인증, 개인정보, 감사, 법적 책임, 사람 승인, rollback과 장애 대응까지 구축해야 한다.
- 오늘날 관점에서 다시 봐야 할 점: 모델 점수 하나가 아니라 목표 달성률, 제약 위반, 위험한 부작용, 사람 개입, 실행 비용·시간, 여러 seed에서의 변동과 환경 버전을 함께 보고해야 한다.

## 9. 용어 정리

| 용어 | 설명 |
|---|---|
| 에이전트형 AI 시스템 | 목표와 상태를 유지하며 모델 호출, 도구 실행과 관찰을 반복하는 전체 응용 시스템 |
| 에이전트 루프 | 관찰에서 행동을 고르고 결과로 상태를 갱신해 종료 조건까지 반복하는 제어 흐름 |
| 계획 | 목표를 하위 목표·행동·의존성과 성공 조건으로 조직하는 표현 또는 과정 |
| 추론 | 현재 목표와 관찰에서 다음 판단을 도출하는 과정. 출력된 설명이 내부 계산의 충실한 증거라는 뜻은 아니다. |
| 도구 호출 | 모델이 구조화된 이름과 인수를 제안하고, 별도 실행기가 API·검색·코드·파일 작업을 수행하는 방식 |
| 관찰 | 도구나 환경이 돌려준 결과, 오류, 상태 변화. 다음 모델 호출의 입력이 된다. |
| 작업 상태 | 완료 단계, 산출물, 실패 횟수, 승인과 체크포인트 등 실행을 이어 가는 구조화된 기록 |
| 영속 메모리 | 실행 사이에 보존하고 검색하는 외부 저장소. 모델 가중치나 문맥 창과는 다르다. |
| 자율성 예산 | 자동 실행을 허용하는 시간, 단계, 비용, 권한과 위험의 한도 |
| Human-in-the-loop | 고위험 행동, 모호한 목표나 예외에서 사람이 승인·수정·중단하는 운영 방식 |
| Sandbox | 코드나 도구의 접근 범위를 격리하는 실행 환경. 모든 외부 부작용을 막는 완전한 안전 보장은 아니다. |
| Agent MLOps | 모델뿐 아니라 프롬프트, 도구, 정책, 상태와 실행 trace를 버전 관리·평가·관측·배포하는 운영 체계 |

## 12. 짧은 결론

에이전트형 AI의 역사적 의미는 LLM이 갑자기 독립적인 행위자가 되었다는 데 있지 않다. 언어 모델의 판단을 상태 기계, 검색, 도구 실행, 메모리, 검증과 사람의 통제에 연결하면서 AI 응용의 단위가 한 번의 응답에서 긴 작업 흐름으로 확장됐다는 데 있다. ReAct와 Toolformer가 보여 준 제한된 연구 결과, LangChain과 Auto-GPT가 보여 준 구현 생태계, 2024년 benchmark가 드러낸 가능성과 낮은 신뢰성을 함께 봐야 이 변화의 규모를 정확히 이해할 수 있다. 현대의 실용적인 에이전트는 무제한 자율성보다 명시된 목표, 최소 권한, 관측 가능한 실행, 제한된 예산, 검증 가능한 성공 조건과 적절한 사람 감독을 갖춘 시스템에 가깝다.
