# 지속적 모델 갱신의 학습·편집·검색 경계 해설

## 1. 한눈에 보기

- 핵심 주제: 배포된 언어 모델을 새 데이터와 피드백에 맞춰 갱신할 때, 가중치 학습·국소 편집·외부 검색·배포 운영이 맡는 역할을 구분하는 법
- 등장 배경: 모델의 지식 시점은 고정되지만 세계와 사용자 요구는 계속 바뀌고, 매번 처음부터 사전 학습하기에는 계산·검증 비용이 큰 상황
- 가장 중요한 아이디어: “지속적 포스트트레이닝”은 하나의 표준 알고리즘이 아니라 연속 사전 학습, 지속 학습, PEFT, 모델 편집, RAG와 MLOps를 묶어 부르는 운영적 관점에 가깝다.
- 이후 LLM/NLP에 남긴 영향: 무엇을 갱신하려는지 먼저 분류하고, 새 지식의 습득뿐 아니라 기존 능력 보존·출처 추적·회귀 검사·롤백까지 하나의 갱신 주기로 평가하게 했다.

> 이 문서는 **102_Continuous Post-Training Incremental Model Updates for Dynamic Language Models.md**의 번역문을 이해하기 위한 해설입니다. 원문은 2025년에 “지속적 포스트트레이닝”이 새 패러다임으로 등장했다고 서술하지만, 그 구성 요소인 지속 학습, 재현 학습, 도메인 적응, LoRA, 모델 편집과 검색 증강은 대부분 더 일찍 연구됐습니다. 따라서 여기서는 원문의 문제의식은 살리되, 서로 다른 기술과 운영 절차를 하나의 방법처럼 읽지 않도록 경계를 복원합니다.

## 2. 핵심 요약

언어 모델은 학습이 끝난 시점 이후의 사건과 문서를 가중치 안에 자동으로 흡수하지 못하며, 배포 중 발견된 오류나 새로운 요구도 별도 절차 없이는 반영하지 못한다. 원문은 이 문제를 해결하기 위해 새 데이터와 피드백으로 모델을 조금씩 갱신하고, 이전 능력을 보존하며, 검증 뒤 배포하는 반복 주기를 제시한다. 이 문제 설정은 타당하지만 “지속적 포스트트레이닝”을 단일한 2025년 발명으로 보는 설명은 지나치게 단순하다. 넓은 말뭉치의 분포를 새로 익히는 연속 사전 학습, 순차 학습에서 망각을 줄이는 지속 학습, 행동을 바꾸는 instruction tuning과 선호도 학습, 적은 매개변수만 갱신하는 LoRA 계열, 특정 사실을 고치는 모델 편집, 최신 문서를 실행 시점에 가져오는 RAG는 서로 다른 문제를 푼다. LoRA는 학습하고 저장할 매개변수를 줄여 주지만, 새 사실의 정확한 저장이나 파국적 망각 방지를 자동으로 보장하지 않는다. EWC·replay 같은 지속 학습 기법도 안정성과 가소성 사이의 절충을 완전히 없애지 못한다. A/B 시험, 버전 관리와 롤백은 갱신을 안전하게 운영하는 장치이지 모델이 무엇을 학습했는지를 보장하는 학습 알고리즘은 아니다. 결국 지속 갱신의 핵심은 하나의 기법을 반복 적용하는 것이 아니라 **갱신 대상에 맞는 수단을 고르고, 새 능력과 기존 능력을 함께 검증하며, 변경 이력을 추적하는 것**이다.

- 무엇을 다루는가: 시간이 흐르며 생기는 지식 노후화, 행동 수정 요구와 배포 피드백을 모델 또는 외부 지식 시스템에 반영하는 방법
- 어떤 문제를 해결하려 했는가: 전체 재학습의 비용을 줄이면서 새 정보와 개선 사항을 더 자주 반영하고, 이전 능력의 회귀를 억제하는 문제
- 어떤 방식이 새로웠는가: 원문은 PEFT·망각 완화·선별 데이터·평가·버전 관리를 하나의 반복적 운영 주기로 묶는다.
- 결과적으로 무엇을 바꾸었는가: 모델 갱신을 일회성 학습 이벤트가 아니라 데이터 수집, 학습 또는 검색, 회귀 검사, 배포와 감사가 이어지는 수명주기 문제로 보게 한다.

## 3. 역사적 배경

지속 갱신의 역사는 2025년에 시작되지 않는다. 순차적으로 새 과제를 학습할 때 과거 과제의 성능이 떨어지는 **파국적 망각**(catastrophic forgetting)은 신경망 연구의 오래된 문제다. 2017년의 Elastic Weight Consolidation, 즉 EWC는 이전 과제에 중요하다고 추정한 매개변수가 크게 움직이지 않도록 벌점을 주는 대표적 접근이었다. 다만 EWC의 초기 실험은 작은 분류·강화학습 환경을 중심으로 했으므로, 이를 현대 LLM의 보편적 갱신 해법으로 곧바로 확대할 수는 없다.

언어 모델 분야에서는 2020년의 domain-adaptive pretraining과 task-adaptive pretraining이 이미 사전 학습된 모델을 새 도메인 또는 과제 말뭉치에서 같은 언어 모델링 목표로 더 학습하는 전략을 체계화했다. 2022년의 TimeLMs는 시간 순서대로 늘어나는 Twitter 자료를 이용해 언어 모델을 갱신했고, 같은 해의 continual knowledge learning 연구는 변화하는 지식을 순차적으로 익히면서 과거 지식의 손실을 측정하는 문제를 명시했다. 이 계보는 시간 변화에 대한 모델 갱신 역시 원문이 제시한 2025년보다 앞서 존재했음을 보여 준다.

한편 LoRA는 2021년에 공개돼 전체 가중치를 바꾸지 않고 저순위 업데이트만 학습하는 길을 넓혔고, MEND 같은 2022년 모델 편집 연구는 특정 입력과 출력의 연결을 빠르게 수정하려 했다. RAG는 2020년부터 가중치를 다시 학습하지 않고 외부 문서를 검색해 답변 근거를 공급하는 별도의 해법을 제시했다. 2024년에는 학습률 재가열과 재감쇠, 이전 데이터 replay를 조합해 LLM의 연속 사전 학습 비용을 줄이려는 연구도 나왔다. 그러므로 2025년의 의미는 단일 기법의 탄생보다, 이미 존재하던 학습·편집·검색·운영 수단을 “계속 갱신되는 모델 서비스”라는 관점에서 함께 보려는 요구가 커졌다는 데 있다.

- 이전 접근법: 주기적 전체 재학습, 도메인 적응 사전 학습, 과제별 미세 조정, 검색 기반 지식 공급
- 당시의 한계: 계산 비용, 새 분포와 과거 분포 사이의 간섭, 수정 효과의 국소성 부족, 배포 버전과 평가 이력 관리 부담
- 이 주제가 필요했던 이유: 최신성·행동 교정·도메인 적응·안전 개선은 서로 다른 갱신을 요구하지만 실제 서비스에서는 하나의 관리 주기 안에서 조정해야 하기 때문

## 4. 핵심 개념 해설

### 4.1 연속 사전 학습, 지속 학습, 현대적 포스트트레이닝

**연속 사전 학습**(continued pretraining)은 이미 학습된 언어 모델을 새 말뭉치에서 언어 모델링 목표로 더 학습하는 절차다. 특정 분야의 문체와 어휘를 익히는 domain-adaptive pretraining, 시간순으로 도착하는 자료를 반영하는 continual pretraining이 여기에 속할 수 있다. 전체 가중치를 갱신할 수도 있고 PEFT를 사용할 수도 있으므로, “연속”은 데이터와 학습 순서를, “PEFT”는 어느 매개변수를 학습하는지를 가리키는 서로 다른 축이다.

**지속 학습**(continual learning)은 데이터나 과제가 순차적으로 바뀔 때 새 정보를 학습하는 가소성과 과거 능력을 보존하는 안정성을 함께 다루는 연구 문제다. Replay는 새 자료와 과거 자료 일부를 섞고, regularization은 중요한 가중치의 변화를 제한하며, 모듈 분리는 과제나 도메인별 간섭을 줄이려 한다. 어느 방법도 망각을 완전히 제거하지 않으므로 새 구간의 성능과 과거 구간의 성능을 동시에 측정해야 한다.

오늘날 **포스트트레이닝**(post-training)은 대개 사전 학습 뒤의 supervised fine-tuning, instruction tuning, 선호도 최적화, RLHF와 안전 조정을 포괄한다. 이는 모델이 요청을 따르고 바람직한 방식으로 응답하도록 행동을 조정하는 목적이 강하다. 최신 세계 지식을 계속 주입하는 연속 사전 학습과 겹칠 수는 있지만 같은 개념은 아니다. 따라서 “지속적 포스트트레이닝”이라는 표현을 쓸 때는 이번 주기가 지식 분포, 과제 능력, 응답 정책 가운데 무엇을 바꾸는지 명시해야 한다.

### 4.2 PEFT와 모델 편집

LoRA 같은 **매개변수 효율적 미세 조정**(PEFT)은 기본 가중치를 동결하고 작은 업데이트만 학습한다. 이는 trainable parameter, optimizer state와 저장 크기를 줄이고, 여러 용도의 adapter를 분리해 관리하는 데 유리하다. 그러나 계산량을 줄인다는 사실만으로 새 지식이 정확히 저장되거나 과거 능력이 유지되는 것은 아니다. Adapter를 차례로 쌓거나 병합할 때도 업데이트가 충돌할 수 있으며, 평가하지 않은 영역의 회귀는 남는다.

**모델 편집**(model editing)은 특정 사실이나 입력–출력 관계를 좁게 바꾸려는 접근이다. 넓은 도메인 자료를 다시 학습하는 것보다 표적이 분명하지만, 수정이 바꿔야 할 표현까지 일반화되는지, 무관한 답변은 그대로 유지되는지, 여러 편집을 반복해도 성능이 버티는지를 따로 검증해야 한다. “프랑스 대통령은 누구인가” 같은 사실 하나를 고치는 일과 의료 문헌 전체의 분포를 익히는 일은 같은 갱신 문제가 아니다.

### 4.3 RAG와 배포 운영

**검색 증강 생성**(RAG)은 최신 문서나 조직 내부 자료를 실행 시점에 검색해 prompt의 근거로 넣는다. 모델 가중치에 정보를 암기시키지 않기 때문에 자료를 빠르게 교체하고 출처를 제시하기 쉽다. 반면 검색 누락, 잘못된 문서, 문맥 해석 실패와 긴급한 접근 권한 관리 같은 별도 오류가 생긴다. 자주 변하고 근거 추적이 중요한 사실에는 RAG가 유리할 수 있고, 넓은 언어 능력이나 응답 습관을 바꾸려면 학습이 더 적합할 수 있다.

버전 관리, canary 배포, A/B 시험, 회귀 검사와 롤백은 **MLOps 안전장치**다. 이들은 어떤 가중치 갱신법과도 결합할 수 있으며 문제가 생겼을 때 영향 범위를 제한한다. 다만 롤백 가능하다고 해서 새 모델이 과거 능력을 보존했다는 뜻은 아니다. 학습 방법의 품질과 배포 절차의 안전성은 각각 증거를 갖춰 평가해야 한다.

## 5. 원문의 논리 구조

원문은 대략 다음 흐름으로 전개됩니다.

1. **문제 제기**: 배포된 모델의 지식과 행동은 학습 시점에 고정되며, 전체 재학습은 느리고 비싸다고 설명한다.
2. **핵심 아이디어**: 새 데이터와 사용자 피드백을 작은 주기로 반영하고 이전 지식을 보존하는 “지속적 포스트트레이닝”을 제시한다.
3. **방법 또는 구조**: LoRA 중심의 PEFT, EWC·replay·분리 adapter, 선별 데이터, 회귀 평가, update scheduling을 하나의 학습 절차로 묶는다.
4. **결과 또는 주장**: 더 빠르고 저렴한 갱신이 최신 정보, 사용자 피드백과 전문 도메인 적응에 활용될 수 있다고 주장한다.
5. **의의와 한계**: 누적 adapter의 복잡성, 회귀와 편향, 큰 분포 변화, 운영 인프라·버전 문제를 인정하면서 장기적으로 적응하는 AI를 전망한다.

이 흐름은 갱신 수명주기를 전체적으로 보는 데 유용하다. 다만 연구에서 직접 입증된 개별 기법, 여러 기법을 조합한 권장 절차, 특정 기업과 산업이 실제로 채택했다는 배포 주장이 한 층에 섞여 있다. 특히 평가·버전 관리·롤백은 중요한 운영 요소지만 PEFT나 지속 학습의 “핵심 기술 혁신”으로 분류해서는 안 된다.

## 6. 왜 중요한가

이 주제의 가치는 “모델도 자주 업데이트할 수 있다”는 당연한 명제보다, **업데이트의 종류를 잘못 고르면 비용은 줄어도 원하는 변화는 얻지 못한다**는 점을 드러내는 데 있다. 최신 사실을 답하게 하려는 요구, 사내 문체를 따르게 하려는 요구, 유해 응답을 줄이려는 요구, 특정 오류 하나를 고치려는 요구는 각각 다른 데이터·목표 함수·검증 지표를 요구한다.

특히 중요한 점:

- **안정성–가소성 절충을 측정하게 한다.** 새 자료에서 점수가 오른 것만으로는 부족하며, 이전 과제·언어·안전 행동과 일반 능력의 회귀를 함께 확인해야 한다.
- **지식의 위치를 설계하게 한다.** 오래 유지될 일반 능력은 가중치 학습, 자주 변하고 출처가 필요한 사실은 검색, 좁은 오류는 편집처럼 변화 속도와 감사 가능성에 맞춰 저장 위치를 고를 수 있다.
- **학습과 운영을 연결한다.** 어떤 데이터와 코드로 만든 버전인지, 어떤 평가를 통과했고 어느 사용자에게 배포됐는지, 문제가 생기면 무엇으로 되돌릴지를 함께 기록해야 갱신이 재현 가능해진다.

이 관점은 계산 효율성도 더 정확하게 읽게 한다. Adapter 파일이 작다는 사실은 전체 학습 시간, 데이터 큐레이션 비용, 평가 비용이나 서비스 인프라가 같은 비율로 줄었다는 뜻이 아니다. 지속 갱신의 실제 비용은 학습뿐 아니라 과거 능력을 다시 확인하는 회귀 평가와 운영 감사까지 포함한다.

## 7. 현대 LLM과의 연결

- **연속 사전 학습과 DAPT**: 새 도메인의 어휘·문체·분포를 넓게 익히는 데 적합하다. 전체 또는 일부 가중치를 바꿀 수 있지만, 데이터 혼합과 학습률을 잘못 정하면 과거 도메인의 성능이 떨어질 수 있다.
- **Instruction tuning과 RLHF**: 사용자의 지시를 따르는 방식, 선호되는 응답 형식과 안전 정책처럼 행동을 조정한다. 최신 사실을 정확히 암기시키는 방법과는 목적과 평가가 다르다.
- **LoRA와 adapter**: 학습 가능한 매개변수와 버전별 저장 부담을 줄여 짧은 실험 주기를 돕는다. 그러나 여러 adapter의 조합, base model 호환성, 병합 후 회귀를 관리해야 한다.
- **모델 편집**: 좁은 사실 또는 행동을 표적으로 삼을 수 있지만 locality, paraphrase에 대한 generalization, 반복 편집의 누적 손상을 검증해야 한다.
- **RAG와 tool use**: 빠르게 바뀌는 문서·데이터베이스·API를 모델 밖에 두고 필요할 때 조회한다. 최신성과 출처 추적에는 유리하지만 retrieval quality와 access control이 새 병목이 된다.
- **평가와 MLOps**: 자동 benchmark, 사람 평가, canary 배포, versioning과 rollback은 어느 갱신법이든 안전하게 운영하기 위한 공통 층이다.

실제 시스템은 이 수단을 조합한다. 예를 들어 기본 모델은 연속 사전 학습으로 도메인 언어를 익히고, instruction tuning으로 응답 행동을 맞추며, RAG로 최신 규정과 문서를 제공할 수 있다. 중요한 것은 이 조합을 모두 “모델이 계속 학습한다”는 한 문장으로 뭉개지 않고 각 층의 실패 원인과 책임 범위를 분리하는 것이다.

## 8. 한계와 비판적 관점

- **역사적 과장**: 지속 학습, EWC, 도메인 적응, 시간순 언어 모델 갱신, LoRA, RAG와 모델 편집은 모두 2025년 이전에 연구됐다. 원문의 “2025년에 등장한 패러다임”은 새 알고리즘의 최초성보다 여러 실천을 묶은 시대적 표어로 제한해 읽어야 한다.
- **미세 조정과 재학습의 혼동**: 전통적 fine-tuning이 언제나 “갱신 데이터 전체로 완전 재학습”을 요구하는 것은 아니다. 새 checkpoint는 서비스 중인 이전 checkpoint와 병행해 학습·검증할 수 있으므로 학습 동안 모델 서비스가 반드시 중단된다는 주장도 일반화할 수 없다.
- **기업 배포 근거 부족**: 원문은 OpenAI, Anthropic, Google DeepMind와 여러 산업이 지속적 포스트트레이닝을 사용한다고 서술하지만 구체적인 시스템, 논문, 모델 버전과 운영 결과를 제시하지 않는다. 탐색·관심과 실제 대규모 채택은 구분해야 한다.
- **LoRA의 역할 과대평가**: PEFT는 업데이트 비용을 줄이는 매개변수화다. 망각 방지, 사실의 정확한 삽입, 서로 다른 adapter의 무충돌 결합은 별도의 증거가 필요하다.
- **EWC와 replay의 적용 범위**: 작은 모델이나 제한된 과제에서 효과를 보인 방법이 거대한 생성 모델의 긴 학습 연쇄에서도 같은 효과를 낸다고 보장할 수 없다. Replay는 과거 데이터의 보관 비용, 개인정보와 저작권 문제도 동반한다.
- **최신성과 진실성의 차이**: 최근 자료를 학습했다고 해서 사실성이 보장되지는 않는다. 잘못된 최신 문서를 학습하면 오류도 내재화되며, 가중치에 저장된 사실은 출처를 감사하고 되돌리기 어렵다.
- **누적 업데이트의 복잡성**: 순차 adapter, 병합, regularization term과 데이터 버전이 늘어나면 어느 변경이 회귀를 만들었는지 추적하기 어려워진다. 작은 업데이트가 많다고 항상 하나의 큰 재학습보다 안전한 것은 아니다.
- **평가의 불완전성**: 새 과제 정확도뿐 아니라 과거 능력, 시간 순서 밖의 일반화, 편집의 locality, 안전·편향, calibration, retrieval 실패와 배포 지연을 함께 측정해야 한다.

오늘날의 더 정확한 결론은 “지속적 포스트트레이닝이 모든 최신성 문제를 해결한다”가 아니다. 갱신하려는 대상과 변화 속도, 근거 추적 필요성, 허용 가능한 회귀와 비용을 기준으로 학습·편집·검색·운영 수단을 선택해야 한다.

## 9. 용어 정리

| 용어 | 설명 |
|---|---|
| 연속 사전 학습 | 사전 학습된 모델을 새 도메인·시점의 말뭉치에서 언어 모델링 목표로 더 학습하는 절차 |
| 지속 학습 | 순차적으로 도착하는 데이터나 과제를 배우면서 과거 능력의 손실을 줄이는 연구 문제 |
| 포스트트레이닝 | 사전 학습 뒤 instruction following, preference alignment, safety와 과제 적응 등을 위해 수행하는 학습 단계 |
| 안정성–가소성 절충 | 기존 지식을 보존하는 안정성과 새 지식을 빠르게 습득하는 가소성 사이의 긴장 |
| 파국적 망각 | 새 데이터 학습 뒤 이전 데이터나 과제의 성능이 크게 떨어지는 현상 |
| Replay | 새 학습 때 과거 데이터 일부를 다시 섞어 망각을 줄이는 방법 |
| EWC | 이전 과제에 중요하다고 추정한 매개변수의 큰 변화를 벌점으로 제한하는 regularization 방법 |
| PEFT | 전체 가중치 대신 일부 또는 새로 추가한 작은 매개변수 집합을 학습하는 방법군 |
| 모델 편집 | 특정 사실이나 입력–출력 관계를 표적으로 삼아 모델 행동을 국소적으로 수정하는 접근 |
| RAG | 외부 문서를 검색해 실행 시점의 입력 문맥에 넣는 방식. 모델 가중치를 바꾸지 않는다. |
| 회귀 검사 | 새 버전이 기존 능력·안전성·품질을 떨어뜨리지 않았는지 이전 평가와 비교하는 절차 |
| 롤백 | 배포된 갱신에 문제가 있을 때 검증된 이전 모델 또는 구성으로 되돌리는 운영 절차 |

## 12. 짧은 결론

지속적 모델 갱신은 2025년에 갑자기 등장한 하나의 기술이라기보다, 오래된 지속 학습 문제와 최근의 LLM 적응·검색·배포 운영이 만나는 설계 영역이다. 연속 사전 학습은 넓은 분포를, instruction tuning과 선호도 학습은 행동을, 모델 편집은 좁은 수정을, RAG는 빠르게 변하는 외부 지식을 주로 담당한다. PEFT는 이 가운데 일부 학습의 매개변수 비용을 낮추지만 망각과 정확성을 자동으로 해결하지 않는다. 좋은 지속 갱신 체계는 방법 이름보다 **무엇을 어디에 갱신했는지, 무엇을 보존해야 하는지, 어떤 근거로 검증하고 되돌릴 수 있는지**를 명확히 기록하는 체계다.
