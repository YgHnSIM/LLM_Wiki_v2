# BLOOM과 BigScience의 개방형 다국어 LLM 해설

## 1. 한눈에 보기

- 핵심 주제: BigScience 협업이 2022년에 공개한 1,760억 매개변수 다국어 언어 모델 BLOOM과 그 개발·공개 방식
- 등장 배경: 초거대 언어 모델의 가중치와 개발 정보가 소수 기업에 집중되면서 재현, 감사, 독립 연구가 어려워진 상황
- 가장 중요한 아이디어: 대규모 국제 협업, 다국어 말뭉치 ROOTS, 공개 가중치와 개발 기록을 결합해 초거대 모델 연구의 접근 범위를 넓힌 것
- 이후 LLM/NLP에 남긴 영향: 모델 카드·데이터 거버넌스·책임 있는 공개를 모델 성능과 함께 논의하는 대표 사례를 제공한 것

> 이 문서는 `082_BLOOM Open-Access Multilingual Language Model and the Democratization of AI Research.md`의 번역문을 이해하기 위한 해설입니다. 원문을 반복하기보다 개념적 배경, 역사적 의미, 현대적 연결점과 후속 검증 과제를 정리합니다.

## 2. 핵심 요약

BLOOM은 BigScience라는 국제 협업이 프랑스의 Jean Zay 슈퍼컴퓨터를 이용해 훈련한 1,760억 매개변수의 디코더 전용 Transformer 언어 모델이다. 영어 중심의 초거대 모델 생태계를 넓히기 위해 ROOTS 말뭉치에 여러 자연어와 프로그래밍 언어를 포함했고, 모델 가중치와 학습 코드, 개발 문서를 연구 공동체에 공개했다. 이 작업의 역사적 의미는 단지 큰 모델 하나를 만든 데 있지 않고, 데이터 선정·거버넌스·환경 비용·모델 위험까지 공동으로 문서화하려 한 과정에 있다. 다만 `open-access`는 아무 제한도 없는 `open source`와 같지 않으며, BLOOM의 배포에는 용도 제한을 둔 책임 있는 AI 라이선스가 적용됐다. 가중치에 접근할 수 있다는 사실도 모델을 직접 실행하거나 미세 조정할 계산 자원까지 공평하게 제공한다는 뜻은 아니다. 또한 46개 자연어를 학습했다는 사실은 모든 언어에서 같은 품질을 달성했거나 언어 편향을 해소했다는 증거가 아니다. 따라서 원문의 ‘민주화’는 완결된 성과라기보다 독립적인 조사와 실험의 문턱을 일부 낮춘 시도로 읽는 편이 정확하다.

- 무엇을 다루는가: BLOOM의 개발 배경, 다국어 훈련, 공개 방식, BigScience 협업 모델
- 어떤 문제를 해결하려 했는가: 초거대 모델에 대한 접근과 의사 결정이 소수 기업에 집중된 문제
- 어떤 방식이 새로웠는가: 천 명 규모의 국제 연구 협업이 데이터와 훈련, 윤리·법적 쟁점을 함께 설계하고 기록한 방식
- 결과적으로 무엇을 바꾸었는가: 초거대 LLM의 가중치 공개와 책임 있는 배포를 둘러싼 실증적 사례를 제공했지만, 접근 불평등 자체를 없애지는 못했다.

## 3. 역사적 배경

2020년대 초 언어 모델의 성능은 매개변수, 데이터, 계산량을 크게 늘리는 방향으로 발전했다. GPT-3 같은 모델은 규모의 효과를 보여 주었지만, 일반 연구자가 가중치와 전체 학습 과정을 조사하기 어려운 서비스형 접근이 중심이었다. 이 때문에 결과를 재현하거나 모델 내부를 감사하고, 특정 언어나 위험을 독립적으로 평가하는 일에는 구조적인 제약이 따랐다.

BigScience는 이런 조건에서 출발한 약 1년짜리 공개 연구 워크숍이었다. 참여자들은 모델 구조만 정한 것이 아니라 어떤 데이터를 포함할지, 데이터 제공자의 권리를 어떻게 다룰지, 모델을 어떤 조건으로 배포할지, 대규모 훈련의 사회·환경 영향을 어떻게 기록할지를 여러 작업반에서 논의했다. BLOOM은 이 협업의 산출물이며, 공공 슈퍼컴퓨팅 자원을 이용해 기업 밖에서도 1,000억 매개변수급 모델을 만들 수 있음을 보여 준 사례다. 동시에 그런 실험조차 대규모 국가 인프라 없이는 어려웠다는 점은 개방성과 자원 집중의 긴장을 드러낸다.

- 이전 접근법: 영어 비중이 높은 데이터로 학습한 폐쇄형 또는 API 중심 초거대 모델
- 당시의 한계: 가중치·훈련 정보 접근 제한, 독립 재현과 감사의 어려움, 낮은 자원 언어의 부족한 대표성
- 이 주제가 필요했던 이유: 모델 연구에 참여할 수 있는 기관과 언어 공동체의 범위를 넓히고 공개 과정 자체를 연구 대상으로 삼을 필요가 있었기 때문

## 4. 핵심 개념 해설

### 4.1 BLOOM과 디코더 전용 Transformer

BLOOM(BigScience Large Open-science Open-access Multilingual Language Model)은 앞에 주어진 토큰을 바탕으로 다음 토큰을 예측하는 자기회귀(autoregressive) 언어 모델이다. 구조적으로는 GPT 계열과 같은 디코더 전용 Transformer에 속한다. 1,760억이라는 수치는 모델이 학습으로 조정하는 매개변수의 수이며, 그 자체가 이해력이나 신뢰성을 보증하지는 않는다. 규모는 계산과 저장 비용에도 직접 영향을 주기 때문에 가중치를 공개해도 모든 사용자가 같은 수준으로 활용할 수 있는 것은 아니다.

### 4.2 ROOTS와 다국어 훈련

ROOTS는 BLOOM 훈련을 위해 구성한 대규모 다언어 말뭉치다. 원문이 언급하는 ‘46개 언어와 13개 프로그래밍 언어’는 훈련 자료가 포괄한 범주를 가리킨다. 이는 영어 이외 언어의 존재를 크게 넓혔다는 뜻이지만, 언어별 데이터 양과 품질, 토큰화 효율, 평가 범위는 서로 다르다. 특히 ‘포함됐다’와 ‘그 언어에서 안정적으로 잘 작동한다’는 별개의 주장이다. 다국어 포괄성은 언어 수만이 아니라 데이터 획득 동의, 공동체 대표성, 정제 과정, 언어별 성능과 위해 평가를 함께 보아야 한다.

### 4.3 공개 접근, 오픈 소스, 민주화의 차이

가중치 공개(open weights)는 연구자가 모델 매개변수를 내려받아 검사할 수 있다는 뜻이다. 오픈 소스(open source)는 보통 소스 코드의 이용·수정·재배포 권리를 정해진 개방형 기준에 따라 보장한다는 더 엄격한 의미로 쓰인다. BLOOM은 BigScience RAIL 계열 라이선스로 배포되어 특정 유해 용도를 제한했으므로, ‘아무 조건 없는 공개’라고 설명하면 부정확하다. 민주화(democratization)는 이보다 더 넓은 정치·사회적 개념이다. 가중치 접근이 투명성과 감사 가능성을 높일 수는 있지만, 하드웨어·전력·저장 공간·전문 인력·언어 공동체의 의사 결정 권한까지 고르게 분배했는지는 별도로 평가해야 한다.

## 5. 원문의 논리 구조

원문은 대략 다음 흐름으로 전개됩니다.

1. 초거대 언어 모델의 역량과 통제가 소수 기업에 집중된 문제를 제기한다.
2. BigScience가 BLOOM을 개방적이고 국제적인 대안으로 개발했다고 설명한다.
3. 다국어 ROOTS 말뭉치, Transformer 구조, Jean Zay에서의 훈련과 공개 자료를 핵심 방법으로 제시한다.
4. 가중치 공개가 연구 접근성, 독립 평가, 언어 포괄성을 확대했다고 주장한다.
5. 이 사례가 이후 개방형 AI 연구, 정책·거버넌스, 국제 협업에 장기적인 영향을 주었다고 평가한다.

이 흐름에서 1~3은 비교적 구체적인 사실 주장이고, 4~5는 ‘접근성 확대’의 정도와 후속 프로젝트에 대한 인과 근거를 추가로 확인해야 하는 평가적 주장이다.

## 6. 왜 중요한가

BLOOM은 초거대 모델의 연구 대상을 최종 가중치에만 한정하지 않았다. 데이터 구축, 모델 카드, 라이선스, 협업 거버넌스, 계산 자원과 환경 비용을 함께 기록함으로써 ‘어떻게 만들고 공개할 것인가’도 기술 연구의 일부임을 보여 주었다. 독립 연구자는 폐쇄형 API만 사용할 때보다 모델을 직접 조사하고 변형하며 재현 가능한 실험을 설계할 여지가 커졌다. 다국어 데이터 구축 과정에 다양한 연구자가 참여한 점도 언어 포괄성을 단순한 벤치마크 점수 이상의 문제로 확장했다.

특히 중요한 점:

- 성능 경쟁과 별개로 가중치·코드·데이터 문서·위험 정보를 어느 범위까지 공개할지 실천적인 기준을 제시했다.
- 초거대 모델 개발을 기업 내부 프로젝트가 아닌 국제 연구 협업으로 수행할 수 있음을 실제 훈련으로 입증했다.
- 공개가 혜택만 낳는다는 단순한 서사를 피하고, 감사 가능성과 오용 위험, 접근 확대와 계산 자원 집중을 함께 검토하게 만들었다.

## 7. 현대 LLM과의 연결

BLOOM은 오늘날의 개방형 가중치 모델 생태계, 다국어 기반 모델, 책임 있는 배포 논의를 이해하는 중요한 연결점이다. 이후의 모델을 BLOOM의 직접적인 결과라고 단정하기보다, 비슷한 문제를 다룬 선행 사례와 비교 기준으로 보는 편이 안전하다.

- Transformer와 GPT 계열: [[055_The Transformer Attention Is All You Need]]의 자기주의 구조와 [[067_GPT-3 and In-Context Learning Emergent Capabilities from Scale]]의 디코더 전용 규모 확장 흐름을 다국어 공개 연구 환경으로 옮겼다.
- 교차언어 학습: [[062_XLM Cross-lingual Language Model for Multilingual NLP]]처럼 여러 언어 사이의 공유 표현을 활용하려는 흐름을 초거대 자기회귀 모델 규모에서 이어 갔다. 다만 다국어 사전학습만으로 지시 이행 능력이 생기는 것은 아니며, 후속 BLOOMZ는 별도의 다국어 지시 미세 조정을 사용했다.
- 평가와 감사: 공개 가중치는 [[079_HELM Holistic Evaluation of Language Models Framework]]처럼 여러 시나리오와 위험을 독립적으로 평가할 가능성을 넓힌다. 그러나 공개 여부와 평가의 포괄성은 자동으로 연결되지 않으므로 언어별 벤치마크와 위해 평가가 별도로 필요하다.

## 8. 한계와 비판적 관점

- 기술적 한계: BLOOM은 매우 큰 메모리와 연산 자원을 요구하며, 자연어·프로그래밍 언어별 학습량과 성능이 균등하지 않다. 다국어 사전학습은 사실성, 추론, 지시 이행, 안전성을 자동으로 해결하지 않는다.
- 이론적 한계: 더 많은 언어를 포함했다는 사실만으로 영어 중심 편향이나 문화적 편향이 ‘해소됐다’고 결론 낼 수 없다. 데이터 대표성과 모델 행동 사이의 관계는 언어별·과제별 평가가 필요하다.
- 실용적 한계: 가중치를 무료로 내려받을 수 있어도 대규모 추론·미세 조정 비용, 네트워크와 저장 공간, 전문 인력의 격차가 남는다. 책임 있는 AI 라이선스의 용도 제한도 이용 가능 범위를 규정한다.
- 오늘날 관점에서 다시 봐야 할 점: 공개는 투명성과 외부 감사를 촉진하는 동시에 오용 가능한 역량의 확산도 쉽게 할 수 있다. 따라서 ‘더 개방적일수록 언제나 더 책임 있다’는 식의 단선적 결론은 피해야 한다.

후속 공개 문서를 작성할 때는 다음 주장을 1차 자료로 대조해야 한다.

| 원문의 표현 | 검증할 사항 |
|---|---|
| “그 규모에서 처음 공개된 모델” | BLOOM과 OPT-175B 등 동시대 모델의 정확한 공개일, 가중치 접근 범위, 라이선스 차이를 비교해야 한다. |
| “최첨단(state-of-the-art)” | BLOOM 논문의 과제별 결과와 비교 모델을 확인해야 하며, 모든 언어·과제에서의 포괄적 우위로 일반화하면 안 된다. |
| “훈련 데이터·가중치·코드가 모두 공개” | ROOTS의 실제 배포 범위, 접근 조건, 저작권·라이선스 때문에 재배포되지 않은 구성 요소가 있는지 확인해야 한다. |
| “46개 언어로 편향을 해소” | 46개 자연어와 13개 프로그래밍 언어의 구분, 언어별 토큰 비중과 성능, 모델 카드의 편향·위해 보고를 확인해야 한다. |
| “민주화했다” | 접근자와 활용자의 지역·기관 분포, 실행 비용, 연구 참여권의 변화를 구분해야 한다. 가중치 공개만으로 민주화가 완성됐다고 볼 수 없다. |
| “후속 연구·정책·거버넌스에 영향을 주었다” | 구체적인 후속 프로젝트나 정책 문서가 BLOOM 또는 BigScience를 인용하는지 확인해야 한다. 시간적 선후만으로 직접 영향을 단정할 수 없다. |
| “70여 개국 1,000명 이상” | BLOOM 논문과 BigScience 공식 기록에서 참여자·국가·기관 집계 기준과 시점을 대조해야 한다. |
| “책임 있는 공개” | 적용된 BigScience RAIL 라이선스의 정확한 판본, 허용·금지 용도, 재배포 조건을 원문으로 확인해야 한다. |

우선 대조할 1차 자료는 BLOOM 논문과 모델 카드, ROOTS 말뭉치 논문·데이터 카드, BigScience RAIL 라이선스 원문, 훈련 자원과 탄소 배출을 다룬 공식 기술 보고서다.

## 12. 짧은 결론

BLOOM은 2022년 LLM 역사에서 ‘얼마나 큰 모델인가’와 함께 ‘누가, 어떤 데이터와 규칙으로 만들고 누구에게 어떻게 공개하는가’를 전면에 놓은 사례다. BigScience는 초거대 다국어 모델의 가중치와 개발 과정을 넓게 공개해 독립 연구와 감사의 가능성을 키웠지만, 라이선스 제약과 막대한 실행 비용, 언어별 불균형까지 없앤 것은 아니다. 따라서 BLOOM의 유산은 민주화의 완성이라기보다 개방성·책임·포괄성·자원 집중 사이의 긴장을 측정 가능한 연구 문제로 만든 데서 찾는 것이 가장 정확하다.
