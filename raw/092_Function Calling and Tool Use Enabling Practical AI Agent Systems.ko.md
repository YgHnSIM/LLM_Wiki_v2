# 함수 호출과 도구 사용: 실용적인 AI 에이전트 시스템을 가능하게 하다
원본 출처: https://mbrenndoerfer.com/writing/function-calling-tool-use-practical-ai-agents

2023년 언어 모델에 도입된 함수 호출 기능을 폭넓게 다루는 안내서다. 구조화된 출력, 도구와의 상호작용, API 통합, 그리고 외부 도구 및 환경과 상호작용하는 실용적인 AI 에이전트 시스템 구축에 미친 혁신적 영향을 살펴본다.

## 2023년: 함수 호출과 도구 사용

2023년 언어 모델에 [함수 호출](/writing/why-ai-agents-need-tools) 기능이 도입된 것은 실용적인 AI 에이전트 시스템 개발에서 획기적인 전환점이었다. 이 기능 덕분에 언어 모델은 외부 도구, API, 환경과 구조적이고 신뢰할 수 있는 방식으로 상호작용할 수 있게 되었다. 그전까지 언어 모델은 대체로 텍스트 생성에만 국한되었고, 외부 세계와의 상호작용도 텍스트 프롬프트와 응답으로 전달할 수 있는 범위에 머물렀다. 데이터베이스에 직접 접근하거나 코드를 실행하고, API를 호출하거나 외부 시스템을 조작할 수 없었기 때문에 이러한 제약은 언어 모델의 실용적 활용을 심각하게 제한했다. 함수 호출의 발전은 이 근본적인 제약을 바꾸어 놓았다. 언어 모델은 과업을 완수하기 위해 언제, 어떻게 도구를 사용할지 추론할 수 있는 능동적 에이전트가 될 수 있었다.

OpenAI는 2023년 6월 [GPT-3](/writing/gpt3-in-context-learning-emergent-capabilities-from-scale).5-turbo와 [GPT-4](/writing/gpt4-multimodal-language-models-reach-human-level-performance)에 통합된 함수 호출 기능을 공개했다. 이는 언어 모델을 현실 세계의 응용 분야에서 실용적으로 활용하게 만드는 데 중요한 진전이었다. 이 혁신을 통해 개발자는 함수나 도구를 모델에 설명할 수 있었고, 모델은 적절한 때에 이 함수를 호출할지 지능적으로 선택해 프로그램으로 실행할 수 있는 [구조화된 출력](/writing/structured-outputs-schema-validated-data-extraction-language-models)을 제공할 수 있었다. 이러한 발전은 AI 커뮤니티가 순수한 언어 생성 너머로 역량을 확장하기 위해 도구를 사용하는 에이전트 시스템의 구축 방법을 활발히 탐구하던 시기에 등장했다. 이전의 도구 증강 언어 모델 연구와 에이전트 프레임워크를 바탕으로 삼았지만, 신뢰할 수 있는 구조화된 출력과 함께 이 기능을 프로덕션에 적용할 수 있는 시스템으로 옮겨 놓았다.

[함수 호출](/writing/why-ai-agents-need-tools)의 더 넓은 의의는 단순한 기술적 능력에 그치지 않았다. 이 발전으로 실제 세계와 진정으로 상호작용할 수 있는 AI 에이전트를 만들 수 있게 되었고, 소프트웨어 개발과 데이터 분석부터 고객 서비스와 자동화에 이르는 여러 분야에 응용의 길이 열렸다. 자연어에서 구조화된 정보를 신뢰성 있게 추출하고 모델의 추론을 바탕으로 외부 함수를 호출하는 능력은 더욱 자율적이고 유능한 AI 시스템을 향한 한 걸음이었다. 또한 텍스트를 생성하는 것 외에는 실시간 정보에 접근하거나 세계에서 행동을 수행할 수 없다는 언어 모델의 근본적인 한계를 해결했다.

이 발전이 등장한 시점은 특히 중요했다. 2022년 말 [ChatGPT](/writing/chatgpt-conversational-ai-becomes-mainstream)가 처음 성공을 거둔 뒤, 함수 호출은 AI 배포에서 다음으로 중요한 질문, 즉 언어 모델을 프로덕션 시스템에서 실제로 유용하게 만드는 방법에 답했다. ChatGPT는 대화형 AI의 가치를 입증했지만 여전히 대체로 텍스트 생성 도구에 머물렀다. [함수 호출](/writing/why-ai-agents-need-tools)은 언어 모델과 현대 애플리케이션을 움직이는 광범위한 소프트웨어 도구 및 서비스 생태계를 이어 주는 다리였다. 이러한 연결은 기존 워크플로와 시스템에 매끄럽게 통합될 수 있는 실용적 AI 애플리케이션을 개발하는 데 결정적인 역할을 했다.

## 문제

[함수 호출](/writing/why-ai-agents-need-tools)이 등장하기 전 언어 모델에는 여러 실용적 응용 분야에서 진정으로 유용한 도구가 되지 못하게 하는 근본적인 한계가 있었다. 모델은 행동을 설명하거나 정보를 제공하는 텍스트를 생성할 수 있었지만, 실제로 그 행동을 수행하거나 실시간 정보에 접근할 수는 없었다. 언어 능력과 실용적 효용 사이의 이러한 간극 때문에 언어 모델이 이론적으로 도울 수 있는 일과 실제로 완수할 수 있는 일이 답답할 정도로 분리되어 있었다.

사용자가 언어 모델에 날씨 확인, 항공편 예약, 데이터베이스 질의를 부탁하는 상황을 생각해 보자. 모델은 마치 이런 일을 수행하는 듯한 텍스트를 생성할 수 있었다. 예를 들어 “날씨를 확인해 드리겠습니다”라고 말한 뒤 그럴듯한 일기 예보를 만들어 낼 수는 있었지만, 이는 실제 현재 날씨 정보가 아니라 학습 데이터의 패턴에 근거해 완전히 지어낸 내용이었다. 마찬가지로 모델은 항공편 예약 확인서처럼 보이는 텍스트를 만들 수 있었지만, 실제 예약이 아닌 무의미한 텍스트일 뿐이었다. 사용자는 모델의 텍스트 출력을 지침으로 삼으면서도 별도의 인터페이스를 통해 실제 작업을 직접 수행해야 했다.

문제는 구조화된 데이터 추출에도 이어졌다. 사용자가 대화에서 특정 정보를 추출해 프로그램에서 사용하려면 형식이 일관되지 않을 수 있는 자연어 출력을 파싱해야 했다. 모델은 어떤 응답에서는 “사용자의 이메일은 [john@example.com](mailto:john@example.com)입니다”라고 말하고, 다른 응답에서는 “연락처: [john@example.com](mailto:john@example.com)”이라고 할 수 있었다. 구조화된 데이터가 필요한 애플리케이션은 형식이 조금만 달라져도 쉽게 실패하는 취약한 텍스트 파싱에 의존해야 했다. 이 때문에 언어 모델과 다른 소프트웨어 시스템을 신뢰성 있게 통합하기가 어려웠다.

AI 기반 애플리케이션을 구축하는 개발자에게 언어 모델에서 [구조화된 출력](/writing/structured-outputs-schema-validated-data-extraction-language-models)을 얻을 수 없다는 점은 상당한 마찰을 일으켰다. 텍스트 응답에서 정보를 추출하기 위한 복잡한 파싱 로직을 작성하고, 여러 형식상의 불일치를 처리하며, 모델 출력이 예상 패턴과 맞지 않는 예외 상황에 대응해야 했다. 이는 개발 부담을 늘렸고 언어 모델 출력에 의존하는 애플리케이션에 실패 지점을 추가했다. 또한 구조화된 인터페이스가 없어서 여러 작업을 신뢰성 있게 연결하기 어려웠고, 자동화할 수 있는 과업의 복잡성도 제한되었다.

또 하나의 결정적 한계는 모델이 실시간 정보나 맥락 정보에 접근할 수 없다는 점이었다. 특정 날짜까지의 데이터로 학습한 언어 모델은 학습 데이터 기준 시점 이후에 발생한 사건, 가격, 시스템 상태를 알 수 없었다. 주가 확인, 사용자 계정 세부 정보 조회, 실시간 데이터베이스 질의처럼 최신 정보가 필요한 응용 분야에는 언어 모델을 적합하지 않게 만드는 요인이었다. 모델은 학습 데이터에 들어 있는 정보로만 작업할 수 있었고, 이는 많은 실용적 응용 분야에 근본적인 제약을 만들었다.

2023년 이전에 개발된 에이전트 프레임워크는 프롬프트 안의 [사고 연쇄](/writing/chain-of-thought-emergence-how-llms-learn-to-reason) 추론과 [도구 설명](/writing/designing-simple-tool-interfaces-ai-agents) 같은 기법으로 이러한 문제 중 일부를 다루기 시작했다. 그러나 이런 접근법은 신뢰성이 낮았다. 모델이 도구 설명을 잘못 이해하거나, 출력 형식을 올바르게 맞추지 못하거나, 실제 API 구조와 맞지 않는 함수 호출을 환각할 수 있었다. 함수를 설명하고 모델이 유효하며 실행 가능한 출력을 생성하도록 보장하는 표준화된 방법이 없었기에 이런 접근법은 프로덕션에 사용할 수 있는 수준에 이르지 못했다. 개발자는 광범위한 [오류 처리](/writing/plan-and-execute-ai-agents)와 재시도 로직을 구축해야 했고, 그 결과 에이전트 시스템은 복잡하고 취약해졌다.

## 해결책

[함수 호출](/writing/why-ai-agents-need-tools)은 언어 모델이 외부 함수와 상호작용하고 [구조화된 출력](/writing/structured-outputs-schema-validated-data-extraction-language-models)을 생성하는 표준화된 방법을 도입함으로써 이러한 문제에 해결책을 제시했다. 해결책은 두 가지 핵심 요소로 이루어졌다. 하나는 함수를 모델에 설명하는 구조화된 방법이고, 다른 하나는 모델이 그 설명과 정확히 일치하는 함수 호출을 요청하도록 하는 신뢰할 수 있는 메커니즘이었다.

함수 호출은 기본적으로 개발자가 구조화된 형식, 일반적으로 JSON Schema를 사용해 함수 스키마를 언어 모델에 제공할 수 있게 하는 방식으로 작동했다. 이 스키마는 함수의 이름과 목적, 그리고 매개변수의 자료형과 제약 조건을 설명했다. 그러면 모델은 대화 맥락을 바탕으로 함수를 호출할지, 호출한다면 어떤 매개변수를 사용할지 추론할 수 있었다. 모델의 응답에는 제공된 스키마에 맞춘 형식으로 특정 매개변수와 함께 특정 함수를 호출해 달라는 구조화된 요청이 포함되었다.

기술적 구현에서는 함수 설명을 인식하고 함수 호출 요청을 특별한 출력 유형으로 생성하도록 언어 모델의 학습 및 추론 과정을 확장했다. 대화에서 함수 스키마가 제시되면 모델은 해당 함수를 호출하는 것이 도움이 되는 상황을 알아보는 법을 학습했다. 모델은 텍스트만 생성하는 대신, 애플리케이션이 프로그램으로 실행할 수 있는 구조화된 함수 호출을 생성할 수 있었다.

[함수 호출](/writing/why-ai-agents-need-tools) 메커니즘은 일반적인 텍스트 생성과 분리된 [구조화된 출력](/writing/constrained-decoding-structured-llm-output) 형식을 사용했다. 모델이 함수를 호출하기로 결정하면 함수 호출임을 나타내는 특수 토큰이나 형식을 출력하고, 이어서 함수 이름과 매개변수가 담긴 JSON 객체를 출력했다. 애플리케이션은 이 구조화된 형식을 신뢰성 있게 파싱할 수 있었으므로 취약한 텍스트 파싱이 필요하지 않았다. 형식은 결정적이며 스키마로 검증되었고, 따라서 함수 호출은 설명된 인터페이스와 정확히 일치했다.

시스템에는 함수 응답을 처리하는 메커니즘도 포함되었다. 애플리케이션이 함수 호출을 실행해 결과를 얻은 뒤에는 그 결과를 도구 응답으로 모델에 다시 제공할 수 있었다. 그러면 모델은 이 정보를 추론에 반영하고, 함수 결과를 참조하는 자연어 응답을 사용자에게 생성할 수 있었다. 이로써 하나의 순환 과정이 만들어졌다. 모델은 어떤 정보나 행동이 필요한지 추론하고, 이를 얻기 위한 함수 호출을 요청하고, 결과를 처리한 뒤, 종합적인 응답을 제공할 수 있었다.

OpenAI의 구현에는 [함수 호출](/writing/why-ai-agents-need-tools)을 실용적이고 신뢰할 수 있게 만든 몇 가지 중요한 설계 결정이 도입되었다. 모델은 모든 프롬프트에 명시적인 지시를 요구하는 대신, 맥락을 바탕으로 함수 호출이 적절한 때를 인식하도록 학습되었다. 모델은 여러 함수를 동시에 다루면서 사용자의 요청에 따라 적절한 함수를 선택할 수 있었다. 출력 형식은 제공된 스키마와 일치하는 JSON을 사용해 엄격하게 구조화되었으므로, 개발자가 쉽게 파싱하고 검증할 수 있었다.

또한 시스템은 사용자의 요청이 대화 형식이더라도 구조화된 정보를 추출하기 위해 항상 함수를 호출하도록 모델에 지시할 수 있는 모드를 지원했다. 이를 통해 텍스트에서 개체를 추출하거나, 콘텐츠를 분류하거나, 사용자의 의도를 구조화된 형식으로 파싱하는 사례가 가능해졌다. 모델은 정교한 파서처럼 작동하며 언어 이해 능력으로 자연어 입력에서 구조화된 데이터를 높은 [신뢰성](/writing/monitoring-reliability-ai-agents)으로 추출할 수 있었다.

## 응용과 영향

[함수 호출](/writing/why-ai-agents-need-tools)은 언어 모델만으로는 구축하기 어렵거나 불가능했던 광범위한 실용적 응용을 가능하게 했다. 가장 즉각적인 응용 분야 중 하나는 소프트웨어 시스템 및 API와 상호작용할 수 있는 AI 에이전트의 구축이었다. 개발자는 자연어 상호작용만으로 이메일을 확인하고, 데이터베이스를 질의하며, API를 호출하거나 소프트웨어 시스템을 제어할 수 있는 에이전트를 만들 수 있었다. 에이전트는 사용자의 요청을 이해하고 어떤 함수를 호출할지 추론한 다음, 그 함수를 실행하고 결과를 바탕으로 의미 있는 응답을 제공했다.

함수 호출 기능은 고객 서비스 애플리케이션을 혁신했다. 언어 모델은 이제 텍스트 응답만 생성하는 대신 고객 데이터베이스에 접근해 계정 정보를 조회하고, 주문 상태를 확인하고, 계정 설정을 변경하거나 다른 작업을 수행할 수 있었다. 함수 호출로 구축한 고객 서비스 에이전트는 “제 주문 상태가 어떻게 되나요?”라는 질문을 받으면 그럴듯하지만 지어낸 응답을 생성하는 대신, 실제로 주문 데이터베이스를 질의해 현재의 실제 정보를 제공할 수 있었다.

소프트웨어 개발 분야에서 [함수 호출](/writing/why-ai-agents-need-tools)은 개발 도구와 상호작용할 수 있는 강력한 코딩 도우미를 가능하게 했다. 이런 도우미는 문서를 검색하고, 코드를 실행하고, 함수를 테스트하고, 파일을 읽는 등 여러 개발 작업을 수행할 수 있었다. 코드 제안을 생성하는 데 그치지 않고 실제로 테스트를 실행하고, 결과를 확인하고, 피드백에 따라 반복적으로 개선할 수 있었다. 이로써 AI 도우미가 소프트웨어 개발 워크플로에 능동적으로 참여할 수 있는 새로운 부류의 개발 도구가 등장했다.

데이터 분석 애플리케이션도 혁신되었다. 함수 호출 기능을 갖춘 언어 모델은 자연어 상호작용만으로 데이터베이스를 질의하고, 분석 스크립트를 실행하고, 시각화를 생성하고, 데이터에서 통찰을 추출할 수 있었다. 사용자가 자신의 데이터에 대해 복잡한 질문을 하면 모델은 어떤 질의나 분석을 실행할지 판단하고 이를 실행한 뒤 결과를 설명했다. 그 결과 비기술 사용자도 데이터 분석에 더 쉽게 접근할 수 있게 되었으며, 강력한 자동 분석 워크플로도 가능해졌다.

전자상거래와 비즈니스 자동화 분야에서도 [함수 호출](/writing/why-ai-agents-need-tools)의 수많은 응용 사례가 나타났다. AI 에이전트는 재고 수준을 확인하고, 주문을 처리하고, 고객 기록을 갱신하고, 보고서를 생성하며, 일상적인 비즈니스 과업을 자동화할 수 있었다. 이런 에이전트는 API를 통해 기존 비즈니스 시스템과 통합되어 복잡한 백엔드 시스템에 자연어 인터페이스를 제공할 수 있었다. 이로써 기업은 새로운 방식으로 워크플로를 자동화하고 고객 서비스를 제공할 수 있게 되었다.

함수 호출은 언어 이해와 현실 세계의 행동을 결합한 새로운 유형의 AI 기반 애플리케이션도 가능하게 했다. 여행 도우미는 항공편의 좌석과 가격을 실시간으로 확인하고, 예약하며, 여행 일정 정보를 제공할 수 있었다. 개인 도우미는 일정을 관리하고, 이메일을 보내고, 알림을 설정하고, 다양한 생산성 도구와 상호작용할 수 있었다. 연구 도우미는 학술 데이터베이스를 검색하고, 논문을 가져오며, 여러 출처의 정보를 종합할 수 있었다.

그 영향은 더욱 정교한 에이전트 프레임워크와 아키텍처의 개발로도 이어졌다. 함수 호출은 에이전트가 과업을 추론하고, 이를 하위 과업으로 나누고, 정보를 수집하거나 행동을 수행하기 위해 함수를 호출하고, 결과를 종합하는 복잡한 다단계 워크플로를 개발자가 구축할 수 있는 토대를 제공했다. 이로써 여러 도구와 정보 출처를 조율해야 하는 복잡한 다단계 문제를 처리할 수 있는 에이전트 시스템을 개발할 수 있게 되었다.

[신뢰성](/writing/monitoring-reliability-ai-agents)과 구조를 갖춘 [함수 호출](/writing/why-ai-agents-need-tools) 출력은 더욱 견고한 프로덕션 애플리케이션을 만드는 데도 기여했다. 애플리케이션은 함수 호출의 매개변수를 스키마와 대조해 검증하고, 오류를 안정적으로 처리하며, 형식이 일관되게 유지된다는 확신을 바탕으로 작업을 재시도할 수 있었다. 이는 언어 모델로 에이전트 시스템을 구축하려던 이전의 시도를 괴롭혔던 취약성을 줄여 AI 기반 자동화를 더욱 신뢰할 수 있고 믿을 만하게 만들었다.

## 한계

혁신적인 영향에도 불구하고 [함수 호출](/writing/why-ai-agents-need-tools)에는 응용 범위를 제한하고 앞으로 발전해야 할 영역을 보여 주는 몇 가지 중요한 한계가 있었다. 근본적인 한계 중 하나는 모델이 함수를 언제, 어떻게 사용할지 올바르게 추론해야 한다는 점이었고, 이러한 추론은 여전히 예외적인 상황에서 실패할 수 있었다. 모델이 잘못된 함수를 선택하거나, 부정확한 매개변수를 제공하거나, 함수 호출이 필요한 상황을 알아보지 못할 수 있었다. 이런 오류는 애플리케이션의 실패나 잘못된 행동으로 이어질 수 있었으므로, 개발자는 광범위한 [오류 처리](/writing/plan-and-execute-ai-agents)와 검증 로직을 구축해야 했다.

함수 호출의 [신뢰성](/writing/monitoring-reliability-ai-agents)은 모델에 제공하는 함수 설명의 품질에 달려 있었다. 함수 스키마가 모호하거나 불완전하거나 부실하게 설명되어 있으면 모델은 사용법을 잘못 이해할 수 있었다. 모델이 함수를 올바르게 사용하도록 개발자는 함수 설명, 매개변수 이름, 문서를 세심하게 작성해야 했다. 이는 개발자에게 추가 부담을 주었고 프롬프트 엔지니어링과 스키마 설계에 관한 전문성을 요구했다.

[함수 호출](/writing/why-ai-agents-need-tools)은 새로운 보안 및 안전 문제도 불러왔다. 텍스트 생성과 달리 함수 호출은 데이터를 수정하고, 물건을 구매하고, 이메일을 보내는 등 실제 결과를 초래하는 행동을 수행할 수 있었다. 이 때문에 악의적 사용, 우발적 행동, 무단 접근의 위험이 생겼다. 함수 호출을 사용하는 애플리케이션은 함수 호출이 적절하고 안전한지 보장하기 위해 세심한 권한 부여와 검증을 구현해야 했다. 모델 자체는 안전한 행동과 위험한 행동을 언제나 구별할 수 있는 것은 아니었으므로 애플리케이션 수준의 안전장치가 필요했다.

함수 호출의 구조적 특성에는 유연성 측면의 한계도 있었다. [구조화된 출력](/writing/structured-outputs-schema-validated-data-extraction-language-models)은 [신뢰성](/writing/monitoring-reliability-ai-agents) 측면에서 가치가 있었지만, 미리 정의된 스키마에 깔끔하게 들어맞지 않는 미묘하거나 복잡한 정보를 표현하는 모델의 능력을 제약하기도 했다. 매우 유연하거나 창의적인 출력이 필요한 애플리케이션에는 함수 호출이 지나치게 경직되어 있을 수 있었고, 이런 경우 함수 제약 없이 언어 모델이 제공하는 자유 형식 텍스트 생성을 선호할 수 있었다.

또 다른 한계는 [함수 호출](/writing/why-ai-agents-need-tools) 워크플로에 수반되는 오버헤드였다. 함수 호출 한 번마다 함수 스키마와 함께 대화를 전송하고, 함수 호출 요청을 받고, 함수를 실행하고, 결과를 모델에 다시 보내는 여러 차례의 API 상호작용이 필요했다. 이로 인해 지연 시간과 비용이 발생했으며, 직접적인 텍스트 생성으로 처리할 수 있는 단순한 과업에는 불필요할 수 있었다. 애플리케이션은 함수 호출의 이점과 이러한 오버헤드 사이에서 균형을 잡아야 했고, 간단한 과업에는 때때로 더 단순한 접근법을 선택했다.

함수 호출에 관해 추론하는 모델의 능력은 학습 데이터와 추론 역량의 제약도 받았다. 함수가 수행하는 과업이 모델의 학습 데이터에 충분히 나타나 있지 않거나 과업에 전문적인 도메인 지식이 필요하다면 모델은 함수를 적절히 사용하는 데 어려움을 겪을 수 있었다. 이 때문에 일반적인 사용 패턴을 벗어난 고도로 전문적이거나 새로운 응용 분야에서는 함수 호출의 효과가 제한되었다.

함수 호출은 실시간 정보와 관련된 언어 모델의 근본적인 한계도 해결하지 못했다. 함수가 최신 데이터를 제공할 수는 있었지만, 모델 자체는 여전히 학습으로 얻은 지식을 바탕으로 작동했기 때문에 학습 이후에 등장한 최근 사건, API 변경, 도메인별 맥락을 이해하지 못할 수 있었다. 모델은 정보를 얻기 위해 함수를 호출할 수 있었지만, 관련 맥락이 부족하다면 어떤 함수를 호출하거나 어떤 질문을 해야 할지 알지 못할 수 있었다.

## 유산과 전망

[함수 호출](/writing/why-ai-agents-need-tools)은 현대 언어 모델 애플리케이션의 중심이 된 [AI 에이전트 구축](/writing/personal-assistant-ai-agent-journey) 시스템의 토대가 되는 패턴을 확립했다. 도구를 모델에 설명하고 구조화된 상호작용을 가능하게 하는 접근법은 에이전트 프레임워크, AI 기반 애플리케이션, 언어 모델 API 설계의 발전에 영향을 미쳤다. 이 패턴은 매우 유용한 것으로 입증되어 여러 언어 모델 제공업체가 채택했고, 현대 AI 개발의 표준 기능이 되었다.

함수 호출의 도입은 언어 모델을 개념화하고 배포하는 방식의 전환점이었다. 모델은 순수한 텍스트 생성기가 아니라 외부 도구와 서비스를 조율할 수 있는 추론 시스템으로 인식되기 시작했다. 이러한 관점의 변화는 더욱 정교한 에이전트 아키텍처, [멀티 에이전트 시스템](/writing/what-are-ai-agents), 언어 이해와 행동 수행 능력을 결합한 AI 애플리케이션의 발전에 영향을 주었다.

현대 AI 에이전트 프레임워크는 [함수 호출](/writing/why-ai-agents-need-tools) 패턴을 광범위하게 토대로 삼아 도구 사용과 외부 상호작용의 핵심 메커니즘으로 활용한다. [LangChain](/writing/building-intelligent-agents-langchain-langgraph-part-1-core-concepts), LangGraph 등의 프레임워크는 언어 모델과 함께 함수를 더 쉽게 정의하고 사용할 수 있는 추상화를 제공하는 한편, 함수 결과 검증, [오류 처리](/writing/plan-and-execute-ai-agents), 워크플로 조율과 같은 기능도 추가한다. 함수 호출 패턴은 이제 AI 에이전트 시스템의 기본 구성 요소로 여겨질 만큼 근본적인 요소가 되었다.

함수 호출의 발전은 언어 모델 개발과 에이전트 아키텍처의 연구 방향에도 영향을 미쳤다. 연구자들은 모델이 여러 함수를 동시에 요청할 수 있는 병렬 함수 호출과 도구 선택 및 순서 결정에 관한 더욱 정교한 추론 같은 확장 기법을 탐구해 왔다. 또한 이 패턴은 언어 인터페이스뿐 아니라 다양한 도구를 사용할 수 있는 멀티모달 모델 연구에도 영향을 주어, 비전, 오디오 등의 양식을 에이전트 시스템에 통합하는 데 기여했다.

앞으로도 함수 호출은 모델 추론 능력의 향상, 더 나은 함수 설명 메커니즘, 더욱 정교한 에이전트 아키텍처와 함께 계속 발전할 것이다. 이 패턴은 코딩 도우미와 데이터 분석 도구부터 고객 서비스 에이전트와 자동화 시스템까지, 언어 이해를 현실 세계의 행동과 실제로 통합하는 새로운 세대의 AI 애플리케이션을 가능하게 했다. 언어 모델의 역량이 커지고 에이전트 프레임워크가 더욱 정교해짐에 따라, [함수 호출](/writing/why-ai-agents-need-tools)은 순수한 언어 생성을 넘어서는 실용적인 AI 애플리케이션의 핵심 동력으로 남을 것이다.

함수 호출의 유산은 행동을 수행하는 시스템에서 AI 안전과 [신뢰성](/writing/monitoring-reliability-ai-agents)을 바라보는 방식으로도 이어진다. 안전하고 적절한 함수 호출을 보장하는 과제는 AI 에이전트 시스템을 위한 더 나은 검증, 권한 부여, 안전 메커니즘의 연구를 촉진했다. 이러한 발전은 함수 호출뿐 아니라 현실 세계에 영향을 미치는 시스템에 AI를 안전하게 배포하는 더 넓은 분야에도 함의를 지닌다.

함수 호출은 언어 모델을 실용적으로 배포하는 과정에서 결정적인 이정표다. 올바른 인터페이스와 학습이 주어지면 모델이 텍스트 생성 이상의 일을 할 수 있음을 보여 주었다. 이 발전은 AI 애플리케이션에 새로운 가능성을 열었고, 오늘날 AI 시스템 구축 방식을 계속 형성하는 패턴을 확립했다. 에이전트 시스템의 역량이 커지고 더 널리 보급됨에 따라 함수 호출 패턴은 여전히 토대가 되는 요소로 남아, 언어 이해와 현실 세계의 행동 사이를 잇는 다리를 제공하고 진정으로 유용한 AI 애플리케이션을 가능하게 한다.
